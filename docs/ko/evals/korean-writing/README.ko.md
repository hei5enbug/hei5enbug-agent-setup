# 한국어 글쓰기 평가

> 영어 원본: [README.md](../../../../evals/korean-writing/README.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

이 평가는 어떤 모델이 사람이 읽을 한국어 글을 가장 자연스럽게 쓰는지 측정한다. `language` 기능과
`scripts/text_review.py`의 모델이 인상이 아니라 기록된 비교에 근거하게 하려는 것이다. 이슈 #72에 답한다. 실제
모델 세션을 실행하고 실제 사용량을 쓰므로 저장소 README의 개발 검사에는 들어가지 않으며, 개발 검사에 들어가는 것은
단위 테스트 `tests/test_korean_writing_eval.py`뿐이다.

## 질문

가상의 출처로 만든 다섯 종류의 한국어 글에서, 후보 작성자 한 모델의 초안을 두 모델 계열의 채점자가 모두 작업 실행의
과반에서 1위로 고르고, 필수 사실이 모두 들어 있으며 사실이 추가되지 않았는가? 그렇다면 그 후보가 이긴다. 아니면 결과는
결론 없음이고 현재 모델을 유지한다.

## 작업

`cases.json`은 작업 다섯 개를 고정한다. 각 작업에는 글 종류, 독자, 가상의 출처, 뜻으로 확인하는 필수 사실이 있으며
작업마다 사실은 다섯 또는 여섯 개다.

| 작업 | 종류 | 출처 |
|---|---|---|
| `t1` | 티켓 댓글 | `demo-a`에 관한 티켓 `ABC-123`과 수정에 대한 영어 개발 메모 |
| `t2` | 채팅 메시지 | `demo-a` 2.3.0 릴리스 노트 초안 |
| `t3` | 풀 리퀘스트 설명 | 웹훅 재시도에 관한 작성자의 영어 작업 메모 |
| `t4` | 공유 문서 섹션 | `main` 리뷰 규칙에 관한 핸드북 메모 |
| `t5` | 최종 보고 | 사용자 요청과 에이전트의 작업 기록 |

작업, 사실, 시드 쌍은 새로 고정한 집합으로만 바꾸고, 기준 모델을 그 집합에서 다시 실행한다.

## 실행기

`kw_run.py`에는 명령이 세 개 있다. 저장소 루트에서 실행한다.

```text
python3 evals/korean-writing/kw_run.py run       --out <folder> [--runs 5] [--tasks t1,t3] [--parallel 4]
python3 evals/korean-writing/kw_run.py seeded    --out <folder>
python3 evals/korean-writing/kw_run.py aggregate --out <folder>
```

`--writer <host>:<model id>`와 `--grader <host>:<model id>`는 기본값을 바꾸며 모델마다 한 번씩 반복한다. host는
`codex` 또는 `claude`다. 기본값은 후보 네 개 `codex:gpt-6.1-sol`, `claude:claude-opus-5-5`,
`codex:gpt-6.1-terra`, `claude:claude-fable-5-2`와 채점자 둘 `codex:gpt-6-astra`, `claude:claude-opus-5-5`다. 이미
있는 출력 폴더는 이어서 실행하며, 끝난 초안과 채점은 다시 실행하지 않는다.

| 설정 | 값 |
|---|---|
| 글쓰기 규칙 | 실행 시점에 `instructions/shared-text.md`에서 읽는다. "Cut and completeness passes"의 1, 2번 항목과 "Readable shared text" 전체다. 실행기가 사본을 두지 않으므로 규칙이 어긋나지 않는다. |
| Claude Code 호출 | `claude -p --model <id> --effort high --output-format json --strict-mcp-config --tools ""`에 플러그인을 끄는 설정 파일을 준다. 결과의 `modelUsage`가 요청한 모델을 가리키지 않으면 그 초안은 실패로 센다. |
| Codex 호출 | 출력 폴더 아래 빈 폴더에서 `codex exec -m <id> -c model_reasoning_effort="high" -s read-only --ephemeral --ignore-user-config --ignore-rules`를 실행한다. 플러그인을 불러오지 않고 모델이 쓸 수 있는 명령이나 파일이 없다. |
| 작성자 입력 | 모든 후보에게 같은 규칙, 종류, 독자, 출처를 준다. 모델은 아무것도 실행하거나 찾아볼 수 없다. |
| 병렬 실행 | 한 번에 호출 네 개, 호출당 900초 제한, 전체 실행 3시간 제한. |
| 실패 | 실패한 호출은 공유 예산 10회 안에서 다시 시도한다. 연속으로 두 번 실패한 모델은 제외하고 이유를 `campaign.json`에 적는다. 할당량 메시지가 나오면 실행을 멈춘다. |

출력 폴더에는 `drafts/`, `grades/`, `seeded/`, `prompts/`(작성자와 채점자에게 준 정확한 프롬프트), `raw/`(CLI 출력),
`run.log`, `campaign.json`이 있고, `aggregate` 뒤에는 `summary.json`이 생긴다.

## 블라인드 채점

작업과 실행마다 모든 후보의 초안을 라벨 A, B, C, D를 붙여 채점자 프롬프트 하나에 넣는다. 라벨 순서는 작업과 실행으로
시드를 준 무작위 섞기에서 나오므로 실행마다 다르지만 같은 실행을 반복하면 같다. 프롬프트에는 규칙, 출처, 필수 사실,
초안이 들어 있고 작성자 이름은 없다.

채점자는 초안마다 빠진 필수 사실, 추가된 사실, 어색하거나 번역투인 표현을 인용과 함께 돌려준다. 그다음 빠진 사실도
추가된 사실도 없는 초안을 가장 자연스러운 것부터 순위를 매기고, 모든 초안을 자연스러움만으로 매긴 순위도 낸다. 사실이
빠진 초안은 아무리 자연스러워도 사실 기준에서 실패한다. 실행기는 작업 실행마다 계열별 채점자를 하나씩 시작한다.

## 시드 검사

`seeded.json`에는 계획된 결함 하나만 다른 초안 쌍이 둘 있다. `kw_run.py seeded`는 채점자마다 각 쌍을 두 초안 순서로
모두 실행하고, 채점자가 아래처럼 행동할 때만 잡았다고 센다.

| 쌍 | 심은 결함 | 채점자가 해야 하는 일 |
|---|---|---|
| `s1_missing_fact` | 티켓 댓글에서 스테이징 검증(`t1`, 사실 `f4`)이 빠졌다 | 그 초안에서 `f4`가 빠졌다고 보고하고 다른 초안에는 빠진 것이 없다고 하며, 다른 초안만 순위에 넣는다 |
| `s2_calque` | 핸드북 섹션이 규칙을 뜻하는 자리에 계약을 썼다(`t4`) | 사실 문제를 보고하지 않고, 고친 초안을 1위로 두며, 결함 있는 초안에서 어색한 표현을 더 많이 든다 |

전체 실행 전에 시드 검사를 실행한다. 하나라도 놓치는 채점자의 순위는 믿을 수 없다.

## 결정 규칙

두 계열의 채점자가 모두 채점된 작업 실행의 과반에서 한 후보를 1위로 고르고, 어느 채점자도 그 후보의 초안에서 빠진
사실이나 추가된 사실을 보고하지 않을 때만 그 후보가 이긴다. 아니면 결과는 결론 없음이며 현재 `language` 모델과 검토
모델을 유지한다. `aggregate`가 이 규칙을 적용한다. 후보당 초안이 다섯 개보다 적은 결과는 확정되지 않은 것으로
표시한다.

경과 시간과 호스트가 보고한 비용은 후보마다 기록하지만 승자를 정하지는 않는다. 품질이 먼저다. 이 규칙은 사실 실패나
덜 자연스러운 초안을 속도나 가격과 맞바꾸지 않는다.

## 결과

2026-11-10에 실행했다. 후보 작성자 넷, 채점자 둘, 작업 다섯, 작업당 실행 다섯 번이므로 초안 100개, 채점자당 채점된
작업 실행 25개다. 실패하거나 다시 시도한 호출은 없고 제외된 후보도 없다. 시드 검사는 채점자 실행 8번(쌍 2, 순서 2,
채점자 2) 모두에서 잡았다. 각 채점자는 작업 실행 하나에서 사실 문제가 없는 초안을 찾지 못해 거기서는 1위를 매기지
않았으므로 1위 횟수의 합이 25가 아니라 24다.

| 후보 | 1위, `gpt-6-astra` | 1위, `claude-opus-5-5` | 사실이 빠진 초안, astra / opus | 사실이 추가된 초안, astra / opus | 어색한 표현, astra / opus | 작성 시간 중앙값 |
|---|---|---|---|---|---|---|
| `gpt-6.1-sol` | 13 | 6 | 25개 중 6 / 5 | 25개 중 0 / 1 | 21 / 73 | 99초 |
| `claude-opus-5-5` | 4 | 4 | 25개 중 3 / 0 | 25개 중 10 / 11 | 55 / 65 | 53초 |
| `gpt-6.1-terra` | 4 | 4 | 25개 중 13 / 10 | 25개 중 0 / 1 | 24 / 67 | 75초 |
| `claude-fable-5-2` | 3 | 10 | 25개 중 2 / 0 | 25개 중 6 / 5 | 45 / 55 | 41초 |

Claude Code CLI는 `claude-opus-5-5` 초안 25개에 0.84달러, `claude-fable-5-2` 초안 25개에 2.24달러를 보고했다. Codex
CLI는 토큰은 보고하지만 비용은 보고하지 않으므로 GPT 후보 둘의 비용은 기록하지 않았다. 두 채점자가 1위에 동의한
작업 실행은 25개 중 12개다.

판정: 결론 없음, 언어 모델과 검토 모델은 그대로 둔다. 두 채점자가 모두 작업 실행의 과반에서 1위로 고른 후보가 없었다
(한 후보가 얻은 최대는 25개 중 13개이고 그것도 한 채점자에서만이다). 모든 후보에게 사실이 빠졌거나 추가된 초안이
있었다.

### 한계

- 결과는 채점자당 작업 실행 25개를 한 번 돌린 것이다. 어느 후보가 더 나은지는 보여 주지 못하고, 이번 측정에서
  승자가 나오지 않았다는 것만 보여 준다.
- 채점자는 각자 자기 계열을 편들었다. `gpt-6-astra`는 GPT 후보 `gpt-6.1-sol`을 가장 자주 1위로 골랐고,
  `claude-opus-5-5`는 Claude 후보 `claude-fable-5-2`를 가장 자주 1위로 골랐다. 두 계열 규칙은 이 때문에 있다.
- 다른 평가가 동시에 실행되었으므로 작성 시간은 교란되어 있으며 대략의 크기만 보여 준다.
- 어색한 표현의 개수는 채점자가 얼마나 많이 드는가에 달려 있다. `claude-opus-5-5`는 모든 후보에서 `gpt-6-astra`보다
  많이 들므로, 개수는 한 채점자 안에서만 비교한다.
- 이슈 #72가 제안한 채점자가 엇갈릴 때의 소유자 선택은 쓰지 않았다. 두 채점자 모두의 과반이 필요한 판정을 바꿀 수
  없기 때문이다.
- 초안은 출력 폴더에 보관하며 여기에 옮겨 적지 않는다.
