# 구현 위임

> 영어 원본: [implementation-delegation.md](../../../instructions/implementation-delegation.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

구현을 worker나 designer에게 위임하기 전에 [구현 실행](implementation-execution.ko.md)을 읽은 다음 이 파일을 읽는다.
현재 호스트의 에이전트 규칙이 worker 도구, 고정 모델과 설정 근거를 관리한다. 할당받은 worker는 세션 지침이나 할당에서
아래의 "할당받은 worker" 섹션을 받으며 이 파일을 읽지 않는다.

레이아웃과 컴포넌트 구조를 유지하는 문구·스타일 값만의 수정은 designer 대신 구현 worker가 맡을 수 있다.

## Worker 할당

모든 worker 할당에는 할당받은 worker라는 사실, 다른 worker가 작업 공간을 수정할 수 있다는 사실과 그 변경을 보존해야
한다는 사실을 알린다. 저장소 실행 계획은 이 항목을 한 번만 기록한다. 각 worker 프롬프트에는 자기 작업과 그 작업에
필요한 맥락만 담는다.

## 일정 관리

각 작업은 호스트의 기존 작업 관리 기능이나 대화에서 `pending`, `running`, `done`, `blocked` 중 하나로 추적한다.
영구 작업 데이터베이스는 추가하지 않는다. 선행 조건이 조정자의 수용 확인을 통과하고 수정 경로와 자원이 비어 있을
때만 작업이 준비 상태가 된다. 수용 확인을 통과하려면 작업에 할당된 검증이 통과해야 한다. 작업과 그 선행 작업을
한 할당에 넣지 않는다. 파일만 공유하는 작업은 worker 하나에게 순서대로 맡길 수 있다.

추가로 시작할 worker 수는 `min(6 - 실행 중인 구현 worker 수, 남은 호스트 자리, 준비된 독립 작업 수)` 이하로 한다.
호스트가 실제로 정의한 한도와 남은 자리를 기준으로 한다. 이 한도에는 메인 세션이나 다른 에이전트가 포함될 수 있다.
예를 들어 메인 세션을 포함해 에이전트 4개가 한도라면 worker는 최대 3개다.

준비된 독립 작업은 함께 시작한다. 일곱 번째 작업처럼 넘치는 작업은 대기열에 두고, 자리와 자원이 비면 배정한다.
호스트 한도를 올려 달라고 요청하지 않는다.

담당 범위가 충돌하는 작업은 절대 겹쳐 실행하지 않는다. 공유 파일, 잠금 파일, 생성 결과물, 데이터베이스, 포트,
빌드 디렉터리를 쓰는 작업은 계획이 작업마다 독립 자원을 제공하지 않는 한 순서대로 실행한다. 수정하는 파일이
다르다는 사실만으로는 독립성이 입증되지 않는다.

## 검토와 통합

담당자가 바뀌었다는 이유만으로 작업자의 유효한 검사 결과를 다시 실행하지 않는다.

의존 작업을 풀기 전에 각 worker가 반환한 변경과 근거를 검토한다. 작업을 수정한 모든 턴에 대해 호스트 기록 또는
호스트 에이전트 규칙이 정한 강제 장치(예: Mod의 역할 고정이나 역할 실행기의 검증)가 선택한 모델과 사고 강도를
보여 줄 때만 위임한 작업을 승인한다. 메인 세션은 자신이 담당한 경로의 통합 수정을 직접 할 수 있다. 다른 담당자가
있으면 worker가 멈춘 뒤 담당 범위를 넘겨받는다. worker가 입력이나 출력 디렉터리를 바꾸는 동안에는 공유 빌드를
실행하지 않는다.

## 실패와 복구

실패하면 의존 작업을 보류하고 완료된 작업을 보존한다.
원인 진단과 수정 방향은 메인 세션에서 정한다. 이전 담당자가 멈춘 뒤에만 worker를 재개하거나 교체하고, 새 담당자에게
현재 diff와 수정한 작업을 준다.

위임에 실패하면 세션의 대체 처리 규칙을 적용한다. 해당 worker를 멈춘 뒤 담당 범위를 넘겨받고 부분 diff를 확인한 다음
남은 승인 작업을 호스트가 정한 대체 경로로, 그런 경로가 없으면 메인 세션에서 계속한다. 검증되지 않은 작업자 결과를
완료로 승인하지 않는다. 입력이 바뀌지 않은 검사는 결과를 재사용한다. 이미 확인한 사용량 한도나 기능 실패를 반복
재시도하지 않고, 상태가 바뀐 근거가 있을 때만 재검토한다. 대체 처리는 빠진 사용자 결정, 권한 제한 또는 실패한 수용
검사를 우회하지 않는다.

## 모델과 사고 강도

위임한 구현은 호스트 에이전트 규칙이 고정한 모델 ID와 사고 강도를 사용한다. 실행 중에 새 릴리스를 찾거나 제공자
별칭을 따르거나 다른 작업자 모델로 바꾸지 않는다. 다만 호스트 에이전트 규칙이 이름 붙인 대체 경로는 예외다. 고정값은
저장소를 수정할 때 갱신한다. 고정 모델이나 사고 강도를 쓸 수 없으면 다른 모델을 고르지 말고, 이름 붙은 대체 경로가
있으면 그 경로를, 없으면 세션의 대체 처리 규칙을 적용한다.

고정 모델 ID와 사고 강도를 각 worker 할당에 기록하고 그 실행 동안 재사용한다.

관련 있는 비밀이 아닌 설정 항목만 살펴본다. 요청한 설정만으로는 실제 적용된 설정의 근거가 되지 않는다. 최소 근거는
명시적인 호출이나 고정된 정의, 실제 모델을 기록한 호스트 기록, 호스트가 문서화한 설정 우선순위에 따라 실제 적용된
사고 강도다. 기능이 없거나, 예상하지 못한 재정의가 있거나, 실제 설정을 확인하지 못하면 영향을 받는 위임을 멈추되
승인된 메인 작업은 계속할 수 있다.

시작 시점 메타데이터가 부족하면, 호스트가 같은 worker에게 후속 메시지를 보내면서 확인된 설정을 유지하거나 명시적으로
다시 적용할 수 있을 때만 준비 확인 전용 할당을 사용한다. 호스트 기록을 확인한 뒤 구현 할당을 보낸다. 이런 이어
보내기나 믿을 수 있는 설정 근거가 없으면 이 경로 대신 세션의 대체 처리 규칙을 적용한다. worker가 근거 없이 스스로
보고한 내용은 호스트 근거를 대신하지 못한다.

재개, 재정의 변경, 대체 경고, 호스트 설정 변경이 있으면 다시 확인한다. 불일치하면 해당 worker를 멈춘다. 입력이
바뀌지 않은 동안에는 확인한 설정을 재사용하고, 수정할 때마다 준비 확인 호출을 반복하지 않는다.

## 할당받은 worker

할당받은 worker는 자기 작업을 직접 실행하며 조정자 역할을 하지 않는다.

- 계획을 준비하거나, 계획이나 설계 절차를 시작하거나, 계획 검토나 독립 검증을 요청하거나, 다른 에이전트를 시작하지
  않는다.
- 수정 허용 경로만 수정하고 보호 경로는 건드리지 않으며 다른 worker의 변경을 보존한다.
- 범위를 넓히거나, 새 설계를 고르거나, 모델이나 사고 강도를 바꾸지 않는다. 빠진 결정이나 충돌하는 변경은 직접
  해결하지 말고 조정자에게 보고한다.
- 할당받은 검사만 할당에 적힌 격리 옵션으로 실행한다.
- 준비 확인 전용 할당이면 아무것도 수정하지 않고 준비 상태를 보고한다.
- 변경한 경로, 검사 결과, 남은 차단 요인을 반환한다.
