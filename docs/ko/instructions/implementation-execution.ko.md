# 구현 실행

> 영어 원본: [implementation-execution.md](../../../instructions/implementation-execution.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

구현은 합의한 변경을 실현하려고 코드, 테스트, 설정, 스크립트, 스킬, 지침, 문서를 바꾸는 작업이다. 통합 중에 생긴
수정도 포함한다. 메인 세션은 조정자다. 요구사항, 조사, 계획, 설계, 검토, 결정과 최종 보고를 맡는다. 사용자가
요청한 계획 문서나 설계 문서 작성도 메인 세션에 남는다. 세션의 위임 규칙에 따라 메인 또는 worker를 담당자로
정한다. 메인이 구현할 수 있으며 같은 수용 검사를 적용한다.

세션 규칙은 높은 수준의 추론, 확인 질문과 권한 결정을 계속 담당한다. UI나 설계 작업을 포함해 구현을 worker나
designer에게 위임하기 전에 [구현 위임](implementation-delegation.ko.md)도 읽는다.

## 작업 준비

첫 구현 변경 전에 모든 변경에 대해 실행할 수 있는 작업 할당을 갖춘다. 본격적인 작업에는 [작업 효율](work-efficiency.ko.md)을
적용해 필수 결과, 선택 후속 작업, 종료 조건과 검사 근거 재사용을 정한다. 이 항목은 기존 할당에 기록한다.

| 시작 조건 | 필요한 조치 |
|---|---|
| 완성된 기존 계획 | 범위, 선행 조건과 worker 할당을 현재 근거와 대조해 확인하고 바뀌지 않은 부분은 그대로 쓴다. |
| 실행 세부 사항이 빠진 계획 | 수정 전에 담당 범위, 의존성, 병렬 조건, 모델과 사고 강도 정책, 검사를 채운다. 합의한 설계는 유지한다. |
| 계획 없음 | 세션 고유의 작업 관리 기능이나 대화에서 간단한 실행 계획을 준비한다. 요청이 없으면 계획 디렉터리를 만들지 않는다. |
| 결과에 영향을 주는 요구사항이나 설계 결정이 미결 | 작업을 배정하기 전에 확인 질문 규칙에 따라 메인 세션에서 조사하고 결정한다. |
| 이미 할당받은 worker | 구현 위임의 "할당받은 worker"를 따른다. 빠진 결정이나 충돌은 조정자에게 보고하고, 다른 계획 절차를 시작하지 않는다. |

이 준비는 사용자가 요청한 구현 계획이 아니다. 계획이나 설계 스킬, 6단계 계획 절차, 독립 검증을 실행하지 않는다.

담당 범위를 분명히 나누는 최소 개수의 작업을 준비한다. 하나로 묶인 작업은 담당자 하나가 맡는다. worker 6개는
목표가 아니라 상한이다. 자리를 채우려고 작업을 쪼개거나 관련 없는 읽기 작업을 묶지 않는다.

언제든 요청이나 합의한 계획의 범위 밖에 있는 추적 파일을 바꾸는 작업을 할당하기 전에 사용자에게 묻는다. 어떤
작업도 수정할 수 없는 공유 파일이 그 예다. 답을 기다리고, 승인 없이는 그런 변경을 하지 않는다.

## 할당 항목

각 할당에는 다음을 적는다.

- 작업 ID와 구체적인 결과
- 수정 허용 경로와 보호 경로
- 선행 조건과 공유 자원 제외 대상
- 검증 방법과 완료 근거. 읽기 전용 결과는 scout 정의가 정한 상태와 경로별 읽음 범위로 시작한다
- 선택한 모델 ID와 사고 강도

메인 담당 작업은 이 항목을 간결하게 기록하고 메인 세션의 현재 모델과 사고 강도를 유지한다. 작업자 모델 확인과
준비 확인 호출은 위임할 때만 적용하며, 직접 작업에서는 수행하지 않는다.

## 수용

결과를 수용하고 통합 검사를 선택할 때 [검사 근거 규칙](work-efficiency.ko.md#검사-근거)을 적용한다. 메인 세션은
직접 수행한 작업을 포함한 모든 작업의 범위, 정확성, 회귀와 검사 근거를 확인한다. 추적 파일을 바꾸는 검사는 구현
작업이므로 담당자가 필요하다. 할당된 검사가 실패하면 원인이 작업 밖에 있어도 실패로 본다.
