# 작업 효율

> 영어 원본: [work-efficiency.md](../../../instructions/work-efficiency.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

본격적인 구현에 적용한다. 짧은 답변과 경로를 아는 파일 조회에는 추가 절차가 필요 없다. 세션의 위임 정책과 기존
구현 배정을 사용하고 스케줄러나 작업 데이터베이스를 추가하지 않는다.

## 범위와 완료

필수 결과, 필수 근거, 선택 후속 작업, 담당자, 종료 조건을 기존 작업 관리 기능이나 대화에 기록한다. 사용자가 새
작업을 요청하면 범위를 수정한다. 새 결함은 요청 결과나 필수 검증을 막을 때만 포함하고, 그렇지 않으면 후속 작업으로
보고한다.

독립적으로 검토할 수 있는 동작은 담당자 한 명에게 묶어서 맡긴다. 같은 변경의 읽기·수정·테스트·문서화마다 다른
작업자를 배정하지 않는다. 실제 선행 작업의 수용 경계는 유지한다. 요구사항·의존성·결함·인수인계가 바뀔 때 작업자에게
알린다. 반복 상태 조회보다 완료 알림이나 호스트 대기 기능을 우선한다. 사용자에게 필요한 진행 안내는 계속하되,
안내만을 위해 로그나 작업자 상태를 다시 조회하지 않는다. 백그라운드 대기나 관찰을 시작할 때는 무엇이 실행되는지
(스크립트인지 모델인지), 무엇을 대상으로 하는지, 예상 시간이 얼마인지 한 줄로 알린다.

15분 동안 새로 수용한 결과나 조치 가능한 근거가 없으면 접근 방식을 한 번 재평가하고, 막힌 원인과 범위가 정해진
다음 행동을 알린다. 생산적인 구현은 단지 오래 걸린다는 이유로 중단하지 않는다. 필수 결과와 검사가 수용되면 끝낸다.
구현한 동작, 검증한 동작, 남은 제한을 구분해 보고한다. 선택 후속 작업이나 선택적인 독립 리뷰 미실행 때문에 수용된
구현을 미완료로 남기지 않는다. 기존 독립 리뷰 승인 계약은 유지한다.

## 검사 근거

각 검사의 범위, 명령, 결과, 관련 입력·환경 상태를 간결하게 기록한다. 같은 검사를 반복하지 않고 유효한 작업자 근거를
받아들인다. 검사 대상 소스·의존성·픽스처·설정·도구 버전이 바뀌지 않았을 때만 결과를 재사용한다. 입력이 바뀌면
관련 결과를 무효화한다. 검사 범위가 불확실하면 필요한 검사를 다시 실행하며 통과로 가정하지 않는다.

구현 중에는 배정된 좁은 검사를, 통합 후에는 필요한 통합 검사를 실행한다. 확인된 실패나 남은 위험 때문에 필요한 경우
검사 범위를 넓힌다. 저장소가 요구하는 릴리스 검사는 유지한다. 원인이 배정된 변경 밖에 있어도 필수 검사 실패는 실패다.
