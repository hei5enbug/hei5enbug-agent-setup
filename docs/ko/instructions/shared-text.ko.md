# 공유 글

> 영어 원본: [shared-text.md](../../../instructions/shared-text.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

사람들이 작업을 파악하려고 읽는 글을 작성하거나 다시 쓰기 전에, 그리고 원본의 줄바꿈이 화면에도 줄바꿈으로
표시되는 Markdown을 쓰기 전에 이 문서를 읽는다. 각 절은 적용 시점을 밝힌다.

## 줄바꿈

- GitHub 이슈, 풀 리퀘스트, 댓글 본문과 그 밖에 원본의 줄바꿈이 화면에도 줄바꿈으로 표시되는 대상에서는 일정
  너비로 줄을 나누지 않고 각 문단과 각 목록 항목을 원본 한 줄에 쓴다. 에이전트를 위한 글에도 적용한다.
- Confluence에 게시할 Markdown 문서 또는 렌더링된 한 줄마다 원본 한 줄을 요구하는 프로젝트의 Markdown 문서에서는
  다음을 따른다.
  - 한 주제의 연속된 문장들은 한 문단에 두고 주제가 바뀌는 곳에만 빈 줄을 넣는다. 같은 주제의 한 문장짜리 문단을
    연달아 두지 않는다.
  - 문단에 여러 줄이 필요하면 의미가 끊기는 문장 끝에서 문단 안의 각 줄을 `<br>`로 끝낸다. 한 줄에 한 문장 또는
    밀접하게 연결된 두 문장을 둔다. 문장 중간에서는 줄을 나누지 않는다.
  - 같은 종류의 항목이 세 개 이상이면 도입 문장과 목록으로 쓴다.
  - 다음 표나 그림만 소개하면서 앞 문단의 주제를 이어 가는 한 문장짜리 문단은 앞 문단의 마지막 줄로 넣는다.
- 이런 글을 게시하거나 마무리하기 전에 `python3 <Source directory>/scripts/markdown_line_breaks.py FILE`을 실행한다.
  GitHub 본문에는 `--max-chars 0`을 추가한다. 작업 흐름에서 로컬 파일을 쓰지 않으면 FILE에 `-`를 지정하고 텍스트를
  표준 입력으로 전달한다. 모든 지적 사항을 고친다.

## 읽기 쉬운 공유 글

이 절은 답변으로 요청받은 요약을 포함한 요약, 동료와 공유하는 문서, Jira 이슈 본문과 댓글, 풀 리퀘스트 설명에
적용한다. `skill-issue-creator`가 쓰는 이슈 본문처럼 코딩 에이전트를 위한 글은 대신 자체 규칙을 따른다.

- 한국어에서는 에이전트 지침의 영어 용어를 직역하지 않고 문맥에 맞는 뜻으로 쓴다. 예를 들어 "contract"는 계약
  대신 규칙, 응답 형식, 정해 둔 동작으로 쓴다. 영어 용어는 문자 그대로의 식별자일 때만 유지한다.
- 독자가 결정이나 규칙을 이해하는 데 영향을 주지 않는 숫자는 뺀다. 필요한 숫자는 대응하는 값과 비교하거나 합계를
  세부 항목으로 나누는 표에 제시하고, 문장 안에 숫자를 나열하지 않는다. 임계값 같은 규칙 상수와 예시에 필요한
  값은 본문에 둔다. 검사에 대해서는 실행한 테스트 수 대신 동작과 조건 등 무엇을 확인했는지 밝힌다.
- 곁의 그림이나 표가 이미 보여 주는 사실은 그림이나 표를 남기고 되풀이하는 문장을 지운다. 앞에는 무엇을 보여
  주는지 한 문장만 남기고, 뒤에는 그 안에 없는 사실만 덧붙인다.
- 더 상세한 원본을 요약할 때는 결정, 이유, 절마다 대표 예시 하나를 남긴다. 전체 목록, 항목별 표, 구현 세부 사항은
  상세 원본에 둔다. 표의 셀에는 요약에서 다루는 항목만 적고 목록 대신 구분자로 연결한다.
- 기존 글을 줄이거나 다시 쓴 뒤에는 이전 글과 대조해 독자에게 필요한 조건, 예외, 범위, 결정 시점 중 빠진 내용을
  모두 복원한다. 이 대조를 맡은 독립 검토자에게는 변경 요약이 아니라 두 버전을 모두 제공한다.
