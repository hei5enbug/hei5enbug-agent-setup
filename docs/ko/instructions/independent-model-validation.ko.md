# 독립 모델 검증

> 영어 원본: [independent-model-validation.md](../../../instructions/independent-model-validation.md)
>
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트는 실행 중 이 문서를 읽거나 사용하지 않는다.

이 영문 파일을 구현 계획, 기술 설계 문서, RFC와 완료된 구현 변경의 독립 검증에 사용하는 단일 기준으로 삼는다.

## 검토 시점

독립 검증은 요청마다 정확히 한 번, 질문 없이 자동으로 실행한다. 실행 시점은 마지막 단계, 즉 남은 작업이 없을 때이며
모든 worker와 메인 세션의 결과를 합친 것이 대상이다. 요청한 계획·설계·RFC는 완성된 초안이 대상이다. 구현은 동작·공개 계약·보안·동시성·
마이그레이션 또는 여러 구성요소가 실질적으로 바뀌면, 통과한 검사와 함께 최종 변경이 대상이다.
일상적인 작은 수정은 사용자가 요청하지 않으면 별도 검토를 생략한다.

worker 한 명의 변경이나 중간 초안처럼 더 이른 검토는 사용자가 해당 산출물에 대해 승인했을 때만 실행한다.
검토 모델과 사고 강도를 밝힌 짧은 질문 하나로 묻고 답을 기다린다. 답과 무관하게 할 수 있는 작업은 먼저 모두 마친다.
사용자가 거절하거나 세션이 답을 받을 수 없으면 그 검토를 건너뛰고, 건너뛴 검토를 산출물 안에 기록하지 않으며,
같은 초안에 대해 다시 묻지 않는다. 할당받은 worker와 더 큰 요청 안에서 실행되는 스킬은 자체 최종 검토를 실행하지 않는다.
최종 검토 한 번은 조율 세션이 실행한다. 필요한 검토자를 사용할 수 없다는 사실을 이미 알면 제한을 보고하고 호출 없이 마친다.

## 검토자 선택

위 규칙에 따라 검토 시점이 되면 완성된 초안을 아래 매핑이 고르는 검토자 정확히 1명에게 읽기 전용 세션으로 전달한다.
검토자에게 확정한 의도, 관련된 신뢰할 수 있는 근거, 완성된 초안을 제공한다. 검토자는 지적만 반환하며,
최종 결정은 작성 세션에서 내린다.

| 작성 모델 계열 | 검토자 | 추론 강도 |
|---|---|---|
| Claude | `gpt-6.1-sol` 또는 `gpt-6-astra` | `high` 또는 `xhigh` |
| GPT | `claude-opus-5-5` 또는 `claude-fable-5-1` | `high` 또는 `xhigh` |

조율 세션이 범위와 위험에 따라 해당 행에서 검토자와 강도를 하나 고른다. 구성요소 하나로 범위가 한정되면 가벼운 모델
(`gpt-6.1-sol`, `claude-opus-5-5`)을 `high`로, 여러 컴포넌트, 공개 계약, 보안, 동시성, 훅이나 가드가 관련되면 더 강한 모델
(`gpt-6-astra`, `claude-fable-5-1`) 또는 `xhigh`를 쓴다.

실행 호스트가 아닌 실제 작성 모델 계열을 선택한다. 위임받은 worker가 쓴 코드는 그 worker의 모델 계열에 속한다.
Claude Code에서 GPT가 작성해도 GPT 행을 따른다.
두 계열이 실질적으로 기여했으면 그 기여를 기록하고, 최종 작성 모델 계열로 검토자 한 명을 선택한다.
모든 기여자에게 독립적이라고 주장하거나 검토 호출을 추가하지 않는다.

고정 모델 ID를 그대로 사용하고 기록한다. 새 릴리스를 찾거나 제공자 별칭을 따르지 않으며, 이 선택과 다른 모델
등급이나 더 낮은 추론 강도로 대체하지 않는다. 검토자는 초안, 저장소 또는 외부 상태를 수정하면 안 된다.

메인 세션의 모델과 사고 강도는 유지한다. 별도 호스트 실행기에 검토자의 모델과 사고 강도를 명시적으로 전달하고,
읽기 전용 도구나 샌드박스를 적용한다. 검토 완료로 인정하기 전에 호스트 기록에서 실제 모델과 사고 강도를 확인한다.
알리지 않은 모델 대체나 사고 강도 상한이 적용된 호출은 완료된 검토가 아니다. 검토를 실행하려고 추가 과금을 켜거나 인증을 바꾸지 않는다.

구현 검토에는 대화 기록 대신 합의한 범위, 전체 변경 diff, 관련 원본 경로, 수용 조건과 검사 결과를 전달한다.
필요한 미추적 파일도 포함한다. 추적 파일만의 diff는 구현을 빠뜨릴 수 있다. 심각도와 근거가 있는 간결한 지적을 반환하고, 변경이 안전한 근거가 되는 사실 하나와 그 사실을
어디까지 증명했는지를 밝힌다. 증명 수준은 주장, `file:line` 인용, 단계별 논증, 스크립트나 테스트 실행, 실행 중인 앱에서의 재현이다.

## 검토 항목

모든 결과물에서 다음 항목에 대해 근거가 있는 지적만 보고한다.

- 누락된 요구사항 또는 인수 조건
- 모순과 실질적으로 모호한 표현
- 근거 없는 가정
- 불필요한 추상화, 추측성 확장성, 관련 없는 리팩터링 또는 과도한 의존성

구현 계획에서는 다음 항목도 확인한다.

- 잘못된 의존성 또는 실행 순서
- 실행하거나 검증할 수 없는 단계
- 불필요한 실행 단위 또는 안전하지 않은 병렬 실행 판단

완료된 구현에서는 다음 항목도 확인한다.

- 정확성, 회귀, 권한 경계와 실패 처리
- 빠진 수용 검사 또는 근거 없는 검증 성공 주장
- 통합 충돌, 안전하지 않은 동시 실행과 불완전한 메인 대체 처리

기술 설계 문서나 RFC에서는 다음 항목도 확인한다.

- 목표 결정을 뒷받침하지 않는 현재 상태 설명
- 누락되거나 부정확한 계약, 제약, 대안 또는 주요 트레이드오프
- 요청하지 않은 구현 단계, 낮은 수준의 세부사항 또는 확장 지점

## 실행 범위

이 과정은 토론이 아니라 검증 1회다. 검토자에게 답변 수정을 요청하거나 다른 검토자를 호출하거나 최종 확정 뒤 검증을
반복하지 않는다. 검토가 실패하거나 검토자를 사용할 수 없어도 두 번째 모델을 호출하지 않는다. 더 이른 검토를 거절한 경우에도
대체 독립 검토를 허용하지 않는다. 작성자의 일상적인 점검과 필수 검사는 계속하되 독립 검증이라고 부르지 않는다.

필요한 모델, 추론 강도, 읽기 전용 실행 또는 모델 실행기를 사용할 수 없다면 다른 설정으로 대체하거나 작성자 점검을 독립 검토로 제시하지 않는다.
역할 실행기의 종료 코드 3이나 4도 같은 뜻이다. 검토자 없이 할 수 있는 작업은 마치고 독립 검증을 수행하지 못한 사실과 사유를 알린다.

## 확정

작성 세션은 모든 지적을 확정한 범위와 신뢰할 수 있는 근거에 대조하고, 지적마다 한 줄 사유와 함께 즉시 수정,
검토할 만함, 기록만, 거부 중 하나로 분류한다. 도달 가능한 호출 경로나 입력 경로를 추적하지 못한 지적은 추적하기 전까지
가능성이며 즉시 수정으로 분류하지 않는다. 근거가 있는 즉시 수정만 한 번 반영하고, 근거 없는 범위 확장은 거부한다.
수정한 뒤 다른 모델 검토를 실행하지 않는다.

실제로 사용한 검토 모델, 추론 강도, 읽기 전용 검증을 한 번 실행한 사실, 각 지적의 분류와 사유, 구현 검토라면 안전 근거
사실과 그 증명 수준, 미해결 지적을 알린다. 검증을 실행하지
못했다면 사용할 수 없었던 조건과 사유를 대신 밝힌다. 사용자가 더 이른 검토를 거절했다면 독립 검증을 실행하지 않았다는
사실만 알린다. 이 결과는 모두 답변에 적고 산출물에는 적지 않는다.
