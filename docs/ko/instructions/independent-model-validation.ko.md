# 독립 모델 검증

> 영어 원본: [independent-model-validation.md](../../../instructions/independent-model-validation.md)
>
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트는 실행 중 이 문서를 읽거나 사용하지 않는다.

이 영문 파일을 구현 계획, 기술 설계 문서, RFC, 이슈 본문과 완료된 구현 변경의 독립 검증에 사용하는 단일 기준으로 삼는다.

## 검토 시점

독립 검증은 요청마다 정확히 한 번, 질문 없이 자동으로 실행한다. 실행 시점은 마지막 단계, 즉 남은 작업이 없을 때이며
모든 worker와 메인 세션의 결과를 합친 것이 대상이다. 요청한 계획·설계·RFC는 완성된 초안이 대상이다. 제안이 동작, 공개 계약,
또는 여러 구성요소를 바꾸는 이슈를 하나 이상 등록하거나 다시 쓰는 요청은 그 이슈들의 본문 전체를 하나의 완성된 초안으로 보고,
트래커에 처음 쓰기 전에 담당 파일을 근거로 검토한다. 구현은 동작·공개 계약·보안·동시성·
마이그레이션 또는 여러 구성요소가 실질적으로 바뀌면, 통과한 검사와 함께 최종 변경이 대상이다.
일상적인 작은 수정은 사용자가 요청하지 않으면 별도 검토를 생략한다. 성능이나 자원 사용을 고치려는 변경, 또는 코드 경로가
하는 작업량을 바꾸는 변경은 일상적인 작은 수정이 아니다.

worker 한 명의 변경이나 중간 초안처럼 더 이른 검토는 사용자가 해당 산출물에 대해 승인했을 때만 실행한다.
검토 모델과 사고 강도를 밝힌 짧은 질문 하나로 묻고 답을 기다린다. 답과 무관하게 할 수 있는 작업은 먼저 모두 마친다.
사용자가 거절하거나 세션이 답을 받을 수 없으면 그 검토를 건너뛰고, 건너뛴 검토를 산출물 안에 기록하지 않으며,
같은 초안에 대해 다시 묻지 않는다. 할당받은 worker와 더 큰 요청 안에서 실행되는 스킬은 자체 최종 검토를 실행하지 않는다.
최종 검토 한 번은 조율 세션이 실행한다. 필요한 검토자를 사용할 수 없다는 사실을 이미 알면 제한을 보고하고 호출 없이 마친다.

## 검토자 선택

위 규칙에 따라 검토 시점이 되면 완성된 초안을 아래 매핑이 고르는 검토자 정확히 1명에게, 실행기의 scratch 폴더만 쓸 수 있는 읽기 전용 세션으로 전달한다.
검토자에게 확정한 의도, 관련된 신뢰할 수 있는 근거, 완성된 초안을 제공한다. 검토자는 지적만 반환하며,
최종 결정은 작성 세션에서 내린다.

| 작성 모델 계열 | 검토자 | 추론 강도 |
|---|---|---|
| Claude | `gpt-6.1-terra` 또는 `gpt-6.2-astra` | `high` 또는 `xhigh` |
| GPT | `claude-fable-5-2` | `high` |

조율 세션이 범위와 위험에 따라 해당 행에서 검토자와 강도를 하나 고른다. Claude가 작성한 결과는 구성요소 하나로
범위가 한정되면 가벼운 모델 `gpt-6.1-terra`을 `high`로, 여러 컴포넌트, 공개 계약, 보안, 동시성, 훅이나 가드가 관련되면
더 강한 모델 `gpt-6.2-astra` 또는 `xhigh`를 쓴다. GPT가 작성한 결과는 항상 `claude-fable-5-2`를 `high`로 쓴다.

실행 호스트가 아닌 실제 작성 모델 계열을 선택한다. 위임받은 worker가 쓴 코드는 그 worker의 모델 계열에 속한다.
Claude Code에서 GPT가 작성해도 GPT 행을 따른다.
두 계열이 실질적으로 기여했으면 그 기여를 기록하고, 최종 작성 모델 계열로 검토자 한 명을 선택한다.
모든 기여자에게 독립적이라고 주장하거나 검토 호출을 추가하지 않는다.

고정 모델 ID를 그대로 사용하고 기록한다. 새 릴리스를 찾거나 제공자 별칭을 따르지 않으며, 이 선택과 다른 모델
등급이나 더 낮은 추론 강도로 대체하지 않는다. 검토자는 초안, 저장소 또는 외부 상태를 수정하면 안 된다.

메인 세션의 모델과 사고 강도는 유지한다. 별도 호스트 실행기에 검토자의 모델과 사고 강도를 명시적으로 전달하고,
검토 완료로 인정하기 전에 호스트 기록에서 실제 모델, 사고 강도, 쓰기 제한을 확인한다. 실행기는 검토자에게 실행마다
만드는 scratch 폴더만 쓸 수 있는 샌드박스를 준다. 독립 검증 호출은 `role_runner.py reviewer --validation`으로 실행해
검토자가 그 폴더 안에서 프로젝트의 테스트, 계산, 설치를 실행하고 그 밖의 것은 수정하지 못하게 한다. Claude 검토자는 그 폴더에서
시작해 저장소의 사본으로 작업한다. 검토자가 다시 실행할 수 있도록 작성자가 실행한 검사 명령과 그 결과를 함께 준다.
알리지 않은 모델 대체나 사고 강도 상한이 적용된 호출은 완료된 검토가 아니다. 검토를 실행하려고 추가 과금을 켜거나 인증을 바꾸지 않는다.

구현 검토에는 대화 기록 대신 합의한 범위, 전체 변경 diff, 관련 원본 경로, 수용 조건과 검사 결과를 전달한다.
작성자가 찾은, 바뀐 함수·계약·스키마·설정의 호출자와 소비자도 전달하고, 변경이 영향을 줄 수 있으면 이전 실행 시간 같은
기준 측정값도 전달한다. 필요한 미추적 파일도 포함한다. 추적 파일만의 diff는 구현을 빠뜨릴 수 있다. 심각도와 근거가 있는 간결한 지적을 반환하고, 변경이 안전한 근거가 되는 사실 하나와 그 사실을
어디까지 증명했는지를 밝힌다. 증명 수준은 주장, `file:line` 인용, 단계별 논증, 스크립트나 테스트 실행, 실행 중인 앱에서의 재현이다.

## 검토 항목

지적이 0건인 것도 유효한 결과다. 모든 결과물에서 실제 문제라고 확신하는 지적만, 근거와 함께 다음 항목에 대해 보고한다.

- 누락된 요구사항 또는 인수 조건
- 모순과 실질적으로 모호한 표현
- 근거 없는 가정
- 불필요한 추상화, 추측성 확장성, 관련 없는 리팩터링 또는 과도한 의존성

구현 계획에서는 다음 항목도 확인한다.

- 잘못된 의존성 또는 실행 순서
- 실행하거나 검증할 수 없는 단계
- 불필요한 실행 단위 또는 안전하지 않은 병렬 실행 판단

완료된 구현에서는 다음 항목도 확인한다.

- 정확성, 회귀, 권한 경계와 실패 처리
- 빠진 수용 검사 또는 근거 없는 검증 성공 주장
- 통합 충돌, 안전하지 않은 동시 실행과 불완전한 메인 대체 처리
- 부작용: 바뀐 함수·계약·스키마·설정마다 그 호출자, 소비자, 저장된 데이터, 배포 설정까지 추적하고, 추적한 경로에서
  닿는 영향만 보고한다
- 현실적인 입력 크기에서의 연산·자원 효율: 반복문 안의 반복되는 비싼 작업, N+1 쿼리나 호출, 한도 없는 스캔이나 적재,
  입력에 따라 늘어나는 메모리, 주어진 기준 대비 실행 시간

기술 설계 문서나 RFC에서는 다음 항목도 확인한다.

- 목표 결정을 뒷받침하지 않는 현재 상태 설명
- 누락되거나 부정확한 계약, 제약, 대안 또는 주요 트레이드오프
- 요청하지 않은 구현 단계, 낮은 수준의 세부사항 또는 확장 지점

## 실행 범위

이 과정은 토론이 아니라 검증 1회다. 검토자에게 답변 수정을 요청하거나 다른 검토자를 호출하거나 최종 확정 뒤 검증을
반복하지 않는다. 다만 사용자가 요청한 반복은 "요청에 따른 반복 검토"를 따른다. 검토가 실패하거나 검토자를 사용할 수 없어도 두 번째 모델을 호출하지 않는다. 더 이른 검토를 거절한 경우에도
대체 독립 검토를 허용하지 않는다. 작성자의 일상적인 점검과 필수 검사는 계속하되 독립 검증이라고 부르지 않는다.

필요한 모델, 추론 강도, 쓰기가 제한된 실행 또는 모델 실행기를 사용할 수 없다면 다른 설정으로 대체하거나 작성자 점검을 독립 검토로 제시하지 않는다.
역할 실행기의 종료 코드 3이나 4도 같은 뜻이다. 검토자 없이 할 수 있는 작업은 마치고 독립 검증을 수행하지 못한 사실과 사유를 알린다.

## 확정

작성 세션은 모든 지적을 확정한 범위와 신뢰할 수 있는 근거에 대조하고, 지적마다 한 줄 사유와 함께 즉시 수정,
검토할 만함, 기록만, 거부 중 하나로 분류한다. 도달 가능한 호출 경로나 입력 경로를 추적하지 못한 지적은 추적하기 전까지
가능성이며 즉시 수정으로 분류하지 않는다. 근거가 있는 즉시 수정만 한 번 반영하고, 근거 없는 범위 확장은 거부한다.
수정한 뒤 다른 모델 검토를 실행하지 않는다. 다만 사용자가 요청한 반복은 예외다.

글 검토 밖에서 세션이 지적을 반영할 때는, 다음 라운드나 쓰기 전에 고친 대목마다 확정한 결정과 신뢰할 수 있는 근거에
대조하고 어긋난 대목은 고친다. 작업자가 지적을 반영할 때는, 작업 지시에 지적마다 요점, 이유, 근거를 주고, 허용된 경로
안에서 같은 요점을 말하는 대목을 모두 고치며 고칠 때마다 그 근거와 대조하라고 요청한다. 작업자를 고칠 문장 목록에
가두지 않는다.

결과는 답변에 적고 산출물에는 적지 않는다. 검토를 실행했다면 검토 결과의 링크나 경로(검토자의 결과 파일이나 지적이 담긴
댓글 등)를 알리는 한 줄과 해결하지 못한 지적을 하나하나 적고, 검토 모델, 추론 강도, 실행 횟수, 지적 분류, 안전 근거는
적지 않는다. 검증을 실행하지 못했거나 사용자가 거절했다면, 그 사실과 이유를 한 줄로 적는다.

## 요청에 따른 반복 검토

사용자가 지적이 없을 때까지 검토하고 고치기를 반복하라고 요청한 검토와, 검토가 멈춘 뒤 사용자가 계속하라고 답한 경우에는 이
절을 따른다. 글 독립 검토도 여기에 든다.

- 첫 라운드 전에, 지적이 남는 라운드가 세 번 이어질 때마다 반복을 멈추고 보고한다고 사용자에게 한 줄로 알린다. 이때는
  아무것도 묻지 않는다.
- 지적이 없는 라운드가 나오면 반복이 끝나고 바로 작업을 이어 간다. 지적 수가 늘거나 줄었다는 사실만으로 반복을 멈추지
  않는다.
- 모든 라운드는 첫 라운드의 검토자와 검토 대상 집합을 유지한다. 검토자, 검토 대상 집합, 고칠 심각도는 멈춘 자리에서 사용자가
  고른 뒤에만 바꾼다.
- 반복 안에서도 [공유 글](shared-text.ko.md)의 "독립 글 검토"가 정한, 지적이 되풀이될 때와 사용자만 결정할 수 있는 지적일
  때의 멈춤은 그대로 적용한다.
- 요청한 때부터, 또는 사용자가 계속하라고 마지막으로 답한 때부터 센 세 번째 라운드에도 지적이 남으면, 그 라운드의 지적을
  "확정"에 따라 반영한 뒤 다음 라운드 전에 멈추고 바깥에는 아무것도 쓰지 않는다. 사용자가 라운드별 지적 수와 심각도, 라운드마다의
  검토자와 검토 대상 집합, 앞선 라운드의 수정이 다른 대목에 일으키거나 남긴 지적의 수, 반복이 한 번도 바꾸지 않은 글에 있는
  지적의 수, 심각도가 높은 지적이나 확정한 결정과 어긋나는 지적이 있는지를 알 수 있게 보고한다. 그런 다음 그대로 계속할지, 검토
  대상 집합이나 검토자나 고칠 심각도를 좁힐지, 멈추고 지금 쓸지를 추천 하나와 함께 한 번만 묻는다. 사용자가 지금 쓰기로 하면,
  작업의 보고에 마지막 라운드의 수정은 다시 검토하지 않았다고 적는다.

보고 예시: "1~3라운드에서 같은 검토자 둘이 지적 9건, 7건, 8건을 냈고 심각도 높은 것도 결정과 어긋난 것도 없었다. 3라운드 지적
중 6건은 2라운드의 수정이 놓친 같은 내용의 복사본이었고 8건을 모두 고쳤다. 게시할 두 페이지를 한 번 더 검토해 중간 심각도
이상을 고치기를 권한다."
