# 사용자에게 묻기

> 영어 원본: [asking-the-user.md](../../../instructions/asking-the-user.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

사용자에게 무엇이든 묻거나 기다리자고 제안하기 전에 이 문서를 읽는다. 언제 물을지는 공통 세션 지침의 확인 질문
규칙이 정한다.

- 일정, 다음 실행, 새 데이터를 기다리자고 제안하기 전에, 현재 권한과 승인 범위 안에서 지금 확인할 방법을 찾는다.
  수동 실행, dry run, 기록된 입력 재생, 과거 같은 구간과의 비교가 그런 방법이다. 그런 방법이 없을 때만 기다리자고
  제안하고, 이유와 가장 빨리 확인할 수 있는 시각을 밝힌다. 승인 규칙이 막는 쓰기는 여전히 먼저 묻는다.
- 호스트 규칙이 필수 질문의 blocking을 허용할 때만 도구를 사용한다. 그렇지 않으면 최종 답변으로 묻고 턴을
  끝낸다. 필수 결정에는 비동기 질문을 사용하지 않는다.
- 선택지는 권장 순서로 나열한다. 호스트의 질문 도구가 자체 자유 입력 줄을 더하는 경우, Claude Code
  `AskUserQuestion`과 Codex `request_user_input`이 그렇듯, 그 줄에 맡기고 "Other", "Custom", "직접 입력"처럼
  사용자에게 입력하라고 하는 이름의 선택지는 만들지 않는다. 그런 선택지에는 입력 칸이 없기 때문이다. 호스트의 도구가
  자유 형식 답변을 받을 수 없는 경우에는 대신 턴을 끝내는 답변에서 묻는다.
- ASCII 다이어그램은 선택을 더 분명하게 할 때만 덧붙인다. 다이어그램이 도움이 되고 호스트의 질문 도구에 Claude Code
  `preview` 같은 미리보기 칸이 있으면 거기에 넣고, 도구에 그런 칸이 없으면, Codex가 그렇다, 질문 문장 아래의 질문
  본문에 넣는다.
- 질문 대화상자만 보는 독자를 기준으로, 질문과 제목, 각 선택지의 이름과 설명을 공통 세션 지침의 답변 규칙에
  맞춰 쓴다. 그 독자는 결정이 무엇에 관한 것인지를 바뀌는 대상을 이름으로 부르는 한 줄로, 선택이 영향을 주는 각
  항목을 대화상자에 보이지 않는 글의 번호나 위치로만 부르지 않고 쉬운 말로 인용하거나 설명해서, 그리고 각 선택지에서
  각 항목이 어떻게 되는지를 알 수 있어야 한다. 질문은 한 문장으로 하고 자세한 내용은 선택지 설명이나 다이어그램에
  둔다. 질문에 이르게 된 과정, 예를 들어 검토자의 지적이나 이전 시도는, 어느 선택지가 맞는지를 바꾸지 않는 한
  뺀다. 예: "demo 주문 테이블에서 안 쓰는 열 두 개를 지울까요? A: legacy_code, 2025년부터 비어 있음; B: old_status,
  status로 복사됨". 각 선택지는 어떤 열이 남는지를 말한다.
- 사용자가 대화에서 쓰지 않은 용어, 약어, 내부 구성 요소 이름이나 코드 식별자가 들어간다면, 같은 뜻의 쉬운 말이 있을
  때 그 말을 쓰고, 예를 들어 메타 데이터베이스는 "스케줄러 자체의 실행 이력 테이블"로 쓴다, 그런 말이 없을 때만
  같은 글 안에서 용어의 뜻을 설명한다.
- Claude Code `AskUserQuestion`처럼 구조화된 입력을 받는 호스트 질문 도구에는 질문, 제목, 각 선택지의 이름과
  설명을 원문 글자로 쓰고, 이스케이프된 JSON에서 가져온 글이라도 `\uXXXX` 같은 JSON 유니코드 이스케이프로 쓰지
  않는다. 한국어, 일본어, 중국어처럼 멀티바이트 문자가 들어간 글은 보내기 전에 한 번 다시 읽고 뜻한 단어와 다른
  글자를 고친다.
- 사용자가 질문 대화상자의 글자가 틀리거나 깨졌다고 알리면 세션 기록 파일에 저장된 자신의 도구 입력부터 읽는다.
  이어서 실행한 대화처럼 대화 안에서는 이전 도구 입력이 실제로는 없던 유니코드 이스케이프로 보일 수 있기 때문이다.
  다른 원인을 들기 전에 보고된 글자가 저장된 입력에 있는지부터 말하고, 그 입력이 맞고 표시된 글이 다를 때만
  호스트나 플러그인을 원인으로 든다.
- 대화가 세션의 이전 질문 도구 입력을 유니코드 이스케이프나 의도하지 않은 다른 형태로 보여 주는데 사용자가 알린 적이
  없으면, 어떤 결론을 내리기 전에 세션 기록 파일에 저장된 그 입력을 읽고, 원문 글자 규칙을 지켰는지를 대화에 표시된
  모습으로 판단하지 않는다. 저장된 입력에 의도한 글자가 들어 있으면 그 표시는 표시상의 부산물로 보고, 요약, 메모리, 보고에
  실수를 기록하지 않고, 고치겠다고 약속하지 않고, 사용자, 호스트, 추적기에 결함을 보고하지 않는다. 저장된 입력 자체에
  이스케이프 글이나 잘못된 글자가 있으면 그렇다고 말하고 다음 질문은 원문 글자로 쓴다. 예: 세션을 이어 실행한 뒤 일본어
  질문 입력이 이스케이프로 보이는데 저장된 입력에는 가나가 들어 있으면, 아무것도 기록하거나 보고하지 않는다.
- 호스트의 출력 형식과 스킬이 따로 정한 질문·중단 규칙을 따른다.
- 임시 조치와 근본 해결이 둘 다 있으면 비용과 영향을 함께 제시하고 사용자가 고르게 한다.
- 로그인 같은 대기 중인 사용자 조치는 한 번만 알린다.
