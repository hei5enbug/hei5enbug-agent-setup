# 사용자에게 묻기

> 영어 원본: [asking-the-user.md](../../../instructions/asking-the-user.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

사용자에게 무엇이든 묻거나 기다리자고 제안하기 전에 이 문서를 읽는다. 언제 물을지는 공통 세션 지침의 확인 질문
규칙이 정한다.

- 일정, 다음 실행, 새 데이터를 기다리자고 제안하기 전에, 현재 권한과 승인 범위 안에서 지금 확인할 방법을 찾는다.
  수동 실행, dry run, 기록된 입력 재생, 과거 같은 구간과의 비교가 그런 방법이다. 그런 방법이 없을 때만 기다리자고
  제안하고, 이유와 가장 빨리 확인할 수 있는 시각을 밝힌다. 승인 규칙이 막는 쓰기는 여전히 먼저 묻는다.
- 호스트 규칙이 필수 질문의 blocking을 허용할 때만 도구를 사용한다. 그렇지 않으면 최종 답변으로 묻고 턴을
  끝낸다. 필수 결정에는 비동기 질문을 사용하지 않는다.
- 선택지는 권장 순서로 나열하고 자유 형식 답변을 허용한다. ASCII 다이어그램은 선택을 더 분명하게 할 때만
  덧붙인다.
- 질문 대화상자만 보는 독자를 기준으로, 질문과 제목, 각 선택지의 이름과 설명을 공통 세션 지침의 답변 규칙에
  맞춰 쓴다. 사용자가 대화에서 쓰지 않은 용어, 약어, 내부 구성 요소 이름이나 코드 식별자가 들어간다면 쉬운 말로
  바꾸거나 같은 글 안에서 뜻을 설명한다. 예를 들어 메타 데이터베이스는 "스케줄러 자체의 실행 이력 테이블"로 쓴다.
- Claude Code `AskUserQuestion`처럼 구조화된 입력을 받는 호스트 질문 도구에는 질문, 제목, 각 선택지의 이름과
  설명을 원문 글자로 쓰고, 이스케이프된 JSON에서 가져온 글이라도 `\uXXXX` 같은 JSON 유니코드 이스케이프로 쓰지
  않는다. 한국어, 일본어, 중국어처럼 멀티바이트 문자가 들어간 글은 보내기 전에 한 번 다시 읽고 뜻한 단어와 다른
  글자를 고친다.
- 사용자가 질문 대화상자의 글자가 틀리거나 깨졌다고 알리면 세션 기록 파일에 저장된 자신의 도구 입력부터 읽는다.
  이어서 실행한 대화처럼 대화 안에서는 이전 도구 입력이 실제로는 없던 유니코드 이스케이프로 보일 수 있기 때문이다.
  다른 원인을 들기 전에 보고된 글자가 저장된 입력에 있는지부터 말하고, 그 입력이 맞고 표시된 글이 다를 때만
  호스트나 플러그인을 원인으로 든다.
- 호스트의 출력 형식과 스킬이 따로 정한 질문·중단 규칙을 따른다.
- 임시 조치와 근본 해결이 둘 다 있으면 비용과 영향을 함께 제시하고 사용자가 고르게 한다.
- 로그인 같은 대기 중인 사용자 조치는 한 번만 알린다.
