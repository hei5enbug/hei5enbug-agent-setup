# 빠른 모드

> 영어 원본: [fast-mode.md](../../../instructions/fast-mode.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

요청에서 사용자가 직접 쓴 글에 `turbogoal`이나 `ulw`가 독립된 단어로 있으면 이 문서를 읽는다. 사용자가 붙여
넣거나 인용한 글, 코드 스팬과 코드 블록은 세지 않는다. 이 모드는 그 요청이 끝날 때까지 유지된다.

빠른 모드는 품질을 낮추지 않으면서 기계가 허용하는 한 가장 빨리 요청을 끝낸다. 토큰 비용은 제약이 아니다.

- 독립적인 작업은 처음부터 병렬 subagent와 역할 실행기로 나눈다. 문맥을 아끼려고 위임 규칙이 고르는 정도보다
  더 나누고, 다음 단계는 입력이 준비되는 즉시 시작한다.
- 오래 걸리는 검사, 빌드, 평가는 백그라운드에서 돌리고 그동안 다른 일을 계속한다.
- 의존성이 긴밀한 단계는 절대 병렬로 돌리지 않는다. 공유 파일과 다른 공유 자원은 여전히 한 번에 한 담당자만 둔다.
- 시작할 때 CPU 코어 수와 사용 가능한 메모리를 잰다. macOS에서는 `sysctl -n hw.ncpu`와 `vm_stat`의 free,
  inactive, speculative 페이지를, Linux에서는 `nproc`와 `free -m`의 available 열을 쓴다. 역할 실행기, 테스트 실행,
  빌드, 평가 실행 같은 로컬 프로세스는 CPU 코어 수에서 하나를 뺀 수와 사용 가능한 메모리 1 GB당 하나 가운데 작은
  수까지만 동시에 돌리되, 적어도 하나는 돌린다. 호스트의 한도도 지킨다. Claude Code에서는
  `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`, Codex에서는 `agents.max_concurrent_threads_per_session`이다. 호스트 안에서
  도는 subagent는 그것이 띄운 로컬 프로세스만 센다.
- Claude Code에서는 호스트 자체의 `ultracode` 키워드가 요청을 다중 에이전트 워크플로로 실행한다. 빠른 모드는
  워크플로를 시작하지 않으며, 사용자가 두 키워드를 함께 쓰면 워크플로가 같은 상한 안에서 돈다.
- 고정되었거나 사용자가 요청한 모델과 effort, 필수 검사, 최종 검토, 모든 승인 규칙은 그대로 지킨다.
- 최종 보고에서 빠른 모드로 실행했다는 것과 계산한 상한을 밝힌다.
