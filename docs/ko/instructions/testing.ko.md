# 테스트 코드

> 영어 원본: [testing.md](../../../instructions/testing.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

언어와 프레임워크에 관계없이 테스트를 작성하거나 수정할 때, 그리고 작업자 할당문에 테스트를 지정할 때 다음 규칙을
적용한다. 작업자 할당문에는 요청하는 테스트마다 그 테스트가 잡아내는 회귀를 명시한다.

## 테스트 추가 여부

- 테스트를 추가하기 전에 기존 테스트가 잡아내지 못하지만 새 테스트가 잡아낼 회귀를 보고서나 할당문에 한 줄로 쓴다.
  쓸 수 없으면 테스트를 추가하지 않는다.
- 기존 테스트가 이미 해당 경로를 실행하면 그 테스트를 확장하거나 아무것도 추가하지 않고, 해당 경로를 다루는 테스트를
  명시한다.
- 데이터베이스 카탈로그에서 스키마를 다시 읽거나, 상수를 다시 단언하거나, 구현 단계를 반복하는 등 검증 대상 코드에서
  기대값을 복사하는 테스트는 작성하지 않는다. 관찰 가능한 동작을 단언한다.
- 변경으로 동작을 추가하거나 바꾸면 같은 변경에서 해당 테스트를 작성하거나 갱신한다. 나중의 후속 작업으로 미루지 않는다.

## 테스트의 속성

- 빠름: 컨테이너, 전체 애플리케이션 컨텍스트, 네트워크 없이 동작을 확인할 수 있으면 그보다 낮은 수준에서 테스트한다.
  동작이 실제 엔진에 의존할 때만 더 무거운 인프라를 시작한다.
- 독립성: 테이블, 파일, 전역 설정, 환경 변수처럼 다른 테스트도 사용하는 상태가 필요하면 테스트가 격리된 상태를 직접
  만들고 소유하거나 고유한 키를 사용하게 한다. 롤백으로 복원할 수 있더라도 공유 fixture를 삭제하거나, 비우거나,
  이름을 바꾸거나, 덮어쓰지 않는다.
- 반복 가능성: 결과가 시간, 무작위성, 순서, 네트워크, 기존 데이터에 좌우될 수 있으면 주입한 시계, 시드, 테스트가 직접
  만든 fixture로 고정한다.
- 자체 검증: 출력이나 로그를 읽지 않고 단언만으로 성공과 실패를 판단한다. 검증 대상 동작을 단언으로 감싸지 말고,
  예상하지 못한 예외가 테스트를 실패하게 한다.

## 구조

- 모든 테스트를 given-when-then 구조로 작성한다. `given`은 상태와 fixture를 준비하고, `when`은 검증 대상 동작을
  정확히 하나만 수행하며, `then`에는 단언만 둔다. 세 단계를 눈에 보이게 구분한다. 프레임워크에 전용 구문이 있으면
  그것을 쓰고, 없으면 단계마다 표시 줄 하나를 둔다.
- `@DisplayName`, `describe`/`it` 제목, 실행기에 표시되는 docstring 같은 테스트 설명은 기대 동작을 서술하는
  자연스러운 한국어 문장으로 쓴다. 식별자, 메서드 이름, 리터럴 값은 그대로 둔다.
- JVM 프로젝트에서는 테스트 fixture를 Instancio로 만든다. 필요한 Instancio API가 불확실하면 추측하지 말고 공식
  문서를 확인한다. 프로젝트가 아직 Instancio에 의존하지 않으면 추가하기 전에 먼저 묻는다.
