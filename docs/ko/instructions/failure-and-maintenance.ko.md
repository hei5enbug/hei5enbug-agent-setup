# 실패 및 유지보수

> 영어 원본: [failure-and-maintenance.md](../../../instructions/failure-and-maintenance.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

재시도 전에 실패를 분류한다. 실행 파일·훅 파일 누락, 기능 거부, 권한 경계, 확인된 사용량 한도 소진은 같은 재시도
대신 조건 변경이나 승인된 작동 경로가 필요하다. 일시 오류로 보이는 경우 동일 조건 재시도는 최대 1회다. 다시 실패하면
진단하고, 입력·환경·서비스 상태가 바뀌었다는 근거를 확보한 뒤 시도한다. 서비스 접근은 기존 경로별 대체 규칙을 따른다.

플러그인 훅 경로가 없으면 해당 훅에 의존하는 작업을 멈추고 구체적인 원인을 알린다. 훅 항목 삭제, 가짜 성공 반환,
신뢰 완화, 다른 버전을 이전 디렉터리에 복사하는 조치는 금지한다. 필요한 승인을 받아 검증된 동일 버전을 복구하거나
호스트가 지원하는 새 세션 경로를 사용한다. 호스트의 Stop 반복을 제어할 수 없으면 외부 복구 단계를 알린다. 누락된
스크립트나 지침이 호스트 자체의 반복을 끝낼 수 있다고 보장하지 않는다.

활성 코딩 에이전트 세션에서 캐시를 교체하는 플러그인 업데이트를 시작하지 않는다. 입력 대기 상태도 살아 있는 세션이다.
영향받는 세션을 종료한 뒤 갱신기의 명시적인 오프라인 경계를 사용하거나 이미 설치된 버전을 반영한다. 업데이트 보류
시 설치 파일과 보안 검사 동작을 유지한다. 수동 업데이트나 다른 프로세스의 로드된 디렉터리 삭제는 통제하지 못한다.
