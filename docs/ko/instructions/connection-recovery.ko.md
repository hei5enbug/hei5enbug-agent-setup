# Codex 연결 복구

> 영어 원본: [connection-recovery.md](../../../instructions/connection-recovery.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

`stream disconnected before completion`을 포함해 Codex 연결이 중단되었을 때 적용한다.
작업의 실제 상태를 복구하는 지침이며 서버 측 처리 오류를 예방하지는 못한다.

## 재시도 전

- 응답이 끊겼다고 도구가 실패한 것은 아니다. 백엔드나 명령이 여전히 실행 중일 수 있다.
  새 턴을 제출하기 전에 현재 스레드나 터미널 상태를 확인한다. 실행 중인 작업에는 프롬프트를
  다시 보내지 말고 상태를 관찰한다. 자신이 시작한 프로세스도 사용자가 허용한 범위에서만 중지한다.
- 최근 관련 대화 기록이나 실행 확인 기록을 읽고 영향을 받은 상태를 확인한다. 로컬 작업은 diff,
  파일, 자신이 시작한 프로세스를, 외부 쓰기는 저장된 대상이나 트랜잭션 확인 기록을 확인한다.
  응답이 없다는 이유로 쓰기를 반복하지 않는다. 결과를 확인할 수 없으면 불확실성을 알리고
  그 결과에 의존하는 작업을 보류한다.
- 사용자 변경과 현재 모델, 추론 강도, 작업 폴더, 권한, 과제 범위를 보존한다.
  보류 중인 결정을 진행하기 전에 [필수 질문 규칙](session/common.ko.md#확인-질문)을 적용한다.

## 안전한 이어가기

지원되는 경우 같은 대화에 다시 연결한다. 런타임이 대기 상태가 되면 확인된 미완료 작업부터
이어간다. 완료된 수정, 커밋, 푸시, 릴리스, 외부 쓰기를 반복하지 않는다. 복구를 위한 편법으로
승인 없이 공유 데몬을 재시작하거나 다른 세션을 닫거나 인증, provider, 네트워크 설정을 바꾸지 않는다.

[재시도 제한](failure-and-maintenance.ko.md#실패-및-유지보수)을 따른다. 일시적인 실패는 상태 확인으로 안전하다고
판단한 뒤에만 같은 조건의 재시도를 최대 한 번 허용한다. 다시 실패하면 원인을 조사하거나 조건이
달라져야 한다. CLI 버전, 시간, 오류 종류, 비공개로 보관한 request ID 등 관련된 비밀이 아닌 진단
정보만 기록한다. request ID 자체로 로컬 원인을 진단할 수는 없다.

## 전송 계층의 한계

기본 `openai` provider는 예약되어 있다. `[model_providers.openai]`를 덮어써 재시도를 조정할 수 있다고
가정하지 않는다. 커스텀 provider의 재시도 및 유휴 시간 제한 설정은 임의의 서버 처리 오류를
예방하지 않으며 사용자 provider를 바꿀 근거도 되지 않는다. 제안한 설정은 실제 CLI 버전의 스키마와
기능 목록에서 확인한다. 알 수 없는 질문 시간 제한·자동 응답 설정을 추가하거나 제거된 전송·압축
기능을 해결책으로 사용하지 않는다.

로컬 클라이언트 연결 해제, provider 스트림 실패, 서버 측 요청 실패는 서로 다르다.
통제된 시험으로 재현한 범위를 정확히 보고한다. 지침 로드, 제한된 관찰 시간 안의 실제 동작,
런타임 보장을 구분한다. 재개에 한 번 성공했다고 무기한 보장이 입증되는 것은 아니다.
