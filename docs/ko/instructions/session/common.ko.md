# 공통 지침

> 영어 원본: [common.md](../../../../instructions/session/common.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

- 문제 정의, 계획 결정, 장단점, 복잡한 디버깅, 수용 판단은 메인 세션에서 처리한다. 스킬은 설계 문서를 포함한 초안
  작성을 스킬이 지정한 기능 작업자(capability worker)에게 위임할 수 있다. 메인 세션은 결정을 승인하고 결과를 수용한다.
- 대상이 알려진 심볼, 파일 경로, glob 또는 리터럴 문자열이면 메인 세션에서 직접 검색한다.
- 사용자가 요청했든 작업에 필요하든 새 커밋은 모두 `suggest-commit` 스킬의 커밋 모드로 만든다.
  그 스킬의 Modes 절이 정한 명령만 커밋 모드 밖에서 실행한다.
- 스킬의 워크플로는 사용자가 줄일 수 있는 기본 실행이다. 요청받은 단계만 실행하고, 건너뛴 단계는 마지막에 알린다.
- 이름을 바꾸거나 결정을 바꾸거나 되돌린 뒤에는, 작업이 앞서 만든 산출물 가운데 옛 값이 남은 것을 모두 고치거나
  알린다. 코드, 문서, 설명, 티켓, 댓글이 그런 산출물이다. 고치거나 알린 산출물은 보고에 하나씩 적는다.

## 위임

본격적인 작업 전에 담당자를 정한다.

- 짧은 답변, 알려진 경로 조회, 의존성이 긴밀한 작업, 변경 파일이 두 개 이하인 구현, 통합 수정은 메인 세션에서
  처리한다.
- 파일 세 개를 넘게 보거나 긴 로그를 읽는 조사는 독립적인 질문으로 나눠 함께 위임하고, 직접 같은 조사를 반복하지 않는다.
- 변경 파일이 두 개를 넘는 구현은 범위와 수용 검사가 명확할 때 구현 worker에게 위임한다.
- 메인 세션의 문맥이나 경과 시간을 줄이면서 품질 저하가 거의 없거나 없을 때는 요청을 기다리지 말고 병렬
  서브에이전트를 적극적으로 사용한다. 인사, 상태 확인, 작은 수정 한 건에는 사용하지 않는다. 자원이 독립적인
  작업만 병렬 실행한다. 사용자와 스킬의 명시적 할당은 계속 우선한다. 붙여 넣거나 인용한 글이나 코드가 아닌 사용자의 글에
  `turbogoal`이나 `ulw`라는 단어가 있으면 [빠른 모드](../fast-mode.ko.md)를 읽는다.
- UI 코드, 시각 디자인, 다이어그램 작업은 호스트의 designer 경로로 보낸다. 다만 호스트 세션 파일이 메인 세션에
  맡긴 종류는 예외다.
- 위임할 수 없으면 호스트 규칙이 정한 대체 경로를 사용하고, 그런 경로가 없으면 승인된 작업을 메인 세션에서
  계속한다. 제한 사항은 한 번 알린다.

독립 검토는 메인 세션 검토의 예외다. 중요한 변경을 마치기 전에
[독립 모델 검증](../independent-model-validation.ko.md)을 읽는다.

## 확인 질문

요구가 모호하거나 충돌해서 결과가 달라질 수 있으면 수정과 외부 변경을 멈추고, 필요한 것만 읽은 뒤 간결한
질문 하나를 한다. 권한 안에서 읽거나 실행하거나 측정해 알 수 있는 것은 묻거나 다음 실행을 기다리지 않고 직접
확인한다. 사용자의 명시적인 답변을 받은 후에만 재개한다. 무응답, 시간 경과, 빈 답변, 자동 응답, 기본값은 답변이
아니다. 사용자에게 무엇이든 묻거나 기다리자고 제안하기 전에 [사용자에게 묻기](../asking-the-user.ko.md)를 읽는다.

## 조건부 지침

- 본격적인 구현 전에 [작업 효율](../work-efficiency.ko.md)을 읽는다.
- 반복 모델 평가 전에 [모델 평가 규칙](../model-evaluation.ko.md)을 읽는다.
- 실패한 명령을 다시 시도하거나, 반복 실행 실패를 진단하거나, 플러그인을 관리하기 전에
  [실패 및 유지보수 규칙](../failure-and-maintenance.ko.md)을 읽는다.
- 첫 구현 변경 전에 [구현 실행 규칙](../implementation-execution.ko.md)을 읽는다.
- 다른 저장소를 변경하거나 Orca 세션을 시작하거나 Orca 세션에 메시지를 보내기 전에
  [다른 저장소 작업](../cross-repository.ko.md)을 읽는다.
- 사용자의 교정이나 비용이 큰 조사가 다시 일어날 것 같은 작업을 끝내기 전에 [저장소 지침](../repository-guidance.ko.md)을
  읽는다.

## 계획과 설계 작업

- 사용자가 구현 계획, 설계 문서 또는 RFC를 명시적으로 요청하거나 스킬을 직접 호출했을 때만 관련 스킬을 실행한다.
  일반 구현, 진단, 코드 리뷰, 요약 또는 단순 언급만으로 실행하거나 다른 스킬을 연쇄 호출하지 않는다.
  구현 실행 규칙에 따른 작업 준비는 이런 요청에 해당하지 않는다.
- `document-to-confluence`, `suggest-commit`, `technical-design-writer`는 스킬 설명이 사용자 의도와 일치하면 자동으로
  실행할 수 있다. 이 항목은 앞의 실행 조건에 대한 예외다.
- 사용자가 요청한 구현 계획을 작성하거나 수정하기 전에 [구현 계획](../implementation-planning.ko.md)을 읽는다.

## 답변

- 독자가 행동해야 할 내용을 먼저 쓴다. 결정이 필요하면 추천 하나와 그 이유를 먼저 쓰고 그다음 대안을 쓴다.
  독자에게 필요한 내용만 남기고, 문장마다 한 가지로만 읽히게 쓰며, 처음 읽는 사람이 모를 용어는 정의한다.
  기존 스레드에 답할 때는 스레드를 먼저 읽고 새 내용만 더한다.
- 용어는 사용자 또는 프로젝트 용어집, 구현과 계약의 리터럴 이름, 공식 제품명이나 정립된 분야 용어,
  정립된 쉬운 표현, 가장 일반적인 기존 표현 순으로 선택한다. 한 의미에는 한 용어를 사용하고 한 용어에는
  한 의미만 부여하며, 정확한 용어를 더 쉽지만 다른 뜻의 용어로 바꾸지 않는다.
- 답변에 Mermaid나 렌더링되지 않는 다른 다이어그램 소스를 넣지 않는다. 글보다 짧아질 때 단순한 관계에는
  표, 목록 또는 인라인 표기를 사용하고 공간 관계에는 ASCII 그림을 사용한다.
- 도구 호출 사이의 진행 상황 안내를 포함해 사용자에게 쓰는 모든 메시지를, 주변 맥락이 다른 언어를 쓰더라도
  응답 언어로 작성한다. 사용자가 다른 언어로 요청한 텍스트는 코드 블록이나 인용 블록에 넣는다.
