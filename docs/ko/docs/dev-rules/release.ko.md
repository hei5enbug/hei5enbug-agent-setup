# 릴리스와 버전

> 영어 원본: [release.md](../../../dev-rules/release.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

이 저장소 개발 규칙은 `AGENTS.md`를 보완한다.

## 기준과 계획 버전

- `HEAD`에서 닿는 가장 새로운 `v<major>.<minor>.<patch>` 태그가 릴리스 기준이다. 매니페스트에만 있는 버전은 이미
  `main`에 있거나 로컬에 설치돼 있어도 계획한 다음 버전이지 기준이 아니다.
- 배포되지 않은 작업 전체를 그 계획한 버전 하나에 유지한다. 기준 이후 첫 변경이 같은 커밋에서 그 버전을 정하고, 이후
  변경은 다시 올리지 말고 그 버전에 합친 뒤 자기 커밋 안에서 아래 표로 자리를 다시 정한다. 로컬 반복 작업마다 의미
  버전을 올리지 않는다.
- 버전을 바꾸기 전에 기준 태그와 계획한 버전을 사용자에게 밝힌다.
- 두 플러그인 매니페스트, `pyproject.toml`, `uv.lock`의 버전을 일치시킨다.
- `tests/test_release_version.py`는 기준보다 낮은 버전, 기준 이후 두 개 이상의 계획 버전(더 낮은 단계의 다음 버전을
  나중에 더 높은 단계로 다시 고른 경우는 제외), 기준 이후 변경이 있는데도 계획 버전이 기준과 같은 경우, 기준 이후 버전
  파일만 바꾸는 커밋을 거부한다.

## 설치와 릴리스

- 태그를 단 릴리스만 설치한다. 사용자가 아직 릴리스하지 않은 작업의 설치를 요청하면 먼저 태그를 달아, 다음 변경이 다음
  계획 버전에서 시작하게 하고 재설치에 cachebuster가 필요 없게 한다.
- 릴리스는 태그만 단다. 릴리스하거나 버전만 바꾸는 별도 커밋은 만들지 않는다.
- 사용자가 릴리스를 배포하면 `HEAD`에서 `README.md`의 모든 개발 검사를 실행하고 `HEAD`에 `v<version>` 태그를 단 뒤
  태그를 푸시한다.

## 버전 자리

배포되지 않은 변경 중 영향도가 가장 높은 항목을 기준으로 다음 의미 버전을 정한다.

| 자리 | 적용 기준 |
|---|---|
| 첫 번째 | 하네스 아키텍처나 핵심 제어 로직이 기존 실행 계약을 대체할 정도로 바뀐다. |
| 두 번째 | 스킬을 추가, 제거 또는 통합하거나 목표, 요구사항 또는 외부 동작 계약을 바꾼다. |
| 세 번째 | 기존 스킬의 목표와 요구사항을 유지한 채 성능, 신뢰성, 평가 품질 또는 출력 품질을 개선한다. 이런 변경이 여러 개여도 한 번만 올린다. |
