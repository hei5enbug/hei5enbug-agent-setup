# 스킬 초안의 작성 pattern

> 영어 원본: [writing-patterns.md](../../../../../skills/skill-builder/references/writing-patterns.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

### 작성 pattern

명령형으로 쓰고 중요한 제약에는 이유를 설명한다. 대문자 강조를 반복하기보다 적응 가능한 원칙을 쓴다.

형식을 제약하는 규칙은 그 규칙이 다스리는 모든 표면을 명시하거나, 표면과 무관하게 서술해야 한다.

정확한 출력 계약에는 템플릿을 제공한다.

```markdown
## Report structure
Use this exact structure:
# [Title]
## Executive summary
## Key findings
## Recommendations
```

모호함을 없앨 때는 예시를 사용한다.

```markdown
## Commit message format
Input: Added user authentication with JWT tokens
Output: feat(auth): implement JWT-based authentication
```

### 포괄적 품질 요구와 대조 평가

초안을 작성하기 전에 "기존 스타일과 일치", "자연스러움", "일관성" 같은 포괄적 품질 요구를 관찰할 수
있는 차원으로 나눈다. 각 핵심 차원마다 근거 신호, 출력에 미쳐야 하는 영향, 우선순위, 동률 처리와
fallback을 정한다. 더 구체적인 체크리스트에서 빠진 필수 차원을 모델이 알아서 복원할 것이라고 가정하지
않는다.

출력 동작을 예시, 기록, 문서 또는 다른 컨텍스트에서 추론한다면 대조 케이스를 포함한다. 작업과 주 입력은
고정하고 결정적인 컨텍스트 신호 하나만 바꾼다. 의도한 출력 차원만 바뀌고 관련 없는 차원은 안정적으로
유지되는지 확인한다. 의도 파악 단계에서 식별한 모든 핵심 추론 차원을 하나 이상의 케이스나 assertion에
연결한다. "스타일과 일치" 같은 포괄적인 assertion은 이름을 붙이지 않은 차원을 검증하지 못한다.

사용자가 간헐적이거나 모델별로 발생하는 결함을 보고했다면 보고된 설정이 필수 평가 모델 어댑터와 일치할
때 그 설정으로 영향받는 구버전과 수정본 쌍을 고정된 실행 예산 안에서 2~3회 반복한다. 구버전이 한 번
성공했다고 보고를 반증한 것으로 처리하지 않는다. 정확한 설정을 사용할 수 없거나 필수 어댑터와 충돌하면
다른 설정으로 대체하지 말고 검증되지 않았다고 기록한다. 관련 없는 케이스는 반복하지 않는다.
