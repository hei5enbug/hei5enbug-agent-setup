# 건너뛴 세션을 수동으로 마무리하기

> 영어 원본: [manual-finish.md](../../../../../skills/orca-plugin-refresh/references/manual-finish.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

스크립트가 잘못 판단해 결과가 `skipped`나 `failed`인 세션에만 사용한다. 예를 들어 명백히 Claude Code를 실행 중인
터미널에 `not_a_claude_session`이 나온 경우다. 현재 요청에서 해당 세션에 대한 사용자 승인을 받은 뒤에만 실행하며,
`blocked`나 `deferred`인 세션에는 실행하지 않는다.

## 명령을 보내기 전 확인

스크립트가 실행하는 확인을 모두 실행한다. 하나라도 실패하면 아무것도 보내지 말고 어떤 확인이 실패했는지 사용자에게 알린다.

1. 턴 기록이 유휴 상태다. 세션 표식이 가리키는 대화 기록에서 가장 최근 턴이 끝났고, 백그라운드 작업, 서브에이전트,
   예약된 깨우기가 남겨야 할 알림이 없다.
2. 화면에 열린 질문이나 승인 프롬프트가 없다.
3. 입력 줄에 직접 입력한 내용이 없다. 회색 추천 문구는 빈 입력으로 센다. `x`를 한 번 입력하고 초안이 정확히 그 `x`만
   표시할 때에만 백스페이스 한 번으로 지운다. 직접 입력한 글이 있으면 대체되지 않고 뒤에 붙는다. 자신이 입력하지 않은
   내용은 절대 지우지 않는다. 줄에 `x`가 남으면 그 위치를 보고한다.

## 전송과 확인

실행에 해당 세션의 작업으로 나열된 것만 하나씩 보낸다. `/reload-plugins`를 먼저 보내고, `/compact`는 세션이
`compact_reason`을 보고할 때만 보낸다. 스크립트처럼 전송 뒤 추가된 대화 기록에서 각 결과를 확인하고, 대화 기록이
없으면 화면에서 확인한다. 세션을 끝내고 재개하려면 `references/resume.md`를 수동으로 따른다.

## 결과별 기록

완료한 작업마다 전체 터미널 핸들로 `python3 <script> record-manual --run-id <run_id> --terminal <handle> --action <reload|compact|clear|resume>
--result <done|failed> [--detail <code>] --json`을 한 번 실행한다. `failed` 결과에는 소문자 `--detail` 코드를
전달하며 세션을 `failed`로 표시하고, 그 작업과 끝나지 않은 다른 작업은 모두 남은 작업으로 유지한다. `done` 결과는
세션의 남은 작업에서 해당 작업만 지운다. 남은 작업이 있는 동안 세션은 실패 전 상태를 보여 주며, 실패한 다른 작업이
남아 있으면 `failed`로 보여 준다. 남은 작업이 없으면 세션을 `done`으로 표시하므로 `status`와 `not_refreshed`에도
반영된다. 남은 작업은 저장된 `actions`이며, 자동 단계가 그것을 비웠으면 `planned` 작업 중 아직 끝나지 않은
작업이다. 새 프로세스가 설치된 플러그인을 불러오므로 `resume`은 계획된 reload도 끝낸다.
이 명령은 실행에 포함되지 않은 터미널과 상태가 `skipped`나 `failed`가 아닌 세션을 거부한다.
유일한 예외는 `--action resume`이다. 실행의 `resumed` 목록에 해당 터미널의 `skipped`나 `failed` 재개가 있으면,
터미널에 세션 결과가 없거나 세션 결과가 이미 `done`이어도 기록이 그 항목을 `done` 또는 `failed`로 바꾸고 `manual`을
표시하며, 세션 결과는 그대로 둔다.
