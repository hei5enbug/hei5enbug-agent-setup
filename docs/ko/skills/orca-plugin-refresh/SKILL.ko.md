# Orca 플러그인 새로고침

> 영어 원본: [SKILL.md](../../../../skills/orca-plugin-refresh/SKILL.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

이 스킬은 `hei5enbug-agent-setup`과 사용자가 고른 다른 플러그인을 업데이트한 뒤, 설치된 버전을 실행 중인
Orca 세션에 세션을 끝내지 않고 적용한다. 스스로 세션을 끝내지 않으며, 사용자가 현재 요청에서 그 세션을 승인한 뒤에만
`resume`으로 세션을 끝내고 다시 연다.

## 업데이트가 실행 중인 세션에 반영되는 방법

| 구분 | Claude Code | Codex |
|---|---|---|
| 스킬, 에이전트, 훅 | `/reload-plugins`가 모든 플러그인을 다시 불러온다 | 다음 턴에서 새 설치본을 자동으로 불러온다 |
| 세션 지침 | `/compact` | `/compact`; 다음 턴에서 지침을 불러온다 |

플러그인의 세션 시작 훅은 Orca 터미널마다 호스트, 플러그인 디렉터리, 대화 기록 경로, 실행 지침의 digest가
담긴 표식을 기록한다. 해당 터미널의 대화형 세션만 표식을 쓴다. 그 터미널에서 시작한 자식 프로세스
`claude -p`나 `codex exec`은 표식을 쓰지 않는다. Orca의 터미널 기록에 에이전트가 없으면, 스크립트는 그 호스트의
입력 줄이 화면 맨 아래에 있을 때만 그 터미널을 표식의 호스트로 본다. 그래서 오래된 표식이 남은 셸은 대상이 되지 않는다.
표식이 없거나 digest가 다르거나, Codex 세션의 플러그인
디렉터리가 교체됐거나, Claude Code 세션이 삭제된 디렉터리를 가리킬 때만 스크립트가 세션을 compact한다. 이
판단은 이 플러그인의 지침 digest만 따르고 다른 플러그인은 보지 않는다. Claude Code가 대화가 너무 짧아
compact할 수 없다고 답하고 대화 기록에 프롬프트가 없으면 스크립트가 `/clear`를 보낸다. 비어 있는 세션에는
잃을 내용이 없기 때문이다. 한 번도 턴을 진행하지 않은 Codex 세션은 첫 턴에서 새 지침을 불러오므로 따로
처리하지 않는다.

## 작업 흐름

`<script>`는 이 `SKILL.md`가 있는 디렉터리의 `scripts/orca_plugin_refresh.py`다.

1. **설치 경로를 고른다.** 새 버전을 설치하려면 `python3 <script> update --json`을 실행한다. 다른 플러그인도
   함께 새로고침하려면 사용자가 말한 ID마다 `--also <plugin@marketplace>`를 전달한다. 이 플래그는 여러 번
   쓸 수 있고 `apply-installed`에서도 쓸 수 있다. `--also`가 없으면 스크립트는 `HEI5ENBUG_REFRESH_PLUGINS`
   환경 변수(쉼표로 구분한 ID)를 쓰고, 그것도 없으면 저장된 `refresh_plugins` 플러그인 옵션을 쓴다. 비어
   있지 않은 첫 출처가 이긴다. ID를 지어내지 않는다. 잘못된 ID는 위치와 함께 `plugin_id_invalid`를 반환하고
   아무것도 실행하지 않는다. 사용자에게 고친 ID를 물어본다. 스크립트는 중복과 이 플러그인 자신의 ID를 빼고
   함께 새로고침할 플러그인을 최대 10개까지 남기며, 넘친 개수는 `companions_dropped`로 알린다. 설치를 이 스킬
   밖에서 이미 마쳤거나 사용자가 설치된 버전을 적용해 달라고 하면 `python3 <script> apply-installed --json`을
   실행한다. 이 명령은 설치 경로를 읽고 마켓플레이스나 설치 명령을 실행하지 않는다.
2. **업데이트 결과를 처리한다.** 각 호스트의 버전 변화를 보고한 뒤 `hosts.<host>.plugins`의 모든 플러그인을
   상태, 버전, 경고와 함께 보고한다.
   - `updated` 또는 `current`: 버전이 바뀌었거나 그대로이며 설치본이 검증됐다.
   - `not_installed`: 해당 호스트에 설치되어 정확히 한 번 활성화된 상태가 아니며 아무것도 실행하지 않았다.
   - `local_source`: 플러그인이 로컬 폴더에서 로드되므로 스크립트는 설치하지 않으며, 커밋하지 않은 코드가
     배포되는 일은 없다. Claude Code는 `/reload-plugins`로 그 폴더를 다시 불러온다.
   - `deferred`: 호스트의 설치 게이트가 막았다. 아래 Codex 게이트를 본다.
   - `error`: `code`와 `message`를 알린다. 이 플러그인이나 세션 적용을 막지 않는다.

   이 플러그인 자체가 호스트에서 로컬 소스로 로드되면 그 호스트는 `local_source: true`로 보고하고, 설치 명령을
   실행하지 않으며, `apply`에는 계속 쓸 수 있다. 이 플러그인의 호스트에 `error`가 있으면 코드와 메시지를 알린다.
   해당 호스트의 세션은 건드리지 않는다.
   Claude Code는 업데이트가 옛 버전 옆에 새 버전을 추가하고 실행 중인 세션이 `/reload-plugins` 전까지 불러온
   디렉터리를 유지하므로 언제든 설치한다. Codex 업데이트는 옛 설치본을 삭제하므로, 호출자가 Codex 턴 안에
   있으면 `update_deferred_active_session`, 최근 30분 안의 Codex 세션이 턴을 끝내지 않았으면
   `codex_turn_in_progress`, Codex 세션을 읽을 수 없으면 `update_deferred_unknown_session_state`로
   보류한다. 보류된 Codex 호스트는 `root`와 `recovery_command`(해석된 함께 새로고침할 플러그인을 `--also`로 다시
   붙인다)와 함께 보고하고, Codex 턴이 끝난 뒤 `update`를 다시 실행하라고 사용자에게 알린다. 스스로 다시 시도하지
   않는다. 게이트는 Codex 설치 직전마다 다시 확인하므로 실행 도중 시작된 턴은 그 플러그인과 이후의 모든 Codex 설치를
   보류하고, 막힌 플러그인은 `deferred`가 되며 Claude Code는 영향받지 않는다. 이후 명령은 반환된 `script` 경로로 실행한다. Codex
   업데이트가 이 스킬을 불러온 설치 디렉터리를 삭제할 수 있기 때문이다. 모든 경고를 보고한다.
   - `unreleased_same_version`: 버전이 바뀌지 않아 Claude Code가 설치본을 유지한다. 이 파일이 Claude Code에
     반영되려면 버전을 올려야 한다고 알린다.
   - `codex_hooks_need_trust`: 플러그인의 훅 정의가 바뀌었거나 새로 생겼거나 사라졌거나, 훅이 있는 플러그인의
     파일이 하나라도 바뀌었다. Codex는 훅 신뢰를 플러그인의 모든 파일에 묶기 때문이다. 이 플러그인이면 스크립트가
     먼저, 설치본이 깨끗한 공식 checkout이고 그 HEAD를 공식 원격이 지금 `main`이나 `v*` 태그로 광고하거나 `main`에 포함할 때
     자기 훅을 다시 신뢰하고, 그러면 이 경고 대신
     `codex_hooks_trusted: true`를 알린다. 그렇지 않으면 경고의 `detail`에 이유를 담는다. 동반 플러그인은
     Codex가 그 훅 중 하나라도 아직 untrusted나 modified로 나열할 때(개수는 `detail`에 담긴다) 또는 그 목록을 읽지
     못했을 때만 이 경고를 유지하며, 스크립트는 동반 플러그인의 훅을 신뢰하지 않는다. Codex가 신뢰하지 않은 훅을
     건너뛰므로 Codex `/hooks`에서 그 플러그인의 훅을 신뢰하도록 요청한다.
   - `unreleased_check_unavailable`: Claude Code가 같은 버전의 파일을 놓쳤는지 확인할 수 없다. 이유를 알린다.
3. **세션에 적용한다.** 이 플러그인의 호스트 업데이트가 성공했거나 `apply-installed` 결과에 그 호스트의 오류가
   없으면 `python3 <script> apply --run-id <run_id> --json`을 셸 제한 시간 600초 이상으로 포그라운드에서
   실행한다. 이 단계는 사용자에게 확인을 묻지 않는다. 어떤 세션에 명령을 보낼지는 스크립트의 확인이 정한다.
   스크립트는 약 20초 동안 한가하고 입력 줄이 비어 있거나 입력한 글을 지운 세션에만
   명령을 보내고, 이미 보낸 명령의 결과를 계속 확인하며 정확히 되돌릴 수 있는 글은 되돌린다. 아직 바쁘거나 준비되지 않은 세션은
   기다리지 않고 분리된 도우미 하나에 `deferred`로 넘긴다.
   `already_running` 오류는 다른 실행이 아직 명령을 보내고 있다는 뜻이다. 끝날 때까지 기다린 뒤 `apply`를
   다시 실행한다. 업데이트에 실패한 호스트는 계속 차단하고, 성공한 호스트는 진행할 수 있다.
4. **모든 세션 결과를 보고한다.** 터미널 접미사, 호스트, 작업 트리, 상태, 완료한 작업, 세부 내용을 표시한다.
   - `done`: 필요한 작업이 모두 확인됐다. `already_current`는 할 일이 없었다는 뜻이다.
     `fresh_session_loads_on_first_turn`은 턴을 진행하지 않은 Codex 세션을 나타낸다.
     `empty_session_cleared`는 비어 있는 Claude Code 세션에 `/clear`를 보냈다는 뜻이다.
     `instructions_load_on_next_turn`은 compact된 Codex 세션이 다음 턴에 지침을 불러온다는 뜻이다.
     `applied_by_session`은 세션이 넘긴 뒤 `/reload-plugins`를 스스로 실행했다는 뜻이다.
   - `skipped`: 세션이 계속 바빴거나, 입력 줄을 읽을 수 없거나, 보내기 직전에 입력이 바뀌었거나, 제한 시간에
     도달했거나, 세션이 닫혔다. `input_clear_failed`는 입력 줄을 지우지 못해 아무것도 보내지 않았거나
     (`input`이 `clear_failed`), 스크립트가 글을 다시 입력했다는 뜻이다.
   - 모든 세션은 `ready_signal`(전송을 허용한 신호인 `host_record` 또는 `tui_idle`)도 보고하고, 입력을 붙들었다면
     `input`(`restored`, 정확히 되돌릴 수 없는 입력이면 `cleared`)도 보고한다.
     Claude Code 세션은 `release`도 보고하며, 설치된 릴리스보다 오래된 릴리스로 실행 중이거나 실행 파일이 없어졌으면 두 버전과
     함께 `host_release_outdated`를 보고한다.
   - `failed`: 보낸 작업이 확인되지 않았거나 Claude Code가 거부했다. `plugin_load_error`는 reload 답이
     `N error(s) during load`를 알렸거나 활성화된 플러그인보다 적게 불러왔다는 뜻이며, `plugin_load`에 보고된 개수가
     있다. `--force`를 요청하는 reload 거부는
     플러그인의 MCP 도구가 바뀌었다는 뜻이다. 사용자 승인 없이 강제로 진행하지 않는다.
     `compact_needs_more_messages`는 대화가 너무 짧아 compact할 수 없다는 뜻이다. 다음 compact 또는 재시작 때
     지침이 갱신된다. `probe_interrupted_check_input`은 스크립트가 입력 줄을 확인하는 동안 입력 줄이 바뀌고
     원래 상태로 돌아오지 않았거나, 그런 확인 중단이 계속됐다는 뜻이다. 스크립트는 직접 입력하지 않은 내용을 지우지 않으므로, 해당 세션 입력 줄에 불필요한 `x`가 있는지
     확인하라고 알린다. `input_restore_unconfirmed`는 저장한 글이 입력 줄에 다시 있는지 확인되지 않았다는 뜻이고,
     `input_not_restored_line_in_use`는 사용자가 새 글을 입력해 저장한 글을 다시 입력하지 않았으며 그 글은 사라졌다는
     뜻이다. 해당 세션의 입력 줄을 확인하라고 알린다. `helper_start_failed`는 이 세션의 후속 작업을 시작하지
     못했다는 뜻이다. `apply`를 다시 실행한다.
   - `blocked`: 해당 호스트의 플러그인 업데이트가 실패했거나 설치 manifest, 훅 대상, 지침 digest가 검증되지
     않았다.
   - `deferred`: 세션이 바쁘거나 준비되지 않아 분리된 도우미가 마무리한다. 5단계를 따른다.
   - `queued_after_turn`: 이 스킬이 실행 중인 세션이다. 5단계를 따른다.
5. **도우미가 마무리하게 한다.** `apply`가 `deferred`나 `queued_after_turn`을 보고하면 첫 결과를 알리고 턴을
   끝낸다. 분리된 도우미 하나가 넘겨받은 모든 세션과 이 세션을 지켜본다. 각 세션 자신의 턴 기록이 먼저
   판단하고, Orca의 한가함 콜백(`orca terminal wait --for tui-idle`)은 그 기록이 판단하지 못할 때만 판단한다.
   세션이 한가해졌다고 알려 오면 도우미는 3초 뒤 다시 확인하고, 설치된 플러그인이 이번 실행과 그대로인지와 세션이 이미 새 지침을 불러왔는지 확인한 뒤에만 남은
   작업을 보낸다. 입력 줄을 읽을 수 없는 경우처럼 다른 이유로 미뤄진 세션은 확인할 때마다 다시 살핀다. 넘긴 뒤
   한 시간 안에 준비되지 않은 세션에는 보내지 않고 `not_idle_before_deadline`이나 마지막 이유로 남긴다.
   터미널이 닫힌 세션은 곧바로 `terminal_gone`으로 건너뛰고 그 대기를 끝낸다. 상태에는 세션마다 최종 결과가
   정해지는 즉시 기록되므로, 도우미가 도는 동안에도 `status`로 진행 상황을 볼 수 있다.
   상태의 `others_finished_at`이 설정돼 있고 이 세션만 아직 `queued_after_turn`이면 다른 모든 세션은 최종 상태이므로
   기다리지 말고 보고한다. 이 세션의 작업은 턴이 끝난 뒤 실행되며, 사용자가 이 세션에서 `/reload-plugins`(나열돼
   있으면 `/compact`도)를 실행하면 완료로 센다.
   모든 세션이 끝나면 도우미는 `python3 <script> status --run-id <run_id> --json`을 실행하라는 프롬프트를 이
   세션에 한 번 보내고, 자신이 시작한 Orca 대기를 모두 끝낸 뒤 종료한다. 그 프롬프트가 오면 명령을 실행하고
   `hosts`의 플러그인 상태와 함께 모든 세션을 보고한다. `not_refreshed`는 업데이트를 받지 못한 세션 목록이다.
   상태의 `self_notification`이 `sent`가 아니면 프롬프트를 전달하지 못한 것이다. 그래도 상태에 작업 결과가
   남아 있다.
6. **재개를 제안한다.** `resume_approval_needed`를 보고한 세션(`plugin_load_error` 또는 `host_release_outdated`)을
   모두 보여 주고 사용자가 승인할 세션을 묻는다. 고치면 그 세션이 끝나고 같은 대화가 다시 열린다.
   `resume`을 실행하기 전에 `references/resume.md`를 읽고, 승인된 터미널에만 실행한다.

`--compact`의 기본값은 `auto`이며 낡은 세션만 compact한다. 사용자가 명시적으로 요청한 경우에만
`--compact always` 또는 `--compact never`를 전달한다. `plan`과 `self-apply`는 스크립트가 스스로 사용하는
내부 하위 명령이므로 직접 실행하지 않는다. Orca 터미널에 명령을 직접 보내지 않으며, 이 요청에서
사용자가 승인한 세션에 `resume`을 실행하는 경우가 아니면 세션을 끝내지 않는다. 스스로 `--force`를 전달하지 않는다.

스크립트는 모든 세션이 `done`, `deferred`, `queued_after_turn` 중 하나이거나 업데이트 또는 `apply-installed` 결과가 ok이면
`0`으로 종료한다. 그렇지 않으면, 그리고 사용법 오류에도 `2`로 종료한다. 이 플러그인에 호스트 오류가 있거나
함께 새로고침할 플러그인 중 하나라도 상태가 `error`이면 업데이트 또는 `apply-installed` 결과는 ok가 아니다.

## 안전과 한계

- 명령은 인자 목록이며 셸을 거치지 않는다. 각 호스트는 한 실행에서 마켓플레이스를 최대 한 번 갱신한 뒤
  플러그인을 갱신한다. Claude Code는 `claude plugin marketplace update`와 `claude plugin update`를, Codex는
  `codex plugin marketplace upgrade`와 `codex plugin add`를 실행한다.
- 설치 성공을 보고하기 전에 설치된 manifest의 이름과 버전, 플러그인 디렉터리를 가리키는 모든 훅 대상을
  확인한다. 이 플러그인은 필수 훅 대상, Claude Code Mod 파일, 지침 digest도 확인한다. 한 플러그인이 실패해도
  다른 플러그인이나 호스트의 성공 결과는 가려지지 않는다.
- Codex 게이트는 최근 30분 안에 수정된 Codex 롤아웃 파일만 읽고, 마지막으로 완성된 줄이 턴의 끝을 기록한
  세션만 유휴로 센다. 마지막 줄이 불완전하거나 읽을 수 없으면 보류한다. 프롬프트 내용은 읽지 않는다.
- 명령은 연결되고 쓰기가 가능하며, 입력이 비어 있거나 아래처럼 지운, 유휴 상태인 터미널에만 보낸다.
  호스트 자신의 턴 기록이 한가함이나 바쁨을 먼저 판단하며, 각 전송 직전에 다시 읽고 그때 판단하지 못하면
  `tui-idle`도 요구한다. 가장 최근 턴이 끝났고, 파일 앞쪽을 포함해 알림을 남긴 백그라운드 작업, 서브에이전트,
  예약된 깨우기가 없는 Claude Code 대화 기록이면 한가함이고,
  진행 중인 턴이면 바쁨이며, Codex 롤아웃은 마지막으로 완성된 줄이 같은 방식으로 판단한다. 기록이 없거나
  불완전하거나 판단할 수 없으면 Orca의 `tui-idle`이 판단한다. 짧은 경쟁 조건은 남아 있다.
- Orca는 Claude Code 입력 줄을 화면에 표시하지 않고 초안으로 제공한다. 이 초안에는 회색 안내 문구도
  포함될 수 있다. 초안이 5초 동안 바뀌지 않으면 스크립트는 문자 하나를 입력한다. 초안이 그 문자 하나와
  정확히 같을 때만 삭제한다. 안내 문구는 교체되고 직접 입력한 내용은 이어 붙지만, 둘 다 원래 상태로
  돌아온다. 확인으로 한 줄짜리 입력 글이며 붙여넣기나 이미지 자리표시도, 맨 앞의 `-`도 없다고 드러나면, 스크립트는 그 글을 메모리에만
  두고 백스페이스로 지운 뒤 명령을 보내며, 마지막 작업이 확인되거나 실패한 뒤 또는 세션을 도우미에 넘기기
  전에 Enter 없이 다시 입력하며, 지우기에 실패해 일부만 지워진 줄은 이어서 채운다. 지우고 되돌리는 사이에 프로세스가 멈추면 그 글은 사라진다. 정확히 되돌릴 수 없는 입력은 같은 방식으로
  지운 뒤 갱신을 적용하고, 보고에는 `cleared`로 표시하며, 지운 입력은 어디에도 보관하지 않는다. 확인이 중단돼도 초안이 원래 상태로 돌아오거나
  비면 스크립트의 문자가 남지 않은 것이므로, 나중에 최대 세 번 더 확인한다. 스크립트는 각 명령을 보내기
  직전에 초안을 다시 확인한다.
- `/clear`는 Claude Code가 compact를 거부하고, 보내기 직전에 다시 읽은 대화 기록에 프롬프트가 없을 때만
  실행한다.
- 각 결과는 전송 뒤 추가된 대화 기록이나 전송 뒤 다시 쓴 표식으로 확인한다. 대화 기록을 이용할 수 없을
  때만 화면을 확인한다.
- 분리된 도우미를 포함해 명령을 보내는 모든 프로세스는 잠금 하나를 공유한다.
- 실행 하나는 도우미를 최대 하나만 시작한다. 도우미는 종료하기 전에 자신이 시작한 Orca 대기를 모두 끝낸다.
  넘겨받은 세션과 이 세션은 최대 한 시간 기다린다.
- 어떤 세션에서 Orca 한가함 대기가 실패하면 도우미는 그 세션을 기한까지 상태 확인 방식으로 살핀다.
- `/compact`는 대화를 요약하므로 지침이 오래된 세션에만 실행한다.
- compact된 Codex 세션은 다음 턴에서 새 지침을 불러오며 결과에도 이 내용을 표시한다.
- Orca가 관리하는 터미널만 다룬다. Orca 밖의 Codex 세션도 최근 30분 안에 롤아웃 파일을 썼다면 설치 게이트에서
  진행 중인 세션으로 센다.
- 이 작업 흐름 밖에서 직접 업데이트하거나 다른 프로세스가 로드된 플러그인 디렉터리를 삭제하는 상황은
  이 스킬이 막을 수 없다.
- 실행 상태는 `~/.local/state/hei5enbug-agent-setup/orca-plugin-refresh/`에 저장한다. `XDG_STATE_HOME`이
  설정되면 그 경로를 사용한다. 표식은 Orca 사용자 데이터 디렉터리에 저장한다. 둘 다 프롬프트나 대화 기록을
  저장하지 않는다.
