# 로컬 데이터 정리

> 영어 원본: [SKILL.md](../../../../skills/local-data-cleanup/SKILL.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

Claude Code와 Codex가 이 컴퓨터에 남긴 회수할 수 있는 로컬 데이터를 찾아 크기별로 보고한다. 찾는 대상은 끝난 세션의 임시
작업 폴더, 대체된 호스트 릴리스와 플러그인 릴리스, 오래된 세션 기록, 오래 방치된 임시 폴더다. 사용자가 고른 항목만 모든
안전 검사를 통과한 뒤에 삭제한다. 사용자가 Claude Code나 Codex가 쓰는 디스크 공간을 찾거나 확보해 달라고 요청할 때만 사용한다.
예를 들면 "Claude랑 Codex가 쓰는 디스크 정리해줘"나 "free up space the agents use"처럼 요청하는 경우다. 또는 사용자가 나중
메시지에서 이 스킬을 실행하라는 한 줄짜리 권고를 승인한 경우에도 사용한다. 자동으로 시작하지 않으며, 일반적인 디스크 정리나
프로젝트 자체의 빌드 산출물에는 사용하지 않는다.

Python 3.12 이상, 호스트 데이터 폴더에 대한 파일 시스템 접근 권한, `ps`, `lsof`, `git` 명령이 필요하다. 명령이 없거나 0이
아닌 종료 코드로 끝나면 그 명령이 필요한 검사는 unknown이 되므로, 그 검사가 다루는 항목은 아무것도 offer 대상이 되지 않는다.
`lsof`는 검색 조건 없이 실행하므로, 어떤 종료 코드도 "일치하는 항목 없음"을 뜻하지 않는다. 관리자 권한이 없으면 `lsof`는 현재
사용자의 프로세스만 본다. 두 번째 판정에는 다른 호스트의 읽기 전용 에이전트가 필요하다.

이 영어 `SKILL.md`와 그 영어 참조 파일만 실행 원본으로 사용한다.

Claude Code와 Codex의 로컬 데이터를 읽기 전용으로 조사한다. 고정된 안전 규칙과 다른 호스트의 독립된 판정에 비추어 각
candidate를 검사하고, 사용자가 고른 것만 삭제한다. 모든 삭제는 되돌릴 수 없으므로 항목은 언제나 사용자가 고른다. 크기나
나이만으로는 어떤 항목도 삭제 대상이 되지 않는다.

## 실행 위치

| 단계 | 담당 |
|---|---|
| 1. 범위 확정 | 메인 세션 |
| 2. 조사 | 메인 세션, 함께 든 스크립트 사용 |
| 3. 두 번째 판정 | 다른 호스트의 읽기 전용 에이전트 |
| 4–5. 병합과 보고 | 메인 세션, 함께 든 스크립트 사용 |
| 6–7. 삭제와 검증 | 사용자가 항목을 고른 뒤에만 메인 세션, 함께 든 스크립트 사용 |

## 경계

- 사용자가 요청했을 때, 또는 사용자가 나중 메시지에서 한 줄짜리 권고를 승인한 뒤에만 시작한다. 디스크가 가득 차 보인다는
  이유로 스스로 시작하지 않는다.
- 1단계부터 5단계까지는 읽기 전용이다. 이 단계들은 크기, 수정 시각, 링크 대상, 프로세스와 열린 파일 상태, Git 상태, 호스트의
  설치된 플러그인 목록, 실행 중인 세션의 기록을 읽는다. 대화 기록과 세션 기록은 메타데이터로만 읽고, 내용은 읽지 않는다.
- 삭제는 6단계에서만, 사용자가 고른 항목에 대해서만, 함께 든 스크립트로만 한다. 어떤 것도 손으로 삭제하거나 이동하거나
  권한을 바꾸지 않는다.
- survey, 판정, 계획 파일은 호스트의 세션 임시 폴더에만 쓴다. 그런 폴더가 없으면 운영체제 임시 폴더 아래에 새 폴더를 만들어
  쓴다. 현재 세션 자신의 임시 폴더는 세션이 활성 상태이므로 report-only로 표시되는데, 이는 예상된 결과다.
- 더 많은 항목을 찾으려고 기준값을 낮추지 않는다. 어떤 종류에 회수할 것이 없으면 그렇다고 말한다.

## 작업 순서

함께 든 스크립트는 이 `SKILL.md`가 있는 디렉터리를 기준으로 한 경로로 실행한다:

```text
python3 scripts/local_data.py <survey|merge|delete> ...
```

모든 하위 명령은 JSON 객체 하나를 출력한다. 종료 코드 0은 정상 완료, 1은 건너뛰었거나 확인하지 못한 항목이 있으면서 완료됨,
2는 잘못된 인자나 입력 파일이다. 2인 경우에는 고친 뒤 다시 실행한다.

### 1. 범위 확정

요청에서 검사할 호스트(기본값은 둘 다), 오래된 세션 기록의 나이 기준(기본값은 30일), 선택 사항인 최소 크기(기본값은 1 MiB)를
가져온다. 사용하는 값은 모두 밝힌다. 사용자가 호스트 기본값과 다른 폴더를 지정한 경우에만 데이터 폴더 옵션을 넘긴다.

### 2. 조사

```text
python3 scripts/local_data.py survey --host <claude|codex|both> [--age-days N] [--min-size SIZE] \
  [--claude-dir DIR] [--claude-plugin-cache DIR] [--claude-install-dir DIR] [--claude-launcher PATH] \
  [--codex-dir DIR] [--temp-root DIR]... [--protect PATH]... --out <temporary folder>/survey.json
```

스크립트는 알려진 데이터 루트와 세션 임시 루트 아래에서 아래 종류의 항목을 찾고, 각 항목을 검사한다:

| 종류 | 예 | 사용자 결정 |
|---|---|---|
| 대체된 릴리스 | `current` 링크나 런처 링크가 가리키는 릴리스보다 오래된 호스트 릴리스 | 아니오 |
| 대체된 플러그인 버전 | 설치된 모든 버전보다 오래된 캐시 플러그인 버전 | 아니오 |
| 끝난 세션의 임시 폴더 | 세션이 끝난 뒤의 그 세션 임시 폴더 | 아니오 |
| 오래된 임시 항목 | 호스트 임시 폴더의 항목 | 아니오 |
| 오래된 세션 기록 | 가장 최근 파일이 나이 기준보다 오래된 기록 | 예 |

Claude Code와 Codex 데이터 폴더의 그 밖의 모든 최상위 항목은 `other`로 나열한다. 데이터베이스, 자격 증명, 설정, 히스토리
같은 상태를 담으면 protected로, 그 밖이면 report-only로 둔다. 사용자가 나머지 공간이 어디로 가는지 볼 수 있게 하려는 것이다. 이 항목들은 절대 offer 대상에 들지 않는다.

크기는 그 항목을 삭제하면 확보되는 디스크 공간이다. 하드링크된 파일은 모든 링크가 항목 안에 있을 때만 센다. 다른 곳에 남은
링크가 그 공간을 계속 쓰기 때문이다.

항목은 모든 검사를 통과해야만 candidate가 된다. 실패했거나 unknown인 검사가 하나라도 있으면 report-only가 된다:

- 실행 중인 프로세스 중 그 항목이나 그 세션을 가리키는 것이 없고, 그 항목을 소유한 기록된 세션 중 활성 상태인 것이 없으며,
  실행 중인 호스트 프로세스 중 대체된 플러그인 버전을 아직 불러올 수 있는 것이 없어야 한다. 오래된 세션 기록도 임시 작업
  폴더와 같은 세션 검사를 받는다. 세션 ID를 읽을 수 없는 기록 파일이 있거나, 프로세스 목록이나 세션 파일을 읽을 수 없으면 이
  검사는 unknown이 된다.
- 어떤 프로세스도 그 항목 아래의 파일이나 작업 폴더를 열고 있지 않아야 한다.
- 그 항목은 `current` 링크나 런처 링크의 대상이 아니고, 설치된 플러그인 경로가 아니며, 그중 하나를 포함하거나 그 안에 있지
  않아야 한다.
- 그 항목 아래의 어떤 것도 최근 24시간 안에 바뀌지 않았어야 한다.
- 그 항목은 상태 데이터베이스, 자격 증명, 설정, 히스토리, 메모리 중 하나가 아니고 이를 포함하지도 않으며, 사용자가
  `--protect`로 보호한 항목도 아니다. 이런 항목은 절대 offer 대상에 들지 않는다. 대체된 릴리스, 캐시된 플러그인 버전,
  플러그인이나 마켓플레이스 패키지 안에서는 상태 데이터베이스와 자격 증명만 따진다. 그 안의 설정처럼 보이는 파일은 코드와
  함께 배포된 것이기 때문이다.
- 해석된 실제 경로가 알려진 데이터 루트와 세션 임시 루트 안에 머물러야 한다.
- 그 항목을 담고 있거나 그 안에 있는 Git 작업 트리에 커밋되지 않은 변경이나, 무시되지 않은 추적되지 않은 파일이 없어야 한다.

### 3. 두 번째 판정

`references/peer-assignment.md`를 survey의 candidate로 채워, 다른 호스트의 읽기 전용 에이전트 하나에게 준다. 이 세션이
Claude Code에서 실행 중이면 Codex에게, Codex에서 실행 중이면 Claude Code에게 준다. 세션의 스킬 검토 역할 경로가 다른
호스트에서 실행되면 그 경로로 실행한다. 실행 근거에 다른 호스트 계열의 모델 이름이 있을 때만 결과를 받아들인다. 에이전트의 JSON
응답은 `peer.json`으로 survey 옆에 저장한다.

그 경로를 쓸 수 없거나, 실패하거나, 같은 호스트에서 실행되거나, 실행 근거에 다른 호스트 계열의 모델 이름이 없으면 판정 파일을
직접 쓰지 않는다. 대신 `--peer-unavailable <reason>`을 넘겨 병합한다. 그러면 모든 candidate는 그 사유와 함께 report-only로
남고, offer 대상이 되는 항목은 하나도 없다.

### 4. 병합

```text
python3 scripts/local_data.py merge --survey <survey.json> (--peer <peer.json> | --peer-unavailable <reason>) \
  --self-host <claude|codex> --out <temporary folder>/plan.json
```

candidate는 peer 판정이 `delete`일 때만 `offer`가 된다. `keep`, `unknown`, 또는 판정이 없으면 peer의 사유와 함께 report-only가
된다. 같은 호스트의 peer 파일은 종료 코드 2로 거부된다.

### 5. 보고

사용자의 언어로, `offer` 항목의 표를 하나 보여 준다. 크기 기준 내림차순(가장 큰 것부터)으로 정렬하고, 번호, 크기, `<codex>` 같은
자리표시자로 루트를 바꾼 경로, 무엇인지, 판정, 사유를 적는다. 오래된 세션 기록 항목에는 사용자의 결정이 필요하다고 표시하고, 그 결과를 밝힌다. 그 안에
든 세션은 더 이상 재개하거나 검토할 수 없게 된다. 그다음 report-only와 protected 항목을 `other` 항목을 포함해 따로
나열한다. 이들도 크기순으로 정렬하고, 각 항목이 offer 대상이 되지 않은 이유와 계획이 가진 모든 참고 사항(예: 회수할 것이 없는
종류)을 적는다. 사용자가 오래된 Claude Code 대화 기록을 더 짧은 기간만 보관하고 싶어 하면, 손으로 지우는 대신 지속적인 대안으로
Claude Code의 `cleanupPeriodDays` 설정을 알려 준다. 마지막으로 offer 항목을 모두 삭제하면 확보되는 총량을 적고, 어느 번호를
삭제할지 묻는다. 이때 삭제는 되돌릴 수 없다고 밝힌다.

### 6. 선택한 항목 삭제

사용자가 나중 메시지에서 항목을 지정한 뒤에만 이것을 실행한다. 사용자가 아무것도 고르지 않거나 거절하면 아무것도 삭제하지 않고
그렇게 말한다.

```text
python3 scripts/local_data.py delete --plan <plan.json> --select <id> [--select <id>]...
```

스크립트는 `offer`가 아닌 ID를 거부하며, 선택한 ID 중 하나라도 거부되면 아무것도 삭제하지 않는다. 먼저 선택한 각 항목에 대해
모든 검사를 다시 수행하고, 상태가 바뀐 항목은 건너뛴다. 선택한 항목 내부에서만, 제거를 막는 폴더에 소유자 권한을 추가한다.
항목 밖의 권한은 절대 바꾸지 않는다.

### 7. 검증과 보고

삭제 출력을 바탕으로, 항목마다 사라졌는지와 확보한 크기를 보고한다. 총량, 건너뛰었거나 실패한 모든 항목과 그 사유, 그리고
protected 항목과 링크 대상이 바뀌지 않았는지도 보고한다. 검증이 실패하면 분명하게 그렇다고 말하고, 사용자의 확인 없이 삭제를
다시 시도하지 않는다.

## 최종 보고

범위와 기준값, 두 번째 판정의 호스트와 모델 근거(또는 그 판정이 unknown이었던 이유), offer 표와 report-only 표, 사용자의 선택,
검증 결과를 밝힌다.
