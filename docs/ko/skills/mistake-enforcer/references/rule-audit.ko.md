# 규칙 누락 점검

> 영어 원본: [rule-audit.md](../../../../../skills/mistake-enforcer/references/rule-audit.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

세션 기록에서 에이전트가 글로 쓴 규칙 중 무엇을 놓치는지 점검하기 전에 이 문서를 읽는다. 절차의 1~5단계를
확장하며, 경계와 증명 규칙은 그대로 적용한다.

1. 기간, 기록 폴더와 글로 쓴 규칙의 출처를 정한다. 출처는 플러그인의 세션 지침과 참조 문서, 스킬, 프로젝트의
   `AGENTS.md` 또는 `CLAUDE.md`다. Claude Code 설정 폴더(`$CLAUDE_CONFIG_DIR` 또는 호스트 기본 폴더)의
   `projects` 폴더를 사용하고, 메인 세션만 센다.
2. 각 집행 훅의 메시지를 글로 쓴 규칙과 원본의 줄에 연결하는 규칙 파일을 작성한 뒤, `scripts/rule_misses.py`를
   `--candidates`와 함께 실행한다. 글로 쓴 규칙이 다루는 모든 `unmatched` 그룹을 연결한 뒤 다시 실행한다.
3. 각 후보를 글로 쓴 규칙에 비추어 분류한다. 사용자가 글로 쓴 규칙을 어긴 에이전트를 교정한 경우, 또는 최종
   보고가 필수 단계를 미완료로 나열하거나 실행하는 대신 제안한 경우에만 누락으로 센다. 새 요청, 질문, 글로 쓰지
   않은 선호는 누락이 아니다. 후보가 많으면 읽기 전용 검토자가 분류할 수 있다. 후보와 규칙 파일을 제공하고,
   근거에 비공개 세부 사항을 담지 않는다.
4. 규칙마다 한 행으로 보고한다. 규칙, `path:line`, 세션 수, 발생 횟수, 답변 100개당 발생 횟수, 현재 집행 방식,
   고른 수준과 수정 전후의 항상 읽는 토큰 수를 적는다. 두 개 이상 세션에서 누락된 규칙은 유형으로, 한 세션에서만
   누락된 규칙은 관찰 항목으로 둔다.
5. 다음 중 효과가 있는 첫 수정안을 고른다. 항상 읽는 글을 늘리지 않고 누락을 차단하거나 기록하는 훅 또는 테스트,
   항상 읽는 코어 대신 커밋·푸시 경로나 조건부 참조처럼 행동하는 지점에 두는 한 줄짜리 실행 조건, 기존 줄의 문구
   수정 순서다. 항상 읽는 문단을 추가하지 않는다. 훅이 이미 차단하거나 상기시키는 규칙은 누락 때문에 그 훅이
   잡지 못하는 피해가 생기지 않는 한 더 고칠 필요가 없다.
6. 실제 누락 사례 또는 그 사례로 만든 픽스처를 이전 버전과 새 버전에서 짝지어 재실행해 각 수정안을 측정한다.
   누락률, 수정 전후의 항상 읽는 분량과 출력 품질을 측정한다. 호스트가 입력 토큰 수를 보고하면 동일한 짧은
   프롬프트에서 그 수로 분량을 측정하고, 그렇지 않으면 바이트로 측정하며 어느 쪽인지 밝힌다. 누락률이 줄고,
   항상 읽는 분량이 늘지 않으며, 품질이 시행 간 변동 범위를 넘어 떨어지지 않을 때만 수정안을 받아들인다.
