# 추천 규칙

> 영어 원본: [recommendation.md](../../../../../skills/report-skill-gap/references/recommendation.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

사용자가 `report-skill-gap`을 부르지 않았을 때 한 줄로 이 스킬을 제안하는 규칙이다.

## 한 줄을 보여 줄 때

다음이 모두 성립할 때만 보여 준다.

- 세션에 남은 작업이 없다.
- 사용자가 에이전트가 이미 끝낸 결과를 정정했고 원인이 한 플러그인의 스킬이나 지침의 빈틈이다.
  또는 사용자가 이 세션에서 끝낸 작업 흐름을 스킬이나 이슈로 만들어 달라고 요청했다.
- 담당 파일에 `scripts/find_tracker.py`를 실행한 결과가 `declared`이고 `target.recommend`가 true이다.
  한 줄을 보여 주기 전에 스크립트를 실행한다.

그 밖에는 아무것도 보여 주지 않는다.
작업이 남은 상태의 정정, 일회성 우회 방법, 도구 결함, 취향 차이, 세션 검토, 스킬에 관한 질문은 한 줄을 받을 자격이 없다.

## 한 줄에 담을 내용

- 메시지의 마지막 줄이며, 분석이 있으면 그 뒤의 별도 문단이다. 응답 언어로 쓰고 질문 하나이다.
- 쉬운 말로 다음을 밝힌다. 무엇을 올리는지, 어디에 올리는지(`target.public`이 true이면 누구나 읽을 수 있는 공개 저장소이고
  아니면 플러그인의 비공개 트래커), 승인하면 어떻게 되는지(`target.preview_required`가 false이면 바로 올리고
  아니면 전체 초안을 먼저 보여 준다), 어떻게 답하면 되는지.
- 이슈가 둘 이상이면 개수를 밝힌다.
- 스킬 이름, "gap", "target", "label", "trigger" 같은 설명 없는 내부 용어를 쓰지 않는다.

## 한 줄 이후

- 그 턴에는 아무것도 등록하지 않는다. 사용자가 이후 메시지에서 승인한 뒤에만 시작한다.
  그 승인은 밝힌 개수의 이슈마다 한 번씩 스킬을 부른 것으로 본다. 침묵이나 관련 없는 답은 승인이 아니다.
- 사용자가 스킬 이름을 부르면 한 줄 없이 바로 시작한다.

## 예시

영어, 비공개 트래커, 바로 등록:

> Should I file this as an issue in the team's private tracker so this mistake stops repeating? If you approve, I will
> file it right away; reply yes to go ahead or no to skip.

한국어, 공개 저장소, 초안 먼저:

> 이 문제를 누구나 읽을 수 있는 공개 저장소에 이슈 1건으로 올려 둘까요? 승인하시면 먼저 전체 초안을 보여 드리고,
> 확인해 주신 뒤에 올립니다. 올리려면 "네", 건너뛰려면 "아니요"라고 답해 주세요.
