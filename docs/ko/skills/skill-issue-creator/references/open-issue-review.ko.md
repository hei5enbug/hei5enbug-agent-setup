# 열린 이슈 점검

> 영어 원본: [open-issue-review.md](../../../../../skills/skill-issue-creator/references/open-issue-review.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

플러그인의 열린 이슈를 현재 상태와 대조하고 구현할 준비가 되도록 만드는 규칙이다. 사용자가 열린 이슈가 여전히 맞는지 묻거나
구현할 준비가 되도록 만들어 달라고 요청하면 3단계 뒤에 읽는다. 스킬의 1, 2, 4~9단계를 대신한다.

## 수집

선언된 트래커의 열린 이슈를 나열한 뒤 현재 계정이 쓴 것만 남긴다. [기존 이슈 갱신](update-in-place.ko.md)처럼 `author.login`을
현재 사용자와 비교한다. GitHub에서는 `gh issue list --repo <location> --state open --json number,title,url,author,body --limit 100`을
실행한다. 다른 사람이 쓴 이슈는 절대 수정하지 않으며, 보고에 점검하지 않았다고 적는다.

## 이슈별 점검

본문 전체를 읽은 뒤 다음을 확인한다.

- 인용한 각 규칙이나 사실을 현재 담당 파일과 대조
- 각 의존 대상의 현재 상태. [구현 가능한 본문](implementable-body.ko.md)과 같은 방식으로 읽는다.
- 다른 열린 이슈와의 겹침. 둘 이상이 제안하거나 바꾸는 같은 파일, 다른 이슈나 의존 대상이 이미 제공하는 부분
- 본문이 구현자에게 맡겨 둔, 사용자만 정할 수 있는 선택
- 각 인수 기준을 스킬 6단계의 시드 입력 규칙과 대조

## 한 번에 묻기

모든 이슈에서 찾은 선택을 모아 호스트의 질문 UI 한 번의 호출로 묻는다. 답이 없는 선택에 의존하는 이슈는 수정하지 않고
나머지는 답을 기다리지 않고 같은 차례에 수정한다.

## 수정

사용자의 요청이 이슈들의 동작, 공개 계약, 여러 구성요소를 바꾸면, 수정할 본문 전체에 대해 7단계의 검토를 첫 쓰기 전에 한 번
적용한다.

[기존 이슈 갱신](update-in-place.ko.md)에 따라 각 본문을 제자리에서 수정한다. 여전히 맞는 내용은 유지하고, 낡은 인용은 지우거나
고치고, [구현 가능한 본문](implementable-body.ko.md)의 의존성 줄과 순서를 추가한다. 겹치는 이슈는 모든 이슈에서 서로를 이름으로
가리키고 구현 순서 하나를 적어 연결한다. 공개 트래커의 공개 정보 유출 검사와 `preview_required`의 승인 규칙은 그 파일의 설명대로
적용한다.

## 보고

점검한 이슈마다 한 줄로, 정확히 다음 중 하나를 보고한다. 변경 없음, 수정됨(어떻게), 결정을 기다리는 중(어떤 결정). 점검하지 않은
이슈와 그 이유를 덧붙인다.
