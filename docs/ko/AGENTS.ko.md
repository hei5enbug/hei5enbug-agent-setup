# 저장소 개발 지침

> 영어 원본: [AGENTS.md](../../AGENTS.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

> 이 지침은 이 저장소를 개발할 때만 적용한다. 플러그인 훅은 `instructions/session/`만 불러오고 이 파일은 불러오지
> 않는다. `instructions/` 아래 내용은 사용자에게 배포되는 플러그인 실행 동작이며 저장소 개발 규칙이 아니지만, 이 저장소
> 작업에도 적용한다. 호스트가 그 규칙을 불러오지 않았다면 `instructions/session/core.md`,
> `instructions/session/common.md`, 현재 호스트용 파일을 먼저 읽는다.

- 목표(소유자, 2026-11-20): 모든 스킬, 에이전트, 지침은 요구사항이 정한 출력을 품질을 낮추지 않고 가장 적은 비용과
  실제 소요 시간으로 만든다.
- 구현 전에 요구사항을 검토한다. 잘못되었거나 정의되지 않은 용어, 여러 가지 가능한 해석, 모순 또는 누락된 결정
  때문에 결과, 범위, 계약 또는 완료 조건이 실질적으로 달라질 수 있으면 가능한 해석과 영향을 설명하고 사용자에게
  질문한다. 코드, 스키마, 용어집 또는 기존 합의로 해석이 하나로 확정되면 그 근거를 밝히고 적용한다. 사용자만 내릴 수
  있는 결정이 확정될 때까지 파일을 수정하거나 외부 상태를 변경하지 않고, 답변을 미리 전제하지 않는 읽기 전용 조사만
  계속한다.
- 훅, 에이전트, 스킬, 설정 또는 플러그인 구조를 변경하기 전에 그 영역의 Claude Code와 Codex 최신 공식 문서를
  확인한다. mod, 훅 이벤트, 설정, 에이전트 옵션 같은 기능도 확인 대상에 포함한다. 필요를 충족하는 지원 기능이 있으면
  직접 만든 코드보다 그 기능을 우선하고, 확인한 기능과 그 방안을 고른 이유를 밝힌다.
- 모든 변경은 일반 사용 시 반복해서 드는 토큰과 컨텍스트 비용, 그리고 출력 품질을 둘 다 개선하거나 최소한 유지해야
  한다. 둘이 충돌하면 품질이 우선한다(소유자, 2026-10-27). 측정한 품질이 더 높은 선택지를 고르고, 토큰을 아끼려고
  품질을 낮추는 선택지는 채택하지 않으며, 늘어난 비용은 측정값과 함께 변경 보고에 기록한다. 정확성과 필수 검증을
  유지하면서 불필요한 지침 로딩, 중복 읽기, 도구 호출과 내용 중복을 줄인다. 불러온 지침과 검증 결과는 관련 입력이
  바뀌지 않은 동안에만 재사용한다. 로컬 작업에서는 변경의 영향을 받는 검사를 실행하고, 해결되지 않은 위험이 있으면
  범위를 넓힌다.
- 각 작업은 사례를 통과하고 `docs/dev-rules/evaluation.md`의 품질 규칙과 효율 규칙이 남기는 다음 중 첫 번째 위치에
  둔다: 결정적인 스크립트, 검사, 테스트 또는 훅; 그 규칙들이 고른 모델로 고정한 스킬이나 에이전트; 메인 세션. 과정과 출력이 거의 달라지지 않는 스킬은 측정으로 고른 비용 효율적인
  모델에서 항상 실행한다. 이것은 측정할 후보의 순서이지 기록 없이 모델을 바꿔도 된다는 허가가 아니다. 규칙, 스킬,
  에이전트, 훅 변경을 측정하기 전에 결정적인 스크립트, 검사, 테스트, 훅이 같은 일을 하거나 강제할 수 있는지 확인하고,
  할 수 있으면 그것도 후보로 측정한다.
- 이 플러그인의 규칙, 스킬, 에이전트, 훅, 경로를 바꾸는 변경은, 그 변경 하나만 다른 이전 변형과 이후 변형으로
  `evals/e2e/harness/cli.py record`가 쓴 `evals/e2e/records/` 아래 기록이 있어야만 채택하거나 기각한다. 그 기록은
  Claude Code와 Codex 양쪽에서 실행하고 `evals/e2e/README.md`의 비교 규칙으로 판정한 것이어야 한다. 기록이 없는 후보는
  결정되지 않은 채 열어 둔다. 판단만으로 닫거나 버리지 않고, 기존 규칙이 충분하다고 판단만으로 말하지도 않는다. 변경의
  측정과 채택에 관한 2026-11-19 소유자 결정은 이 항목 전체의 예외다.
  - 한 영역을 바꾸는 여러 변경의 회귀 사례는 그 변경들을 묶은 상태에서 한 번 실행하고, 묶음이 실패할 때만 변경별로
    나눈다. 각 변경의 효과를 보이는 사례는 변경별로 실행한다.
  - 사람이 읽는 글은 형식 요건을 스크립트로 검사하고, 표현 품질은 소유자가 변경 전후 글을 가린 A/B 비교로 판정한다.
    소유자가 변경 후 글이 같거나 낫다고 판정한 사례만 통과한다.
  - 규칙, 스킬, 에이전트, 훅, 경로를 바꾸더라도 모델이 읽는 글은 바꾸지 않는 변경(예: 스킬에 든 스크립트, 훅 코드)은
    기록 없이 결정적 테스트와 실제 실행 한 번으로 채택한다.
  - 다음은 소유자가 Codex와 GPT 모델을 제외하는 동안에만 적용한다. Claude Code 기록만으로 채택하고, 아직 남은 Codex
    실행을 변경 보고에 적는다. 글 검토는 고정된 검토 모델을 바꾸지 않고, 글 검토 스크립트의 모델 옵션으로 실행마다
    `claude-sonnet-5-5`나 `claude-opus-5-5`를 골라 한 번 실행한다. 소유자가 승인한 생략 규칙이 허용하는 경우에만
    생략하고, 소유자가 규칙을 승인하기 전에는 생략하지 않는다. 최종 리뷰는 GPT 리뷰어를 다시 쓸 수 있을 때까지 미룬다.
- 모델 호출 비용이 드는 평가를 설계하거나 실행하기 전, 이슈의 수용 기준을 쓰기 전, 측정한 후보 가운데 고르기 전,
  `config/writing-surfaces.json`에 나열된 규칙 파일, 스킬, 지침이 사람이 읽는 글을 쓰는 방식이나
  `scripts/text_review.py`를 바꾸기 전, `language`
  기능이나 `scripts/text_review.py`의 모델을 바꾸기 전에 `docs/dev-rules/evaluation.md`를 읽는다.
- 항상 로드되는 표면, 즉 스킬 description, `SKILL.md` 본문, 세션 지침 파일에는 그 표면을 쓰는 모든 실행에 필요한
  규칙만 둔다. 특정 조건에서만 필요한 규칙은 참조 파일로 옮기고, 표면에는 "<동작> 전에 <참조>를 읽는다." 형태의
  한 줄 항목만 남긴다. 그 참조를 읽는 일과 참조가 없을 때 멈추는 일은 세션 코어의 조건부 지침 규칙을 따른다.
  이슈를 구현하는 변경은 품질 평가 결과와, 바뀐 항상 로드 텍스트의 변경 전후 크기를 줄 수나 토큰으로 보고한다.
  한 가지 동작에만 필요한 개발 규칙은 하위 `AGENTS.md`가 아니라 `docs/dev-rules/`에 두고 루트에 트리거 줄을 남긴다.
  Codex는 작업 폴더보다 아래에 있는 `AGENTS.md`를 읽지 않기 때문이다.
- 사람이 읽는 모든 영어 Markdown 파일에는 의미가 완전히 같은 한국어 번역본을
  `docs/ko/<저장소 루트 기준 원본 경로의 마지막 .md를 .ko.md로 바꾼 경로>`에 유지하고, 원본과 번역본을 함께 수정,
  이동 또는 삭제한다. 각 번역본은 제목으로 시작하고, 그다음 인용 블록에서 상대 경로로 영어 원본을 링크하며 비권위
  문서이고 실행 중에는 절대 읽지 않는다고 밝힌다. `skills/`, `agents/`, `instructions/` 안에는 `.ko.md` 파일을 두지
  않으며 이 폴더 아래의 파일에서 `.ko.md` 파일로 링크하지 않는다. `README.md`처럼 루트에 있는 독자용 문서만 한국어
  번역본을 링크할 수 있다. 코드, 스키마, 테스트 자료, 생성 아티팩트 또는 영어가 아닌 문서는 복제하지 않는다.
- 스킬을 변경하기 전에 `skills/skill-builder/SKILL.md`의 현재 내용이 이미 로드되어 있지 않으면 읽는다. 직접 수정할
  때는 "Portability contract", "Core loop", "Translated mirrors" 절만 읽고, 스킬을 새로 만들거나 평가 절차를 탈 때는
  파일 전체를 읽는다. 변경에 맞는 직접 수정 또는 평가 절차를 따른다. 플러그인 구조, 매니페스트 또는 훅을 변경할 때는
  호스트가 `plugin-creator`를 제공하면 사용하고 기존 플러그인 계약을 보존한다.
- 공통 동작은 하나의 기준 원본에 두고 실제 호스트 차이만 분리한다. 세션 지침이 이미 규정한 규칙은 그곳에만 두고,
  다시 쓰지 말고 참조한다.
- [규칙 집행](docs/rule-enforcement.ko.md)은 글로 쓴 규칙마다 그 규칙을 집행하는 검사를 짝지어 둔다. 사용자 교정이 검사로
  집행되지 않는 기존 규칙을 되풀이하면 같은 변경에서 그 파일이 설명하는 대로 한 단계 올리고 해당 행을 갱신한다.
  검사가 실수를 불가능하게 만들면 그 글로 쓴 규칙을 지운다.
- 이슈를 만들기 전에 기존 이슈를 검색한다. 이슈, 풀 리퀘스트, 댓글, 커밋 메시지는 영어로 쓰고 기존 이슈의 관례를
  따른다. 파일, 커밋 또는 메시지에 담을 수 있는 내용은 이 파일 끝의 "공개 경계" 절을 따른다.
- 기본으로 저장소 구현은 Claude Code 플러그인 작업자 서브에이전트에, 범위가 정해진 읽기 전용 근거 수집은 `scout`에,
  조정자가 승인한 기계적 문서 수정은 `writer`에 맡기고, 사소하지 않은 변경은 모든 작업이 끝난 뒤 최종 검토를 한 번
  받는다. 저장소 작업을 서브에이전트, CLI 프로세스 또는 Codex 역할에 맡기기 전, `.codex/agents/`의 역할이나 플러그인
  에이전트 정의를 바꾸기 전, 그리고 그 최종 검토를 고르거나 실행하기 전에 `docs/dev-rules/delegation.md`를 읽는다.
- 서브에이전트에 주는 과제는 목표, 제약, 검사, 반환 형식과 위임 규칙이 요구하는 모든 항목을 빠짐없이 적고, 관련 없는
  내용은 적지 않는다.
- 커밋, 버전 변경, 태그, 릴리스 배포 또는 플러그인 설치 전에 `docs/dev-rules/release.md`를 읽는다.
- 이 저장소를 변경하기 전에, `tests/test_model_pins.py`의 `PINS_VERIFIED_ON`이 14일보다 오래됐으면
  `docs/dev-rules/model-pins.md`를 읽는다.
- Orca CLI가 설치되어 있지 않아 테스트를 건너뛰면, 검사가 통과했다고 보고하기 전에 Orca를 설치하고 다시 실행할지
  사용자에게 묻는다.

## 공개 경계 (보호됨)

이 저장소, 그 이력의 모든 커밋, 그리고 이 저장소의 모든 태그, 브랜치, 이슈, 풀 리퀘스트, 리뷰, 댓글은 공개된다.
어느 것에도 다음 내용을 담아서는 안 된다.

- 실제 기기의 로컬 절대 경로 또는 실제 사용자 이름, 호스트 이름, 홈 폴더
- 비밀값, 자격 증명, 토큰, 비공개 키, 계정 식별자, 내부 URL 또는 그 밖의 보안상 민감한 내용
- 비공개 조직이나 공개되지 않은 플러그인에만 해당하는 내용: 이름, 제품, 서비스, 저장소, 인프라, 스키마,
  티켓 키, 사람 또는 채널

예제, 테스트 자료, 평가 데이터에는 `example.com`, `/home/test`, `/tmp/work`, `<plugin-root>`, `ABC-123`,
`demo` 스키마처럼 명백히 가상의 값만 쓴다. 이 저장소는 범용으로 유지하며, 이 저장소에 의존하는 플러그인의
이름을 쓰거나 그 플러그인을 설명하지 않는다.

매번 커밋하기 전에 `python3 -m pytest tests/test_public_boundary.py`를 실행하고 스테이징된 diff와 커밋 메시지에
위 값이 있는지 살핀다. 발견한 내용은 모두 고친 뒤 커밋한다. 공개된 이력에서 이런 값을 발견하면 작업을 멈추고
소유자에게 보고하며, 소유자의 명시적 승인이 있을 때만 이력을 다시 쓴다.

소유자가 현재 대화에서 이 절을 이름으로 지목하고 변경을 명시적으로 요청한 경우에만 이 절을 변경, 완화, 이동
또는 삭제한다. 그 변경은 다른 변경 없이 단독 커밋으로 만들고, 같은 커밋에서 `tests/test_public_boundary.py`의
절 해시도 갱신한다. 다른 작업을 요청받았다는 이유로 이 절을 바꿀 권한이 생기지는 않는다.
이 절은 이 파일의 마지막에 둔다.
