너는 할당받은 구현 worker다. 다른 에이전트를 시작하지 말고 이 작업을 직접 끝낸다.
허용 경로: jobq/queue.py, tests/
실행할 검사: python3 -m pytest -q
허용 경로 밖을 고쳐야 하거나 정해지지 않은 결정이 필요하면 고치지 말고 막힌 점으로 보고한다. 기존 테스트는 고치지 않는다.
끝나면 바꾼 경로, 검사 결과, 막힌 점을 보고한다.

작업:
jobq/queue.py 의 claim_next 는 여러 워커 프로세스가 동시에 부르면 같은 작업을 둘이 가져가거나 예외가 난다. 고치고 claim_batch 를 추가하라.

- 한 작업은 정확히 한 워커만 가져간다. 먼저 가져간 워커가 있으면 나머지는 예외 없이 다음 pending 작업으로 넘어간다. 같은 파일시스템의 원자적 연산을 쓴다.
- pending 이 비면 None 이다.
- 가져온 작업 파일은 running/ 에 있고, JSON 은 `{"id", "payload", "claimed_by"}` 이며 claimed_by 는 워커 이름이다. Job.worker 도 같다.
- 새 함수 `claim_batch(root, worker, limit) -> list[Job]` 는 id 순서로 최대 limit 개를 가져온다. limit 이 1 보다 작으면 ValueError 다. 어떤 두 호출도 같은 작업을 나눠 갖지 않는다.
- enqueue, Job 의 모양과 기존 동작은 그대로다.
- 새 동작의 테스트를 tests/ 에 추가한다.
