재고 서비스를 여러 프로세스가 같은 데이터 파일로 동시에 쓰면 주문이 재고보다 많이 들어가거나 한쪽 갱신이 사라져. 이걸 막아줘. 요구사항은 이래.

- inventory/app.py 에 transaction(data_file=None, config=None, clock=utcnow) 컨텍스트 매니저를 추가해. 데이터 파일 옆의 `<데이터 파일 이름>.lock` 파일에 프로세스 사이에서 통하는 배타 잠금을 잡고(표준 라이브러리만), 잠금을 잡은 뒤에 데이터를 새로 읽어서 App을 넘겨줘. 블록이 정상으로 끝나면 저장하고, 예외가 나면 저장하지 말고 그 예외를 그대로 다시 올려. 어느 경우든 잠금은 풀려야 해.
- 잠금을 못 잡고 Config.lock_timeout 초를 넘기면 LockTimeout(InventoryError 하위 클래스)을 올려. 메시지에 데이터 파일 경로가 들어가야 해. lock_timeout이 0이면 기다리지 않고 바로 실패해.
- Config.lock_timeout 은 INVENTORY_LOCK_TIMEOUT(초, float, 기본 10)에서 읽어. 숫자가 아니거나 음수거나 nan/inf면 ConfigError.
- CLI에서 데이터를 바꾸는 명령(item add, warehouse add, stock receive, stock adjust, order create, order ship, order cancel, import items, import stock)은 전부 transaction 안에서 실행해서, 동시에 여러 프로세스가 돌려도 하나씩 차례로 처리되게 해. 읽기 전용 명령(item list, warehouse list, stock show, order show, order list, report)은 잠금 없이 지금처럼 돌아야 해.
- 잠금을 못 잡아서 실패하면 다른 InventoryError처럼 stderr에 `error: ...` 한 줄과 종료 코드 2.
- 기존 create_app(...) 과 app.save() 는 그대로 동작해야 해.

README 설정 표에 INVENTORY_LOCK_TIMEOUT을 넣고 동시 사용에 대한 설명도 한두 문장 써줘. 한국어 미러도 같이.

구현은 직접 하지 말고 구현 워커 에이전트에게 맡겨서 진행해줘. 결과 확인은 네가 해.
