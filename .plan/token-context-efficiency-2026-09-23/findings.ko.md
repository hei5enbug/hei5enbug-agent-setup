# 발견 근거와 개선 후보

> 영어 원본: [findings.md](findings.md)
> 이 문서는 사람이 읽기 위한 비권위 한국어 미러다. 실행 지침으로 사용하지 않는다.

[개선안](README.ko.md)에 기록한 커밋의 저장소를 조사했다.
로딩 규칙이나 중복 프롬프트는 비용 발생 지점의 근거지만, 실행 비용 절감의 증명은 아니다.
아래 최적화 효과는 [검증](validation.ko.md)을 통과하기 전까지 미측정이다.
F01은 확인된 품질 정책 모순이다. F02–F03은 신뢰할 수 있는 채택 근거를 마련하는 작업이다.
F17은 새로운 결함을 주장하는 대신 이미 적용된 최적화를 보존한다.

## 품질과 측정

### F01 — 최적화 코드가 정확도 저하를 명시적으로 허용

**근거:** [improve_description.py](../../skills/skill-builder/scripts/improve_description.py)의
`improve_description` 122줄은 100–200단어를 유지하라고 하면서 “even if that reduces accuracy”라고 지시한다.
이는 [Execution Methods](../../skills/skill-builder/references/execution-methods.md)의
“Measurement and decision” 및 사용자 제약과 충돌한다.

**개선:** 정확도 희생·단어 수 문장을 명시적인 우선순위로 바꾼다.
실행할 의도와 실행하지 않을 의도를 모두 보존한 뒤, 1,024자 안에서 가장 짧고 명확한 설명을 작성한다.
간결성 선호를 유지하며 길이 상한을 채워야 할 목표로 취급하지 않는다.
`improve_description`은 기존 유효성 검사, 재시도 한 번, 사용할 수 없는 후보 거부를 유지한다.
의미 품질 채점 기능은 추가하지 않는다. `run_loop`는 평가한 최고 점수 선택을 유지한다.
작성 절차가 선택된 설명을 채택하기 전에 사례별 저하와 실제 호스트 라우팅을 확인한다.
S1은 프롬프트 우선순위와 기존 재시도·거부 동작을 검사한다. 실제 품질·비용에는 F02–F03의 관문을 적용한다.

### F02 — 정적 제한만으로 실제 실행 비용을 알 수 없음

**근거:** [session_context.py](../../scripts/session_context.py)의 `render_context`는 9,000바이트를 제한한다.
[quick_validate.py](../../skills/skill-builder/scripts/quick_validate.py)의 `validate_skill`은 메타데이터를 검사한다.
[model_runner.py](../../skills/skill-builder/scripts/model_runner.py)의 `run_model`은 응답 문자열만 반환하며
모델 사용량이나 사고 강도 확인 자료를 제공하지 않는다.
[시간 측정 계약](../../skills/skill-builder/references/schemas.md)의 “timing.json”은 이미 토큰과 문자 수를
구분하고 측정값 부재를 허용한다.

**개선:** 평가 작업 디렉터리에 실제 실행기의 사용량과 경과 시간을 수집한다.
참조 읽기, 도구 출력, 재시도, 실제 모델·사고 강도, 문맥 복원 사건도 함께 기록한다.
기존 호스트 실행기나 별도 측정 파일을 남기는 래퍼를 사용하되 stdin/stdout 응답 계약은 보존한다.
파일 크기로 사용량을 만들거나 일반 스킬 실행에 측정 프레임워크를 추가하지 않는다.
확인할 수 없는 값은 null로 두고, 해당 값이 필요한 주장이나 채택 판단만 막는다.
방안별 검토에 따라 논리적 사용량, 활성 문맥, 금전 비용, 완료 시간을 구분한다.
캐시가 입력 토큰을 없앤다고 가정하지 않고 캐시 읽기·쓰기, 탐색 추가 비용, 복구 비용을 기록한다.

### F03 — 현재 평가 범위로는 요청한 보존 조건을 입증할 수 없음

**근거:** 플러그인 스킬 7개에 동작 사례 48개가 있고, 별도 실행 조건 시험 20개는
`document-to-confluence`에만 있다. `deep-interview`, `flowchart-design`, `tiki-taka`, 독립
`omo-model-config`에는 동작용 `evals/evals.json`이 없다.
결과물에 의존하는 일부 사례는 `files: []`만 지정하며 실행 가능한 소스 입력이 없다.
스크립트 단위 테스트는 실제 모델의 스킬 준수를 입증하지 않는다.

[technical-design-writer/evals/evals.json](../../skills/technical-design-writer/evals/evals.json)의 사례 6은
[Independent model validation](../../instructions/independent-model-validation.md)의 “Confirmation gate”가
요구하는 초안 완성 후 승인 분기를 모델링하지 않고 독립 검토를 기대한다.
[decision-navigator/evals/evals.json](../../skills/decision-navigator/evals/evals.json)의 사례 3은
티켓 하나를 해결하면서 `map.md`만 수정한다고 기술한다. 해결 시에는 티켓 파일도 수정한다.

**개선:** 유효한 사례를 유지하고, 모호하거나 오래된 기대 결과를 권위 있는 계약에 맞춘다.
실제 입력과, 필요한 경우 사용자·서비스의 응답 순서를 준비한다.
검증 표에 따라 누락된 분기를 추가하고 사용할 수 없는 호스트 경로를 명시한다.
모의 쓰기, 지어낸 입력, 구조 검사를 실제 전체 실행의 성공으로 집계하지 않는다.

## 라우팅과 인터뷰 문맥

### F04 — 설명에 절차 세부 정보와 긴 유사 표현 목록이 포함됨

**근거:** 플러그인 설명 전체는 4,779자, 5,006바이트다.
[docs-rewrite](../../skills/docs-rewrite/SKILL.md),
[technical-design-writer](../../skills/technical-design-writer/SKILL.md),
[deep-interview](../../skills/deep-interview/SKILL.md), [tiki-taka](../../skills/tiki-taka/SKILL.md)의
frontmatter에는 긴 실행 문구 목록이나 실행 절차가 들어 있다.

**개선:** 네 설명부터 목적, 실행할 조건, 실행하지 않을 경계, 명시적 호출 전용 여부를 보존하며 줄인다.
본문에서 이미 강제하는 절차 세부 정보를 라우팅 설명에서 덜어낸다.
실제로 실행 조건 판별에 도움이 되는 언어별 예시는 유지한다.
핵심 사용 목적과 명시 호출·제외 경계는 선택적 예시 앞에 두고 목록에서 설명이 줄어드는 경우도 시험한다.
원본과 후보를 이식 가능한 모의 라우팅 및 실제 호스트 라우팅으로 비교한다.
모든 호스트가 compatibility 메타데이터나 모든 설명을 같은 방식으로 로딩한다고 가정하지 않는다.

### F05 — Deep Interview가 라운드마다 같은 참조 읽기를 요구

**근거:** [Deep Interview](../../skills/deep-interview/SKILL.md)의 25–26줄 참조 목록,
“Form the Question”, “Score and Report”,
[ask-ui.md](../../skills/deep-interview/references/ask-ui.md)와
[scoring-and-state.md](../../skills/deep-interview/references/scoring-and-state.md)의 첫 지시가 해당한다.
두 참조 합계는 14,128바이트다. 반복해서 읽을 수 있는 분량이며 라운드당 토큰 측정값은 아니다.

**개선:** 첫 사용 전에 읽고, 질문·상태 갱신마다 적용하되 리비전·기능·문맥이 달라지면 다시 읽는다.
두 참조와 진입 문서의 읽기 조건에 이 차이를 명시한다.
질문 전에는 현재 지침과 실제 도구 스키마에서 질문 하나, 요청 필드, 헤더 길이, 선택지 범위,
추천 표시, 자유 입력, 답변 대기 규칙을 확인한다.
점수화 전에는 현재 차원, 최솟값 집계, 가중치, 임계값, 단계·종료 규칙을 찾는다.
필요한 규칙이 없으면 동작 전에 해당 참조를 다시 읽는다. “이미 읽음” 표시만 믿지 않는다.
재개나 문맥 압축이 관측되면 다음 UI·점수 동작에서는 무조건 참조를 다시 읽는다.
점수화, 모든 구성요소 확인, 현재 도구 스키마, 필수 승인은 매번 그대로 적용한다.
최소 10라운드 인터뷰와 문맥 압축 후 이어가기 사례로 검증한다.

### F06 — UI 참조에 모든 호스트의 구현이 함께 들어 있음

**근거:** 10,159바이트인 [ask-ui.md](../../skills/deep-interview/references/ask-ui.md)의
“Per-host routing”에는 서로 유사한 긴 JSON 예시 두 개와 Codex·일반 텍스트 대안 규칙이 함께 있다.

**개선:** F05의 로딩 기록에 유의미한 UI 읽기 비용이 여전히 남을 때만 평가한다.
`ask-ui.md` 파일 하나를 유지한다. “Core principle”, “The unified question model”,
선택한 “Per-host routing” 분기, “Answer handling (all hosts)”, “Quick selection checklist”의
규칙 전체를 읽는다.
실제 사용 가능한 기능과 상위 호스트 규칙으로 선택하며 무관한 호스트 예시만 제외한다.
신뢰할 수 있는 절 단위 읽기가 불가능하거나 총비용이 더 크면 전체 파일을 읽는다.
공통 체크리스트와 주 세션 규칙은 같은 파일에 둔다. 작은 어댑터 파일 네 개를 추가하지 않는다.
별도로 승인된 변경이 아니라면 기존 Codex 모드 관문과 대안 조건을 유지한다.
본문을 줄이면서 자유 입력, 선택지 제한, 주 세션의 질문 책임, 답변 대기가 가려져서는 안 된다.

### F07 — 라운드가 늘수록 인터뷰 이력과 검토 입력이 커질 수 있음

**근거:** [scoring-and-state.md](../../skills/deep-interview/references/scoring-and-state.md)의
“State Shape”, “Ontology Tracking”은 라운드와 온톨로지 스냅샷을 보존한다.
[lateral-review-panel.md](../../skills/deep-interview/references/lateral-review-panel.md)는 상속 문맥을
허용하지만 무관한 이력을 제외하는 입력 구성을 정의하지 않는다.

**개선:** 결정·근거 이력을 보존하면서 간결한 현재 상태를 별도로 유지한다.
매번 전체 인터뷰 기록을 다시 출력하지 않고 변경 사항을 보고한다.
기존 검토 관점마다 확정 범위, 현재 점수, 관련 결정, 모순, 근거 위치, 변경 가정을 전달한다.
필요하면 원래 근거를 조사할 수 있게 한다.
네 관점, 가능한 환경에서의 독립성, 양방향 단계 이동 검토, 모든 구성요소 점수화, 전체 최종 명세를 보존한다.
승인 없는 상태 파일 작성이나 손실이 있는 이력 삭제는 하지 않는다.

## Skill Builder와 렌더링

### F08 — 모든 다이어그램에 렌더러별 내보내기 절차를 로딩

**근거:** [Flowchart Design](../../skills/flowchart-design/SKILL.md)의 “Visual Tokens”,
“Outer Frame and Export”, “Final Checklist”는 공통 시각 요구사항, SVG 속성,
PNG의 두 번 렌더링 후 자르기 절차를 27,852바이트의 진입 문서에 함께 둔다.

**개선:** 의미 정규화, 토큰 역할, 간격, 분기·반복 예외, 라벨, 공통 완료 점검은 `SKILL.md`에 남긴다.
SVG 절차는 `references/svg-rendering.md`, 래스터 내보내기는 `references/png-export.md`로 옮긴다.
실제 결과물에 따라 하나 또는 둘 다 읽는다.
진입 문서에 결과 형식별 점검을 남겨 PNG 작업에서 자르기와 확인이 누락되지 않게 한다.
±5% 간격, 양 끝 여백, 글자 경계, 화살촉·그림자, 접근성, 최종 이미지 확인을 유지한다.
두 번 렌더링하는 자르기 절차를 검증되지 않은 저비용 휴리스틱으로 대체하지 않는다.

### F14 — 커밋 문맥 수집에 불필요한 작업과 규칙 잘라내기가 있음

**근거:** [suggest-commit](../../skills/suggest-commit/SKILL.md)의 “Fast Context Pass”는
변경 없음으로 종료하기 전에 이력과 규칙을 수집하고 `grep ... | head -10`을 쓴다.
마지막 제약은 대개 명령 하나면 충분하다고 하지만 절차에는 여러 개별 명령을 나열한다.

**개선:** 요청 범위, 상태, HEAD를 먼저 확인하고 관련 변경이 없으면 스타일 수집 전에 종료한다.
독립된 읽기는 호스트 도구로 함께 호출하되 반환 코드를 따로 보존하고 `&&`로 의존시키지 않는다.
호스트가 독립 도구를 함께 호출하지 못하면 같은 명령을 순서대로 실행하고 각 결과를 보존한다.
같은 수정에서 마지막의 “빠른 문맥 명령 하나” 문구도 이 기능별 절차에 맞춘다.
`rg`로 규칙을 찾고 실제 적용되는 문단을 읽는다. 첫 일치 열 개를 전체 규칙으로 간주하지 않는다.
HEAD가 없는 경우, 스테이징만 지정한 경우, 경로 지정 분기를 보존한다.
파일 이름·통계만으로 동작을 주장할 수 없으면 가장 작은 관련 diff를 읽는다.
검색 결과에서 관련 호출자, 계약, 설정, 실패 경로, 테스트로 범위를 확장한다.
정해진 읽기 횟수가 아니라 영향받는 동작을 확인했을 때 멈춘다.
필요하면 변경된 공개·공통 계약의 사용처를 저장소 전체에서 찾는다. 기존 LSP·AST 도구는 근거를 더할 때만 쓴다.

### F22 — 정상적인 답변 전용 토론에도 복구·질문 파일 규칙을 로딩

“Resume failure recovery”, “Deliverable writing rules”, 전체 “Unresolved-question file” 계약을 둔다.

**개선:** 복구 상세는 `references/recovery.md`, 미해결 질문 파일 작성은
`references/unresolved-questions.md`로 옮긴다.
진입 문서에는 수신 불확실 시 중단, 연결 해제와 실패의 구분, 참조 읽기 조건을 유지한다.
답변 전용 모드의 파일 쓰기 금지는 파일 동작 전에 둔다.
모델·사고 강도, 교환 횟수, 양쪽의 영향 범위 조사, 쟁점 장부, 마지막 발언 규칙,
지속 실행, 첫 고정 계약·이후 변경분 프롬프트, 정상 정리를 보존한다.
상대를 저렴한 모델로 교체하거나 필요한 독립 조사를 합치지 않는다.

### F23 — 막힌 갱신 미리보기에서도 복구 상세를 로딩

**근거:** [orca-plugin-refresh-resume](../../skills/orca-plugin-refresh-resume/SKILL.md)는 매번
수동 재개, 명령 해시 승인, 임대 잠금 복구, 완료 여부가 불분명한 상황의 처리를 함께 로딩한다.
[orca_plugin_refresh.py](../../scripts/orca_plugin_refresh.py)의 `plan_output`, `_public_receipt`는
이미 간결하고 안전한 출력과 비공개 근거 경로를 제공한다.

**개선:** 반환 상태·오류로 선택하는 `references/recovery.md`에 복구 절차를 옮긴다.
작업자 실패, 남은 임대 잠금, `needs_manual_command`, `manual_resume_requires_terminal_check`,
`complete_but_not_confirmed`, `complete_but_not_delivered`에서 읽는다.
apply 전 미리보기가 단순히 막힌 경우에는 본문의 절차로 중단한다.
사전 조건, 정확한 계획 승인, apply 후 턴 종료, 트랜잭션 중 폴링 금지,
무작정 재시도·재전송·재개 금지, 복구 경로는 본문에 유지한다.
훅 등록, 레지스트리 쓰기, 잠금, 식별 확인, 개인정보 보호, 작업자 검사는 바꾸지 않는다.
짧은 스킬이므로 추가 읽기를 상쇄할 절감이 없을 수 있다. 비교 결과가 불분명하면 기존 구성을 유지한다.

### F24 — 독립 모델 설정에서 큰 고정 소스 묶음을 반복 취급

**근거:** [omo-model-config](../../standalone-skills/omo-model-config/SKILL.md)의
“Required inputs and authority”는 필수 업스트림 파일 20개와 관련 조건부 테스트를 지정한다.
“Freshness gate”는 불일치 시 전체를 다시 가져오도록 의도적으로 요구한다.

**개선:** 확정한 SHA에서 독립적인 필수 파일을 함께 가져오고 정확한 소스 식별 정보를 유지한다.
같은 실행의 후속 선택·검증에서는 이미 읽은 소스를 재사용한다.
전체 자료를 반복 출력하지 않고 대상별 근거와 필수 최종 보고를 제공한다.
매 실행의 현재 SHA 확인, 부분 변경에서의 필수 소스, 전체 재조회 관문은 줄이지 않는다.
전체 대상 열거, 허용 목록·순서·제공자·사고 강도 규칙, 형식 보존, 외부 동기화 승인을 유지한다.
실행 간 캐시나 추측에 기반한 업스트림 파서는 이 계획에 포함하지 않는다.

## 캐시 재사용·도구 탐색·문맥 복원

### F25 — 큰 고정 스킬 본문 앞에 변하는 최적화 자료가 배치됨

**근거:** [improve_description.py](../../skills/skill-builder/scripts/improve_description.py)의
`improve_description`은 현재 설명, 점수, 시도 이력을 변하지 않은 `skill_content` 앞에 둔다.
앞쪽 블록이 바뀌면 재사용 가능한 접두부가 짧아진다. 캐시 후보이며 토큰 감소가 증명된 것은 아니다.
`run_eval.py::build_routing_prompt`는 이미 고정 스킬 메타데이터 뒤에 질문을 둔다.
`session_context.py::render_context`도 같은 경로·지침 파일이면 결정적인 결과를 만든다.
공식 작동 원리와 호스트·API 경계는 [방안별 검토](strategy-assessment.ko.md)에 기록했다.

**개선:** F11을 별도로 비교한 뒤 `improve_description.py`의 추가 후보 하나를 비교한다.
고정 역할·작업·출력 규칙과 변하지 않은 스킬 내용을 앞에 두고 현재 설명, 점수, 실패, 이력을 뒤에 둔다.
모든 자료, 권위 경계, 정확한 응답 계약을 보존한다. 현재 후보와 원본 frontmatter의 설명을 명확히 구분한다.
시험 없이 블록 순서 변경이 동작에 영향을 주지 않는다고 주장하지 않는다.
의도적으로 바꾸는 입력 외에는 시험 중 모델, 사고 강도, 도구 정의, 직렬화를 고정한다.
고정 지침에 시각을 넣거나 짧은 프롬프트 길이를 채우거나 무관한 스킬을 미리 읽지 않는다.
제공자 중립 실행기에 캐시 API 옵션을 지어내지 않는다.
캐시를 무효화하더라도 실제 소스 경로와 최신 상태 확인 규칙은 보존한다.
콜드·불명·웜 조건과 캐시 생성·재사용 전체 비용을 비교한다. 적중은 보장되지 않는다.

### F26 — 도구 탐색에 호스트 기능 계약이 필요

**근거:** 플러그인 매니페스트는 스킬을 배포하며 API 도구 레지스트리를 구현하지 않는다.
`document-to-confluence`의 소스·호스트 기능 표는 작업 경로를 정하지만 큰 지연 도구 목록의
탐색 범위를 제한하는 방법은 정의하지 않는다. 현재 호스트·도구 검색 동작은 방안별 검토에 정리했다.
모든 스키마가 지금 로딩된다는 근거는 없다. 낭비를 주장하기 전에 측정한다.

**개선:** 이미 조건부로 읽는 `instructions/services.md`에 공통 호스팅 도구 탐색 규칙을 둔다.
`skill-builder/SKILL.md`, `document-to-confluence/SKILL.md`의 기존 기능 안내는 활성 규칙을 따른다.
규칙을 복제하거나 독립 패키지의 필수 의존성을 추가하지 않는다.
호스트의 기본 탐색으로 서비스·동작을 찾고 선택한 도구의 인자·출력 계약 전체를 확인한다.
도구 식별 정보와 스키마가 유효하면 재사용한다.
지연 탐색이 없으면 현재 도구와 기존의 기능 부재 처리 경로를 사용한다.
결과가 모호하거나 없으면 서비스·동작 질의를 구체화하거나 관련 목록을 확인한다.
도구를 지어내거나 필수 동작을 조용히 생략하지 않는다. 권한 범위와 서비스 접근 규칙을 유지한다.
스킬 frontmatter에 `defer_loading`을 추가하거나 범용 로더를 만들거나 설치된 MCP 연결을 바꾸지 않는다.
이미 작거나 지연 로딩되는 목록은 변경하지 않는 것도 유효하다. 탐색 실패와 지연을 측정한다.

### F27 — 기존 체크포인트에 명시적인 복원 완전성 검사가 필요

**근거:** Deep Interview 점수 상태, Decision Navigator 지도·티켓, Tiki-taka의 문맥 내 쟁점 장부는
이미 서로 다른 경계에서 작업을 보존한다. F05는 지침 재로딩을 보호하지만 작업 상태의 문맥 전환을
단독으로 입증하지는 못한다. 요약·압축 기능 자체가 무손실을 증명하지 않는다.

**개선:** 새 전역 메모리 시스템을 만들지 않고 기존 상태·복구 절을 확장한다.
체크포인트에는 목표·범위, 제약·예외, 확인된 결정과 추론의 구분, 소스·리비전 위치,
완료 결과물, 실패 시도와 이유, 검증 결과와 공백, 미해결 질문, 승인 범위,
미완료 부수 효과, 활성 잠금·세션·트랜잭션 식별 정보, 다음 동작을 보존한다.
비밀값은 넣지 않는다. 민감한 식별 정보에는 기존 보호된 확인 자료 경로를 사용한다.
이어가기 전에 관련 지침을 복원하고 체크포인트 사실을 권위 있는 결과물과 대조한다.
근거가 오래되었거나 없으면 다시 읽거나 해당 동작을 멈춘다. 불확실한 동작을 재시도로 바꾸지 않는다.
승인된 영속화만 사용한다. 읽기 전용 인터뷰에 상태 파일을 추가하거나 Tiki-taka 쟁점 장부를 저장하지 않는다.
토론·갱신 중 새 세션을 강제하거나 이력을 삭제하거나 점유·임대 잠금을 우회하지 않는다.
해당 절차가 허용하고 필수 상태를 안전하게 복원할 수 있을 때만 새 문맥을 선택한다.
요약 생성, 재로딩, 재탐색, 캐시 재구성, 이어가기 완료 비용을 함께 측정한다.
