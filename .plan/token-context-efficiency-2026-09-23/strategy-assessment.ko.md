# 열 가지 방안을 저장소의 품질 계약에 맞게 적용

> 영어 원본: [strategy-assessment.md](strategy-assessment.md)
> 이 문서는 사람이 읽기 위한 비권위 한국어 미러다. 실행 지침으로 사용하지 않는다.

열 가지 제안은 유용한 검토 기준이다. 적용 가능한 방법을 채택하고 기존 보호 장치를 유지한다.
제시된 순위는 저장소에서 측정한 성능이 아니라 가설로 취급한다.
아래 판단은 [구현 개선안](README.ko.md)과 [발견 사항](findings.ko.md)을 보강한다.

## 점수와 판단 기준

1–5점 척도에 다음 가중치를 적용하면 제시된 총점 열 개가 모두 맞는다.

`100 × (0.40Q + 0.35V + 0.15S + 0.10A) / 5 = 8Q + 7V + 3S + 2A`.

사용자가 제시한 순서대로 총점은 `88, 79, 78, 75, 73, 72, 70, 65, 63, 62`다.
Q는 제안의 품질 보존, V는 근거의 강도, S는 절감 잠재력, A는 적용성을 뜻한다.
각 값은 사용자가 제시한 판단이며 실제 측정값이나 보정된 확률이 아니다.
공식 문서는 작동 조건의 근거다. 이 저장소의 V가 4점임을 입증하지는 않는다.

품질, 승인, 성능의 필수 관문을 먼저 적용한다.
이를 충족할 수 있는 후보 사이에서만 우선순위를 비교한다.
높은 절감 점수로 요구사항 누락을 상쇄할 수 없다. 겹치는 방안의 절감량을 더해서도 안 된다.
따라서 F11 프롬프트 중복 제거와 F25 접두부 순서 변경은 따로 비교한다.

“1–5번은 품질을 거의 건드리지 않는다”는 설명은 채택 규칙으로 쓰기에는 너무 넓다.
모델 입력이 동일한 캐시 재사용과 캐시에 맞추려고 입력을 재작성하는 작업은 효과가 다르다.
지침 제거, 판단의 스크립트 대체, 도구 탐색 지연, 읽기 범위 축소는 필요한 정보를 잃을 수 있다.
실행 경로가 바뀌면 모두 [검증 계획](validation.ko.md)의 Sonnet·Luna 기준을 적용한다.

제공자가 이 플러그인에서 직접 검증한 권고가 아니다.

## 네 가지 효과 구분

| 효과 | 필요한 근거 | 근거가 될 수 없는 것 |
|---|---|---|
| 논리적 토큰 감소 | 비교 가능한 전체 입력·출력·추론 사용량. | 캐시 입력 증가. |
| 활성 문맥 감소 | 실제 로딩 자료와, 제공되는 경우 최대 유지 문맥. | 낮아진 요금이나 상위 세션만의 문맥. |
| 금전 비용 감소 | 적용되는 실제 요금 또는 검증된 단가·겹치지 않는 사용량으로 계산한 추정치라는 표시. | 단순 토큰 합계, 구독 지출로 표시한 API 정가 추정, 제공자의 최대 할인율. |
| 완료 시간 단축 | 탐색, 캐시 생성, 수정, 복구를 포함한 요청부터 사용 가능한 결과물까지의 시간. | 캐시가 적중한 성공 호출 하나의 지연. |

OpenAI는 접두부 재사용과 캐시 처리의 비용·지연 절감을 설명한다.
Claude는 캐시 입력도 문맥 용량에 포함된다고 명시한다. 이를 근거로 캐시 비용과 문맥 감소를 구분한다.
[OpenAI 프롬프트 캐시](https://developers.openai.com/api/docs/guides/prompt-caching),
[Claude 문맥 창](https://platform.claude.com/docs/en/build-with-claude/context-windows).

고정 내용이 여전히 올바를 때만 안정적으로 유지한다.
필수 소스 갱신, 권한 변경, 지침 수정은 캐시 재사용보다 우선한다.
지원하는 호스트의 도구 탐색과 캐시는 함께 사용할 수 있다.
앞쪽 도구 목록을 수동으로 바꾸는 작업은 별개이며 접두부 캐시를 무효화할 수 있다.
[OpenAI 도구 검색](https://developers.openai.com/api/docs/guides/tools-tool-search),
[Claude Code 프롬프트 캐시](https://code.claude.com/docs/en/prompt-caching).

## 저장소가 제어하는 범위

| 제어 주체 | 조절 가능한 대상 | 개선안 처리 |
|---|---|---|
| 이 저장소 | 지침 문구, 참조 선택, 스킬 메타데이터, 프롬프트 조립, 로컬 출력, 기존 도구. | 측정으로 확인한 F01–F27 후보를 여기서 구현한다. |
| 에이전트 호스트 | 시스템 문맥, 스킬 목록 제한, 도구 스키마 탐색, 설치된 MCP 연결, 자동 문맥 압축. | 사용 가능한 동작을 확인·측정하고 기존 지원 경로를 사용한다. 이번 작업에서 설치·설정을 바꾸지 않는다. |
| API 애플리케이션·제공자 | 캐시 키, 유지 시간·분기점, 지연 도구 등록, 압축 API, 요금·사용량 집계. | 실제 요청을 소유한 애플리케이션에서만 검토한다. 현재 `model_runner.py`는 외부 명령에 stdin을 전달하며 제공자 요청 본문을 소유하지 않는다. |

호스트가 이미 상당한 지연 로딩을 담당한다.
Codex는 스킬 선택 후 본문을 읽으며 목록 공간이 부족하면 설명을 줄일 수 있다.
현재 Claude Code 문서는 초기 스킬 설명·도구 이름과 이후 본문·스키마를 구분한다.
설명 앞부분에 발견 가능하고 정확한 실행 조건을 보존하고, 실제 읽은 자료와 목록에만 나온 자료를 구분해 시험한다.
[스킬 작성](https://learn.chatgpt.com/docs/build-skills),
[Claude Code 확장](https://code.claude.com/docs/en/features-overview).

도구 검색은 탐색 작업을 추가하므로 도구가 적을 때는 적합하지 않을 수 있다.
초기 스키마 감소와 함께 탐색 실패, 재시도, 총지연을 평가해야 한다.
[Anthropic 고급 도구 사용](https://www.anthropic.com/engineering/advanced-tool-use).

일반적인 비용 팁을 모두 이 저장소에 복사하지 않는다.
예를 들어 MCP보다 CLI를 우선하거나 테스트 출력을 `grep`·`head`로 거르는 권고는
저장소의 서비스 접근 규칙, 정확한 실패·종료 코드 보존 요구를 바꾸지 않는다.
[Claude Code 비용 안내](https://code.claude.com/docs/en/costs)는 후보 근거이며 로컬 계약의 예외가 아니다.
