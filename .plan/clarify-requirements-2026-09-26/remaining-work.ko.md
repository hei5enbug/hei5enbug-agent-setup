그 사실이 제약을 조용히 완화할 권한을 주지는 않는다.

## R1: 관측된 비용 문제 해결

최종 읽기 전용 참조 누락 비교에서 기존은 20.235초, 입력/출력 26,714/708토큰이었고 후보는
29.686초, 57,558/1,223토큰이었다. 한 번의 관측이며 전체 분포의 저하 추정은 아니다.
후보는 질문·평가 전에 올바르게 멈추고 한국어 미러를 대신 쓰지 않았다. 이 결과를 유지하며 추가 작업을 조사한다.

1. 기준 커밋을 내보내고 후보와 모든 참조·해시를 고정한다. 일회용 작업 공간에서 작업·파일·권한·모델·effort를 같게 한다.
2. 실제 지침 읽기·도구 호출·재시도·답변을 확인한다. 필수 검사와 참조 누락 동작을 보존하는 중복만 제거한다.
   기존이 더 빨랐다는 이유로 검증을 생략하거나 필수 예외를 지워 지침을 줄이지 않는다.
3. 지원되는 Codex 환경에서 [run_readonly_trials.py](run_readonly_trials.py)의 `missing-scoring`을 실행한다.
   시작 전에 대응 실행 세 쌍을 고정한다. 이 실행기는 Claude나 사람 UI를 다루지 않는다.
4. 같은 호스트와 비교 가능한 컨텍스트·캐시 조건에서 사례별로 비교한다. 원본 사용량 항목과 경과 시간을
   보존하고, 캐시·추론 하위 항목을 중복 합산하거나 누락 데이터를 0으로 취급하지 않는다.
5. 수정본도 실패하거나 결론이 불명확하면 그 결과를 기록하고 후보로 유지한다. 유리한 평균이 나올 때까지 반복하지 않는다.

이전의 스냅샷 혼합 진단은 계속 제외한다. 최종 한 쌍의 관측은 진단에는 유용하지만 합의된 반복 채택 검증을 대체하지 않는다.

## R2–R3: 실제 동작과 채택 근거

저장소의 [평가 어댑터](../../skills/skill-builder/references/execution-methods.md)를 따른다.
Claude Code에서는 Sonnet 5/high, Codex에서는 gpt-5.6-luna/xhigh를 사용한다.
실제 모델과 effort를 확인한다. 기존 기록에는 요청한 선택자는 있지만 Codex가 재보고한 모델 ID는 없다.
요청 설정만으로 실제 실행 정체가 확인됐다고 하지 않고, 다른 모델로 바꾸거나 Codex에서 Sonnet을 실행하지 않는다.

실제 주 세션 질문 사례에는 사람 운영자가 참여한다. Codex의 엄격한 인터뷰는 Plan 모드와 지원 질문 UI를 쓴다.
운영자 안내서는 모델 입력 밖에 두고 질문이 나왔을 때만 답한다. 질문·답변의 대응과 응답 대기 시간을 기록하고
에이전트가 사람을 대신하지 않는다. 잠금 경합·쓰기·복구는 분리된 일회용 지도에서, 피드백은 허용된 로컬
시안으로 확인한다. 실제 외부 트래커·운영 페이지·사용자 결정 지도는 평가 대상으로 쓰지 않는다.

[coverage.ko.md](coverage.ko.md)의 관련 분기를 모두 다룬다. 기존 후보 사례 29개뿐 아니라 대표 greenfield
조사와 아직 실행되지 않은 실제 탐색의 긍정·부정 사례도 포함한다. 기존 사례 대응은
[source-cases.json](candidate/clarify-requirements/evals/source-cases.json)을 사용한다.
새 통합 사례는 어떤 원래 절차를 비교 기준으로 쓰는지와 그 이유를 기록한다.
명시적 호출, 질문 하나, 결정 전 근거, 수치 기준 선택, 미승인 쓰기 금지, 엄격한 종료, 범위 변경,
위임 가정, 라운드 제한, 재개 상태, 사람의 시안 반응, 티켓·지도 트랜잭션을 각각 확인한다.

기존 [측정·채택 기준](../token-context-efficiency-2026-09-23/validation.md#metrics-and-adoption-gates)을 적용한다.
관련 사례·실제 호스트마다 세 쌍을 사전에 정하고 원본·후보 순서를 교대한다. 모든 중요 품질 조건을 보존한다.
좋은 평균으로 요구사항 누락을 상쇄하지 않는다. 비교 가능한 조건에서 사례별 완료 시간과 전체 사용량의
중앙값·관측 최댓값을 비교한다. 모든 참여자·도구·재시도·복구를 포함한다. 준비·채점 비용은 따로 측정하고
사람의 원래 대기 시간도 보존한다. 바이트로 토큰 절감을 추론하거나 두 모델 결과를 한 점수로 합치지 않는다.

각 사례에 소스 해시·설정 근거·작업·입력·도구 동작·출력·채점·시간·사용량 완전성·통과/실패/미검증 상태를
기록한다. 정확한 조건은 도구로 검사하고 의미·사용 가능성은 원본·산출물 근거로 판단한다.
사용할 수 없는 호스트나 누락 지표는 미검증으로 남긴다. 필수 설정을 쓸 수 있으면 현재 스킬 평가 절차에 따라
독립 채점을 수행한다. 기존 읽기 전용 예비 실행은 설치 플러그인 라우팅·실제 UI·경합·복구의 근거가 아니다.

## R4–R5: 교체, 검사, 전달

정확히 고정한 후보가 채택 기준을 통과하면 다음을 수행한다.

1. 자체 완결 후보를 `skills/clarify-requirements/`에 두고 같은 변경에서 기존 두 등록 디렉터리를 폐지한다.
   공통 절차와 조건부 참조를 한 원본으로 유지한다. 새 `agents/openai.yaml`의 명시적 호출 정책과 호스트 질문 어댑터를 유지한다.
2. `.decision-navigator/` 사용자 데이터, 티켓 유형·상태·파일명, 잠금 소유권·순서를 보존한다.
   사용자 지도나 잠금을 이동·삭제하지 않는다. 관련 테스트·평가는 새 스킬과 함께 옮긴다.
3. README의 스킬 목록·이행 안내를 갱신하고 폐지 경로 링크가 있는 다른 언어판도 수정한다.
   `tests/test_korean_mirrors.py`의 고정 입력 경로를 바꾸고 저장소에 남은 옛 이름의 실행 참조를 찾는다.
   기준 목록은 보존하며, 옛 경로를 없앨 때 과거 기록의 소스 링크는 해당 고정 커밋을 가리키게 한다.
4. 영어 문서와 완전한 한국어 미러를 함께 갱신한다. 후보 기록에 날짜가 있는 전환 결과를 추가하되 과거 관측을
   새 기본값을 측정한 것처럼 다시 쓰지 않는다.
5. 최신 공개 릴리스와 다른 미릴리스 변경을 확인한다. 통합은 최소 minor 변경이며 AGENTS.md에 따라 전체
   미릴리스 변경 중 가장 큰 영향으로 다음 버전 하나를 고른다. 현재 후보만 보고 버전을 추정하지 않는다.
   `.codex-plugin/plugin.json`, `.claude-plugin/plugin.json`,
   `pyproject.toml`, `uv.lock`을 맞춘다. 실제 프로젝트 버전에 묶인 검사는 필요한 경우 갱신하되 무관한
   입력 자료의 고정 예시 버전을 일괄 치환하지 않는다.
6. 현재 README의 개발 검사인 전체 스킬 메타데이터·Python·Node 렌더러 검사를 실행한다.
   플러그인·미러·링크·패키징도 확인한다. 패키지의 실행 참조·스크립트가 완전하고 평가 캐시가 포함되지 않아야 한다.
7. 최종 변경 범위와 공백을 확인하고 suggest-commit으로 근거에 맞는 제목을 고른 뒤, 허용된 교체 변경을
   커밋·푸시한다. 로컬·원격 커밋 일치와 실제 작업 트리 상태를 보고한다. 릴리스 게시나 실제 세션 새로고침은 별도 작업이다.

전환 전에 통합 검증이 실패하면 기존 기본값과 후보·근거를 유지한다. 나중에 교체를 되돌려야 하면 해당 변경만
정상적인 검토 커밋으로 되돌리고 무관한 작업·평가 근거·모든 사용자 지도 데이터를 보존한다.
hard reset이나 사용자 상태 삭제를 되돌림 수단으로 쓰지 않는다.

## 완료 기록

R1–R5 상태를 완료로 바꾸기 전에 완료 리비전과 근거 링크를 추가한다. 사용할 수 없는 선행 조건과 정확한
실패는 해당 행에 기록한다. 최종 전환 커밋·선택한 버전·필수 검사 결과·원격 확인을 함께 남긴다.
후보 패키지나 이 문서의 커밋만으로 R3–R5가 완료되는 것은 아니다.
