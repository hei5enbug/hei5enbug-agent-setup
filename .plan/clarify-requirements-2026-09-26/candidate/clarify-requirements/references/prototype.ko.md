# 프로토타입 절차

> 영어 원본: [prototype.md](prototype.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

프로토타입은 설계 질문 하나에 답하는 폐기 가능한 아티팩트다. 목적지를 전달하는 데 사용하지 않고
결정을 더 쉽게 내리는 데 사용한다.

## 분기 선택

- 비즈니스 로직, 상태 전환, 데이터 형태 또는 API 표면에는 [논리 프로토타입](prototype-logic.ko.md)을 읽는다.
- 레이아웃, 정보 계층 또는 시각적 상호작용에는 [UI 프로토타입](prototype-ui.ko.md)을 읽는다.

분기가 불명확하고 사람에게 질문할 수 있으면 질문한다. 아니면 주변 코드에서 추론하고 가정을 밝힌다.

## 공통 규칙

1. 아티팩트를 만들기 전에 정확한 질문을 쓴다.
2. 아티팩트가 프로토타입임을 분명히 표시하고 관련 코드 가까이에 둔다.
3. 프로젝트의 런타임, 작업 실행기와 규칙을 재사용한다.
4. 사람이 실행할 명령이나 URL 하나를 제공한다.
5. 지속성이 시험할 질문이 아니면 상태를 메모리에 둔다.
6. 운영 수준의 마감, 넓은 추상화와 관련 없는 경계 처리를 생략한다.
7. 모든 상호작용 뒤에 관련 상태나 변형을 보이게 한다.
8. 사람의 반응을 근거로 사용하고 HITL 티켓에서 사람을 대신해 답하지 않는다.

## 기록과 정리

선택된 결정과 선택 이유를 기록한다. 결정 메모와 임시 코드 위치를
`.decision-navigator/<effort>/artifacts/prototypes/<ticket>/` 아래 두고 티켓에서 연결한다.
프로토타입 결과를 외부 추적기나 연결된 문서 서비스에 게시하지 않는다.

검증된 아이디어만 운영 작업으로 옮길 수 있으며 지도의 Notes가 실행을 명시한 경우에만 가능하다.
결정을 기록한 뒤 메인 코드에서 프로토타입 뼈대를 제거한다.
