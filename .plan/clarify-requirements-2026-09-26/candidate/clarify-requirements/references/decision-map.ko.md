# 결정의 지속적 기록

> 영어 원본: [decision-map.md](decision-map.md)
> 이 문서는 사람이 읽기 위한 비권위 한국어 미러다. 실행 지침으로 사용하지 않는다.

로컬 지도 접근 전에 이 파일과 `local-tracker.md`를 읽는다. 명시적 지도 요청이나 해당 위치의 저장 승인이
있을 때만 지도를 사용한다. `.decision-navigator/<effort>/`와 기존 지도·티켓·상태·잠금 형식은 유지한다.
스킬 이름 변경으로 사용자 데이터를 이동하지 않는다. 저장소 원격이 있어도 외부 이슈 트래커를 조사·설정·조회·
수정하지 않는다. 지도 작업에 이슈 트래커 API, 연결된 티켓 도구, `gh`, `glab`를 사용하지 않는다.

목적지는 명세, 계획 전 결정, 비개발 영역을 포함한 어떤 분야의 변경일 수 있다. 기본적으로 티켓은 구현
작업 조각이 아닌 결정을 해결한다. 목적지까지의 길이 명확해지면 끝난다. Notes에 유효한 사용자 구현 권한이
명시된 경우에만 지도 안에서 구현한다. 지도 존재나 에이전트가 쓴 메모가 권한을 주지 않는다.

## 지도와 티켓의 의미

설명과 링크에는 지도·티켓의 Markdown 제목을 사용한다. 번호나 파일 슬러그만 쓰지 않는다.
지도는 색인이므로 한 줄 요약과 답을 담은 티켓의 이름 있는 상대 링크만 둔다. 전체 답을 중복하지 않는다.
지도로 개요를 읽고 필요한 티켓 본문과 Notes 원본을 찾아 읽는다.
최종 답변의 링크에는 실제 파일 경로를 사용한다. 경로 구성요소를 `...`로 바꾸거나 템플릿 자리표시자를
남기지 않는다. 저장된 지도의 상대 링크는 해당 지도 디렉터리를 기준으로 해석한다.

```markdown
## Destination
<이 작업이 길을 찾는 명세·결정·변경을 한두 줄로 쓴다.>

## Notes
<도메인 맥락·문서·상시 선호·명시적인 실행 권한.>

## Decisions so far
- [<해결된 티켓 제목>](tickets/<file>.md) — <한 줄 요약>

## Not yet specified
<아직 정확히 표현할 수 없는 범위 안의 질문.>

## Out of scope
<이 목적지 범위를 벗어나는 일.>
```

열린 티켓을 지도에 나열하지 않는다. 로컬 트래커 계약에 따라 숫자 순으로 메타데이터를 탐색한다.
적격 티켓은 open이며 모든 선행 티켓이 해결됐고 잠겨 있지 않아야 한다. frontier에는 적격 티켓 전체가
포함된다. 숫자 순서는 그 집합에서 다음 티켓을 고르는 기준이며 뒤의 적격 티켓을 frontier에서 제외하지 않는다.
정확한 질문이면 막혀 있어도 티켓이다.
범위 안에서 예상되지만 정확히 표현할 수 없는 질문은 Not yet specified에 둔다. 이를 추측성 티켓으로
미리 쪼개지 않는다. 해결된 결정·현재 티켓·미명세 영역·범위 밖 일을 구분한다.

범위 밖 일은 현재 목적지의 티켓으로 바뀌지 않는다. 목적지를 바꾸면 새 작업을 시작한다. 기존 티켓이 범위
밖으로 판명되면 Answer에 이유를 적고 resolved로 바꾼 뒤 Decisions so far가 아닌 Out of scope에 연결한다.
무효화된 티켓이나 지도·산출물을 삭제하기 전에 사용자에게 묻는다.

## 공통 반복 절차 안의 티켓 작업

| 종류 | 필요한 근거나 결정 | 필수 참조와 완료 |
|---|---|---|
| `research` | 문서·API·로컬 자료의 에이전트 단독 사실 확인 | `research.md`. 출처가 있는 직접 답, 불확실성, 영향, 연결한 조사 결과를 기록한다. |
| `prototype` | 거친 구체적인 산출물에 대한 사람 반응 | `prototype.md`와 논리/UI 분기. 사람의 반응과 결정을 보존한다. |
| `grilling` | 기본 유형인 사람 판단 | `../SKILL.md` 공통 절차. 용어·경계·장기 설계는 `domain-modeling.md`. 합의된 결정을 확인받는다. |
| `task` | 결정을 하기 전에 필요한 선행 작업 | 가능하고 허용되면 에이전트 단독 수행. 아니면 사람에게 정확한 체크리스트를 준다. 완료된 뒤 결과 사실과 안전한 산출물 위치를 기록하고 해결한다. 자격 증명을 노출하지 않는다. |

사람 참여 작업은 실제 사람과 주고받아야 한다. 에이전트가 대신 답하지 않는다. 조사와 에이전트 단독 작업은
검증된 근거로 해결할 수 있다. task는 목적지를 구현하기 위해서가 아니라 결정을 막는 선행 조건을 풀기 위해
존재한다. 시안은 일회성 결정 근거이며 운영 산출물이 아니다. 답·이유·후속 티켓에 미치는 영향을 기록한다.
보조 자료는 artifacts/에 둔다.

## 새 지도 만들기

지도 작성은 한 세션의 작업이며 사람의 결정을 직접 해결하지 않는다. 공통 절차를 너비 우선으로 사용한다.

1. `domain-modeling.md`를 읽는다. 최종 산출물·결정·변경, 사용자, 실행 전에 필요한 결정, 제외 범위,
   바꿀 수 없는 제약을 확인한다. 지도를 만들기 전에 한두 줄 목적지 표현을 확인받는다.
2. 깊이 파고들기 전에 전체를 살핀다. 정확한 질문·의존성·아직 표현할 수 없는 범위 안 영역·제외한 일을
   찾는다. 길이 이미 명확하고 한 세션에 끝나면 지도를 만들지 않는다. 관리 비용을 설명하고 진행 방법을 묻는다.
3. Destination/Notes, 비어 있는 Decisions so far, Not yet specified의 불확실성을 담은 map.md를 만든다.
   tickets/, claims/, artifacts/를 만든다. `.decision-navigator/.gitignore`에 `*/claims/`를 추가하면서
   기존 제외 규칙을 보존한다. 일시적인 잠금은 버전 관리하지 않는다.
4. 정확한 질문의 번호 티켓을 먼저 만들고 두 번째 순회에서 Blocked by를 연결한다. 아직 표현할 수 없는
   영역은 Not yet specified에 둔다. `local-tracker.md`의 유형·상태를 유지한다.
5. `research.md`로 독립 조사 티켓을 시작한다. 공유 변경 자원이 없고 호스트 한도 안이면 티켓마다
   작업 에이전트를 쓰고, 불가능하면 순차 처리하며 병렬 기능 부재를 밝힌다. 결과는 artifacts/research/에
   저장하고 각 티켓에 연결한다.
6. 지도 작성을 마친다. 조용히 다음 사람 티켓으로 넘어가지 않는다.

## 지도 이어가기

독립 조사 티켓 예외 외에는 세션당 티켓 하나만 해결한다. 작업명이나 지도만 지정해도 된다.
사용자가 티켓을 고를 필요는 없다. 작업 선택 전에 Destination을 확인한다.

1. 지도와 필요한 Notes 원본을 읽는다. 지정 티켓 또는 숫자 순 첫 적격 티켓을 고른다.
   작업 전에 `scripts/local_lock.py`로 잠근다. Status 수정은 잠금이 아니다.
   실패하면 적격 티켓을 다시 탐색하고, 성공하면 티켓을 다시 읽는다.
2. 그 질문에 공통 명확화 절차를 적용하고 해당 유형의 참조만 읽는다. 관련 선행·해결 답변은 필요할 때
   읽는다. 필요한 규율이 불분명하면 공통 인터뷰와 도메인 모델링을 쓴다. 기존 답과 범위를 보존한다.
3. 해결 기록 전에 티켓을 다시 읽어 동시 수정을 확인한다. `local-tracker.md`의 정확한 트랜잭션을 따른다.
   티켓 잠금 상태에서 Answer와 resolved를 쓰고 같은 소유자로 map.md를 잠근다. 지도를 다시 읽고
   병합·저장한 뒤 지도 잠금, 티켓 잠금 순서로 해제한다.
4. 새 티켓은 지도 잠금 안에서 만든다. 이름을 먼저 할당한 뒤 의존성을 연결한다. 구체화된 미명세 영역은
   제거해 새 티켓 한 곳에만 남긴다. 다른 세션의 결정을 보존한다. 해당하면 범위 밖 규칙을 적용한다.
   무효화된 티켓은 갱신하거나 삭제 전에 묻는다.

다른 소유자 잠금을 풀거나 오래됐다는 이유로 강제 해제하지 않는다. 실패한 트랜잭션은 잠금과 정확한
복구 지점을 보존한다. 자신의 잠금도 도우미로 해제한다. 해결 쓰기 전에 사용자가 중단하면 티켓을 open으로
두고 소유 잠금·상태를 보고해 재개가 명확하도록 한다. 중단을 해결로 취급하거나 잠금 디렉터리를 직접 지우지 않는다.

재개 후에는 변경된 원본을 다시 읽고 쓰기 전에 대기 중 동작을 대조한다. 지도 저장은 다른 곳의 새 상태 파일을
허용하지 않으며, 요청한 명세의 최종 확인을 대체하지 않는다.
