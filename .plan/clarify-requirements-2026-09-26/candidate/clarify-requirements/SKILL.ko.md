# 요구사항 명확화

> 영어 원본: [SKILL.md](SKILL.md)
> 이 문서는 사람이 읽기 위한 비권위 한국어 미러다. 실행 지침으로 사용하지 않는다.

이름은 `clarify-requirements`다. 근거, 한 번에 질문 하나, 불확실성 재평가로 목표·요구사항·열린 결정을
명확히 한다. 확인된 결정이나 승인된 명세를 만들고, 요청하면 로컬 결정 지도를 여러 세션에서 이어간다.
사용자가 이 스킬을 호출하거나 이 명확화 절차의 실행을 명시적으로 요청한 경우에만 사용한다.
파일 시스템 없이 대화할 수 있다. 로컬 지도에는 파일 시스템과 원자적 잠금을 위한 Python 3가 필요하다.
질문 UI와 독립 작업 에이전트는 정해진 호스트별 대체 절차를 따른다.

영어 지침만 실행하고 한국어 미러는 사람이 참고한다. 이 스킬은 자체 완결적이며 형제 스킬을 호출하지 않는다.
`references/`, `scripts/`는 이 스킬 디렉터리를 기준으로 찾는다. 필수 자료가 없으면 이를 보고하고
관련 동작을 중단한다. 규칙을 만들어내지 않는다.

## 요청한 결과 확정

이 절차를 명시적으로 요청했을 때만 시작한다. 일반 질문·불명확한 요구사항·큰 프로젝트·위험한 변경은
실행 조건이 아니다. 그런 요청은 직접 처리하고 이 절차를 먼저 제안하지 않는다. 사용자 언어를 쓰며
식별자·경로·명령·스키마 키·상태 토큰은 보존한다.

목표·제약·원하는 결과·기존 권한을 파악한다. 큰 입력을 요약할 때 결정·근거·제약·비목표를 보존한다.
기존 산출물 변경인 brownfield와 새 작업인 greenfield를 구분한다. 요청과 기존 지도의 Destination에서
출력을 정하고 해석 차이가 중요하면 쓰기 전에 질문 하나로 확인한다.

| 요청한 동작 | 첫 관련 동작 전에 읽을 자료 |
|---|---|
| 엄격한 인터뷰 또는 실행 가능한 명세 | 수치 평가·검토·라운드 제한·종료를 정한 `references/specification-gates.md`. |
| 지정한 티켓을 포함한 지도 생성·계속 | 지도 접근 전에 `references/decision-map.md`, `references/local-tracker.md`. |
| 지도 안의 명세 | 위 두 행 모두. 평가 범위를 명시한다. 티켓 하나가 준비됐다고 전체 목적지가 준비된 것은 아니다. |
| 지도·명세 없이 결정 하나 | 아래 공통 절차. 수치 명세 기준이나 지도 관리 비용을 추가하지 않는다. |

허용된 기록·시안·선행 작업을 제외하고 조사는 읽기 전용이다. 명시한 위치의 저장을 요청하거나 승인하지
않았으면 상태를 대화에 둔다. 지도 요청은 로컬 절차와 명시된 기록을 허용하며 외부 트래커를 허용하지 않는다.
복잡하다는 이유로 쓰기 권한이 생기지 않는다. 기존의 유효한 권한은 정확한 범위 안에서 존중한다.
점수·명세 승인·에이전트가 작성한 메모가 목적지 실행 권한을 뜻하지 않는다.

## 하나의 명확화 반복 절차

1. **빈틈 선택.** 사실·확인된 결정·가정·모순·비목표·열린 질문을 구분하고 선행 조건을 먼저 해결한다.
   엄격한 작업은 점수 계약의 가장 약한 구성요소·차원을 고른다. 지도에서는 첫 동작 전에 적격 티켓을
   선택해 잠근다. 질문 라운드 동안 같은 잠금을 유지하고 반복할 때마다 다시 선택하거나 잠그지 않는다.
2. **조사와 재평가.** 관련 코드·설정·이력·문서·동작을 확인하고 경로·심벌·명령·관찰을 인용한다.
   외부 사실은 일차 자료를 우선하며 필요한 최신 사실을 확인한다. 충돌을 드러내고 사실과 추론을 구분한다.
   해당하면 지도 유형별 조사·시안·선행 작업 참조를 읽는다. 에이전트 단독 티켓은 사람 질문 없이 근거로
   해결할 수 있지만 사람 판단에는 실제 사람의 답이 필요하다.
3. **필요하면 질문 하나.** 미해결 판단·의도·범위·트레이드오프·해석만 묻고 조사 가능한 사실은 묻지 않는다.
   사용자 질문은 모두 주 세션에서 한다. 엄격한 작업은 질문·확인마다 모드 조건과 대체 절차를 포함한
   `references/ask-ui.md`를 따른다. 일반 결정은 지원 질문 UI나 일반 질문을 사용하고 기다린다.
   모호하거나 충돌하는 답에는 구체적 예를, 선택에는 근거 있는 추천과 짧은 이유를 준다.
   도구 선택지 제한을 지키고 선택지를 구분하며 자유 입력을 허용한다. 사람 대신 답하지 않는다.
4. **답변 확인.** 결정·이유·사용자 제약·비목표·확인된 맥락을 추출한다. 의미가 손실될 수 있으면 점수나
   해결 기록 전에 해석을 확인하고 요구사항을 만들어내지 않는다. 명시적으로 위임된 선택은 확인 전까지
   가정으로 표시한다. 엄격한 작업은 `references/auto-answer-uncertain.md`와 점수의 확신 규칙을 쓴다.
5. **재평가와 기록.** 불확실성 변화는 경과 라운드가 아니라 근거나 답에 연결한다. 모순·불일치·회피·범위
   확장은 불확실성을 높일 수 있다. 다툼이 있는 버전을 보존하고 확장된 범위를 다루기 전에 구성요소를
   갱신한다. 엄격한 작업은 수치 갱신·보고·단계별 검토·라운드 제어를 여기서 적용한다.
   일반 결정은 거짓 수치 정밀도를 만들지 않고 구체적인 빈틈을 설명한다. 확인된 답은 한 곳에 기록하고
   지도는 티켓의 색인이 된다. 요청 범위와 지도 세션 제한 안에서만 계속한다.

## 완료 또는 중단

결정 하나에서는 사람 판단을 확인받고 답·근거·불확실성·영향을 보고한다. 엄격한 명세는
`specification-gates.md`의 모든 종료 조건과 템플릿을 따른다. 지도는 해결 트랜잭션을 지킨다.
목적지까지의 길이 명확하고 열린 결정과 범위 안 미명세 영역이 없어야 완료한다.
다른 티켓이나 수치가 통과해도 미응답 사람 결정은 열린 상태로 남는다.

조기 종료·라운드 한도에는 미해결 빈틈을 보존하고 해당하면 엄격한 절차의 위험 표시 결과를 제공한다.
근거가 없으면 미검증으로 표시한다. 불확실한 지도 쓰기 후에는 정해진 복구 지점과 잠금을 유지하고
불확실한 부수 효과를 재시도하거나 오래돼 보이는 잠금을 강제 해제하지 않는다.
허용된 산출물 경로와 검증 한계를 반환한다. 결과 승인과 다음 행동을 구분하며 명시적이고 유효한 권한 안에서만 실행한다.

## 컨텍스트와 기능

리비전·관련 도구 계약·현재 컨텍스트가 유효할 때만 지침과 근거를 재사용한다. 필수 단계에서 규칙을 다시
적용하고 변경·컨텍스트 손실 후에는 관련 동작 전에 다시 읽는다. 엄격한 점수·UI 규칙은 필요한 매 동작에서
사용할 수 있어야 한다. 티켓·지도는 이전에 읽었더라도 잠금 후 다시 읽는다. 전체 보관소가 아니라
관련 티켓 본문을 필요할 때 읽는다.

권위 있는 원본을 버리지 않고 현재 빈틈과 관련 근거를 컨텍스트에 둔다. 저장은 승인된 곳에서만 한다.
재개 후에는 결정·권한·리비전·대기 중 동작·열린 빈틈을 원본 상태와 대조한다. 복구할 수 없으면 관련 동작을 중단한다.
작업 에이전트는 제한된 근거를 주 세션에 돌려준다. 필수 독립 검토 컨텍스트가 가능하면 사용하고,
불가능하면 정해진 관점을 순차 적용한다. 도구·에이전트 실패는 기능을 바꿀 뿐 계약을 바꾸지 않는다.
파일 시스템·Python이 없으면 지도 접근·잠금이 불가능함을 보고하고 현재 사실로 가능한 대화만 계속한다.
잠금·저장·독립 검토·병렬 실행을 한 척하지 않는다.
