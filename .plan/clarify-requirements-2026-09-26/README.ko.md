# 요구사항 명확화 통합 후보

> 영어 원본: [README.md](README.md)
> 이 문서는 사람이 읽기 위한 비권위 한국어 미러다. 실행 지침으로 사용하지 않는다.

사용자는 통합 절차와 이름을 승인한 뒤, 실제 질문 UI에 참여하기 어려워 이번에는 후보까지만 준비하도록
선택했다. 이 디렉터리는 실행 가능한 자체 완결 후보다. 플러그인은 여전히 `skills/`의 기존 두 스킬을
탐색하며 후보는 그 경로 밖에 있다. 설치된 플러그인과 사용자 결정 지도는 바꾸지 않는다. 저장소 버전은
`0.6.0`을 유지한다.

후보는 근거 수집, 필요한 사람 질문 하나, 답변 확인, 불확실성 재평가, 기록을 하나의 반복 절차로 묶는다.
엄격한 명세 종료 조건과 지속적 지도는 그 절차의 조건부 기능이다. 일반 티켓에 지도를 쓴다는 이유만으로
명세 수치 기준을 추가하지 않는다. 기존 `.decision-navigator/` 데이터·유형·상태·원자적 잠금은 유효하다.

| 자료 | 목적 |
|---|---|
| [후보 진입점](candidate/clarify-requirements/SKILL.md) | 실행할 영어 절차. 옆의 한국어 미러는 사람이 읽는 자료다. |
| [요구사항 대응](coverage.md) | 기존 두 계약과 합의한 통합 요구를 후보 파일·평가 사례에 연결한다. |
| [검증 기록](verification.md) | 완료한 검사, 제한된 실제 실행 관측, 남은 전환 조건을 확인한다. |
| [남은 작업](remaining-work.ko.md) | 열린 작업, 선행 조건, 완료 근거, 이후 교체 절차를 추적한다. |
| [시험 기록](trial-results.json) | 소스 해시, 개별 실행, 실제 사용량, 진단 중 실패를 확인한다. |

## 로컬 사용과 검사

저장소 루트에서 후보를 검증하고 결정적 검사를 실행한다.

```bash
python3 skills/skill-builder/scripts/quick_validate.py .plan/clarify-requirements-2026-09-26/candidate/clarify-requirements
python3 -m pytest .plan/clarify-requirements-2026-09-26/candidate/clarify-requirements/tests
```

시험은 일회용 파일 복사본에서 하고 실제 주 세션에 그 복사본의 SKILL.md를 명시한다.
평가를 위해 실제 사용자 스킬 디렉터리에 설치하지 않는다. 지도 입력도 시험 공간에 복사하며 저장소에
있는 원본 평가 티켓을 해결하거나 잠그지 않는다. 패키징 도구로 후보 밖에 `.skill` 파일을 만들 수 있다.
기존 패키징 계약의 제외 규칙에 따라 일반 실행에 불필요한 평가 산출물 등이 패키지에서 제외된다.

재현 가능한 비대화형 비교는 baseline.json의 커밋을 임시 디렉터리에 내보낸 다음 절대 경로로 실행한다.
출력 디렉터리는 비어 있어야 한다.

```bash
python3 .plan/clarify-requirements-2026-09-26/run_readonly_trials.py \
  --baseline-root <exported-baseline> \
  --candidate <absolute-candidate-directory> \
  --output-dir <empty-temporary-directory> --case frontier --pairs 3
```

다른 읽기 전용 사례는 `missing-scoring`이다. 실행기는 양쪽 지침과 참조를 고정하고 순서를 번갈아 실행하며
사용량·실제 명령 수·실패·경과 시간을 기록한다. 정확히 `gpt-5.6-luna`, `xhigh`를 요청한다.
확인된 모델 정보가 없으면 null로 남긴다. 이 실행은 실제 질문 UI·쓰기·사람 확인·설치 플러그인 탐색을
검사하지 않는다. 원본 대화 기록은 임시 작업 공간에 남긴다. 요약에서는 요청한 설정과 관측한 근거를 구분한다.

## 실제 질문 UI 평가

기존 어댑터는 Claude Code의 Sonnet 5/high와 Codex의 gpt-5.6-luna/xhigh를 요구한다.
Codex에서 Sonnet을 실행하는 것은 금지한다. Claude 시험은 Claude Code에서 시작하고 두 호스트 모두
실제 주 세션을 사용한다. Codex 엄격한 인터뷰는 ask-ui.md에 따라 Plan 모드를 쓴다.
운영자를 에이전트로 대체하거나 일반 텍스트 모의를 실제 UI 검증으로 세지 않는다.

엄격한 인터뷰에는 후보 사례 1–13과 운영자 안내서를 사용하고, 지도 사람 참여 사례는 14–20이다.
운영자는 답변 안내서를 모델 입력에 넣지 않고 질문이 나올 때만 답한다. 질문 순서가 달라지면 관련 없는
예정 답변을 주입하지 말고 실제 질문과 답변의 대응을 기록한다. 사람의 응답 대기 시간을 보존하고 비교가
불가능한 시간은 따로 표시한다. 양쪽 입력·권한·수용 기준·모델·effort를 같게 하고, 관련 사례마다 시작 전에
세 쌍의 예산을 고정한다. 원본과 후보의 참조 경로를 분리한다.

## 기본 스킬 전환 조건과 이행

후보 준비만으로 대상 모델의 품질이나 실행 비용 동등성이 입증되지는 않는다. 전환에는 합의된 실제
호스트, 필수 사람 참여 사례, 모든 중요 기준 보존, 충분한 전체 시간·사용량 근거가 필요하다.
근거가 없으면 성공이 아니며 잡음이 크거나 불완전한 비교로 채택하지 않는다.

조건을 통과하면 `skills/clarify-requirements/`로 전환한다. 기존 두 등록 디렉터리를 함께 없애고 README와
호스트 메타데이터를 새 이름 하나로 옮긴다. 독립적으로 유지하는 절차 세 개를 만들지 않는다.
기존 지도 저장 경로와 잠금 도우미 계약을 유지한다. `tests/test_korean_mirrors.py`의 고정 평가 경로도
갱신하고 이동한 스킬 검사·평가를 유지한다. 과거 기록의 원본 링크는 옛 디렉터리를 없앨 때 고정 커밋을 가리킨다.

AGENTS.md에 따라 스킬 통합은 minor 변경이다. 전환 시 최신 공개 릴리스를 확인하고 다음 minor 하나를
정한다. 두 플러그인 매니페스트·pyproject.toml·uv.lock을 일치시킨다. 후보 반복마다 버전을 올리지 않는다.
전달 전에 README의 모든 개발 검사와 필요한 플러그인 검증을 실행한다. 이후 릴리스나 실제 세션 새로고침은
각 작업에 대한 별도 권한을 따른다.
