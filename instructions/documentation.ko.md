# 문서 파일

> 영어 원본: [documentation.md](documentation.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

사용자가 기술 설계 문서, 아키텍처 제안서, RFC, 시스템 설계, 데이터 설계, API 설계 또는 설계 개요를 명시적으로
요청하거나 스킬을 직접 호출했을 때만
[기술 설계 문서 작성](../skills/technical-design-writer/SKILL.ko.md)을 사용한다. 새 문서와 개선 작업은 설계 문서 절차와
공통 독립 모델 검증 규칙을 함께 적용한다. 일반 문서에는 이 스킬을 불러오거나 실행하지 않는다.

일반 문서에는 다음 작성 규칙을 직접 적용한다.

- 고등학생이 이해할 수 있게 쓴다. 기본적인 개발 용어는 사용할 수 있다. 구체적인 주어와 동사를 사용하고,
  한 문장에는 하나의 주장만, 한 문단에는 하나의 중심 생각만 둔다.
- 세션 지침의 용어 선택 순서를 따른다. 정확한 식별자와 계약 이름을 보존하고, 한 의미에는 한 용어만 사용한다.
- 한국어 표현은 문맥, 독자, 장르, 프로젝트의 기존 용례와 자연스러운 어울림을 기준으로 고른다. 익숙한 외래어나 널리
  쓰이는 표현을 더 순수하거나 쉽다는 이유만으로 기계적으로 바꾸지 않는다. 예시는 판단 근거일 뿐 문서 전체에 적용할
  치환표가 아니다.
- 페이지마다 독자 목표 하나를, 섹션마다 책임 하나를 둔다. 제목은 최대 3단계까지 사용한다. 표, URL, 코드, 정확한
  문자열을 제외한 Markdown 본문 줄은 120자 안으로 쓴다.
- 공통 필드가 있는 비교 대상이 3개 이상이면 표를 사용한다. 복잡한 분기, 상태 변화, 상호작용, 경계, 의존성 또는
  데이터 관계가 더 분명해질 때만 다이어그램을 사용한다.
- 주제마다 상세 원본을 하나만 둔다. 문서 경로와 제목으로 안정적으로 참조하고 모든 링크와 제목을 확인한다.

채팅 답변에는 공통 지침의 용어와 답변 형식 규칙만 적용한다.
