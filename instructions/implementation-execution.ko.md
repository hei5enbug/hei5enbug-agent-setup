# 구현 실행

> 영어 원본: [implementation-execution.md](implementation-execution.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

구현은 합의한 변경을 실현하려고 코드, 테스트, 설정, 스크립트, 스킬, 지침, 문서를 바꾸는 작업이다. 통합 중에 생긴
수정도 포함한다. 메인 세션은 조정자다. 요구사항, 조사, 계획, 설계, 검토, 결정과 최종 보고를 맡는다. 사용자가
요청한 계획 문서나 설계 문서 작성도 메인 세션에 남는다. 세션의 위임 규칙에 따라 메인 또는 worker를 담당자로
정한다. 메인이 구현할 수 있으며 같은 수용 검사를 적용한다.

높은 수준의 추론, 요구사항 확인, 권한 결정은 여전히 세션 규칙이 관리한다. worker 도구, 고정 모델, 설정 근거는
현재 호스트의 에이전트 규칙이 관리한다. 할당받은 worker는 작업에 다른 섹션이 필요하지 않으면 아래 "할당받은 worker"
섹션만 읽는다.

## 작업 준비

첫 구현 변경 전에 모든 변경에 대해 실행할 수 있는 작업 할당을 갖춘다.
본격적인 작업의 필수 결과, 선택 후속 작업, 종료 조건, 검사 근거 재사용에는
[작업 효율](work-efficiency.ko.md)을 적용한다. 기존 배정에 이 항목을 함께 기록한다.

| 시작 조건 | 필요한 조치 |
|---|---|
| 완성된 기존 계획 | 범위, 선행 조건, worker 할당을 현재 근거와 대조해 확인하고 바뀌지 않은 부분은 그대로 쓴다. |
| 실행 세부 사항이 빠진 계획 | 수정 전에 담당 범위, 의존성, 병렬 조건, 모델과 사고 강도 정책, 검사를 채운다. 합의한 설계는 유지한다. |
| 계획 없음 | 세션 고유의 작업 관리 기능이나 대화에서 간단한 실행 계획을 준비한다. 요청이 없으면 계획 디렉터리를 만들지 않는다. |
| 결과에 영향을 주는 요구사항이나 설계 결정이 미결 | 작업을 배정하기 전에 메인 세션에서 요구사항 확인 규칙에 따라 조사하고 결정한다. |
| 이미 할당받은 worker | 아래 "할당받은 worker"를 따른다. 빠진 결정이나 충돌은 조정자에게 보고하고, 다른 계획 절차를 시작하지 않는다. |

이 준비는 사용자가 요청한 구현 계획이 아니다. 계획이나 설계 스킬, 6단계 계획 절차, 독립 검증을 실행하지 않는다.

담당 범위를 분명히 나누는 최소 개수의 작업을 준비한다. 하나로 묶인 작업은 담당자 하나가 맡는다. worker 6개는 목표가
아니라 상한이다. 자리를 채우려고 작업을 쪼개거나 관련 없는 읽기 작업을 묶지 않는다.

언제든 요청이나 합의한 계획의 범위 밖에 있는 추적 파일을 바꾸는 작업을 할당하기 전에 사용자에게 묻는다. 어떤 작업도
수정할 수 없는 공유 파일이 그 예다. 답을 기다리고, 승인 없이는 그런 변경을 하지 않는다.

## 할당 항목

각 할당에는 다음을 적는다.

- 작업 ID와 구체적인 결과
- 수정 허용 경로와 보호 경로
- 선행 조건과 공유 자원 제외 대상
- 검증 방법과 완료 근거
- 선택한 모델 ID와 사고 강도

메인 담당 작업은 이 항목을 간결하게 기록하고 메인 세션의 현재 모델과 사고 강도를 유지한다.
작업자 모델 확인과 준비 확인 호출은 위임할 때만 적용하며, 직접 작업에서는 수행하지 않는다.

worker에게 할당할 때는 할당받은 worker라는 사실, 다른 worker가 같은 작업 공간을 수정하고 있을 수 있다는 사실, 그 변경을 보존해야
한다는 사실을 알린다. 저장소 실행 계획은 이 항목을 한 번만 기록한다. 각 worker 프롬프트에는 자기 작업과 그 작업에
필요한 맥락만 담는다.

## 일정 관리

각 작업은 호스트의 기존 작업 관리 기능이나 대화에서 `pending`, `running`, `done`, `blocked` 중 하나로 추적한다.
영구 작업 데이터베이스는 추가하지 않는다. 선행 조건이 조정자의 인수 확인을 통과하고 수정 경로와 자원이 비어 있을
때만 작업이 준비 상태가 된다. 인수 확인을 통과하려면 작업에 할당된 검증이 통과해야 한다. 작업과 그 선행 작업을 한 할당에
넣지 않는다. 파일만 공유하는 작업은 worker 하나에게
순서대로 맡길 수 있다.

추가로 시작할 worker 수는 `min(6 - 실행 중인 구현 worker 수, 남은 호스트 자리, 준비된 독립 작업 수)` 이하로 한다.
호스트가 실제로 정의한 한도와 남은 자리를 기준으로 한다. 이 한도에는 메인 세션이나 다른 에이전트가 포함될 수 있다.
예를 들어 메인 세션을 포함해 에이전트 4개가 한도라면 worker는 최대 3개다.

준비된 독립 작업은 함께 시작한다. 일곱 번째 작업처럼 넘치는 작업은 대기열에 두고, 자리와 자원이 비면 배정한다.
호스트 한도를 올려 달라고 요청하지 않는다.

담당 범위가 충돌하는 작업은 절대 겹쳐 실행하지 않는다. 공유 파일, 잠금 파일, 생성 결과물, 데이터베이스, 포트,
빌드 디렉터리를 쓰는 작업은 계획이 작업마다 독립 자원을 제공하지 않는 한 순서대로 실행한다. 수정하는 파일이
다르다는 사실만으로는 독립성이 입증되지 않는다.

## 검토와 통합

작업자 결과의 수용과 통합 검사 선택에는 [검사 근거 규칙](work-efficiency.ko.md#검사-근거)을 적용한다.
담당자가 바뀌었다는 이유만으로 작업자의 유효한 검사 결과를 다시 실행하지 않는다.

의존 작업을 풀기 전에 각 worker가 반환한 변경과 근거를 검토한다. 작업을 수정한 모든 턴의 호스트 기록이 선택한 모델과
사고 강도를 보여 줄 때만 위임한 작업을 승인한다. 메인 세션은 직접 수행한 작업을 포함한 모든 작업의 범위, 정확성, 회귀와
검사 근거를 확인한다. 자신이 담당한 경로의 통합 수정은 직접 할 수 있다. 다른 담당자가 있으면 worker가 멈춘 뒤
담당 범위를 넘겨받는다. 추적 파일을 바꾸는 검사는 구현 작업이므로 담당자가 필요하다.
worker가 입력이나 출력 디렉터리를 바꾸는 동안에는 공유 빌드를 실행하지 않는다.

## 실패와 복구

실패하면 의존 작업을 보류하고 완료된 작업을 보존한다. 할당된 검사가 실패하면 원인이 작업 밖에 있어도 실패로 본다.
원인 진단과 수정 방향은 메인 세션에서 정한다. 이전 담당자가
멈춘 뒤에만 worker를 재개하거나 교체하고, 새 담당자에게 현재 diff와 수정한 작업을 준다.

위임에 실패하면 세션의 대체 처리 규칙을 적용한다. 해당 worker를 멈춘 뒤 담당 범위를 넘겨받고, 부분 diff를 확인한 다음
남은 승인 작업을 메인 세션에서 계속한다. 검증되지 않은 작업자 결과를 완료로 승인하지 않는다. 입력이 바뀌지 않은 검사는
결과를 재사용한다. 이미 확인한 사용량 한도나 기능 실패를 반복 재시도하지 않고, 상태가 바뀐 근거가 있을 때만 재검토한다.
대체 처리는 빠진 사용자 결정, 권한 제한 또는 실패한 수용 검사를 우회하지 않는다.

## 모델과 사고 강도

위임한 구현은 호스트 에이전트 규칙이 고정한 모델 ID와 사고 강도를 사용한다. 실행 중에 새 릴리스를 찾거나 제공자 별칭을
따르거나 다른 작업자 모델로 바꾸지 않는다. 고정값은 저장소를 수정할 때 갱신한다. 고정 모델이나 사고 강도를 쓸 수 없으면 다른 모델을 고르지 말고
세션의 대체 처리 규칙을 적용한다.

고정 모델 ID와 사고 강도를 각 worker 할당에 기록하고 그 실행 동안 재사용한다.

관련 있는 비밀이 아닌 설정 항목만 살펴본다. 요청한 설정만으로는 실제 적용된 설정의 근거가 되지 않는다. 최소
근거는 명시적인 호출이나 고정된 정의, 실제 모델을 기록한 호스트 기록, 호스트가 문서화한 설정 우선순위에 따라
실제 적용된 사고 강도다. 기능이 없거나, 예상하지 못한 재정의가 있거나, 실제 설정을 확인하지 못하면 영향을 받는
위임을 멈추되 승인된 메인 작업은 계속할 수 있다.

시작 시점 메타데이터가 부족하면, 호스트가 같은 worker에게 후속 메시지를 보내면서 확인된 설정을 유지하거나 명시적으로
다시 적용할 수 있을 때만 준비 확인 전용 할당을 사용한다. 호스트 기록을 확인한 뒤 구현 할당을 보낸다. 이런 이어 보내기나
믿을 수 있는 설정 근거가 없으면 이 경로 대신 세션의 대체 처리 규칙을 적용한다. worker가 근거 없이 스스로 보고한 내용은
호스트 근거를 대신하지 못한다.

재개, 재정의 변경, 대체 경고, 호스트 설정 변경이 있으면 다시 확인한다. 불일치하면 해당 worker를 멈춘다. 입력이 바뀌지
않은 동안에는 확인한 설정을 재사용하고, 수정할 때마다 준비 확인 호출을 반복하지 않는다.

## 할당받은 worker

할당받은 worker는 자기 작업을 직접 실행하며 조정자 역할을 하지 않는다.

- 계획을 준비하거나, 계획이나 설계 절차를 시작하거나, 계획 검토나 독립 검증을 요청하거나, 다른 에이전트를 시작하지
  않는다.
- 수정 허용 경로만 수정하고 보호 경로는 건드리지 않으며 다른 worker의 변경을 보존한다.
- 범위를 넓히거나, 새 설계를 고르거나, 모델이나 사고 강도를 바꾸지 않는다. 빠진 결정이나 충돌하는 변경은 직접
  해결하지 말고 조정자에게 보고한다.
- 할당받은 검사만 할당에 적힌 격리 옵션으로 실행한다.
- 준비 확인 전용 할당이면 아무것도 수정하지 않고 준비 상태를 보고한다.
- 변경한 경로, 검사 결과, 남은 차단 요인을 반환한다.
