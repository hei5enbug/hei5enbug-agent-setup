# 작업 효율

영어 원본: [work-efficiency.md](work-efficiency.md).
이 문서는 사람이 읽는 비권위 한국어 번역본이며 실행 지침으로 사용하지 않는다.

본격적인 구현, 반복 모델 평가, 플러그인 관리, 반복 실행 실패 진단에 적용한다.
짧은 답변과 경로를 아는 파일 조회에는 추가 절차가 필요 없다.
세션의 위임 정책과 기존 구현 배정을 사용하고 스케줄러나 작업 데이터베이스를 추가하지 않는다.

## 범위와 완료

필수 결과, 필수 근거, 선택 후속 작업, 담당자, 종료 조건을 기존 작업 관리 기능이나 대화에 기록한다.
사용자가 새 작업을 요청하면 범위를 수정한다. 새 결함은 요청 결과나 필수 검증을 막을 때만 포함하고,
그렇지 않으면 후속 작업으로 보고한다.

독립적으로 검토할 수 있는 동작은 담당자 한 명에게 묶어서 맡긴다.
같은 변경의 읽기·수정·테스트·문서화마다 다른 작업자를 배정하지 않는다. 실제 선행 작업의 수용 경계는 유지한다.
요구사항·의존성·결함·인수인계가 바뀔 때 작업자에게 알린다. 반복 상태 조회보다 완료 알림이나 호스트 대기 기능을 우선한다.
사용자에게 필요한 진행 안내는 계속하되, 안내만을 위해 로그나 작업자 상태를 다시 조회하지 않는다.

15분 동안 새로 수용한 결과나 조치 가능한 근거가 없으면 접근 방식을 한 번 재평가하고,
막힌 원인과 범위가 정해진 다음 행동을 알린다. 생산적인 구현은 단지 오래 걸린다는 이유로 중단하지 않는다.
필수 결과와 검사가 수용되면 끝낸다. 구현한 동작, 검증한 동작, 남은 제한을 구분해 보고한다.
선택 후속 작업이나 선택적인 독립 리뷰 미실행 때문에 수용된 구현을 미완료로 남기지 않는다.
기존 독립 리뷰 승인 계약은 유지한다.

## 검사 근거

지침을 읽을 때는 현재 컨텍스트에 남아 있고 바뀌지 않은 내용을 재사용한다. 관련 입력이 바뀌거나 필요한 내용이
더 이상 컨텍스트에 없으면 해당 원본을 다시 읽는다. 새 에이전트·재시작·압축만으로 이전 내용이 남아 있다고
판단하지 않는다. 필수 시작 지침 읽기는 유지하고 선택한 작업의 참조만 따른다. 전역적으로 다시 읽지 않는
캐시는 만들지 않는다.

각 검사의 범위, 명령, 결과, 관련 입력·환경 상태를 간결하게 기록한다.
같은 검사를 반복하지 않고 유효한 작업자 근거를 받아들인다. 검사 대상 소스·의존성·픽스처·설정·도구 버전이
바뀌지 않았을 때만 결과를 재사용한다. 입력이 바뀌면 관련 결과를 무효화한다.
검사 범위가 불확실하면 필요한 검사를 다시 실행하며 통과로 가정하지 않는다.

구현 중에는 배정된 좁은 검사를, 통합 후에는 필요한 통합 검사를 실행한다.
확인된 실패나 남은 위험 때문에 필요한 경우 검사 범위를 넓힌다. 저장소가 요구하는 릴리스 검사는 유지한다.
원인이 배정된 변경 밖에 있어도 필수 검사 실패는 실패다.

## 모델 평가

추가 모델 시험과 벤치마크에 적용한다. 일반 구현, 단위 테스트, 필요한 빌드,
별도 계약을 따르는 독립 마무리 리뷰에는 적용하지 않는다. 현재 평가의 실행 권한은 재사용한다.
종료한 실험과 당시 예산은 새 실험의 실행 권한이 아니다.

시작 전에 판단할 질문, 확정한 사례·기준, 실행기 설정, 시험 예산, 중단 사유를 적는다.
경계 사례를 포함한 대표 사례 최대 3개와 묶음 전체 기한 15분을 기본값으로 한다.
쌍 비교는 각 방식을 1회씩 실행하므로 모든 호스트를 합쳐 최상위 시험 시작 최대 6회이며 재시도도 포함한다.
재개·호스트 전환·작업자가 같은 횟수와 기한을 공유하고 묵시적으로 초기화하지 않는다.

실제 CLI 호출, 자격 증명을 노출하지 않는 인증 가능 여부, 제공되는 사용량 한도, 픽스처 의존성, 출력 파싱을 확인한다.
승인된 작은 시험 1건을 품질 검사·사용량 기록까지 끝낸 후 확대한다. 이 시험도 예산에 포함한다.
측정한 시간으로 다음 묶음 전에 경과 시간과 남은 작업의 예상 범위를 알린다.
실제 경과 시간, 병렬 작업자 시간, 일부만 보고된 토큰을 구분한다.
달러 비용을 지어내거나 알 수 없는 사용량 한도가 충분하다고 가정하지 않는다.

추가 사례로 답할 수 있는 미해결 판단이 있고 명시적으로 승인된 더 큰 예산 안에 있을 때만 확대한다.
그렇지 않으면 결론 미확정으로 보고하고 필요할 때만 구체적인 확대안을 요청한다. 최대 예산은 목표가 아니다.
사례·호출·시간 상한, 사용자 중단, 필수 기능 미지원, 확인된 사용량 소진, 잘못된 계측 환경 중 먼저 발생한 조건에서
새 실행을 멈춘다. 유효한 부분 근거를 보존한다. 실행 환경 실패는 품질 실패도 통과도 아니다.

하위 프로세스 시험은 기존 기능으로 남은 묶음 시간 이하의 타임아웃을 설정하고 소유한 시험 프로세스만 정리한다.
안전한 중단을 지원하지 않으면 새 실행을 멈추고 대기 중인 호출과 시간 초과 가능성을 알린다.
지침은 엄격한 타임아웃을 강제할 수 없다. 근거가 바뀌거나 확대가 명시적으로 승인됐을 때만 중단한 묶음을 다시 열고,
이전 측정값은 지우지 않는다.

## 실패와 플러그인 관리

재시도 전에 실패를 분류한다. 실행 파일·훅 파일 누락, 기능 거부, 권한 경계, 확인된 사용량 한도 소진은
같은 재시도 대신 조건 변경이나 승인된 작동 경로가 필요하다.
일시 오류로 보이는 경우 동일 조건 재시도는 최대 1회다. 다시 실패하면 진단하고,
입력·환경·서비스 상태가 바뀌었다는 근거를 확보한 뒤 시도한다. 서비스 접근은 기존 경로별 대체 규칙을 따른다.

플러그인 훅 경로가 없으면 해당 훅에 의존하는 작업을 멈추고 구체적인 원인을 알린다.
훅 항목 삭제, 가짜 성공 반환, 신뢰 완화, 다른 버전을 이전 디렉터리에 복사하는 조치는 금지한다.
필요한 승인을 받아 검증된 동일 버전을 복구하거나 호스트가 지원하는 새 세션 경로를 사용한다.
호스트의 Stop 반복을 제어할 수 없으면 외부 복구 단계를 알린다.
누락된 스크립트나 지침이 호스트 자체의 반복을 끝낼 수 있다고 보장하지 않는다.

활성 코딩 에이전트 세션에서 캐시를 교체하는 플러그인 업데이트를 시작하지 않는다.
입력 대기 상태도 살아 있는 세션이다. 영향받는 세션을 종료한 뒤 갱신기의 명시적인 오프라인 경계를 사용하거나,
이미 설치된 버전을 반영한다. 업데이트 보류 시 설치 파일과 보안 검사 동작을 유지한다.
수동 업데이트나 다른 프로세스의 로드된 디렉터리 삭제는 통제하지 못한다.
