# 호스팅 서비스 접근

> 영어 원본: [services.md](services.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

Google Drive, Docs, Slides, Sheets, Atlassian, Azure DevOps, Figma, Slack, Notion과 다른 호스팅
콘텐츠에는 해당 서비스의 MCP 도구를 우선 사용한다. 익명 요청에는 사용자 세션이 없으므로 비공개 링크는
HTTP 401로 실패할 수 있다. 실제 공개 페이지이거나 해당 호스트를 다루는 MCP 서버가 없을 때만 직접 가져온다.

## 접근 대체 경로

접근 경로 하나가 실패해도 서비스를 사용할 수 없다고 판단하지 않는다. 경로가 실패하면 서비스를 사용할 수 없다고
보고하기 전에, 현재 세션에서 사용할 수 있는 다른 경로를 하나씩 모두 시도한다.

1. 해당 서비스의 MCP 도구. 먼저 검색하거나 로드해야 하는 지연 도구와, 같은 서비스를 다루는 다른 연결된 서버를
   포함한다.
2. 해당 서비스의 설치되고 인증된 CLI. `command -v`와 CLI 자체의 도움말 또는 인증 상태 명령으로 확인한다.
3. 자격 증명을 숨긴 채 사용하는 인증된 CLI나 클라이언트(예: CLI의 범용 API 명령)를 통한 서비스의 REST API
4. 호스트가 제공하는 경우 인증된 브라우저 세션

현재 경로가 없거나, 연결이 끊겼거나, 인증되지 않았거나, 시간 초과가 났거나, 필요한 작업이나 필드를 지원하지
않으면 다음 경로를 시도한다. 한 경로의 not-found 또는 권한 오류는 다른 경로가 확인해 줄 때까지 그 경로의
실패로 취급한다. 각 경로는 한 번씩 시도하고, 일시적 오류에는 한 번 더 재시도한다. 사용자가 거절했거나, 승인
게이트가 충족되지 않았거나, 사용 가능한 모든 경로가 실패하면 전환을 멈춘다.

모든 경로에서 같은 범위, 승인, 검증을 유지한다. 사용자의 계정이 아닌 다른 계정으로 작업하지 않으며, 경로를
동작시키려고 자격 증명을 출력하거나 기록하거나 전달하지 않는다. 다른 경로로 쓰기를 재시도하기 전에 대상을 다시
읽어 앞선 시도가 반영되지 않았음을 확인해, 쓰기가 두 번 일어나지 않게 한다.

성공한 경로와 실패한 각 경로 및 그 사유를 보고한다. 사용 가능한 모든 경로가 실패한 뒤에만 서비스를 사용할 수
없다고 보고한다.

## 브라우저 담당자

실제로 공유하는 제어 자원마다 담당자 한 명을 둔다. 도구가 탭을 정확히 지정하면 탭 단위,
전역 포커스를 바꾸면 브라우저·창 전체 단위로 정한다. 탭이 다르다고 마우스·키보드 입력이 독립적이지는 않다.
기존 작업 관리 기능으로 조정하고 브라우저 프레임워크나 상주 잠금 서비스를 추가하지 않는다.

승인된 MCP·API 경로를 우선한다. 브라우저가 필요하면 쓰기 전에 대상 탭·URL·계정·작업을 식별하고,
매번 쓰기 직전에 대상을 다시 확인한다. 탭·계정·입력이 예상과 다르게 바뀌면 쓰기를 멈추고 사용자 입력을 보존한 채
담당 관계를 한 번 조정한다. 다른 세션과 경쟁하며 탭 전환이나 클릭을 반복하지 않는다.
쓰기 결과가 불확실하면 재시도 전에 결과를 읽는다. 승인·제출 경계를 유지하며 신청서 작성 요청을 제출 권한으로 보지 않는다.
