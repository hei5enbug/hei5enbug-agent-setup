# 구현 계획

> 영어 원본: [implementation-planning.md](implementation-planning.md)
>
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트는 실행 중 이 문서를 읽거나 사용하지 않는다.

영문 `implementation-planning.md`를 실행 기준으로 사용한다.

사용자가 구현 계획을 명시적으로 요청한 경우에만 이 지침을 적용한다. 구현 계획은 실행자가 설계를 추가하지 않고 요청한
변경을 구현할 수 있게 해야 한다. 의도와 범위를 확정하고, 구체적인 변경 대상과 의존성을 찾고, 작업을 불필요하게
쪼개지 않으며, 위험에 맞는 검증 방법을 제시한다.

아래 6단계를 순서대로 모두 실행한다. 추론과 최종 결정은 메인 세션에서 담당한다. 독립 검토자는 완성된 초안을
확인하지만 결정을 내리거나 파일을 수정하지 않는다.

## 1. 의도와 범위 확정

구현 세부사항을 정하기 전에 요청과 신뢰할 수 있는 근거에서 다음 항목을 확정한다.

- 목표와 확인할 수 있는 결과
- 범위에 포함되는 동작과 결과물
- 목표가 아닌 항목
- 제약과 불변 조건
- 변경하면 안 되는 파일, 인터페이스, 데이터 또는 동작
- 인수 조건

실질적으로 다른 구현을 허용하는 미결 결정을 해소한다. 사용자가 포함했거나 요청한 결과가 인접 문제를 해결하지 않으면
작동할 수 없는 경우가 아니라면 범위를 넓히지 않는다.

## 2. 구현 계획 수립

확정한 범위를 만족하는 가장 작은 구현 전략을 선택한다. 근거로 식별할 수 있다면 변경해야 하는 모듈, 파일,
인터페이스, 스키마, 설정, 마이그레이션, 테스트를 구체적으로 적는다. 파일 편집 목록보다 동작과 계약의 변경을 먼저
설명한다. 의존성과 선행 결정을 실행 단계 안에 숨기지 않고 기록한다.

현재 요구사항이 없는 확장 지점, 필요성이 입증되지 않은 새 추상화, 관련 없는 리팩터링, 인수 조건에 필요하지 않은
의존성을 추가하지 않는다.

## 3. 실행 단위 구성

실행자에게 명확한 담당 범위와 검증 경계를 주는 최소 개수의 실행 단위를 만든다. 각 단위에는 결과, 변경 대상, 선행
조건, 완료 근거를 적는다. 파일, 변경 가능한 상태, 생성 결과 또는 빌드 자원을 공유하지 않을 때만 병렬 실행으로
표시한다. 나머지 의존 순서는 명시한다.

하나로 수행해야 할 변경을 관리 목적의 단계로 나누지 않는다. 실행 단위는 파일을 열거나 이름을 바꾸거나 조사하는 데서
끝나지 않고, 검토할 수 있는 동작, 계약, 마이그레이션 또는 검증 결과를 만들어야 한다.

## 4. 검증 계획 수립

모든 인수 조건과 주요 위험을 근거에 연결한다. 각 실행 단위의 결과를 입증하는 가장 좁은 검사를 정한 뒤, 실행 단위
사이의 동작을 확인하는 통합 검사를 정의한다. 호환성, 실패, 마이그레이션, 롤백, 보안, 성능 검사는 확정한 범위나
위험이 요구할 때만 포함한다. 좁은 단위 검사로 저장소 전체나 런타임 동작을 입증했다고 판단하지 않는다.

## 5. 계획 검증

완성된 초안에 [독립 모델 검증](independent-model-validation.ko.md)을 적용한다. 사용자 확인 게이트, 검토자에게
제공할 내용, 모델 선택, 검토 항목, 실행 범위, 실패 처리, 결과 보고는 공통 검증 지침에서 관리한다. 그 게이트를
통과하기 전에는 초안을 검토자에게 보내지 않는다.

## 6. 계획 확정

검증을 실행했다면 검토자의 모든 지적을 확정한 범위와 신뢰할 수 있는 근거에 대조한다. 근거가 있는 수정은 메인
세션에서 반영한다. 근거 없는 범위 확장은 거부하고, 근거만으로 해소할 수 없는 주요 지적은 미해결로 기록한다.
검토에서 제거한 과설계를 되살리지 않는다. 검증을 실행하지 않았다면 확정한 범위와 신뢰할 수 있는 근거만으로
확정한다.

실질적으로 다른 구현을 허용하는 미결 결정이 남아 있으면 계획을 확정하지 않고 사용자에게 묻는다. 그런 결정이 없으면
실행자가 설계를 추가하지 않고 수행할 수 있는 최소 계획으로 확정하고, 공통 검증 지침에 따라 결과를 알린다.

## 출력 템플릿

같은 계약을 유지할 수 있다면 저장소의 기존 템플릿에 맞게 제목을 바꾼다. 선택 항목은 자리 표시자로 채우지 않고
생략한다.

```markdown
# <결과 중심 제목>

## 의도와 범위

- 목표:
- 범위:
- 목표가 아닌 항목:
- 제약:
- 보호 대상:
- 인수 조건:

## 구현 전략

<선택한 동작과 계약 변경, 변경 대상, 의존성, 근거>

## 실행 단위

| 단위 | 결과와 변경 | 의존 대상 | 병렬 조건 | 검증 |
|---|---|---|---|---|

## 통합 검증

<실행 단위 전체의 인수 조건 및 위험 검증>

```

## 완료 검사

- 필요한 범위, 목표가 아닌 항목, 제약, 보호 대상, 인수 조건이 명시되어 있다.
- 모든 단계는 실행할 수 있고 위험에 맞는 완료 근거가 있다.
- 의존성과 순서가 정확하고 병렬로 표시한 작업에는 공유 변경이나 빌드 경합이 없다.
- 추측성 확장, 관련 없는 리팩터링, 과도한 의존성, 불필요한 실행 단위가 남아 있지 않다.
- 공통 독립 검증 규칙을 모두 지켰다.
- 실행자가 설계를 추가해야 하는 미결 결정이 남아 있지 않다.
