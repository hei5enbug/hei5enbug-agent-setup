# Claude Code 계획 및 에이전트

> 영어 원본: [claude-agents.md](claude-agents.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

[독립 모델 검증](independent-model-validation.ko.md)이 정한 검토자 호출은 아래 시점, 에이전트 선택, worker 규칙의 예외다.

## 내장 서브에이전트

- `general-purpose`, `Explore`, `Plan`, `claude`, fork를 포함한 내장 서브에이전트는 사용하지 않는다. 예외는
  `claude-code-guide`와 `statusline-setup`이며, 목적이 좁아 `scout`나 `worker`와 겹치지 않는다. 종류를 비우면
  `general-purpose`가 실행되므로 서브에이전트 종류를 항상 지정한다.
- 플러그인의 에이전트 차단 훅은 종류를 비운 호출과, 위 두 예외를 뺀 모든 내장 종류를 거부한다. 플러그인 에이전트나
  사용자·프로젝트·CLI·관리 설정이 제공하는 정의처럼 그 밖의 모든 종류는 통과시킨다. 호출이 거부되면 맞는 플러그인
  에이전트를 쓰거나 메인 대화에서 작업한다.

## 조사

- 세션의 위임 규칙이 선택한 범위가 한정된 조사에는 계획 중이든 실행 중이든 `hei5enbug-agent-setup:scout`를 사용한다.
- 각 `hei5enbug-agent-setup:scout`에 질문 하나와 좁은 검색 범위 하나를 지정한다.
- 결과에 파일 경로, 코드 심볼과 구체적인 근거를 요구한다.
- 결과를 단서로 취급한다. 계획하거나 결정하기 전에 핵심 주장을 메인 대화에서 확인한다.
- 플러그인이 `hei5enbug-agent-setup:scout`를 함께 설치한다. 사용할 수 없으면 메인 대화에서 조사한다.
- 모델은 scout 정의에 고정되어 있다. 호출 단위 모델은 정의보다 우선하므로 넘기지 않는다.

## 스킬 작업자

- 스킬이 검토 페르소나, 조사 티켓, 채점처럼 독립된 읽기 전용 작업자를 요구하면 `hei5enbug-agent-setup:scout`를
  사용하고 그 역할의 지시와 출력 계약을 전달한다. 역할이 만드는 파일은 메인 대화가 쓴다. 웹 접근이나 수정이 필요한
  역할은 메인 대화에서 수행한다.
- 스킬이 시험 출력을 쓰는 작업자를 요구하면 서브에이전트 대신 스킬이 고정한 모델과 사고 강도로 별도 `claude -p`
  프로세스를 실행한다.

## 구현

구현은 [구현 실행 규칙](implementation-execution.ko.md)에 따라 조정한다. 이 섹션은 Claude Code worker 연동만 덧붙인다.

- 구현을 위임할 때는 `hei5enbug-agent-setup:worker`만 사용한다. worker 정의에 `claude-sonnet-5-5`와 `high`가 고정되어 있다.
  호출 단위 모델은 정의보다 우선하므로 호출이나 재개할 때 넘기지 않는다. 다른 에이전트로 바꾸지 않는다.
- 실행에서 처음 호출하기 전에 환경 변수와 모든 설정 파일에서 비밀이 아닌 다음 입력만 살펴본다. worker 정의,
  `CLAUDE_CODE_SUBAGENT_MODEL`과 `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`,
  `CLAUDE_CODE_EFFORT_LEVEL` 같은 사고 강도 재정의, `maxEffortLevel`이나 조직 한도 같은 사고 강도 상한, 대체나 폴백
  경고다. 사용자 설정은 바꾸지 않는다.
- Claude Code는 세션 도중에 설정을 다시 읽을 수 있고, 강제된 서브에이전트 모델은 정의보다 우선한다.
  구현 작업을 담은 후속 메시지를 보낼 때마다 이 입력을 다시 확인한다.
- `/tasks`나 서브에이전트 transcript 같은 호스트의 서브에이전트 기록이 `claude-sonnet-5-5`를 실제 모델로, `high`를
  사고 강도로 기록하고 설정이 그 사고 강도를 낮출 수 없으면 근거로 인정한다. 제공자 내부의 추론 원격 측정은
  필요하지 않다. 기록된 모델이 다르거나, `high`보다 낮은 상한, 모순된 재정의, 알 수 없는 실제 우선순위가 있으면
  근거로 부족하다.
- 그 기록은 Claude 설정 디렉터리(`CLAUDE_CONFIG_DIR` 또는 `~/.claude`)의 `projects/<project>/` 아래 transcript에서
  읽는다. 세션 transcript의 시작 결과에 worker의 `agentId`와 `resolvedModel`이 있고,
  `<session-id>/subagents/agent-<agentId>.jsonl`의 각 assistant 항목에 `model`과 `effort`가 있다.
- 시작 결과에는 모델이 나오지 않으므로 각 worker는 준비 확인 전용 할당으로 시작한다. 기록 확인을 통과하면 같은
  worker에게 구현 할당을 보낸다. 이 경로는 그 후속 메시지가 고정 모델을 유지할 때만 사용한다. 이런 이어
  보내기를 쓸 수 없으면 두 단계 경로 대신 세션의 대체 처리 규칙을 적용한다. 재개한 뒤에는 설정을 다시 확인한다.
- 호스트 한도는 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`다. 실행 중인 서브에이전트는 세지만 메인 세션은 세지 않는다.
  현재 값과 남은 자리를 기준으로 하고 이 값을 바꾸지 않는다.
- 플러그인 worker나 서브에이전트 기록이 없으면 해당 위임을 멈추고 세션의 대체 처리 규칙을 적용한다.

## 공통 라우팅 추가 규칙

에이전트나 모델 runner를 호출하기 전에 [공유 모델 라우팅](model-routing.ko.md)을 읽으며
[작업 효율](work-efficiency.ko.md)의 지침 재사용 규칙을 따른다. 메인 모델·프로필 변경이나 세션 재개 후에는
호출 전에 해당 계약의 실제 설정 검사를 적용한다.

공개 조사는 `researcher` 역할과 공개 검색·가져오기 도구를 사용할 수 있을 때만 맡긴다. 호출 단위 모델은
전달하지 않는다. 역할 정의는 `claude-sonnet-5-5`와 `medium`으로 고정되어 있다. 결과를 신뢰하기 전에 역할
정의와 비밀이 아닌 실제 설정, 호스트의 서브에이전트 기록을 확인한다. 조건을 충족하지 못하면 메인 대화에서
계속한다.

Skill Builder 평가 참여자는 평가 어댑터의 필수 모델 표를 사용한다. 대상 스킬의 메타데이터나 frontmatter는
평가자 설정을 덮어쓰지 않는다. 실제 설정이 Skill Builder 표와 일치할 때만 scout를 쓴다. 일치하지 않으면
실제 모델과 사고 강도를 확인할 수 있는 Skill Builder 승인 runner를 쓰거나 기능 미지원 경로를 따른다.
요구 사고 강도를 낮추거나 운영 scout 설정을 바꾸지 않는다.

스킬 계약과 평가 설정이 researcher의 확인된 설정을 허용하고 공개 도구를 사용할 수 있을 때만 범위가 한정된
공개 조사를 맡긴다. 비공개·인증이 필요한 원격 접근과 모든 편집은 메인 대화에서 처리한다.

Claude Code에서 메인 모델을 GPT로 바꿔도 실행 호스트는 Claude Code로 유지된다. Claude Code의 도구, 권한,
역할 정의와 실행 규칙 및 worker의 고정 모델과 사고 강도를 계속 적용한다. 실제 위임 결과물의 작성 모델
계열에 따라 검토자를 선택한다. 실행 호스트로 검토자 계열을 추정하지 않는다.
