# 다이어그램

> 영어 원본: [diagrams.md](diagrams.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

다이어그램 원본을 텍스트로 게시하면 텍스트로 남는다. Confluence는 fenced 다이어그램 블록을 코드 블록으로
렌더링하므로 페이지에 넣기 전에 각 다이어그램을 이미지로 바꿔야 한다.

## 경로 결정

| 상황 | 경로 |
|---|---|
| 스페이스에 작동하는 다이어그램 매크로가 있고 사용자가 원본 유지를 원함 | 매크로를 사용하고 저장된 페이지에서 렌더링을 확인한다. |
| 매크로가 없거나 누군가에게 실패함 | 이미지로 렌더링해 첨부한다. |
| 헤드리스 브라우저가 없음 | 원본을 유지하고 렌더링이 남았다고 알린다. |

설치된 앱에 의존하는 다이어그램 매크로가 조직 전체에서 깨질 수 있으며 여기서 고칠 수 없다.
사용하기로 정하기 전에 렌더링을 확인한다. 실패하면 페이지가 끝났다고 알리지 않고 이미지로 전환한다.

## 이미지 렌더링

두 방식 모두 첨부 이미지로 끝난다.

**다이어그램 언어 렌더러.** 다이어그램 원본이 이미 있고 기본 모양으로 충분할 때 가장 빠르다.

**직접 만든 HTML·CSS.** `assets/diagram-template.html`에서 시작한다. 작성은 느리지만 간격, 레이블 위치와
색상을 제어하고 문서의 모든 다이어그램을 일관되게 만들 수 있다. 기본 렌더링이 답답하거나 레이블이 겹치거나
여러 다이어그램이 한 묶음처럼 보여야 할 때 사용한다.

두 방식 모두 `scripts/render_diagrams.mjs`로 결과를 캡처한다.

### 이름과 브라우저 플래그

- 각 다이어그램 요소의 `id`에는 문자, 숫자, `-`, `_`만 사용한다. ID가 이미지 파일 이름이 되며
  스크립트는 다른 문자를 발견하면 캡처 전에 거부한다.
- 같은 파일 이름을 만드는 요소가 둘이면 캡처 전에 실행을 중단한다. `--strip-prefix`는 ID 시작 부분에
  있는 접두사만 제거하므로 `--strip-prefix dia-`는 `mydia-x`를 바꾸지 않는다.
- 브라우저 샌드박스를 켠다. 샌드박스를 시작할 수 없는 컨테이너나 CI 이미지에서만 `--no-sandbox`를
  전달하고 보고서에 밝힌다.
- 캡처가 실패해도 브라우저를 닫으므로 남은 프로세스가 생기지 않는다.

## 중요한 설정

| 설정 | 이유 |
|---|---|
| 글꼴 목록 | 문서 언어의 글리프를 포함하는 글꼴을 고른다. 빠진 글리프는 경고 없이 빈 상자나 대체 모양이 된다. |
| 기기 배율 | 페이지가 이미지를 줄여도 텍스트가 선명하도록 1보다 크게 캡처한다. 2나 3이 적절하다. |
| 요소 캡처 | 주변 여백이 없도록 viewport가 아니라 다이어그램 요소를 캡처한다. |
| 명시적 요소 크기 | 캡처 컨테이너에 확정된 너비와 높이를 준다. 콘텐츠 기준 크기는 예측하지 못하게 줄거나 늘 수 있다. |

## 결과 확인

이 단계는 필수이며 스크립트로 대체할 수 없다.

렌더링된 이미지를 모두 열어 다음을 확인한다.

- 레이블끼리 또는 연결선과 겹침
- 요소 가장자리에서 잘린 텍스트
- 렌더링되지 않은 글리프
- 잘못된 위치에서 끝나는 연결선
- 그림 주변의 여백

크기 검사와 본문 검증으로는 이런 문제를 알 수 없으며 이미지를 봐야 한다.

호스트가 이미지를 표시하지 못하면 이를 알리고 게시 전에 사용자가 확인하도록 요청한다.
직접 보지 못한 이미지를 게시하지 않는다.

## 반복

원본을 고치고 다시 렌더링한 뒤 다시 본다. 같은 파일 이름으로 업로드해 첨부 파일에 새 버전을 추가하고
가로세로비가 바뀐 경우에만 본문의 `height`를 수정한다.

## 문서 전체의 일관성

한 문서에서 같은 도형 언어, 색 의미, 글꼴과 연결선 스타일을 유지한다.
독자는 시각 체계를 한 번만 학습한다.

템플릿 색은 시작점이다. 문서의 모든 다이어그램에서 같은 색이 같은 의미라면 어떤 일관된 색 구성도 사용할 수 있다.
