# 첨부 파일

> 영어 원본: [attachments.md](attachments.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

Confluence 페이지의 모든 이미지는 해당 페이지의 첨부 파일이다. 본문은 첨부 파일을 가리킬 뿐이다.

## 순서

먼저 업로드하고 나중에 참조한다. 아직 없는 첨부 파일을 본문에서 가리키면 깨진 자리 표시자로 보인다.
고치려면 다시 읽고 수정하고 저장해야 한다.

## 서로 다른 두 식별자

첨부 파일에는 서로 다른 식별자 두 개가 있다.

| 식별자 | 형태 | 용도 |
|---|---|---|
| 첨부 파일 ID | `att` 뒤에 숫자 | 삭제 같은 첨부 파일 관리 |
| 미디어 파일 ID | UUID | 본문의 미디어 노드가 요구하는 값 |

미디어 파일 ID 자리에 첨부 파일 ID를 써도 오류가 나지 않는다. Confluence가 식별자 문자열을 이름으로 한
빈 첨부 파일을 만들고 독자는 미리 보기 오류를 본다.

다운로드 URL로 참조하면 식별자를 고를 필요가 없다.

```
/wiki/download/attachments/PAGE_ID/FILENAME
```

특별히 미디어 노드가 필요하지 않으면 이 형식을 사용한다.

## 같은 이름은 새 버전

기존 이름으로 파일을 업로드하면 두 번째 첨부 파일이 아니라 해당 첨부 파일의 새 버전이 생긴다.
다운로드 URL은 바뀌지 않는다.

따라서 다이어그램을 다시 렌더링하기 쉽다. 이미지를 다시 만들고 같은 이름으로 업로드한 뒤 비율이 바뀐
경우에만 본문의 `height`를 수정한다.

## 제한될 수 있는 업로드 경로

업로드 도구가 시작 디렉터리 밖의 경로를 거부하면서 실제 원인이 아니라 경로 순회 오류를 표시할 수 있다.

이때 도구가 허용하는 디렉터리로 파일을 옮긴 뒤 다시 업로드한다. 버전 관리에서 무시하는 저장소 안의
준비 디렉터리를 사용하면 파일을 접근할 수 있으면서 저장소에 포함하지 않을 수 있다.
파일을 쓰기 전에 `git check-ignore`로 디렉터리가 무시되는지 확인한다.

그런 디렉터리가 없으면 추측하지 말고 파일을 둘 위치를 사용자에게 질문한다.

## 삭제 승인

삭제는 영구적이며 첨부 파일의 모든 버전을 제거한다.

삭제 전에 다음을 수행한다.

1. 삭제할 첨부 파일과 필요 없는 이유를 나열한다.
2. 본문에서 더 이상 참조하지 않는지 확인한다.
3. 명시적인 답을 기다린다.

사용자가 동의하지 않으면 실수 뒤 정리 목적으로도 첨부 파일을 삭제하지 않는다.
사용하지 않는 첨부 파일은 해가 없지만 참조 중인 파일을 삭제하면 문제가 생긴다.

## 업로드를 사용할 수 없을 때

호스트에 업로드 경로가 전혀 없으면 다음을 수행한다.

1. 파일을 한 디렉터리에 둔다.
2. 업로드 뒤 사용할 다운로드 URL로 본문을 작성한다.
3. 어느 페이지에 어떤 파일을 첨부해야 하는지와 본문이 해당 이름으로 준비됐음을 사용자에게 알린다.

이미지를 알리지 않고 생략하거나 다른 방식으로 인라인 처리하지 않는다.
