# 예약 알림 서비스 동작 방식

이 문서는 예약 알림 서비스가 예약 변경을 감지해 고객에게 알림을 보내는 방식을 설명한다.
운영자는 이 문서로 알림 지연과 발송 실패 지점을 찾는다.

## 1. 구성 요소

| 구성 요소 | 역할 |
|---|---|
| 변경 감지기 | 예약 시스템의 변경 이벤트를 1분마다 읽는다. |
| 알림 작성기 | 이벤트 종류와 고객 언어에 맞는 알림 문구를 만든다. |
| 발송기 | 문자와 이메일 발송 시스템에 알림을 보낸다. |

## 2. 처리 흐름

변경 감지기가 이벤트를 읽으면 알림 작성기가 문구를 만든다. 발송기는 그 문구를 고객이 선택한 채널로 보내고 발송 결과를 기록한다.

### 재시도

발송이 실패하면 발송기는 5분 간격으로 최대 3번 다시 보낸다.

## 3. 장애 대응

알림이 30분 넘게 오지 않으면 변경 감지기의 마지막 처리 시각부터 확인한다.
