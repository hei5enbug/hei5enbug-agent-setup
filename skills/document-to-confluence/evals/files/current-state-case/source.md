# 수집기 동작 방식

이 문서는 선사 스케줄 수집기가 VM에서 어떻게 기동되고 실행되는지 설명한다.

## 배포 위치

수집기는 Ubuntu VM 한 대에서 실행된다. 2026-09-16 기준으로 코드와 VM 설정을 확인해 이 문서를 작성했다.
수집기 프로세스는 systemd 사용자 유닛으로 등록되어 있어 VM이 재부팅되면 자동으로 다시 시작된다.

## 구성과 책임

| 구성 요소 | 설명 |
|---|---|
| 스케줄러 | cron이 매시 정각에 수집 작업을 시작한다. 작업 하나는 선사 하나의 항차 목록을 가져온다. |
| 스크래퍼 | 선사 사이트에 요청을 보내고 기항 일정을 파싱한다. 파싱 결과는 내부 API로 전송한다. |
| VPN 데몬 | VM에서 계속 실행되며 VPN 연결을 유지한다. 연결이 끊기면 스스로 다시 연결한다. |

## 수집 흐름

스크래퍼는 VPN 출구 IP로<br>요청을 보낸다. VPN이 끊기면 network lock이 VPN 밖으로 나가는 트래픽을 막는다.
그래서 사무실 IP가 선사 사이트에 노출되지 않는다.
2026-09-22 network lock 시험에서는 VPN을 강제로 끊고 5분 동안 외부 요청 120건을 보냈으며 차단률은 100%였다.

## 데이터 갱신

수집 결과는 서버의 스케줄 테이블에 항차 단위로 덮어쓴다. 오래된 항차는 삭제 배치가 매일 새벽 3시에 지운다.
삭제 배치는 2026-09-25 현재 전체 대상 3만 건 중 2만 1천 건을 지웠다.

## 장애 대응

VM이 부팅될 때 rc.local이 방화벽 규칙을 다시 적용한다.
방화벽 규칙이 없으면 network lock도 동작하지 않으므로, 재부팅 뒤에는 방화벽 규칙이 적용됐는지 먼저 확인한다.
