# 세션 회고

> 영어 원본: [SKILL.md](SKILL.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

한 저장소에서 하루 동안 진행한 Claude Code와 Codex 코딩 에이전트 세션 기록을 검토하고, 그 근거를 플러그인별로 묶어
기존 스킬의 구체적인 개선점과 새 스킬 후보로 바꾼다. 사용자가 "오늘 이 레포 세션 히스토리 보고 스킬 개선점 정리해줘"나
"review today's agent sessions for skill improvements"처럼 한 저장소의 하루 세션을 돌아보며 스킬이나 플러그인 개선점을
찾아 달라고 할 때, 그리고 이어서 남은 결정을 정리하거나 그 결과로 계획안을 써 달라고 할 때 사용한다. 대화 하나를
요약하거나, 실패 하나를 디버깅하거나, 코드를 리뷰할 때는 사용하지 않는다.

호스트의 세션 폴더를 읽을 수 있는 파일 시스템 권한과, 함께 들어 있는 목록 스크립트를 위한 Python 3.12 이상이 필요하다.
독립된 읽기 전용 작업자는 선택 사항이며, 없으면 메인 세션이 직접 세션을 읽는다.

이 영어 `SKILL.md`와 영어 참조 파일만 실행 원본으로 사용한다. `SKILL.ko.md`와 다른 `.ko.md` 파일은 사람을 위한 비권위
번역본이므로 실행 중에 절대 읽지 않는다.

하루 동안의 에이전트 세션에서 잘못됐거나 반복된 일을 찾고, 이를 근거가 있는 스킬 개선으로 바꾼다. 근거는 세션 기록에서
나오고, 개선 결정은 메인 세션이 내린다.

## 실행 위치

각 작업자 단계는 세션의 기능 경로로 실행한다. 담당이 메인 세션인 단계는 메인 세션이 직접 맡고, 사용자에게 묻고,
결과를 받아들인다.

| 단계 | 담당 |
|---|---|
| 1. 대상 확정 | 메인 세션 |
| 2. 세션 목록 | `investigation` |
| 3. 근거 수집 | `investigation` |
| 4. 원본 대조 | 메인 세션 |
| 5–7. 개선 표, 남은 결정 질문, 요청 시 계획 | 메인 세션 |

## 경계

- 세션 기록, 사용자 저장소, 설치된 플러그인은 절대 바꾸지 않는다.
- 작업자 지시문과 결과는 호스트의 세션 임시 폴더에만 쓴다. 호스트에 그런 폴더가 없으면 운영체제 임시 폴더 아래에 새
  폴더를 만든다.
- 저장소에는 7단계에서만, 그 저장소의 `.plan/` 폴더 아래에만 쓴다.
- 세션 기록에는 비밀 값과 비공개 대화가 있을 수 있다. 근거에 필요한 몇 단어만 인용하고, 인증 정보·토큰·개인 정보는 어떤
  결과물에도 옮기지 않는다.
- 호스트, 티켓 키, 사람처럼 한 조직에만 해당하는 내용은 이 스킬이 아니라 대상 저장소의 계획안에만 둔다.

## 작업 순서

### 1. 대상 확정

요청에서 날짜(기본값은 로컬 시간대의 오늘), 세션을 읽을 저장소(기본값은 현재 작업 디렉터리), 개선 대상 플러그인을 정한다.
여러 저장소가 보이는 상황에서 "이 레포"라고 하는 것처럼 요청이 모호하면 고른 해석을 밝힌다.

### 2. 세션 목록

이 `SKILL.md`가 있는 디렉터리를 기준으로 경로를 해석해 함께 들어 있는 스크립트를 실행한다.

```text
python3 scripts/list_sessions.py --date <YYYY-MM-DD> --cwd <repository path> [--tz <zone>] [--claude-dir <dir>] [--codex-dir <dir>]
```

스크립트는 `sessions`와 `skipped`가 든 JSON 객체 하나를 출력한다. 탐색을 마치면 0, 잘못된 인자면 2, 세션 폴더가 있지만
목록을 읽지 못하면 1로 끝난다. `--claude-dir`이나 `--codex-dir`은 사용자가 다른 세션 폴더를 지정할 때만 넘긴다.
`skipped` 항목은 모두 보고한다.

검토할 세션을 고른다.

- `source`가 `cli`처럼 대화형인 세션을 검토한다. `source`가 `subagent`인 Codex 세션은 `parent_session_id` 아래로 묶어
  하나로 검토한다.
- 작업자 실행기가 시작한 `exec` 세션 같은 자동 실행은 사용자가 요청하지 않으면 뺀다.
- 지금 진행 중인 세션은 기록 대신 대화 자체로 검토한다.

### 3. 근거 수집

고른 세션이나 묶음마다 읽기 전용 작업자 하나를 세션의 `investigation` 기능으로 실행하고, `references/scout-assignment.md`의
지시문을 준다. 그 기능 경로를 쓸 수 없으면 같은 지시문으로 메인 세션이 기록을 읽는다. 작업자는 근거만 돌려주며,
여섯 항목으로 나눈다: 사용자 요청, 정정·불만·반복 지시, 실패와 재시도, 스킬 사용, 반복된 수동 작업, 확인하지 못한 것.
개선안은 절대 내지 않는다.

작업자 결과를 받아들이기 전에 `investigation` 항목이 고정한 모델과 effort로 실행됐는지 확인한다. 작업자가 실패하면 그
기능의 대체 경로를 한 번 쓰고 대체 사실을 보고한다.

### 4. 원본 대조

스킬, 스크립트, 규칙의 결함을 주장하는 근거는 모두 설치된 플러그인 원본을 읽고, 원인이 되는 파일과 줄을 인용한다.
확인하지 못한 주장은 미확인으로 표시하고, 사용자가 달리 정하지 않으면 개선 항목에서 뺀다.

### 5. 개선 표 작성

결과는 사용자의 언어로 플러그인별로 묶어 보여 준다.

- 기존 스킬: 스킬마다 제목 하나를 두고, 어떻게 바꿀지만 짧은 불릿으로 적는다.
- 새 스킬: 플러그인, 가칭, 하는 일, 근거 세션, 기대 효과를 표로 적는다.

모든 항목에 근거 세션을 짧은 약칭으로 달고, 약칭은 작은 표로 한 번 정리한다. 마지막에 확인하지 못한 것을 적는다.

### 6. 남은 결정 질문

사용자만 정할 수 있는 것, 특히 서로 다른 세션의 요청끼리 충돌하거나 요청이 플러그인 규칙과 충돌하는 것을 모은다.
선택지와 함께, 권장안을 맨 앞에 두고 몇 개씩 묻는다. 답을 기다린 뒤 표를 갱신한다. 답이 새 결정을 낳을 때만 다시 묻는다.

### 7. 계획안 작성(요청 시)

사용자가 계획안을 요청하면 저장소마다 `<repository>/.plan/<설명적인 이름>/` 아래에 계획안 하나를 쓴다. 호스트에 구현
계획 규칙이 있으면 그 규칙을 따르고, 없으면 목표, 범위, 결정, 스킬별 변경, 테스트, 검증을 적는다. 저장소에 다른 것은
쓰지 않는다.

## 최종 보고

검토한 세션과 뺀 세션, 작업자의 모델 근거, 개선 표, 내린 결정, 7단계를 했다면 계획안 경로를 보고한다.
