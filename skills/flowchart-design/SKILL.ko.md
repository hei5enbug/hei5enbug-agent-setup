# 플로우차트 디자인 표준

> 영어 원본: [SKILL.md](SKILL.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

SVG, HTML/CSS, Figma, FigJam, draw.io, Mermaid, 래스터 산출물에 걸쳐 명확한 정적 흐름도를 설계, 수정,
검증하고 내보낸다. 플로우차트, 프로세스 맵, 아키텍처 흐름, 의사 결정 흐름, 다이어그램 체계 통일, 간격과
경로 복구, 겹침 제거, 접근성 있는 레이블, viewBox 조정, PNG 내보내기 교정에 사용한다. 의미 그래프와 도구별
렌더링을 분리하고 기능 기반 대체 경로를 사용해 여러 에이전트 호스트에서 동작한다.

의미와 레이아웃 절차는 모든 에이전트 호스트에서 동작한다. 편집 가능한 렌더링, 이미지 확인, 브라우저 측정,
내보내기에는 그에 맞는 호스트 기능이 필요하다. 그런 기능이 없어도 텍스트 명세 대체 경로를 쓸 수 있다.

영어 `SKILL.md`와 영어 참조 파일만 실행 원본으로 사용한다. `SKILL.ko.md`를 비롯한 `.ko.md` 파일은 비권위
인간용 번역본이며 실행 중에는 절대 불러오지 않는다.

서로 다른 도구(SVG, HTML/CSS, Figma, draw.io)로 만드는 정적 흐름도의 공통 명세다.
목표는 이 문서를 따르는 모든 도표가 같은 디자인 시스템에서 나온 것처럼 보이게 하는 것이다.
아래 규칙은 **절대값이 아니라 상대적 동작**을 규정한다.
노드 수, edge 기하, 도메인 의미는 도표마다 다르므로 구체적인 크기와 오프셋은 현재 작업에 맞게 고른다.
이 문서의 값을 베끼지 말고 **한 도표 묶음 안에서 일관되게** 적용한다.

이 표준은 프로젝트별 용어보다 레이아웃 원칙, 간격 규율, 레이블 규칙, 단순화 기준, 외곽 프레임 처리를
우선한다.

## 0. 이식 가능한 절차

호스트나 그리기 도구와 무관하게 같은 논리적 단계를 모두 수행한다.

### 0.1 기능 확인

제품 이름을 요구하지 않고 사용할 수 있는 가장 강력한 경로를 고른다.

1. **네이티브 편집 canvas**: 호스트가 다이어그램 노드와 연결선을 만들고 확인할 수 있을 때
2. **코드 기반 벡터**: 파일을 편집하고 렌더링할 수 있을 때. 기하가 결정적인 SVG를 우선한다
3. **다이어그램 DSL**: 텍스트에서 그림을 그리는 기능만 있을 때. 위상 구조에 사용하고, 시각 제어가 가능해지면
   내보내거나 다듬는다
4. **HTML/CSS**: 브라우저 렌더링이 가능하고 측정된 텍스트·레이아웃이 도움이 될 때
5. **텍스트 명세**: 렌더링 기능이 전혀 없을 때. 시각 검증을 한 것처럼 꾸미지 말고 의미 그래프, 레이아웃 계약,
   렌더러가 바로 쓸 수 있는 소스를 반환한다

병렬 실행, 이미지 확인, 브라우저 자동화는 검증을 개선하지만 선택 사항이다. 없는 기능은 정확히 보고해야 하며
의미 그래프를 바꿔서는 안 된다.

### 0.2 의미 그래프 먼저 만들기

좌표를 정하기 전에 원본을 다음으로 정규화한다.

- 안정적인 ID, 간결한 레이블, 역할, 선택적 상세를 가진 노드
- 출발, 도착, 결과 레이블, edge 유형을 가진 방향 edge
- 결과를 구별할 수 있는 분기
- 실제 소유나 단계 경계를 나타내는 group
- 명시적인 시작·종료 지점과 외부 시스템
- 의도한 주 읽기 방향

고아 노드, 중복 ID, 끊어진 edge, 선형 흐름으로 표현된 순환, 결과를 구별하지 못하는 분기 레이블은 거부하거나
해결한다.
업무 의미가 모호하면 시각적으로 옮기기 전에 질문한다.

### 0.3 레이아웃 계약 선택

8절에서 pattern 하나를 고르고 읽기 방향, 노드 rank, group 중첩, edge 경로 정책, token 집합, 레이블 문법,
대상 형식, 편집 가능성 요구를 명시한다.

자동 레이아웃이 의미 순서를 조용히 바꾸지 못하게 한다. 렌더러가 계약을 지킬 수 없으면 레이아웃을 단순화하거나
더 잘 제어할 수 있는 표현을 고른다.

### 0.4 단계별 렌더링

프레임과 rank, 노드, 주요 edge, 분기, group, 레이블, 장식 순서로 렌더링한다. 레이블이나 노드를 제거한 뒤에는
다시 측정한다.
기존 디자인 시스템의 컴포넌트와 변수를 쓸 수 있으면 사용하고, 없으면 작은 로컬 token 집합 하나를 정의한다.

### 0.5 세 수준 검증

1. **의미**: 원본의 모든 사실이 한 번씩 표현되고, edge 방향과 분기 결과가 정확하며, 없는 전이가 나타나지
   않는다.
2. **기하**: 정렬, 간격, 경로, 포함 관계, 잘라내기, 겹침 규칙을 통과한다.
3. **렌더 결과**: 실제 최종 SVG, PNG 또는 canvas 내보내기를 전달 크기에서 확인한다. 소스가 맞다는 것만으로는
   충분하지 않다.

렌더 결과를 확인할 수 없으면 결과를 `시각 검증 안 됨`으로 표시하고 남은 확인 항목을 정확히 밝힌다.

## 1. 핵심 원칙

1. **흐름이 먼저, 장식은 나중이다.** 독자는 한 번에 좌우 또는 상하 방향을 파악할 수 있어야 한다.
2. **같은 역할은 같은 시각 문법을 쓴다.** 동일한 플랫폼, 동일한 edge 의미, 동일한 group 범주는 묶음 안의 모든
   도표에서 항상 같은 색, 모양, 구조를 공유해야 한다.
3. **의미보다 간격이 먼저 무너져서는 안 된다.** 노드를 제거하거나 숨기면 발행 전에 남은 노드와 edge를 다시
   배분한다.
4. **숨긴 요소는 흔적을 남기지 않는다.** group 테두리, 부제, 노드를 제거하면 외곽 프레임과 `viewBox`도 다시
   계산해야 한다.
5. **우연한 겹침은 없다.** 포함 관계(group → 내용물, 노드 → 자신의 아이콘과 레이블)가 아닌 두 요소는 시각적으로
   겹쳐서는 안 된다.
   여기서 "시각적"은 경계 상자 중심뿐 아니라 글자 획과 아이콘 획을 포함한다.

이 원칙들은 뒤의 규칙과 충돌할 때 항상 우선한다.

## 2. 시각 token

token은 **상대적 비중과 역할**로 규정하며 절대값으로 규정하지 않는다. 도표 묶음마다 구체적인 값을 한 번 정하고
모든 곳에서 재사용한다.

### 2.1 canvas

- 기본적으로 밝고 중립적인 단색 배경을 쓴다.
- 여러 흐름을 한 화면에서 비교하는 개요형 도표는 배경에 아주 옅은 색조 변화를 줄 수 있다.
- 바깥 여백은 SVG 요소를 키우는 것이 아니라 `viewBox` 잘라내기로 조절한다.
- 프레이밍 목표는 "실제 내용에 꼭 맞게"이며 "임의 canvas 안에서 가운데 정렬"이 아니다.

### 2.2 글자

위계를 정하고 묶음 전체에서 일관되게 유지한다.

| 역할 | 상대적 비중 |
|---|---|
| 기본 UI 글꼴 | 산세리프(예: Pretendard Variable 계열) |
| 식별자 글꼴 | 경로, 명령, 태그, 변수 이름에 쓰는 고정폭(예: JetBrains Mono 계열) |
| group 머리글 | 도표에서 가장 높은 위계 |
| subgroup 머리글 | group 머리글보다 아래, 노드 레이블보다 위 |
| 노드 주 레이블 | 본문보다 약간 무겁게 |
| 노드 보조 레이블 | 주 레이블보다 한 단계 가볍게 |
| subgroup 부제 | 가장 가벼운 보조 텍스트 |
| edge 레이블 | 노드 주 레이블과 같거나 약간 가볍게 |

### 2.3 노드

- 노드의 경계는 `<g class="node">` group 전체다. 아이콘 상자, 이미지, 주 레이블, 보조 레이블을 모두 포함하며
  아이콘 사각형만을 뜻하지 **않는다**.
- 기본 노드 모양은 흰색 채움과 부드러운 테두리를 가진 둥근 사각형이다. 한 줄 도표에서 안정적으로 읽히는
  정사각형에 가까운 비율을 고른다.
- 개요용 압축 노드는 같은 모양 언어를 작은 크기로 유지한다. 아이콘도 함께 줄어들지만 시각적 중심은 그대로
  유지한다.
- 주 레이블은 독자가 먼저 알아야 할 범주(플랫폼, 자원 유형)다. 보조 레이블은 형제 노드와 이 노드를 구별하는
  식별자(경로, 명령, 태그, 역할 상세)다.
  주 레이블만으로 모호할 때만 보조 레이블을 쓴다.

**내부 영역은 서로 배타적이어야 한다.** 노드마다 `아이콘 영역`, `주 레이블 영역`, `보조 레이블 영역`, 선택적
`본문 영역`을 사각형으로 미리 선언한다. 어떤 영역도 다른 영역과 겹칠 수 없다.
`text-anchor="middle"`로 노드의 수평 중앙에 놓은 레이블이라도, 측정한 너비 때문에 경계 상자가 아이콘 영역까지
밀고 들어가면 위반이다. 이때는 다음 중 하나를 고른다.

- (a) `text-anchor="start"`로 바꾸어 `아이콘 영역 오른쪽 + 여백`에 고정한다
- (b) 노드를 넓힌다
- (c) 레이블을 줄인다(하위 범주 단어를 빼거나 줄여 쓴다)

눈대중으로 중앙을 맞추는 것은 금지한다. 발행 전에 고정폭은 `글자 크기 × 글자 수`로 경계 상자를 계산하고,
가변폭은 렌더링된 SVG에서 측정한다.
같은 역할의 노드(예: 한 줄에 놓인 모든 처리 단계)는 모두 이 검사를 통과해야 하며, 레이블이 가장 긴 노드가
기준을 정한다.

**같은 노드 안의 격자 일관성.** 한 노드 안의 모든 텍스트 요소는 같은 수평 기준(`x`)을 공유한다.
주 레이블, 보조 레이블, 본문 레이블이 서로 다른 `x`를 쓰면 노드 내부 격자가 깨진다. 각 레이블이 저마다의
맥락에서 중앙에 보이더라도 독자는 어긋남을 느낀다.
기준이 정말로 두 개 필요하면 노드의 영역 정의에 각각을 선언한다.
예를 들어 가운데 정렬한 주 레이블이 아이콘 옆에 놓이고 본문 블록은 왼쪽 정렬로 남을 수 있다.
같은 역할의 모든 노드에 같은 기준 쌍을 적용한다.
텍스트마다 즉흥적으로 기준을 정하는 것은 금지한다.

### 2.4 edge

| 스타일 | 의미 | 시각 비중 |
|---|---|---|
| accent | 사용자나 개발자가 시작한 동작 | 가장 두드러진 선 색과 두께 |
| solid | 기본 전달, 배포, 실행 흐름 | 중립 기준선 |
| dashed | 보조적이거나 약한 연결. 꼭 필요할 때만 사용 | 가장 낮은 시각적 존재감 |

edge 기하 규칙:

- 모든 edge는 기본적으로 끝에 화살촉을 둔다.
- 화살촉 끝점은 아이콘 상자나 아이콘 이미지가 아니라 **노드 group 전체**(`<g class="node">`)에 고정한다.
  아이콘만 가리키는 것처럼 보이는 화살표는 잘못 고정된 edge이므로 다시 계산한다.
- 화살촉 끝과 노드 경계 사이에 작고 일관된 숨 쉴 틈을 둔다.
  SVG marker 화살촉을 쓸 때는 marker 글리프가 노드 안쪽과 겹치지 않도록 경로 끝점을 노드 경계보다 조금 바깥에
  둔다.
- 아래에서 위로 가는 edge는 도착 노드 아이콘 상자의 아래가 아니라 가장 낮은 레이블 영역의 바깥 경계를 겨눈다.
  위에서 아래로 가는 edge는 가장 위쪽 레이블 영역에 같은 규칙을 적용한다.
- 두 번 꺾이는 edge는 두 수직 구간의 길이가 같아야 한다.
  그러면 가운데 축의 y가 시작 y와 끝 y의 중점이 된다.
  예외: 순환을 닫는 회귀 edge, 장애물을 피해야 하는 분기 edge, 공유 대상으로 합류하는 병합 edge는 길이가 다른
  구간을 쓸 수 있다. 이런 edge에서는 겹침 회피와 레이블 가독성이 우선이며, 도표 묶음 안에서 같은 종류의 edge에는
  같은 오프셋을 일관되게 적용한다.
- 숨 쉴 틈을 어떤 값으로 정하든 도표 전체에 동일하게 적용한다.
- **숨 쉴 틈은 edge 양쪽 끝에서 대칭이다.** 시작점이 출발 노드 경계에서 3px 떨어져 있으면 끝점도 도착 노드
  경계에서 3px 떨어져야 한다.
  한쪽은 붙고 다른 쪽은 떨어진 비대칭 간격은 작성자의 부주의를 드러내며, edge가 한쪽 끝에 억지로 끼워진 것처럼
  보인다.
  이 규칙은 band 사이의 제어 edge와 band 안의 파이프라인 edge에 모두 적용한다.
  컨테이너 경계에서 시작해 노드 경계 위에서 끝나는 edge는 끝점이 잘못된 것이다.

## 3. 레이아웃

### 3.1 정렬

- 기본 형태는 **한 줄짜리 좌→우 선형 흐름**이다.
- 복잡도가 높아지면 줄을 쌓을 수 있지만, 각 줄은 내부적으로 같은 열 리듬을 유지한다.
- 여러 흐름을 나란히 보여 주는 개요 도표에서는 모든 줄이 같은 x축 열에 정렬한다.
- **band 간 열 정렬.** 쌓인 band에서 서로 관련된 항목은 같은 x축 열을 공유한다.
  위 단계와 그 아래 산출물, 오케스트레이터와 그것이 제어하는 단계들이 그 예다.
  m:n 대응에서는 명시적인 연결선을 그리거나, 열 수를 맞추거나, 두 band를 독립적으로 다룬다.
  일부 항목만 band 사이에서 정렬되고 나머지는 0이 아닌 값만큼 어긋나는 반쪽 정렬은 정렬이 아예 없는 것보다
  나쁘다. 독자가 관계를 추론하지만 자세히 보면 그 추론이 무너지기 때문이다.

### 3.2 간격 리듬

- 한 줄 안에서 노드 사이 간격은 모두 같으며, 그 결과 같은 줄의 edge 길이도 모두 같아진다.
- 같은 방향으로 가는 edge는 가능한 한 같은 길이 리듬을 유지한다.
  회귀, 분기, 병합 edge는 "edge" 절의 예외를 따른다. 선형 리듬을 맞추는 대신 종류별로 일관된 오프셋을 유지한다.
- 수평과 수직 edge는 서로 다른 리듬을 가질 수 있지만, 축마다 자기 체계를 일관되게 유지한다.
- 노드를 제거한 뒤에는 남은 노드를 다시 배분해 특정 edge만 비정상적으로 길어지지 않게 한다.
  중간 노드를 없앤 직접 연결이 더 정확할 때만 긴 edge를 남긴다.
  그 경우에도 정렬, 레이블 중심 맞춤, 외곽 프레임 균형을 유지한다.
- **컨테이너 안의 내용 간격은 균일하다.** band, group, subgroup, 저장 상자 같은 한 컨테이너 안의 인접 항목은
  그 컨테이너 평균 간격의 ±5% 안에서 배치한다.
  다른 항목이 180~190px 간격인데 하나만 240px인 것처럼 튀는 간격은 항목이 빠졌거나 범주가 바뀌었다는 신호로
  읽힌다. 둘 다 의도가 아니면 다시 배분한다.
  범주 구분이 의도라면 얇은 구분선, 부제, 레이블이 붙은 여백 같은 명시적 구분 표시를 넣어 독자가 의도한 간격과
  레이아웃 실수를 구별할 수 있게 한다.

### 3.3 줄바꿈

한 줄이 너무 길면 다음 순서로 처리한다.

1. 먼저 중복을 제거한다.
2. 그래도 길면 줄바꿈 레이아웃으로 바꾼다.
3. 줄을 바꾼 뒤에도 각 줄은 내부적으로 같은 간격을 유지한다.
4. 줄 전환 edge는 수직이나 L자 모양일 수 있지만, 각 줄의 읽기 방향은 분명해야 한다.

전형적인 줄바꿈은 이렇다. 1행은 좌→우로 읽고, 전환 edge는 수직이며, 2행은 우→좌이거나 다시 좌→우로 읽는다.
도표마다 읽기 규칙 하나를 정하고 이후 모든 줄에 그대로 적용한다.

## 4. 외곽 프레임과 내보내기

도표의 완성도는 노드 안쪽보다 외곽 프레이밍이 더 크게 좌우한다. 구조가 바뀔 때마다 프레임을 다시 계산해야 한다.

### 4.1 viewBox

`viewBox`는 **현재 보이는** 내용의 경계 상자를 기준으로 다시 계산한다. 노드, edge, 화살촉, 텍스트(내림 획
포함), 아이콘, group 테두리, 획, marker, 그림자가 대상이다.
숨긴 group, 제거한 노드, 이전 레이아웃에서 남은 좌표는 제외해야 한다. 이전의 넉넉한 canvas를 그대로 물려받지
않는다.

`viewBox`를 다시 계산한 뒤에는 첫 노드에서 왼쪽 가장자리까지, 마지막 노드에서 오른쪽 가장자리까지, 위쪽
텍스트에서 위 가장자리까지, 아래쪽 텍스트에서 아래 가장자리까지의 네 거리가 시각적으로 균형 있게 보여야 한다.

### 4.2 PNG 내보내기

브라우저 viewport 크기, `100vh` 높이, 전체 페이지 스크린샷은 최종 산출물로 유효하지 않다.
전달용 PNG는 렌더링된 보이는 내용에 맞춰 잘라낸 뒤 **네 변에 같은 값으로** 다시 여백을 준다.

보이는 내용에는 노드, edge, 화살촉, 아이콘, 텍스트, group 컨테이너, 절 제목, 구분선이 포함된다.
브라우저 viewport 여백, `100vh` 때문에 생긴 페이지 공간, CSS 레이아웃 여백, 숨긴 group이나 부제의 흔적, 이전
레이아웃에서 남은 `viewBox` 여백은 제외한다.

절차:

1. SVG나 HTML을 평소대로 렌더링한다.
   페이지 껍데기가 도표보다 큰 빈 공간을 만들지 않도록 제한하고, SVG 높이가 viewport에 억지로 맞춰지지 않고
   `viewBox` 비율을 따르게 한다.
2. 같은 배경을 쓰되 SVG 시각 요소를 숨긴 상태로 한 번 더 렌더링한다. 목표는 원본과 같은 배경(옅은 그라데이션
   포함)을 가진, 내용이 없는 이미지다.
3. 두 렌더 결과를 비교해 실제 내용 영역을 찾는다. 배경색만으로 잘라내지 않는다. 흰색 아이콘 채움이 배경으로
   오인되고, 모서리 색 기준 잘라내기는 그라데이션에서 실패한다.
4. 그 경계 상자에 맞춰 산출물을 잘라낸다.
5. 잘라낸 결과의 네 변에 같은 여백을 다시 준다. 목표는 "꼭 맞되 답답하지 않게"이며, 도표 묶음마다 한 번 정해
   재사용한다. 절대값보다 묶음 전체의 일관성이 중요하다.
6. 반복 수정 이력을 추적할 수 있도록 파일 이름 뒤에 timestamp를 붙여 저장한다.

### 4.3 최종 PNG 검증

저장한 PNG를 열어 눈으로 확인한다.

- 위아래 여백이 같아 보인다.
- 좌우 여백이 같아 보인다.
- 내림 획, 화살촉, group 테두리, 아이콘 그림자가 잘리지 않았다.
- 숨긴 요소나 이전 레이아웃에서 남은 빈 영역이 없다.

렌더링된 PNG가 시각적으로 균형을 잃었으면 `viewBox`만 다시 손대며 쫓아가지 말고, 보이는 내용을 기준으로 래스터
결과를 다시 잘라내고 같은 여백을 다시 적용한다.
문서에는 검증한 PNG만 참조한다. 원본 viewport 캡처와 검증 전 렌더 결과는 산출물에 절대 넣지 않는다.

## 5. 레이블

### 5.1 노드 레이블

- 주 레이블은 독자가 먼저 알아야 할 범주를 담는다.
- 보조 레이블은 주 레이블만으로 모호할 때만 넣는다.
- 경로, 태그, 명령, 변수 이름처럼 식별자 형태의 값은 고정폭 글꼴로 표시한다.
- 노드가 주, 보조, 2차 보조 레이블을 함께 쓰면 그 위계가 시각적으로 분명해야 한다.

### 5.2 edge 레이블

- edge는 **무슨 일이 일어나는지**를, 노드는 **무엇인지**를 설명한다. 그 정보를 양쪽에 중복해서 넣지 않는다.
- edge 레이블은 각 edge의 기하학적 중앙에 둔다.
- 기본 위치는 edge 위쪽이다. 위쪽에 주의를 끄는 요소(분기선, 인접 레이블)가 있으면 아래쪽으로 옮긴다.
  도표 묶음마다 위쪽 오프셋 값 하나와 아래쪽 오프셋 값 하나를 정해 일관되게 적용한다.
- 수직 edge에서는 레이블의 주축을 edge의 중점에 둔다.
- 레이블이 하나만 빠져 있으면 그 전이가 의미 있는지 판단한다. 의미가 있으면 레이블을 달고, 없으면 균형을 맞추려고
  이웃 레이블을 늘리지 않는다.
- **edge 레이블 배경판은 edge 선을 덮어야 한다.** edge가 레이블 글자를 지나갈 때만 배경판을 넣는다.
  텍스트 경계 상자보다 조금 큰 canvas 색 사각형을 써서 선을 가린다.
  레이블이 edge에서 떨어져 있어 선이 글자를 가로지르지 않으면 배경판은 불필요하므로 넣지 않는다.
  어떤 edge 구간도 덮지 않는 배경판은 기능 없는 시각적 잡음이다. 배경판은 특정 충돌을 해결하려고 존재하며,
  충돌이 없으면 배경판도 없다.

### 5.3 길이와 밀도

- 레이블은 짧게 쓰고 동사로 시작한다.
- 한 edge 레이블에 두 전이의 의미를 겹쳐 넣지 않는다.
- 중간 단계를 없애서 한 edge가 두 단계를 나타내게 되면 복합 레이블을 쓸 수 있다.
  먼저 의미상 가장 자연스러운 이웃 edge로 레이블을 옮겨 본다.

### 5.4 접근성과 텍스트 동등성

- 색만으로 의미를 나타내지 않는다. 역할 색을 모양, 레이블, 아이콘 또는 선 스타일과 함께 쓴다.
- 최종 전달 크기에서 채움과 배경 대비 텍스트 대비가 읽을 만한지 확인한다.
- 도착 지점만으로 결과가 분명한 경우가 아니면 모든 결정 edge에 명시적인 결과 레이블을 단다.
- 텍스트 동등물을 유지한다. 순서가 있는 노드·edge 데이터, 접근 가능한 SVG title과 description 또는 옆에 붙인
  구조적 요약이 그것이다.
- 지원되는 편집 canvas와 DOM·SVG 소스에서는 안정적인 읽기 순서를 사용한다.
- 꼭 필요한 문장을 래스터 이미지 안에만 두지 않는다.

## 6. group과 subgroup

### 6.1 group을 쓸 때

다음 중 하나 이상이 성립할 때만 group 컨테이너를 쓴다.

- 여러 노드가 하나의 플랫폼이나 범주를 공유한다.
- 개요 도표처럼 열 자체가 의미를 가진다.
- 한 플랫폼이 도표 전체에 반복해서 나타나고 배경 구획이 실제로 이해를 돕는다.

### 6.2 group 스타일

역할 계열마다 색조 하나를 정하고 묶음의 모든 도표에서 재사용한다.

| 역할 계열 | 배경 색조 | 테두리 |
|---|---|---|
| 입력·출처 | 차분하고 신뢰감 있는 색 | 같은 계열, 뚜렷하게 |
| 처리·오케스트레이션 | 중립적이고 절제된 색 | 같은 계열, 시선을 덜 끌게 |
| 저장·배포 산출물 | 약간 따뜻하거나 구별되는 색 | 같은 계열, 경계를 분명하게 |
| 런타임·실행 환경 | 안정적이고 마무리감 있는 색 | 같은 계열, 자연스럽게 이어지게 |

group 컨테이너는 개별 노드보다 부드럽고 조금 더 큰 둥근 모양을 쓴다.

### 6.3 subgroup

subgroup은 기존 파이프라인의 일부를 묶는다. 스타일은 의도적으로 조용하게 유지한다. 점선 테두리, 거의 흰색에
가까운 배경을 쓰고 제목과 부제는 꼭 필요할 때만 넣는다.

subgroup 제목과 부제가 아무것도 더하지 않으면 숨긴다. 그리고 subgroup을 시각적으로 완전히 없애거나 안쪽 노드만
남긴다.
어느 쪽이든 이후 레이아웃과 외곽 프레임을 다시 계산한다.

### 6.4 컨테이너와 캡션 규율

**컨테이너 범위는 선언한 논리적 범위와 일치한다.** 컨테이너는 단계, 산출물 경로 또는 노드를 감쌀 수 있다.
좌우 가장자리는 감싼 항목들의 바깥 가장자리와 맞춘다.
대신 일정한 안쪽 여백을 주고 싶으면 네 변에 같은 값을 적용하고 명시적인 padding 상수로 문서화한다.
"컨테이너가 덮어야 할 범위"와 "좌표가 실제로 덮는 범위"의 불일치는 시각적 모순이다. 독자는 작성자의 의도가
아니라 좌표에서 범위를 읽는다.

**group 캡션 정렬은 도표마다 규칙 하나를 따른다.** 한 도표의 모든 group, band, subgroup 캡션은 다음 중 하나의
같은 수평 정렬 규칙을 쓴다.

- (a) canvas 왼쪽 여백(모든 캡션이 같은 `x`)
- (b) 그 캡션이 속한 컨테이너의 왼쪽 가장자리
- (c) 그 캡션이 감싼 첫 항목의 왼쪽 가장자리

도표마다 규칙 하나를 골라 일관되게 적용한다.
일부 캡션은 canvas 왼쪽, 다른 캡션은 컨테이너 왼쪽에 두는 식으로 두 규칙을 섞으면, 각 캡션이 따로 보면
"규칙대로" 놓였더라도 레이아웃이 일관되지 않게 읽힌다.

**소스 코드 주석은 실제 좌표와 일치한다.** 레이아웃 관련 인라인 주석은 실제 좌표와 속성에 맞아야 한다.
이는 SVG, HTML/CSS와 프로그램으로 만든 draw.io나 Figma 출력에 모두 적용된다.
`x=270, width=820` 옆에 `spans X 230-1150`이라고 적힌 주석은 거짓이다. 작성자의 의도를 흐리고 검토를 어렵게
만든다.
주석은 docstring이 아니라 도표 계약의 일부다. 좌표가 바뀌면 같은 수정에서 주석도 갱신한다.

## 7. 단순화

흐름도는 시스템 전체가 아니라 **독자가 따라가야 할 것**을 담는다. 다음 중 하나라도 해당하면 그 노드는 제거
후보다.

- 앞 노드의 보조 레이블이 이미 그것을 가리킨다.
- 들어오는 edge 레이블이 그 노드가 나타내는 전이 결과를 이미 설명한다.
- 존재하기는 하지만 독자가 흐름을 따라가는 데 필요하지 않다.
- 추가하면 정보는 늘지 않고 edge만 길어진다.

노드 제거는 이 파일의 "레이아웃"과 "외곽 프레임과 내보내기"에 따라 레이아웃, edge 길이 리듬, 레이블 배치,
`viewBox`를 모두 다시 적용해야 완료된다.

| pattern | 사용 시점 | 비고 |
|---|---|---|
| 개요 | 여러 흐름을 한 페이지에서 비교할 때 | 열을 먼저 읽고, 각 행을 독립된 흐름으로 읽는다. 같은 행 index는 같은 의미 수준을 뜻한다. |
| 선형 | 짧은 단일 경로 흐름 | 가장 안정적인 기본형. group 컨테이너 없이 노드와 edge만으로 읽혀야 한다. |
| 단순화 선형 | 긴 흐름을 핵심 전이만 남겨 압축할 때 | 선형 모양을 유지하며 간격과 레이블 규율도 그대로 적용한다. |
| 줄바꿈 선형 | 한 줄에 담기에 길지만 분기가 필요하지는 않은 선형 흐름 | 쌓인 여러 줄에 걸쳐 하나의 순차적 읽기를 이어 간다. |
| 분기와 병합 | 결정 하나에서 둘 이상의 결과가 나왔다가 다시 합류할 때 | 결정 노드를 주축에 두고 모든 결과에 명시적 레이블을 단다. 대안 결과는 주 lane 위나 아래의 평행 lane으로 보내고, 결과마다 edge 하나로 공유 대상에 병합한다. 분기 lane은 주 lane을 피하려고 길이가 다른 꺾임 구간을 쓸 수 있다. |
| 제한 재시도 | 성공하거나 한도에 도달할 때까지 반복하는 단계 | 전진 경로는 주축에 그리고, 회귀 edge는 재시도 대상 단계를 관통하지 않고 감싸 도는 순환 하나로 그린다. 회귀 edge에는 재시도 조건과 한도를, 탈출 edge에는 성공 조건을 레이블로 단다. 회귀 edge는 같은 줄 리듬 대신 자기 오프셋을 일관되게 유지한다. |
| 오류 탈출 | 흐름에 다시 합류하지 않고 빠져나가는 실패 | 실패에는 주축 밖에 자체 종료 노드를 주고, 결정이나 실패 단계에서 edge 하나로 연결한다. edge에는 실패 조건을 레이블로 달고 종료 노드는 끝 상태로 표현한다. 오류 탈출을 주 lane으로 되돌리지 않는다. |

pattern 하나를 명시적으로 고른다. 의도 없이 둘을 섞으면 품질이 떨어진다. 결정, 순환 또는 오류 경로가 있는
흐름은 마지막 세 pattern 중 하나를 쓰며, 선형이나 개요 프레임 안에 들어갈 수 있다. 선형 규칙을 맞추려고 단순한
선형 사슬로 다시 그리는 일은 결코 없다.

## 9. 최종 체크리스트

도표를 완료로 선언하기 전에 모든 항목을 확인한다. 각 항목은 위의 규칙으로 되돌아간다. 이 목록은 요약이 아니라
통과 기준이다.

**구조**

- 흐름 방향이 한 번에 읽힌다.
- 같은 의미 수준의 노드가 같은 축을 공유한다.
- 중복이 남아 있지 않다.
- 포함 관계가 아닌 요소끼리 겹치지 않는다. 긴 식별자 레이블(고정폭 8자 이상 또는 시각적으로 넓은 가변폭
  레이블)은 눈대중이 아니라 측정했다.
- 한 노드 안의 모든 텍스트 요소가 같은 수평 기준을 공유하거나, 노드 역할별로 기준을 명시적으로 선언했다.

**간격**

- 같은 줄의 edge 길이가 같다.
- 근거 없이 비정상적으로 긴 구간이 없다.
- 제거 후에 재배분을 수행했다.
- edge의 숨 쉴 틈이 양쪽 끝에서 대칭이다.
- 컨테이너 안 동종 항목의 간격이 평균의 ±5% 안에서 균일하다.

**레이블**

- 노드 레이블과 edge 레이블이 같은 정보를 반복하지 않는다.
- edge 레이블이 짧고 동사로 시작한다.
- 식별자는 고정폭으로 표시된다.
- edge 레이블 배경판이 있다면 실제로 그 아래 edge 선을 덮는다. 어떤 edge 구간도 덮지 않는 배경판은 제거했다.

**프레이밍**

- 바깥 여백이 넉넉하지 않고 꼭 맞다.
- 숨긴 요소에서 남은 빈 영역이 없다.
- `viewBox`를 현재 내용 기준으로 다시 계산했다.
- 전달용 PNG를 보이는 내용에 맞춰 잘라내고 네 변에 같은 여백을 다시 주었다.
- 컨테이너의 좌우 가장자리가 선언한 논리적 범위와 일치한다. 또는 네 변에 같은 안쪽 여백을 명시적으로 적용했다.

**일관성**

- 같은 역할 계열이 묶음 전체에서 같은 색, 아이콘, 글자 문법을 쓴다.
- 같은 계열의 도표가 같은 간격 리듬을 공유한다.
- 선택한 pattern(개요 / 선형 / 단순화 / 줄바꿈 / 분기와 병합 / 제한 재시도 / 오류 탈출)이 분명하다.
- 각 체크리스트 항목을 선택한 pattern의 규칙 아래에서 적용했다. 유효한 분기나 순환 그래프를 선형 사슬로 펴지
  않았고, 회귀·분기·병합 edge는 같은 줄 리듬이 아니라 "edge"의 예외로 판단했다.
- 모든 group, band, subgroup 캡션이 하나의 수평 정렬 규칙을 따른다.
- 레이아웃에 대한 소스 코드 주석이 실제 좌표와 일치한다.

**의미 정합성**

- 안정적인 노드 ID가 고유하고, 모든 edge가 존재하는 두 노드로 연결된다.
- edge 방향과 결정 결과가 원본 자료와 일치한다.
- 원본의 한 사실이 의도 없이 별개 노드로 중복되지 않았다.
- 순환, 재시도, 오류 경로가 주 흐름과 시각적으로 구별된다.
- 도표에 명시적인 시작과 종료 상태가 있거나, 없는 이유를 문서화했다.

**접근성**

- 색이 의미의 유일한 전달 수단이 아니다.
- 텍스트 대비와 최종 크기 가독성을 확인했다.
- 텍스트로 동등한 노드·edge 표현이나 접근 가능한 설명이 있다.
- 형식이 지원하는 범위에서 읽기 순서가 보이는 흐름과 일치한다.

**전달 근거**

- 편집 가능한 소스와 렌더링된 산출물이 같은 리비전에 해당한다.
- 소스 마크업만이 아니라 최종 내보낸 산출물을 확인했다.
- 수행할 수 없었던 시각·접근성 확인은 가정하지 않고 밝혔다.
- 출력 경로와 형식이 요청과 일치하며, 임시 렌더 결과를 최종 파일로 제시하지 않았다.
