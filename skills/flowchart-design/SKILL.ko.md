# 플로우차트 디자인 표준

> 영어 원본: [SKILL.md](SKILL.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

SVG, HTML·CSS, Figma, FigJam, draw.io, Mermaid와 래스터 출력에서 명확한 정적 흐름도를 설계, 수정,
검증하고 내보낸다. 플로우차트, 프로세스 지도, 아키텍처·결정 흐름, 다이어그램 체계 통합, 간격과 경로 수정,
겹침 제거, 접근 가능한 레이블, viewBox 정리와 PNG 내보내기 수정에 사용한다.

의미 그래프와 도구별 렌더링을 분리하고 기능에 따른 대체 경로를 사용한다. 의미와 레이아웃 절차는 모든
에이전트 호스트에서 작동한다. 편집 가능한 렌더링, 이미지 검사, 브라우저 측정과 내보내기는 해당 기능이
필요하며 없으면 텍스트 사양을 제공한다.

영어 `SKILL.md`와 영어 참조 파일만 실행 원본으로 사용한다. 한국어 `.ko.md` 파일은 사람용 번역본이다.

여러 도구로 만든 차트가 하나의 디자인 시스템에서 나온 것처럼 보이게 한다. 아래 규칙은 절대 수치가 아니라
상대 동작을 정의한다. 노드 수, edge geometry와 의미에 맞는 구체적인 크기와 offset을 현재 작업에서 정하고
한 차트 묶음 안에서 일관되게 사용한다. 프로젝트 용어보다 레이아웃, 간격, 레이블, 단순화와 외곽 프레임을
우선한다.

## 0. 이식 가능한 절차

### 0.1 기능 확인

제품 이름에 의존하지 않고 사용할 수 있는 가장 강한 경로를 선택한다.

1. 노드와 connector를 만들고 검사할 수 있으면 네이티브 편집 canvas
2. 파일을 수정하고 렌더링할 수 있으면 코드 기반 vector, 결정적인 geometry에는 SVG 우선
3. 텍스트 렌더링만 가능하면 topology용 diagram DSL, 시각 제어가 가능해지면 내보내거나 개선
4. 브라우저가 있고 텍스트·레이아웃 측정이 유용하면 HTML·CSS
5. 렌더링 기능이 없으면 시각 검증을 했다고 주장하지 않고 의미 그래프, 레이아웃 계약과 renderer-ready 원본

병렬 처리, 이미지 검사와 브라우저 자동화는 검증을 강화하지만 필수는 아니다. 빠진 기능을 정확히 알리고
의미 그래프는 바꾸지 않는다.

### 0.2 의미 그래프 먼저 만들기

좌표를 정하기 전에 다음으로 정규화한다.

- 안정적인 ID, 간결한 레이블, 역할과 선택적인 상세가 있는 노드
- source, target, 결과 레이블과 edge 유형이 있는 방향 edge
- 결과를 구분할 수 있는 결정 branch
- 실제 소유권이나 단계를 표현하는 group
- 명시적인 시작·끝 지점과 외부 시스템
- 주 읽기 방향

고립 노드, 중복 ID, 끊긴 edge, 선형으로 표현한 cycle과 결과를 구분하지 못하는 branch 레이블을 해결한다.
업무 의미가 모호하면 시각화 전에 질문한다.

### 0.3 레이아웃 계약 선택

8절의 pattern 하나를 고르고 읽기 방향, 노드 rank, group 중첩, edge 경로 정책, token, 레이블 문법,
대상 형식과 편집 가능 요구사항을 밝힌다. 자동 레이아웃이 의미 순서를 몰래 바꾸게 두지 않는다.
renderer가 계약을 지키지 못하면 레이아웃을 단순화하거나 제어 가능한 표현을 선택한다.

### 0.4 단계별 렌더링

프레임과 rank, 노드, 주 edge, branch, group, 레이블, 장식 순으로 렌더링한다.
레이블이나 노드를 제거하면 다시 측정한다. 기존 디자인 시스템이 있으면 재사용하고 아니면 작은 로컬 token
집합 하나를 정의한다.

### 0.5 세 수준 검증

1. **의미:** 원본 사실이 한 번씩 표현되고 edge 방향과 branch 결과가 맞으며 지어낸 전환이 없다.
2. **geometry:** 정렬, 간격, 경로, 포함 관계, crop과 겹침 규칙을 만족한다.
3. **렌더링:** 실제 최종 SVG, PNG 또는 canvas 출력을 전달 크기로 검사한다.

렌더링 검사가 불가능하면 `not visually verified`로 표시하고 남은 검사를 정확히 밝힌다.

## 1. 핵심 원칙

1. 흐름을 장식보다 먼저 이해할 수 있어야 한다.
2. 같은 역할, 플랫폼, edge 의미와 group 범주는 같은 색, 도형과 구조를 사용한다.
3. 노드를 숨기거나 제거하면 게시 전에 남은 노드와 edge를 다시 배치한다.
4. 숨긴 요소는 흔적을 남기지 않는다. group 테두리, 부제나 노드를 제거하면 외곽과 `viewBox`를 다시 계산한다.
5. 포함 관계가 아닌 두 요소는 glyph와 icon stroke를 포함해 시각적으로 겹치지 않는다.

충돌할 때 이 원칙이 뒤 규칙보다 우선한다.

## 2. 시각 token

token은 절대값이 아니라 상대적인 무게와 역할로 정의한다. 차트 묶음마다 값을 한 번 정해 재사용한다.

### 2.1 canvas

- 기본 배경은 밝고 중립적인 단색이다.
- 여러 흐름을 비교하는 overview는 매우 약한 배경 색조 변화를 사용할 수 있다.
- SVG 요소를 늘리지 않고 `viewBox` crop으로 외부 여백을 정한다.
- 임의 canvas 중앙이 아니라 실제 콘텐츠에 밀착하도록 frame을 잡는다.

### 2.2 글자

| 역할 | 상대 무게 |
|---|---|
| 기본 UI 글꼴 | sans-serif, 예: Pretendard Variable |
| 식별자 글꼴 | 경로, 명령, tag, 변수에는 monospace, 예: JetBrains Mono |
| group 제목 | 차트에서 가장 높은 계층 |
| subgroup 제목 | group 아래, 노드 레이블 위 |
| 노드 주 레이블 | 본문보다 조금 굵음 |
| 노드 보조 레이블 | 주 레이블보다 한 단계 가벼움 |
| subgroup 부제 | 가장 가벼운 보조 텍스트 |
| edge 레이블 | 노드 주 레이블과 같거나 조금 가벼움 |

### 2.3 노드

- 노드 경계는 icon box만이 아니라 icon, 이미지, 주·보조 레이블을 포함한 전체 `<g class="node">`다.
- 기본은 흰 채움과 부드러운 테두리의 둥근 사각형이다. 한 행에서 안정적으로 읽히는 정사각형에 가까운 비율을 쓴다.
- compact overview 노드는 같은 도형 언어를 작게 유지하고 icon 중심을 보존한다.
- 주 레이블에는 먼저 알아야 할 범주, 보조 레이블에는 형제를 구분하는 경로, 명령, tag, 역할 상세를 쓴다.
  주 레이블만으로 모호할 때만 보조 레이블을 사용한다.

노드 내부의 `icon zone`, `main-label zone`, `sub-label zone`, 선택적인 `body zone`은 서로 겹치지 않는다.
가운데 정렬한 레이블의 실제 bounding box가 icon 영역에 들어가면 다음 중 하나를 선택한다.

- `text-anchor="start"`를 사용하고 `icon-zone-right + padding`에 고정
- 노드 확대
- 의미를 보존해 레이블 단축

눈으로 중앙을 추측하지 않는다. monospace는 `font-size × glyph-count`, 비례 글꼴은 렌더링 SVG로 bounding
box를 계산한다. 같은 역할 노드에서 가장 긴 레이블이 최소 크기를 정한다.

한 노드의 모든 텍스트는 같은 수평 anchor `x`를 사용한다. 둘이 정말 필요하면 zone 정의에 각각 선언하고
같은 역할의 모든 노드에 같은 쌍을 적용한다. 텍스트마다 임의 anchor를 쓰지 않는다.

### 2.4 edge

| 스타일 | 의미 | 시각 무게 |
|---|---|---|
| accent | 사용자나 개발자가 시작 | 가장 눈에 띄는 색과 굵기 |
| solid | 기본 전달, 배포 또는 실행 흐름 | 중립 기준선 |
| dashed | 꼭 필요한 보조 또는 약한 연결 | 가장 낮음 |

- 기본적으로 모든 edge 끝에 화살표를 둔다.
- 끝점은 icon이 아니라 전체 노드 group에 고정한다.
- 화살촉과 노드 경계 사이에 작은 일정 간격을 둔다. SVG marker는 glyph가 내부에 겹치지 않게 path 끝을
  경계 바깥에 둔다.
- 아래에서 위로 가는 edge는 대상 노드에서 가장 아래 레이블 영역의 외곽을 향한다. 반대 방향도 가장 위
  레이블 영역에 같은 규칙을 적용한다.
- 두 번 꺾이는 edge는 두 수직 구간 길이를 같게 하고 중간 y를 시작과 끝 y의 중간으로 둔다.
  loop를 닫는 return, 장애물을 피하는 branch, 공통 대상으로 합치는 merge는 예외다. 이때는 겹침 방지와
  레이블 가독성을 우선하고 같은 유형의 offset을 일관되게 유지한다.
- 선택한 간격을 차트 전체에 동일하게 적용하고 edge 양 끝에 대칭으로 둔다.
  container에서 시작해 노드 경계 위에서 끝나는 식의 잘못된 끝점을 허용하지 않는다.

## 3. 레이아웃

### 3.1 정렬

- 기본은 한 행의 왼쪽에서 오른쪽 선형 흐름이다.
- 복잡하면 행을 쌓을 수 있지만 각 행은 같은 열 리듬을 유지한다.
- 여러 흐름의 overview는 모든 행을 같은 x축 열에 맞춘다.
- 쌓인 band의 관련 항목은 같은 x축 열을 공유한다. m:n 관계면 connector를 명시하거나 열 수를 맞추거나
  band를 독립으로 취급한다. 일부만 어긋난 반정렬은 존재하지 않는 관계를 암시하므로 사용하지 않는다.

### 3.2 간격 리듬

- 한 행의 모든 노드 사이 간격과 같은 행 edge 길이를 같게 한다.
- 같은 방향 edge는 가능한 한 같은 길이 리듬을 유지한다. return, branch, merge는 유형별 offset을 유지한다.
- 수평과 수직 edge는 서로 다른 리듬을 쓸 수 있지만 각 축 안에서는 일관돼야 한다.
- 노드를 제거하면 남은 노드를 재분배한다. 제거한 중간 노드보다 직접 연결이 정확할 때만 긴 edge를 유지하고
  정렬, 레이블 중앙과 외곽 균형을 보존한다.
- 한 container 안 인접 항목의 간격은 평균의 ±5% 안에서 균등해야 한다. 의도적인 범주 경계라면 얇은 구분선,
  부제 또는 레이블이 있는 여백으로 표시한다.

### 3.3 줄바꿈

한 행이 너무 길면 중복 제거, wrapped layout 전환, 각 행의 균등 간격 유지 순으로 처리한다.
행 전환 edge는 수직 또는 L자일 수 있지만 각 행의 읽기 방향은 분명해야 한다. 첫 행 뒤의 행을 오른쪽에서
왼쪽 또는 다시 왼쪽에서 오른쪽으로 읽도록 정하고 모든 후속 행에 같은 규칙을 적용한다.

## 4. 외곽 프레임과 내보내기

구조가 바뀔 때마다 frame을 다시 계산한다. `viewBox`는 현재 보이는 노드, edge, 화살촉, descender를 포함한
텍스트, icon, group 테두리, stroke, marker와 shadow의 bounding box로 계산한다. 숨긴 group, 제거한 노드,
이전 레이아웃 좌표를 제외한다. 다시 계산한 뒤 왼쪽·오른쪽과 위·아래 외곽 거리가 시각적으로 균형이어야 한다.

### 4.1 PNG 내보내기

브라우저 viewport, `100vh` 높이와 전체 페이지 스크린샷은 최종 출력이 아니다. 실제 보이는 콘텐츠로 crop하고
네 면에 같은 값의 padding을 다시 넣는다. 보이는 콘텐츠에는 노드, edge, 화살촉, icon, 텍스트, group,
섹션 제목과 구분선이 포함되며 브라우저 여백, CSS padding과 숨긴 요소나 이전 `viewBox` 흔적은 제외한다.

1. SVG·HTML을 정상 렌더링하고 page shell 여백을 제한하며 SVG 높이는 `viewBox` 비율을 따른다.
2. 같은 배경에서 SVG 시각 요소만 숨긴 두 번째 렌더링을 만든다.
3. 두 결과의 차이로 실제 콘텐츠 영역을 찾는다. 흰 icon이나 gradient 때문에 배경색만으로 crop하지 않는다.
4. bounding box로 crop한다.
5. 네 면에 같은 padding을 넣는다. 차트 묶음에서 한 번 정한 값으로 밀착되지만 답답하지 않게 한다.
6. 반복 결과를 추적하도록 basename에 timestamp postfix를 붙인다.

최종 PNG를 열어 상하·좌우 padding이 각각 같고 descender, 화살촉, group 테두리, shadow가 잘리지 않으며
숨긴 요소나 이전 레이아웃의 빈 영역이 없는지 확인한다. 불균형하면 `viewBox`만 반복 수정하지 않고 보이는
래스터 콘텐츠로 다시 crop하고 같은 padding을 적용한다. 문서는 검증된 PNG만 참조한다.

## 5. 레이블

- 주 노드 레이블에는 먼저 필요한 범주를 쓰고 모호할 때만 보조 레이블을 쓴다.
- 경로, tag, 명령, 변수 같은 식별자는 monospace로 표시한다.
- 주, 보조, 2차 보조 레이블의 계층을 분명히 한다.
- edge는 무엇이 일어나는지, 노드는 무엇인지를 설명하며 같은 정보를 반복하지 않는다.
- edge 레이블을 geometry 중앙에 두고 기본은 위에 놓는다. 위에 경쟁 요소가 있으면 아래에 놓으며 차트
  묶음마다 위·아래 offset 하나씩을 일관되게 쓴다. 수직 edge도 주축 중간에 둔다.
- 빠진 레이블 하나가 의미 있는 전환이면 붙이고 아니면 주변 레이블에 임의 공간을 추가하지 않는다.
- 선이 glyph를 통과할 때만 canvas 색 plate를 텍스트 bounding box보다 조금 크게 넣어 선을 가린다.
  선을 가리지 않는 plate는 시각 잡음이므로 제거한다.
- 레이블은 짧고 동사로 시작한다. 한 edge에 전환 의미 둘을 쌓지 않는다. 중간 노드 제거로 두 단계를
  나타낼 때만 복합 레이블을 허용하며 먼저 의미상 자연스러운 인접 edge로 옮길 수 있는지 확인한다.

### 접근성과 텍스트 동등성

- 색만으로 의미를 표현하지 않고 도형, 레이블, icon 또는 선 스타일을 함께 사용한다.
- 최종 크기에서 텍스트 대비와 가독성을 확인한다.
- 대상만으로 결과가 분명하지 않으면 모든 결정 edge에 결과 레이블을 붙인다.
- 순서가 있는 노드·edge 데이터, 접근 가능한 SVG title·description 또는 인접한 구조 요약을 보존한다.
- 지원되는 편집 canvas와 DOM·SVG에서 안정적인 읽기 순서를 사용한다.
- 필수 설명을 래스터 이미지 안에만 두지 않는다.

## 6. group과 subgroup

여러 노드가 플랫폼이나 범주를 공유하거나, overview 열 자체에 의미가 있거나, 반복 플랫폼의 배경 분할이
이해를 실제로 돕는 경우에만 group을 사용한다.

| 역할 계열 | 배경 색조 | 테두리 |
|---|---|---|
| 입력·원본 | 차분하고 신뢰감 있는 색 | 같은 계열의 분명한 선 |
| 처리·조정 | 절제된 중립색 | 같은 계열의 약한 선 |
| 저장·배포 아티팩트 | 조금 따뜻하거나 구별되는 색 | 같은 계열의 분명한 경계 |
| 런타임·실행 환경 | 안정적이고 결론적인 색 | 같은 계열의 자연스러운 연결 |

group은 노드보다 부드럽고 조금 큰 둥근 모양을 사용한다. subgroup은 기존 pipeline 일부를 감싸며 dashed
테두리와 거의 흰 배경을 쓰고 꼭 필요할 때만 제목이나 부제를 둔다. 제목과 부제가 정보를 더하지 않으면
숨기고 subgroup 자체를 제거하거나 내부 노드만 유지한 뒤 레이아웃과 외곽을 다시 계산한다.

container 좌우 경계는 감싼 항목의 논리 범위와 맞아야 한다. inset을 쓰면 네 면에 같은 값을 적용하고 padding
상수로 기록한다. 독자는 의도가 아니라 좌표에서 범위를 읽는다.

한 차트의 group, band, subgroup caption은 canvas 왼쪽 padding, 자체 container 왼쪽, 첫 내부 항목 왼쪽 중
하나의 수평 정렬 규칙을 모두 공유한다. 규칙을 섞지 않는다.

SVG, HTML·CSS, 프로그래밍 방식 draw.io·Figma 출력의 인라인 레이아웃 주석은 실제 좌표와 속성에 맞아야 한다.
좌표가 바뀌면 같은 수정에서 주석도 갱신한다.

## 7. 단순화

흐름도는 전체 시스템이 아니라 독자가 따라야 할 내용을 기록한다. 앞 노드 보조 레이블이나 들어오는 edge가
이미 설명하거나, 독자가 흐름을 이해하는 데 필요 없거나, 정보 없이 edge만 늘리는 노드는 제거 후보다.
노드를 제거한 뒤 레이아웃, edge 길이, 레이블과 `viewBox`를 다시 적용해야 제거가 끝난다.

## 8. 추천 pattern

| pattern | 사용 상황 | 참고 |
|---|---|---|
| Overview | 한 페이지에서 여러 흐름 비교 | 열을 먼저 읽고 각 행을 독립 흐름으로 읽는다. 같은 행 번호는 같은 의미 수준이다. |
| Linear | 짧은 단일 흐름 | 가장 안정적인 기본값이며 group 없이 노드와 edge만으로 읽혀야 한다. |
| Simplified Linear | 긴 흐름을 필수 전환으로 축약 | 선형 모양과 간격·레이블 규율을 유지한다. |
| Wrapped Linear | branch가 필요하지 않지만 한 행에 너무 긴 선형 흐름 | 쌓인 행에서도 하나의 순차 읽기를 유지한다. |
| Branch and Merge | 둘 이상 결과가 나중에 다시 합쳐지는 결정 | 결정을 주축에 놓고 결과마다 레이블과 edge를 둔다. 대안은 평행 lane으로 보내 공통 대상에 합치며 장애물을 피하려고 bend 길이를 다르게 할 수 있다. |
| Bounded Retry | 성공하거나 한도에 이를 때까지 반복 | 주 경로는 주축에 두고 return edge는 재시도 단계를 관통하지 않고 둘러간다. 재시도 조건·한도와 성공 출구를 표시하고 유형별 offset을 유지한다. |
| Error Exit | 다시 합쳐지지 않고 흐름을 떠나는 실패 | 주축 밖 terminal 노드로 edge 하나를 보내고 실패 조건을 표시한다. end state로 보이며 주 lane에 되돌리지 않는다. |

pattern 하나를 명시적으로 고른다. 결정, loop 또는 오류 경로는 마지막 세 pattern 중 하나를 Linear나 Overview
프레임 안에서 사용할 수 있으며 선형 규칙을 맞추려고 평면 chain으로 바꾸지 않는다.

## 9. 최종 체크리스트

완료 전에 다음을 모두 검사한다.

**구조:** 한 번에 읽히는 방향, 같은 의미 수준의 공통 축, 중복 제거, 포함 관계 밖 겹침 없음, 긴 식별자
레이블 측정, 노드 내부 anchor 일치 또는 역할별 명시

**간격:** 같은 행 edge 길이 일치, 이유 없는 긴 구간 없음, 제거 뒤 재분배, 양 끝의 대칭 간격,
container 안 같은 유형 항목 간격이 평균 ±5% 이내

**레이블:** 노드와 edge 정보 중복 없음, 짧고 동사로 시작, 식별자 monospace, 실제 edge 선을 가리는 plate만 유지

**프레임:** 밀착된 외부 padding, 숨긴 요소의 빈 영역 없음, 현재 콘텐츠 기준 `viewBox`, 보이는 콘텐츠로
crop하고 네 면에 같은 padding을 둔 PNG, 선언 범위와 맞는 container 경계

**일관성:** 같은 역할의 색·icon·글자 문법, 같은 묶음의 간격 리듬, 분명한 pattern, branch·loop를 선형으로
평면화하지 않음, 예외 규칙으로 return·branch·merge 평가, caption 정렬 하나, 실제 좌표와 맞는 주석

**의미 무결성:** 고유한 안정 ID, 기존 노드 두 개에 연결되는 edge, 원본과 맞는 방향·결과, 의도 없는 사실
중복 없음, 주 흐름과 구분되는 cycle·retry·error, 명시적인 시작·종료 또는 없는 이유

**접근성:** 색 이외의 의미 수단, 최종 크기 대비·가독성, 텍스트 동등 표현이나 접근 가능한 설명,
보이는 흐름과 맞는 읽기 순서

**전달 근거:** 같은 개정의 편집 원본과 렌더링 결과, 최종 아티팩트 직접 검사, 불가능한 검사의 공개,
요청과 맞는 경로·형식, 임시 렌더링을 최종 파일로 제시하지 않음
