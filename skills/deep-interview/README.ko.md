# Deep Interview (심층 인터뷰 스킬)

> 이 문서는 한국어 사용자가 내용을 확인하기 위한 참고 설명입니다. 에이전트가 스킬을
> 실행할 때 읽거나 사용하는 지침이 아닙니다. 유일한 실행 지침은 `SKILL.md`와 그 문서가
> 지정한 영어 참고 자료입니다.

모호한 아이디어를 바로 구현하지 않고, **한 번에 하나씩** 핵심 질문을 던져 숨은 가정을 드러내고,
매 답변마다 **모호성 점수를 수학적으로 측정**해 통과 모호성 **1% 이하**가 될 때까지 인터뷰를 반복한 뒤
실행 가능한 **사양서(spec)** 로 정리하는 소크라테스식 요구사항 인터뷰 스킬입니다.

이 스킬은 **여러 코딩 에이전트에서 그대로 동작**합니다 (OpenCode · Codex CLI · Claude Code).
인터뷰는 항상 **각 에이전트의 네이티브 ask UI**를 통해 진행됩니다 — 자세한 라우팅은
`references/ask-ui.md`를 따릅니다.

> 원본: Gajae-Code의 `deep-interview` 워크플로 스킬을 포팅해, 호스트 전용 상태/CLI/핸드오프
> 장치를 제거하고 에이전트 독립적으로 바꿨습니다.
> [Ouroboros 프로젝트](https://github.com/Q00/ouroboros)에서 영감을 받았습니다.

## 핵심 특징 — 각 에이전트의 네이티브 ask UI 사용

모든 인터뷰 질문은 호스트 에이전트의 네이티브 질문 도구로 제시됩니다. 세 도구의 스키마가 거의
동일해서(질문 텍스트 + 짧은 `header` + 2~4개 `options{label, description}` + 자유 입력) 하나의
질문 모델을 그대로 매핑할 수 있습니다. 질문과 선택지 설명은 고등학생도 이해할 수 있을 만큼
충분히 자세히 쓰고, 선택지는 항상 추천도가 높은 순서로 정렬하며, 가장 추천하는 선택지의 라벨
끝에는 ` (추천)`을 붙입니다.

| 에이전트 | 네이티브 도구 | 비고 |
|---|---|---|
| Claude Code | `AskUserQuestion` | `header` ≤ 12자, options 2~4개, "Other" 자유 입력 자동 제공. **서브에이전트에서는 불가** → 인터뷰 질문은 메인 세션에서만 |
| OpenCode | `question` | 답할 때까지 작업 일시정지, 커스텀 답변 기본 허용, `question` 권한 키 |
| Codex CLI | `request_user_input` | 실험적, 1~3개 질문. 또는 MCP elicitation / 승인 프롬프트 |
| 그 외/없음 | 인라인 폴백 | `## Question N` + 맥락 + `A)`(추천)/`B)`/`C)`/`D) 직접 입력` 블록 후 턴 종료 |

네이티브 도구가 있으면 **가짜 객관식을 일반 텍스트로 흉내 내지 않습니다.** 도구가 없을 때만
인라인 폴백을 쓰고, 질문을 제시한 뒤 턴을 끝내 사용자의 답을 기다립니다.

## 사용 시점

- 사용자가 모호한 아이디어만 있고, 구현 전에 요구사항을 철저히 정리하고 싶을 때
- "deep interview", "interview me", "ask me everything", "don't assume", "make sure you
  understand", "I have a vague idea", "ouroboros", "socratic" 같은 표현을 쓸 때
- 자율 실행으로 "내가 원한 건 이게 아닌데" 결과가 나오는 것을 피하고 싶을 때

다음의 경우에는 사용하지 않습니다.

- 파일 경로·함수명·인수 기준이 명확한 구체적 요청 → 바로 실행
- 간단한 수정/단일 변경
- "그냥 해줘" / "질문 건너뛰어" → 인터뷰를 끝내고 아는 범위로 `pending approval` 사양서만 작성
  (파일을 변경하거나 실행을 위임하지 않음)
- 이미 계획/PRD가 있고 실행만 요청한 경우 → 요청한 실행 경로 사용

## 작업 흐름

1. **Phase 0 — 임계값 확정 (선행 필수)**: 기본 통과 임계값 `0.01`(모호성 1% = 명확도 99%). 사용자가
   더 엄격한 값을 말하면 그 값을 사용하고, 더 느슨한 값을 말하면 `0.01`로 캡합니다. 첫 줄에 반드시
   `Deep Interview threshold: <%> (source: <출처>)`를 출력.
2. **Phase 1 — 초기화**: 아이디어 파싱, 브라운필드/그린필드 판별(읽기 전용 탐색이 먼저), 과도하게
   큰 입력은 먼저 요약, 인터뷰 상태를 대화 안에서 추적.
3. **Round 0 — 토폴로지 게이트**: 점수화 전에 최상위 컴포넌트(1~6개)를 한 번 확인·고정. 상세한
   한 컴포넌트가 덜 상세한 형제 컴포넌트를 가리지 않도록.
4. **Phase 2 — 인터뷰 루프**: 가장 약한 차원을 겨냥해 한 번에 한 질문 → 점수화 → 진행 보고.
   필요 시 자동 리서치(2a′)·자동 답변(2b′)·자유답변 정제(2b″), 그리고 3회 연속 에이전트 해결 시
   사용자에게 질문을 돌리는 변증법 리듬 가드.
5. **Phase 3 — 측면 검토 패널**: 모호성 마일스톤 전환 시 researcher/contrarian/simplifier
   (+범위 변화 시 architect) 읽기 전용 페르소나를 병렬(또는 호스트가 서브에이전트를 못 띄우면
   순차)로 소집해 사각지대를 드러냄.
6. **Phase 4 — 사양서 결정화**: 종료/수용 가드 + 한 문장 목표 재진술 게이트 통과 후 사양서 생성.
7. **Phase 5 — 실행 브리지**: 사양서를 `pending approval`로 두고 네이티브 ask UI로 다음 단계를
   제시. 명시적 승인 전에는 절대 구현하지 않음.

## 모호성 점수 (수학적 게이트)

- 통과 기준은 항상 **모호성 1% 이하**입니다. 빠른 인터뷰/표준 인터뷰 같은 깊이 프리셋도 통과 기준을
  1%보다 느슨하게 만들 수 없고, 명시적으로 조기 종료할 때만 위험을 경고하고 멈출 수 있습니다.
- 그린필드: `ambiguity = 1 - (goal × 0.40 + constraints × 0.30 + criteria × 0.30)`
- 브라운필드: `ambiguity = 1 - (goal × 0.35 + constraints × 0.25 + criteria × 0.25 + context × 0.15)`
  (기존 코드를 안전하게 수정하려면 시스템 이해가 필요하므로 Context 차원 15% 추가)

점수는 **양방향·비단조**입니다. 나중의 답변이 기존 사실과 모순되거나(A), 내부 비일관(B),
회피성(C), 범위 확장(D)을 일으키면 모호성이 **올라갈 수 있습니다.** 또한 라운드마다 온톨로지
(핵심 엔티티) 안정도 비율을 계산해 도메인 모델이 수렴하는지 추적합니다.

## 생성 파일 (Output Contract)

- 인터뷰 상태는 기본적으로 **대화 안에서** 추적합니다(별도 상태 파일 불필요).
- 최종 사양서는 **사용자가 명시적으로 경로를 주거나 확인했을 때만** 디스크에 씁니다. 기본 제안
  경로는 `.deep-interview/deep-interview-{slug}.md`이며, 임의의 추론 경로에 파일을 만들지
  않습니다. 경로를 주지 않으면 사양서를 대화에 인라인으로 제시합니다.
- 쓸 때는 호스트의 일반 파일 쓰기 도구를 사용합니다. 별도 CLI나 필수 상태 디렉터리는 없습니다.

## 언어 매칭

- 질문·선택지·설명·진행 보고·사양서 산문은 사용자의 대화 언어에 자동으로 맞춥니다.
- 한 질문 블록은 하나의 주된 언어로 작성하고, 어색하게 언어를 섞지 않습니다.
- 파일 경로, 슬러그, 코드 식별자, 명령어, 도구 이름, JSON 키, 고정 상태 토큰
  (`pending approval` 등), Phase 0 임계값 표기 줄, 숫자 점수는 영어/원문 그대로 둡니다.

## 파일 구성

```
skills/deep-interview/
├── SKILL.md                              # 메인 스킬 (Phase 0~5 전체 로직)
├── README.ko.md                          # 이 문서
└── references/
    ├── ask-ui.md                         # 각 에이전트 네이티브 ask UI 라우팅 (핵심)
    ├── auto-research-greenfield.md       # 그린필드 자동 리서치 프래그먼트
    ├── auto-answer-uncertain.md          # 사용자 opt-out 시 자동 답변 프래그먼트
    └── lateral-review-panel.md           # 측면 검토 패널 페르소나 프래그먼트
```

## 안전 규칙

- 명시적 실행 승인 전에는 **읽기 전용**입니다. 소스 수정, 변경 명령 실행, 커밋/푸시/PR, 구현
  위임을 하지 않습니다. 쓸 수 있는 유일한 산출물은 Output Contract에 따른 사양서뿐입니다.
- 사실 질문(현재 스택·버전·기존 패턴)은 탐색으로 확인해 인용하고, **결정**(목표·범위·트레이드오프·
  원하는 동작)은 항상 사용자에게 묻습니다.
- Deep Interview는 요구사항 스킬이지 실행 스킬이 아닙니다.
