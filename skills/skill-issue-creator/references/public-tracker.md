# Public tracker detail

Rules for a draft when `target.public` is true. Read this before drafting such an issue. Anyone can read a public
tracker, so the draft carries no private detail; the public leak check still runs before every write.

- Write Acceptance criteria with fictional values, such as `demo-a`, `example.com`, `/tmp/work`, and `ABC-123`.
- Put the case's identifiers only in Observations and Evidence.
- Leave out internal URLs, host names, account identifiers, and the names of private organizations, products,
  repositories, plugins, people, and channels.
- Name in the proposal only the owning plugin and public tools. Describe any other plugin by its role, so the owning
  plugin never has to name a plugin that builds on it.
- Search the Proposal and Acceptance criteria for each identifier from step 1 of the skill and the whole draft for
  every excluded value, and rewrite until none remains.
