# 문서 윤문

> 영어 원본: [SKILL.md](SKILL.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

읽히는 방식을 바꾸되, 말하는 내용은 절대 바꾸지 않는다.

## 권한과 범위

영어 `SKILL.md`만 실행 기준 원본으로 사용한다. 이 파일, `references/patterns.md`,
`evals/evals.json`의 한국어는 대상 언어 자료이지 지시가 아니다. 이 스킬은 우선순위가 더 높은
지침 다음에 적용한다.

| 적용 대상 | 적용하지 않는 대상 |
|---|---|
| 사용자가 대화에 제공한 텍스트 | 주제나 개요에서 새 글을 쓰는 일 |
| 게시 전 에이전트 초안: 리뷰 코멘트, 커밋 메시지, PR 설명, 채팅 답글 | 언어 간 번역 |
| 경로가 주어진 문서 파일이나 코드 주석 | 요약, 압축, 확장 |
| 어색하다, 기계가 쓴 것 같다, 읽기 어렵다고 한 텍스트 | 내용이 사실인지 판단하는 일 |

제외 대상이 요청에 섞여 있으면 윤문을 먼저 하고, 나머지는 하지 않았다는 사실과 이유를 분명히 밝힌다.

AI 탐지기 우회를 요청하면 평소대로 문장을 개선한다. 어떤 탐지기도 통과한다고 보장하거나 주장하지 않는다.

## 불변 요소

아래 각 요소는 의미를 담고 있다. 결과에 같은 값으로 그대로 재현한다. 보통의 윤문이 이 값들을
소리 없이 바꾸기 때문에 이 스킬이 존재한다. 이 파일의 어떤 선택지, 모드, 강도도 이 표의 항목을
완화하지 않는다.

| 요소 | 그대로 살아남아야 하는 것 |
|---|---|
| 수량 | 모든 수치, 단위, 범위, 날짜, 정밀도. 반올림, 근사, "약" 같은 완충어 추가 금지 |
| 조건과 예외 | 모든 조건절, 예외, 전제, 단서를 같은 개수로, 같은 대상에 대해 |
| 부정과 범위 | 부정과 모두·일부·전혀·최소·최대 같은 한정사. 이중부정을 긍정으로 바꾸지 않는다 |
| 확신도 | 단정, 추측, 가능성, 전언의 등급. "~인 것 같다"를 단정으로 올리거나 단정을 추측으로 내리지 않는다 |
| 요구 강도 | 필수, 권고, 허용, 금지의 차이. 요청은 요청으로, 제안은 제안으로 유지 |
| 행위자와 방향 | 누가, 무엇에, 어느 방향으로. 피동을 능동으로 바꿀 때 원문에 없는 행위자를 만들지 않는다 |
| 시제와 상 | 완료, 진행, 예정 |
| 리터럴 문자열 | 고유명사, 제품·모델명, 코드 식별자, 파일 경로, URL, 명령, 오류 문구, 버전, 인용, 직접 인용문을 글자 단위로 |
| 화행 | 묻는지, 요청하는지, 보고하는지, 약속하는지 |
| 심각도 | 심각도 라벨, 차단 여부, 우선순위 표시 |
| 장르와 문체 | 장르, 독자, 격식 수준, 시점, 기존 용어 |
| 미해결 질문 | 원문이 답하지 않은 것은 결과에서도 답하지 않은 채로 둔다 |

## 금지되는 변경

- 원문에 없는 사실, 이유, 원인, 예시, 비유, 연결어, 결론 추가
- 원문에 있는 사실 삭제. 반복 제거는 "허용되는 변경"에서만 가능하다
- 두 가지로 읽히는 표현을 한쪽으로 확정
- 결론을 원문보다 강하거나 약하게 만들기
- 원문이 암시만 한 원인을 단정하거나, 추측을 발견처럼 제시
- 정중체, 중립체, 직설체의 경계를 넘는 어조 변경
- 기계가 쓴 느낌을 줄이려고 격식체를 구어체로 바꾸기
- 원문보다 문학적으로 만들거나, 한 상투구를 다른 상투구로 바꾸기

이 규칙을 어기지 않고는 개선할 수 없는 구절은 그대로 두고 보고한다. 어색한 문장을 그대로 두는
것이 옳은 결과이고, 의미를 바꾸는 것은 옳지 않다.

## 허용되는 변경

- 문장 분리, 결합, 순서 변경
- 번역투, 겹친 피동, 명사 중심 표현 제거. 예: "확인을 진행하다" → "확인하다", "보여지다" → "보인다"
- 조사, 어미, 띄어쓰기, 맞춤법 교정
- 두 구절이 정확히 같은 내용일 때만 반복 삭제. 의미가 조금이라도 다르면 둘 다 유지
- 문단 분리, 결론을 근거 앞으로 이동
- 독립된 사안이 둘 이상이면 목록으로 변환
- 세 개 이상 항목이 세 개 이상 비교 축을 공유하면 표로 변환
- 식별자, 경로, 명령을 글자 변경 없이 인라인 코드로 표시

## 한국어 패턴 층

원문이 한국어이면 `references/patterns.md`에 정리된 AI 문체와 번역투 패턴도 함께 고친다. 그 파일을
읽고 이 원문에 해당하는 패턴만 살핀다. 발견한 구간만 국소적으로 고치고 전역 치환은 하지 않는다.
이 층은 표현만 바꾸므로 "불변 요소"의 모든 항목이 그대로 유지된다.

생략된 선택지는 원문에서 추론한다. 사용자가 명시하면 언제나 그쪽이 우선한다.

| 선택지 | 값 | 효과 |
|---|---|---|
| `장르` | `칼럼`, `리포트`, `블로그`, `공적` | 목표 장르. "불변 요소"가 장르와 문체를 보호하므로 장르 변경에는 명시적 요청이 필요하다 |
| `강도` | `보수`, `기본`, `적극` | 편집 폭. 기본값 `기본` |
| `최소심각도` | `S1`, `S2`, `S3` | 대상 패턴. 기본값 `S2` |

`S1`은 이중 피동이나 빈 상투구 같은 명백한 국소 결함, `S2`는 문장을 기계적으로 만드는 반복적·맥락
의존 패턴, `S3`은 적극적 윤문에서만 건드릴 미세한 선호다. 임계값은 더 강한 등급을 포함하므로
`S2`는 `S1`과 `S2`를 함께 다룬다.

`보수`는 확신이 높은 국소 편집만, `기본`은 해당하는 `S1`·`S2` 패턴에, `적극`은 더 넓은 리듬과 구조
변경에 사용한다. 이미 자연스러운 글은 그대로 두거나 분명한 편집 몇 개만 한다. 작업했다는 것을
보이려고 고쳐 쓰지 않는다.

## 구조 가드

형식 변환이 허용되므로 한계가 필요하다. 짧은 글을 과하게 구조화하면 엉킨 채 두는 것만큼 가독성을 해친다.

- 원문이 세 문장 이하이고 사안이 하나면 목록이나 문단 구조를 만들지 않는다
- 사안 하나를 여러 목록 항목으로 쪼개지 않는다
- 제목을 새로 만들지 않는다. 원문에 절이 있으면 그 이름을 유지한다
- 구조는 한 단계만 만든다. 원문이 이미 중첩된 경우에만 중첩을 유지한다
- 원문의 형식 계열을 유지한다. 평문은 평문으로, Markdown은 Markdown으로
- 의미를 담은 Markdown 구조, 목록 의미, 문단 경계를 보존한다

## 애매함

잘 쓰이지 않은 글에는 두 가지로 읽히는 구절이 대개 있다. 한쪽을 고르면 의미가 바뀌므로 애매함을
보존해야 할 내용으로 취급한다.

1. 두 가지 이상으로 읽히는 구절을 모두 표시한다.
2. 그 해석들을 모두 열어두는 표현을 고른다. 열어두는 자연스러운 표현이 없으면 그 구절은 원문 그대로 둔다.
3. 그 구절을 가능한 해석과 함께 "확인 필요"에 적는다. 한쪽을 고르지 않는다.

## 절차

1. 장르, 독자, 문체, 입장, 서식 역할을 파악한다.
2. 원문의 주장을 순서대로 나열하고, 각 주장이 어떤 불변 요소를 담는지 표시한다. 이 목록은 작업
   자료이지 출력이 아니다.
3. 애매한 구절과 보호 대상을 표시한다.
4. "허용되는 변경"과 "구조 가드" 안에서 고쳐 쓴다. 원문이 한국어이면 한국어 패턴 층을 함께 적용한다.
5. 대조로 검증한다. 결과의 주장을 나열해 2단계와 하나씩 맞춘다. 개수가 같아야 하고, 순서 대응이
   유지되어야 하며, 모든 불변 값이 동일해야 한다. 새로 생긴 주장은 지우고, 사라진 주장은 되살린다.
6. 자연스러움, 리듬, 문체, 과잉 편집을 점검한다. 한 상투구를 다른 상투구로 바꾼 편집은 되돌린다.
7. 결과와 무엇을 왜 바꿨는지, 무엇을 그대로 두었는지 보고한다.

편집이 전체 문장의 3분의 1을 넘으면 충실도 검토를 한 번 더 한다. 적극 강도나 장르 변경 요청 없이
절반 넘는 문장을 고쳐 썼으면 넓은 편집을 되돌리고 국소적으로 다시 시도한다. 실제 diff를 측정하지
않았다면 이를 정성적 안전장치로 취급한다.

## 정밀 검토

사용자가 `--strict` 또는 `정밀 모드`를 요청하거나 입력이 8,000자를 넘으면 정밀 검토를 실행한다.
자동 승격은 짧은 진행 안내 한 줄로 알린다.

별도 하위 에이전트나 호스트별 오케스트레이션 없이 현재 에이전트에서 수행한다.

1. 문서 전체 맥락을 유지한 채 절 단위로 기본 절차를 완료한다.
2. 불변 요소 표, 보호 문자열, 인과 관계에 대해 별도 충실도 검토를 한다.
3. 남은 대상 패턴과 과잉 편집에 대해 별도 자연스러움 검토를 한다.
4. 문제가 된 구간만 다시 시도한다. 두 번 재시도 후 멈추고 해결되지 않은 구간을 그대로 보고한다.

정밀 검토는 검증 깊이를 바꾸는 것이지 요청된 어조나 윤문 강도를 바꾸지 않는다.

## 후속 요청

후속 요청은 대화에서 사용할 수 있는 가장 최근 원문이나 결과에 적용한다.

| 사용자 신호 | 동작 |
|---|---|
| `특정 카테고리만 다시` | 그 패턴 범주만 건드리고 나머지 구간은 보존한다 |
| `이 문단만` | 지정하거나 인용한 문단만 고쳐 쓴다 |
| `2차 윤문` | 최근 결과를 다시 검토해 남은 문제만 고친다 |
| `윤문 강도 조정` | 관련 없는 내용을 다시 열지 않고 새 강도를 적용한다 |
| `장르 바꿔서` | 사실과 입장을 보존한 채 장르 처리를 바꾼다 |

참조한 텍스트를 더 이상 사용할 수 없으면 다시 제공해 달라고 요청한다.

## 출력

다음 구조를 사용한다.

```markdown
<고쳐 쓴 텍스트. 원문의 언어와 형식으로>

**주요 변경**
- <무엇을 왜 바꿨는지, 3~6줄>

**확인 필요**
- <두 가지로 읽혀 그대로 둔 구절과 가능한 해석>
```

- 원문의 언어를 유지한다. 번역하지 않는다.
- 애매한 곳이 없으면 "확인 필요"를 생략한다.
- 사용자가 고쳐 쓴 텍스트만 요청하면 그 텍스트만 출력한다.
- 고칠 것이 없으면 짧게 그렇게 말하고 원문을 그대로 돌려준다.
- 에이전트 초안은 게시 규약을 글자 그대로 유지한다. 멘션, 신원 ID, 심각도 접두사, 서명, 커밋 타입 접두사.
- 저장소 파일은 변경 내용을 보여주고 승인을 받은 뒤에 쓴다. 산문과 주석만 고치고 코드, 명령,
  설정값은 건드리지 않는다.
- 사용자가 파일 출력을 요청하지 않으면 실행 디렉터리, 보고서, 지표 파일을 만들지 않는다.
- 변경률, 등급, 탐지기 점수, 통과 횟수를 지어내지 않는다. 실제로 측정한 수치만 보고한다.

## 예시

한국어 원문, 리뷰 코멘트, 독립된 사안이 둘이므로 목록 변환이 허용된다.

```text
원문:
성능이 좀 안좋아진거 같은데 아마 N+1 때문일수도 있을것 같습니다 그리고 로그가
너무 많이 찍히는것도 있고 일단 확인해보시면 좋을것 같아요

결과:
다음을 확인해 보시면 좋겠습니다.

- 성능이 나빠진 것 같습니다. N+1 때문일 수도 있습니다.
- 로그가 지나치게 많이 남습니다.
```

추측은 추측으로 남고, 제안은 요청이 되지 않고 제안으로 남는다.

규칙을 어긴 윤문과 올바른 윤문.

```text
원문:
캐시 만료가 5분인데 좀 짧은 것 같습니다

잘못된 결과:
캐시 만료 시간이 5분으로 너무 짧으니 늘려야 합니다.

올바른 결과:
캐시 만료 시간이 5분인데, 조금 짧은 것 같습니다.
```

잘못된 쪽은 추측을 단정으로 올리고 원문에 없는 지시를 더했다.

애매함을 열어둔 경우.

```text
원문:
값이 없으면 기본값을 쓰는데 그게 맞는지 모르겠네요

결과:
값이 없으면 기본값을 씁니다. 그게 맞는지 모르겠습니다.

확인 필요:
- "그게"가 기본값을 쓰는 동작을 가리키는지, 기본값 자체를 가리키는지 원문만으로는
  정해지지 않아 그대로 두었습니다.
```

## 완료 기준

- [ ] 2단계와 5단계의 주장 목록이 하나씩 대응하고, 추가도 누락도 없다.
- [ ] "불변 요소"의 모든 항목이 원문과 결과에서 같은 값이다.
- [ ] "금지되는 변경" 항목이 하나도 발생하지 않았다.
- [ ] 모든 구조 변경이 "구조 가드"를 만족한다.
- [ ] 애매한 구절을 모두 열어두었거나 "확인 필요"에 보고했다.
- [ ] 언어, 장르, 문체, 형식 계열이 원문과 일치한다.
- [ ] 탐지기 관련 주장, 지어낸 수치, 요청하지 않은 파일이 없다.
- [ ] 저장소 파일은 변경을 보여주고 승인받은 뒤에만 썼다.
