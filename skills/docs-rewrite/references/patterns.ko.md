# 자연스러운 한국어 문장 패턴

> 영어 원본: [patterns.md](patterns.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

`SKILL.md` 절차가 이 참조를 읽으라고 할 때만 사용한다. 한국어 표현은 대상 언어 신호와 예시이며 지침이 아니다.

일치한다고 자동으로 오류가 되지는 않는다. 수정 전에 표현이 반복되거나 직역투이거나 정형적이거나 장르에
맞지 않는지 확인한다. 꾸며서 바꾸기보다 삭제하거나 직접적인 한국어 동사를 사용한다.

## 보호할 내용

다음 항목을 수정 대상으로 삼지 않는다.

- 고유명사, 기관, 제품, 모델명, 약어와 분야 용어
- 수치, 날짜, 단위, 공식, 인용, 링크, 코드와 법률 문구
- 직접 인용과 정확한 형태가 중요한 문구
- 불확실성, 인과 방향, 범위, 부정, 입장과 사실 강조

문장 순서를 바꿔야 할 때만 보호 항목을 이동할 수 있으며 텍스트와 의미를 그대로 유지한다.

## A. 번역투

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| A-1 | `~에 대해(서)` | 자연스러우면 목적격 조사를 직접 붙인다. |
| A-2 | 반복되는 `~를 통해/통하여` | 의미에 따라 `~로`, `~해서` 또는 직접 동사를 사용한다. |
| A-3 | `~에 있어(서)` | `~에서`, `~을 볼 때` 또는 직접적인 절을 사용한다. |
| A-4 | 반복되는 `~라는 점에서` | 이유나 관계를 직접 쓴다. |
| A-5 | `~와 관련하여/관련된` | `~에`, `~의` 또는 구체적인 동사를 사용한다. |
| A-6 | 반복되는 `~에 기반하여/바탕으로` | `~로`, `~을 근거로` 또는 `~을 보고`를 사용한다. |
| A-7 | 데이터를 포함한 추상 관계에 물리 동사를 쓰는 have, make, take, give 직역 | 한국어 동사, 형용사 또는 정확한 분야 동작을 복원한다. |
| A-8 | `판단되어진다` 같은 이중 피동 | 피동이나 능동 하나만 사용한다: `판단된다`. |
| A-9 | `~에 의해`가 있는 피동 | 행위자를 알면 주어로 쓴다. |
| A-10 | 반복되는 `~할 수 있다` | 가능성이 주장에 포함되지 않으면 직접 쓴다. |
| A-11 | 반복되는 `~을 위해` | 정확한 의미에 따라 `~려고`, `~도록` 또는 직접 수식어를 사용한다. |
| A-15 | 인지 동사를 가진 추상 주어 | 구체적인 주어를 쓰거나 근거와 주장을 나눈다. |
| A-16 | 반복되는 `그/그녀/그것/그들` | 생략하거나 한국어에 맞는 직함이나 명사구를 사용한다. |
| A-18 | 왼쪽으로 길게 뻗는 수식어 | 문장을 나누거나 설명을 명사 뒤에 둔다. |
| A-19 | `~에서의/~에로의/~으로의/~에의` | 절로 풀어 쓴다. 일반적인 `~의`는 제외한다. |

다음은 국소 수정의 예시다.

| 원문 | 가능한 수정 |
|---|---|
| `X에 대해 논의한다` | `X를 논의한다` |
| `경쟁력을 가지고 있다` | `경쟁력이 있다` 또는 `경쟁력이 강하다` |
| `AI에 의해 생성된` | `AI가 만든` |
| `합의가 이루어졌다` | `합의했다` 또는 `합의에 이르렀다` |
| `좌표를 비운다` | 계약이 빈 값을 뜻하면 `좌표를 빈값으로 둔다` |
| `응답이 돌아간다` | `응답을 반환한다` |
| `시설이 달린다` | 소속 관계를 설명한다면 `시설이 속한다` |

고정 치환이 아니라 예시로 사용한다.

## B. 영어 병기와 용어

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| B-1 | 언급할 때마다 같은 영어를 한국어와 병기 | 도움이 되는 첫 언급에만 영어를 둔다. |
| B-2 | 일반 문장에 피할 수 있는 영어 | 분야 의미를 유지할 수 있으면 한국어를 사용한다. |

번역이 더 혼란스러운 `LLM`, `GPU`, `MCP`, `API` 같은 정립된 용어는 유지한다.
제품명을 바꾸지 않으며 정확한 표현이 중요하면 영어 인용을 보존한다.

## C. 기계적인 구조

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| C-5 | 공식 칼럼이나 보고서의 이모지 | 제거한다. 가벼운 제품 문구나 소셜 글의 유용한 이모지는 유지한다. |
| C-7 | 정형적인 `먼저·반면·결국` 순서 | 실제 관계를 분명히 하는 연결어만 유지한다. |
| C-8 | 반복되는 병렬 질문 | 유용한 질문 하나를 남기고 나머지는 직접 쓴다. |
| C-9 | 장식용 `(1)·(2)·(3)` 번호 | 문장에 통합한다. 기능적인 절차 번호는 유지한다. |
| C-10 | 반복되는 `X: Y` 부제 | 장식 부제를 줄이고 탐색용 제목은 유지한다. |
| C-11 | 연결 어미 뒤 쉼표 | 문법상 필요하지 않으면 제거한다. |

체크리스트, 절차, 비교표 또는 참조 목록을 문장으로 평면화하지 않는다.
구조가 장르에서 장식적이고 반복적일 때만 문제다.

## D. 상투적이고 부풀린 표현

결론 전환 표현에는 `결론적으로`, `따라서`, `요약하면`, `정리하면`이 있다.

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| D-1 | 반복되는 결론 전환 | 중복 표현을 지우거나 문단 순서로 전환을 보인다. |
| D-2 | `시사하는 바가 크다/주목할 만하다` | 삭제하거나 근거가 있는 중요성을 직접 쓴다. |
| D-3 | 의미 없는 `본질적으로/핵심적으로` | 삭제한다. 실제 구분을 만들 때만 유지한다. |
| D-4 | 반복되는 과장이나 과장과 완곡 표현의 결합 | 같은 입장과 강도를 가진 쉬운 문구를 사용한다. |
| D-5 | `시대가 부른다` 같은 추상의 의인화 | 실제 행위자를 알면 사용한다. |
| D-6 | `지금이야말로 ~할 때다` 같은 정형적 결말 | 근거가 있는 주장이나 동작으로 끝낸다. |
| D-7 | 반복되는 `X에서 Y로` 전환 공식 | 가장 분명한 하나를 남기고 나머지는 직접 쓴다. |

상투어에 내용이 없으면 삭제하고 다른 상투어로 바꾸지 않는다.
글쓴이의 판단을 보존한다면 `매우 획기적인 변화라고 할 수 있다`를 `상당한 변화로 볼 수 있다`로 바꿀 수 있다.

## E. 리듬과 종결

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| E-1 | 비슷한 길이의 문장이 많음 | 아이디어를 추가하지 않고 기존 내용을 합치거나 나눈다. |
| E-2 | 반복되는 종결이나 `~고 있다` | 한국어 용법과 문체가 허용할 때만 바꾼다. |
| E-7 | 한 목소리에서 높임 수준이 섞임 | 인물이나 인용 차이가 없으면 한 수준을 유지한다. |

보고서의 자연스러운 한국어는 `~다`를 반복할 수 있다. 연극적인 변화를 억지로 만들지 않는다.
리듬은 내용을 재배치해서만 수정하고 군더더기를 추가하지 않는다.

## F. 명사화, 수식어와 중복

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| F-1 | 반복되는 `매우/정말/대단히` | 근거 없는 강조는 삭제하고 의미 있는 강도는 유지한다. |
| F-2 | `중요하고 핵심적인` 같은 동의어 중복 | 의도한 뉘앙스에 맞는 단어를 남긴다. |
| F-4 | 빽빽한 `-성/-적/-화` 명사화 또는 공식 제목의 모호한 동작 명사 | 구체적 동사나 형용사를 복원하고 제목에는 대상과 실제 동작을 쓴다. |
| F-5 | 추상적인 `~적 명사` 연결 | 관계를 풀어 쓰거나 구체적인 표현을 사용한다. |
| F-6 | 분류사가 없는 숫자 또는 모호한 집합·개수 표현 | 개수인지 집합인지 판단하고 수를 추론하지 않은 채 올바른 분류사나 정립된 집합 용어를 넣는다. |

`정책의 시행이 필요하다`는 `정책을 시행해야 한다`로 바꿀 수 있다. 의도가 맞으면 `구조적 문제`는
`구조 자체의 문제`가 될 수 있다. 기술 제목의 `기존 요청의 해석`은 `기존 API 요청 처리`,
`기존 ID의 처리 판정`은 `기존 Location ID 처리 규칙`이 될 수 있다.

F-6에서 `테이블은 아홉이다`는 `테이블은 9개다`가 될 수 있다. `코드 셋`은 문맥에 따라 코드 3개를
뜻할 때만 `코드 3개`로 쓰고 컬렉션이면 정립된 집합 용어를 사용한다. `응답은 둘이다`는 반환 항목의
이름을 쓰거나 `두 값을 반환한다`로 바꿀 수 있다. `둘 이상`, 정확한 계약 문자열과 수학 집합 용어는 유지한다.

## G. 완곡 표현과 확실성

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| G-1 | 반복되는 `~것이다/~할 것이다` | 원문이 현재 주장을 할 때만 현재형으로 바꾼다. |
| G-2 | 반복되는 `~로 보인다/~인 듯하다` | 확실성을 높이지 않고 반복을 줄인다. |
| G-3 | 반복되는 안전한 균형 표현 | 실제 균형이나 주의를 포함한 원래 입장을 유지한다. |

자신 있게 들리게 하려고 가능성을 확실성으로 바꾸지 않는다.
근거가 불확실하면 같은 불확실성을 유지하며 문장 구조만 바꾼다.

## H. 접속사와 메타 도입

초기 접속사에는 `또한`, `따라서`, `나아가`, `아울러`가 있다.
메타 도입 표현에는 `이는`, `이 점에서`, `이 관점에서`, `이 말은`이 있다.

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| H-1 | 잦은 초기 접속사 | 문장 순서로 충분한 접속사를 제거한다. |
| H-2 | 반복되는 `하지만/그러나` | 대비를 합치거나 관계가 분명할 때만 다르게 쓴다. |
| H-3 | 반복되는 메타 도입 또는 `그 예다` 같은 모호한 예시 지시 | 참조를 문장에 통합하거나 주어와 관계를 이름으로 쓴다. 대상과 역할이 분명하면 가까운 지시어를 유지한다. |
| H-4 | 반복되는 `즉` | 실제로 다시 설명하는 내용이 뒤에 올 때만 유지한다. |

## I. 격식 표현과 의존 명사

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| I-1 | 반복되는 `~인 것이다/~한 것이다` | 강조가 필요하지 않으면 직접 종결한다. |
| I-2 | `X은 ~라는 점에 있다` | 요점을 직접 쓴다. |
| I-3 | 반복되는 `~다는 뜻이다/~다는 의미다` | 의미를 문장 자체에 넣는다. |
| I-4 | 반복되는 권고 | 원문이 뒷받침하면 직접 주장하거나 지시한다. |

공식 문서의 격식을 낮추지 않는다. 가벼운 말투가 아니라 직접적인 공식 한국어를 목표로 한다.

## J. 시각적 장식

| ID | 신호 | 문맥에 따른 처리 |
|---|---|---|
| J-1 | 과도한 굵은 강조 | 계층이나 의미에 필요한 강조만 유지한다. |
| J-2 | 강조에 반복해서 쓰는 따옴표 | 직접 인용과 실제로 표시할 용어만 유지한다. |
| J-3 | 칼럼이나 에세이의 장식 글머리 | 문장에 통합하고 기능적인 목록은 유지한다. |

## 장르 조정

| 장르 | 보통 허용 | 보통 줄임 |
|---|---|---|
| 칼럼 또는 에세이 | 개인 목소리와 기존 비유 | 장식 제목, 이모지와 기계적인 목록 |
| 보고서 | 분명한 제목, 수치, 인용과 기능 목록 | 과장, 모호한 중요성과 장식 이모지 |
| 블로그 | 친근한 말투, 질문과 유용한 목록 | 반복되는 정형 나열 |
| 공식 연설 | 공식 문어체와 의도적인 반복 | 가벼운 말투, 이모지와 근거 없는 미사여구 |

이는 기본값이며 장르 변경을 허용하지 않는다. 사용자가 지정한 독자와 형식을 따른다.

## 최종 검사

결과를 원문과 비교해 다음을 확인한다.

1. 모든 사실, 수치, 이름, 인용, 링크와 기술 용어가 유지됐다.
2. 부정, 불확실성, 인과 방향, 범위와 입장이 바뀌지 않았다.
3. 각 수정이 확인된 패턴을 고치며 이유 없이 다른 구간을 다듬지 않았다.
4. 장르, 높임 수준, 관점, 형식 의미와 문단 목적이 유지됐다.
5. 비유, 근거, 의견 또는 더 강한 결론을 추가하지 않았다.
6. 지나치게 수정하지 않았다. 많은 문장을 바꿨으면 필요가 가장 적은 수정을 되돌린다.
