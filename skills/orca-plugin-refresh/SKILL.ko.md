# Orca 플러그인 새로고침

이 스킬은 영향을 받는 코딩 에이전트 세션이 끝난 뒤에만 `hei5enbug-agent-setup`을 업데이트한다. 사용자가
이미 설치한 버전을 실행 중인 Orca 세션에 적용할 수도 있다. 세션을 다시 시작하거나 대화를 바꾸지 않는다.

## 업데이트가 실행 중인 세션에 반영되는 방법

| 구분 | Claude Code | Codex |
|---|---|---|
| 스킬, 에이전트, 훅 | `/reload-plugins` | 다음 턴에서 새 설치본을 자동으로 불러온다 |
| 세션 지침 | `/compact` | `/compact`; 다음 턴에서 지침을 불러온다 |

플러그인의 세션 시작 훅은 Orca 터미널마다 호스트, 플러그인 디렉터리, 대화 기록 경로, 실행 지침의 digest가
담긴 표식을 기록한다. 해당 터미널의 대화형 세션만 표식을 쓴다. 그 터미널에서 시작한 자식 프로세스
`claude -p`나 `codex exec`은 표식을 쓰지 않는다. 표식이 없거나 digest가 다르거나, Codex 세션의 플러그인
디렉터리가 교체됐거나, Claude Code 세션이 삭제된 디렉터리를 가리킬 때만 스크립트가 세션을 compact한다.
Claude Code가 대화가 너무 짧아 compact할 수 없다고 답하고 대화 기록에 프롬프트가 없으면 스크립트가
`/clear`를 보낸다. 비어 있는 세션에는 잃을 내용이 없기 때문이다. 한 번도 턴을 진행하지 않은 Codex 세션은
첫 턴에서 새 지침을 불러오므로 따로 처리하지 않는다.

## 작업 흐름

`<script>`는 이 `SKILL.md`가 있는 디렉터리의 `scripts/orca_plugin_refresh.py`다.

1. **설치 경로를 고른다.** 새 플러그인을 업데이트할 때는 `python3 <script> update --json`을 실행한다.
   명시적인 오프라인 실행 확인이 필요하므로 업데이트는 기본적으로 보류된다. Orca 세션이 보이지 않아도
   기본 동작은 같다. 보류된 업데이트를 자동으로 다시 실행하지 않는다. 사용자가 영향을 받는 모든 코딩
   에이전트 세션이 끝났다고 명시하고 오프라인 업데이트를 요청하면
   `python3 <script> update --offline --json`을 실행한다. 스크립트는 활성 호스트, 플러그인, Orca 세션
   상태가 있으면 여전히 거부한다. 이 스킬 밖에서 이미 설치를 마쳤거나 사용자가 설치된 버전을 적용해
   달라고 하면 `python3 <script> apply-installed --json`을 실행한다. 이 명령은 설치 경로를 읽고 마켓플레이스나
   설치 명령을 실행하지 않는다.
2. **업데이트 결과를 처리한다.** 각 호스트의 버전 변화를 보고한다. 호스트에 `error`가 있으면 코드와
   메시지를 알린다. 해당 호스트의 세션은 건드리지 않는다. 보류된 호스트는 현재 `root`와 `recovery_command`도
   반환한다. 영향을 받는 세션이 끝난 뒤, 활성 호스트·플러그인·Orca 터미널 환경이 없는 일반 터미널에서만
   해당 명령을 사용한다. Orca 인벤토리는 관리되는 터미널만 보여 주므로 Orca 외부의 코딩 에이전트 세션이
   끝났는지는 확인할 수 없다. 인벤토리를 읽을 수 없거나, 잘렸거나, 형식을 이해할 수 없으면
   `update_deferred_unknown_session_state`로 보류한다. 이후 명령은 반환된 `script` 경로로 실행한다. Codex
   업데이트가 이 스킬을 불러온 설치 디렉터리를 삭제할 수 있기 때문이다. 모든 경고를 보고한다.
   - `unreleased_same_version`: 버전이 바뀌지 않아 Claude Code가 설치본을 유지한다. 이 파일이 Claude Code에
     반영되려면 버전을 올려야 한다고 알린다.
   - `codex_hooks_need_trust`: 훅 정의가 바뀌었다. Codex가 신뢰하지 않은 훅을 건너뛰므로 Codex `/hooks`에서
     플러그인 훅을 신뢰하도록 요청한다.
   - `unreleased_check_unavailable`: Claude Code가 같은 버전의 파일을 놓쳤는지 확인할 수 없다. 이유를 알린다.
3. **세션에 적용한다.** 호스트 업데이트가 성공했거나 `apply-installed` 결과에 오류가 없으면
   `python3 <script> apply --run-id <run_id> --json`을 셸 제한 시간 600초 이상으로 포그라운드에서 실행한다.
   스크립트는 240초 동안 바쁜 세션이 한가해지길 기다리고, 입력 줄이 비어 있는 세션에만 명령을 보낸다.
   그 뒤에는 새 명령을 보내지 않고 이미 보낸 명령의 결과를 최대 5분 더 확인한다. `already_running` 오류는
   다른 실행이 아직 명령을 보내고 있다는 뜻이다. 끝날 때까지 기다린 뒤 `apply`를 다시 실행한다. 업데이트에
   실패한 호스트는 계속 차단하고, 성공한 호스트는 진행할 수 있다.
4. **모든 세션 결과를 보고한다.** 터미널 접미사, 호스트, 작업 트리, 상태, 완료한 작업, 세부 내용을 표시한다.
   - `done`: 필요한 작업이 모두 확인됐다. `already_current`는 할 일이 없었다는 뜻이다.
     `fresh_session_loads_on_first_turn`은 턴을 진행하지 않은 Codex 세션을 나타낸다.
     `empty_session_cleared`는 비어 있는 Claude Code 세션에 `/clear`를 보냈다는 뜻이다.
     `instructions_load_on_next_turn`은 compact된 Codex 세션이 다음 턴에 지침을 불러온다는 뜻이다.
   - `skipped`: 세션이 계속 바빴거나, 보내지 않은 입력이 남았거나, 입력 줄을 읽을 수 없거나, 보내기 직전에
     입력이 바뀌었거나, 제한 시간에 도달했거나, 세션이 닫혔다.
   - `failed`: 보낸 작업이 확인되지 않았거나 Claude Code가 거부했다. `--force`를 요청하는 reload 거부는
     플러그인의 MCP 도구가 바뀌었다는 뜻이다. 사용자 승인 없이 강제로 진행하지 않는다.
     `compact_needs_more_messages`는 대화가 너무 짧아 compact할 수 없다는 뜻이다. 다음 compact 또는 재시작 때
     지침이 갱신된다. `probe_interrupted_check_input`은 스크립트가 입력 줄을 확인하는 동안 사용자가 입력했다는
     뜻이다. 스크립트는 직접 입력하지 않은 내용을 지우지 않으므로, 해당 세션 입력 줄에 불필요한 `x`가 있는지
     확인하라고 알린다. `helper_start_failed`는 이 세션의 후속 작업을 시작하지 못했다는 뜻이다. `apply`를
     다시 실행한다.
   - `blocked`: 해당 호스트의 플러그인 업데이트가 실패했거나 설치 manifest, 훅 대상, 지침 digest가 검증되지
     않았다.
   - `queued_after_turn`: 이 스킬이 실행 중인 세션이다. 5단계를 따른다.
5. **현재 세션은 마지막에 마친다.** 이 스킬이 실행 중인 세션에 작업이 필요하면 `apply`는 분리된 도우미에
   맡기고 `queued_after_turn`을 반환한다. 결과를 바로 알린 뒤 턴을 끝낸다. 도우미는 이 세션이 한가해질 때까지
   기다리고 작업을 적용한 다음 `python3 <script> status --run-id <run_id> --json`을 실행하라는 프롬프트를
   보낸다. 그 프롬프트가 오면 명령을 실행하고 결과를 보고한다. 상태의 `self_notification`이 `sent`가 아니면
   프롬프트를 전달하지 못한 것이다. 그래도 상태에 작업 결과가 남아 있다.

사용자가 명시적으로 요청한 경우에만 `--compact always` 또는 `--compact never`를 전달한다. Orca 터미널에
명령을 직접 보내거나 세션을 종료·재시작하지 않는다. 스스로 `--force`를 전달하지 않는다.

## 안전과 한계

- `--offline`이 명시되어 있고 호출자에게 활성 코딩 에이전트, 플러그인, Orca 터미널 환경이 없을 때만
  `update`가 마켓플레이스나 설치 명령을 실행한다. `CLAUDECODE`, `CODEX_THREAD_ID`, `CODEX_SESSION_ID` 같은
  호스트 표식, 플러그인 root 변수, `ORCA_TERMINAL_HANDLE`은 활성 신호로 본다. 연결된 코딩 에이전트 터미널은
  입력을 기다리는 중이어도 활성 상태다.
- `--offline`은 영향을 받는 코딩 에이전트 세션이 끝났다는 확인이지 우회 수단이 아니다. 활성 환경 신호나
  읽을 수 있는 Orca 인벤토리의 연결된 코딩 에이전트 터미널이 있으면 업데이트를 보류한다. Orca가 설치돼도
  인벤토리 전체를 읽을 수 없으면 상태를 알 수 없다고 보고 보류한다. Orca CLI가 없으면 명시적인 오프라인
  확인과 활성 환경 부재를 근거로 진행할 수 있다.
- 설치 성공을 보고하기 전에 호스트 manifest와 버전, 각 필수 훅 대상, 지침 digest를 확인한다. 한 호스트가
  실패해도 다른 호스트의 성공 결과는 유지하며, 실패 호스트는 계속 차단한다.
- 명령은 연결되고 쓰기가 가능하며, 입력이 비어 있고, 유휴 상태인 터미널에만 보낸다. 확인과 전송 사이의
  짧은 경쟁 조건은 남아 있다.
- Orca는 Claude Code 입력 줄을 화면에 표시하지 않고 초안으로 제공한다. 이 초안에는 회색 안내 문구도
  포함될 수 있다. 초안이 5초 동안 바뀌지 않으면 스크립트는 문자 하나를 입력한다. 초안이 그 문자 하나와
  정확히 같을 때만 삭제한다. 안내 문구는 교체되고 직접 입력한 내용은 이어 붙지만, 둘 다 원래 상태로
  돌아온다. 입력 중인 세션은 건너뛰고 명령을 보내지 않는다. 스크립트는 각 명령을 보내기 직전에 초안을
  다시 확인한다.
- `/clear`는 Claude Code가 compact를 거부하고, 보내기 직전에 다시 읽은 대화 기록에 프롬프트가 없을 때만
  실행한다.
- 각 결과는 전송 뒤 추가된 대화 기록이나 전송 뒤 다시 쓴 표식으로 확인한다. 대화 기록을 이용할 수 없을
  때만 화면을 확인한다.
- 이 세션의 분리된 도우미를 포함해 명령을 보내는 모든 프로세스는 잠금 하나를 공유한다.
- `/compact`는 대화를 요약하므로 지침이 오래된 세션에만 실행한다.
- compact된 Codex 세션은 다음 턴에서 새 지침을 불러오며 결과에도 이 내용을 표시한다.
- Orca가 관리하는 터미널만 다룬다. Orca 외부 세션이 끝났다는 확인은 사용자가 제공해야 한다. 인벤토리만으로
  세션 종료를 입증할 수 없다.
- 이 작업 흐름 밖에서 직접 업데이트하거나 다른 프로세스가 로드된 플러그인 디렉터리를 삭제하는 상황은
  이 스킬이 막을 수 없다.
- 실행 상태는 `~/.local/state/hei5enbug-agent-setup/orca-plugin-refresh/`에 저장한다. `XDG_STATE_HOME`이
  설정되면 그 경로를 사용한다. 표식은 Orca 사용자 데이터 디렉터리에 저장한다. 둘 다 프롬프트나 대화 기록을
  저장하지 않는다.
