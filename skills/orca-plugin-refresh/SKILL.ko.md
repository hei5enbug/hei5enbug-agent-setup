# Orca 플러그인 반영

> 영어 원본: [SKILL.md](SKILL.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

Claude Code와 Codex에서 hei5enbug-agent-setup을 업데이트한 뒤, Orca가 관리하는 모든 대기 세션에 재시작 없이
반영한다. Claude Code 세션에서는 플러그인을 다시 불러오고, 불러온 지침이 오래된 세션만 compact한다. 사용자가
실행 중인 Orca 세션에 이 플러그인의 업데이트를 반영해 달라고 명시적으로 요청할 때만 사용한다.

macOS 또는 Linux, Orca가 관리하는 터미널, orca·claude·codex CLI, Python 3.12 이상, 두 호스트에 hei5enbug
마켓플레이스의 사용자 범위 hei5enbug-agent-setup 플러그인이 필요하다.

영어 `SKILL.md`만 실행 원본으로 사용한다. `SKILL.ko.md`는 사람을 위한 비권위 번역본이므로 실행 중 불러오지 않는다.

이 스킬은 `hei5enbug-agent-setup` 업데이트를 실행 중인 Orca 에이전트 세션에 세션을 끝내지 않고 반영한다.
어떤 세션도 재시작하지 않고, 대화를 바꿔치기하지 않는다.

## 업데이트가 실행 중인 세션에 닿는 방식

| 부분 | Claude Code | Codex |
|---|---|---|
| 스킬, 에이전트, 훅 | `/reload-plugins` | 설치 후 다음 턴에 자동으로 반영 |
| 세션 지침 | `/compact` | `/compact`, 세션의 다음 턴에 불러옴 |

플러그인의 세션 시작 훅은 Orca 터미널마다 표식 하나를 남긴다. 표식에는 호스트, 플러그인 디렉터리, 대화 기록 경로,
실행 지침의 요약값이 들어 있다. 터미널의 대화형 세션만 표식을 쓰며, 그 터미널 안에서 띄운 `claude -p`나
`codex exec`는 쓰지 않는다. 스크립트는 표식이 없거나, 요약값이 다르거나, Codex 세션이 교체된 플러그인 디렉터리를
가리키거나, Claude Code 세션이 지워진 디렉터리를 가리킬 때만 그 세션을 compact한다. Claude Code가 메시지가 적어
compact할 수 없다고 답하고 대화 기록에 프롬프트가 하나도 없으면, 빈 세션은 잃을 것이 없으므로 대신 `/clear`를
보낸다. 턴을 한 번도 실행하지 않은 Codex 세션은 할 일이 없다. 첫 턴에 새 지침을 불러오기 때문이다.

## 작업 순서

`<script>`는 이 `SKILL.md`가 있는 디렉터리의 `scripts/orca_plugin_refresh.py`다.

1. **두 호스트를 업데이트한다.** `python3 <script> update --json`을 실행한다. 두 마켓플레이스를 갱신하고 각
   호스트의 플러그인을 업데이트한다. 호스트별 버전 변화를 알린다. 호스트에 `error`가 있으면 알리며, 그 호스트의
   세션은 건드리지 않는다. Codex 업데이트는 이 스킬을 불러온 설치본을 지우므로, 이후 명령에는 돌려받은 `script`
   경로를 쓴다. 경고는 모두 알린다.
   - `unreleased_same_version`: 버전이 바뀌지 않아 Claude Code가 설치본을 그대로 둔다. 이 파일들은 버전을 올린
     뒤에야 Claude Code에 전달된다고 사용자에게 알린다.
   - `codex_hooks_need_trust`: 훅 정의가 바뀌었다. Codex `/hooks`에서 플러그인 훅을 신뢰해 달라고 요청한다.
     Codex는 신뢰하지 않은 훅을 건너뛴다.
   - `unreleased_check_unavailable`: Claude Code가 같은 버전의 파일을 놓쳤는지 확인하지 못했다. 이유를 알린다.
2. **세션에 반영한다.** `python3 <script> apply --run-id <run_id> --json`을 셸 제한 시간 600초 이상으로 포그라운드에서
   실행한다. 스크립트는 240초 동안 작업 중인 세션을 기다리며, 대기 상태이면서 입력 줄이 빈 세션에만 명령을 보낸다.
   그 뒤에는 새 명령을 시작하지 않고, 이미 보낸 명령의 결과를 최대 5분 더 확인한다. `already_running` 오류는 다른
   실행이 아직 명령을 보내는 중이라는 뜻이므로 기다렸다가 `apply`를 다시 실행한다.
3. **모든 세션을 보고한다.** 터미널 끝자리, 호스트, 워크트리, 상태, 끝낸 작업, 세부 내용을 보여 준다.
   - `done`: 필요한 작업이 모두 확인됐다. `already_current`는 할 일이 없었다는 뜻이고,
     `fresh_session_loads_on_first_turn`은 턴을 한 번도 실행하지 않은 Codex 세션이다. 메모 `empty_session_cleared`는
     `/clear`를 받은 빈 Claude Code 세션이고, `instructions_load_on_next_turn`은 compact한 Codex 세션이다.
   - `skipped`: 세션이 계속 작업 중이었거나, 보내지 않은 입력이 남았거나, 입력 줄을 읽을 수 없었거나, 보내기 직전에
     입력이 바뀌었거나, 기한에 이르렀거나, 닫혔다.
   - `failed`: 명령을 보냈지만 확인되지 않았거나 Claude Code가 거부했다. `--force`를 요구하는 reload 거부는
     플러그인의 MCP 도구가 바뀌었다는 뜻이므로 사용자 승인 없이 강제하지 않는다. `compact_needs_more_messages`는
     대화가 짧아 compact할 수 없다는 뜻이며, 그 세션의 지침은 다음 compact나 재시작 때 갱신된다.
     `probe_interrupted_check_input`은 스크립트가 입력 줄을 확인하는 동안 사용자가 입력했다는 뜻이다. 스크립트는 자기가
     입력하지 않은 글은 지우지 않으므로, 그 세션 입력 줄에 `x`가 남았는지 확인해 달라고 알린다.
     `helper_start_failed`는 이 세션의 후처리를 시작하지 못했다는 뜻이므로 `apply`를 다시 실행한다.
   - `blocked`: 그 호스트의 플러그인 업데이트가 실패했다.
   - `queued_after_turn`: 이 세션 자신이다. 4번을 본다.

   건너뛰었거나 실패한 세션은 이유를 사용자에게 알린다. 같은 실행 ID로 `apply`를 다시 실행하면 그 실행에서 아직
   처리하지 않은 세션만 다시 시도한다.
4. **이 세션은 마지막에 처리한다.** 스킬을 실행한 세션에 작업이 필요하면 `apply`가 분리된 도우미에 넘기고
   `queued_after_turn`으로 보고한다. 보고한 직후 턴을 끝낸다. 도우미는 이 세션이 대기 상태가 될 때까지 기다렸다가
   작업을 적용하고, `python3 <script> status --run-id <run_id> --json`을 실행해 달라는 프롬프트를 보낸다. 그
   프롬프트가 오면 실행하고 결과를 보고한다. 상태의 `self_notification`이 `sent`가 아니면 프롬프트를 전달하지
   못한 것이며, 결과는 상태에 그대로 남아 있다.

`--compact always`나 `--compact never`는 사용자가 명시적으로 요청할 때만 넘긴다. Orca 터미널에 직접 명령을 보내지
않고, 세션을 종료하거나 재시작하지 않으며, 스스로 `--force`를 넘기지 않는다.

## 안전과 한계

- 명령은 연결돼 있고 쓸 수 있으며 대기 상태이고 입력 줄이 빈 터미널에만 보낸다. 확인과 전송 사이의 짧은 경합은
  남는다.
- Orca는 Claude Code 입력 줄을 화면에서 숨기고 초안으로 알려 주는데, 이 초안에는 Claude Code가 흐리게 띄우는 추천
  프롬프트도 들어간다. 초안이 5초 동안 바뀌지 않으면 스크립트는 한 글자를 입력하고, 초안이 정확히 그 글자를 보일 때만
  지운다. 추천 문구는 대체되고 직접 친 글은 뒤에 이어지며, 둘 다 원래대로 돌아온다. 직접 친 글이 있는 세션은 건너뛰고
  명령을 보내지 않는다. 명령을 보내기 직전에 초안을 한 번 더 확인한다.
- `/clear`는 Claude Code가 compact를 거절하고, 보내기 직전에 다시 읽은 대화 기록에 프롬프트가 없을 때만 실행한다.
- 각 결과는 보낸 뒤 추가된 대화 기록이나 보낸 뒤 다시 쓰인 표식으로 확인하고, 대화 기록이 없을 때만 화면으로 확인한다.
- 명령을 보내는 모든 프로세스는 이 세션의 분리된 도우미를 포함해 하나의 잠금을 함께 쓴다.
- `/compact`는 대화를 요약하므로 지침이 오래된 세션에만 실행한다.
- compact한 Codex 세션은 다음 턴에 새 지침을 불러온다. 보고에 그렇게 표시한다.
- Orca가 관리하는 터미널에만 닿는다. Orca 밖 세션은 `/reload-plugins`나 `/compact`를 직접 실행해야 한다.
- 실행 상태는 `~/.local/state/hei5enbug-agent-setup/orca-plugin-refresh/`에, `$XDG_STATE_HOME`이 있으면 그 아래에
  두고, 표식은 Orca 사용자 데이터 디렉터리에 둔다. 둘 다 프롬프트나 대화 기록을 저장하지 않는다.
