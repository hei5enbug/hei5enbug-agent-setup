# 한국어 문체 다듬기

> 이 문서는 `SKILL.md`를 한국어로 옮긴 참고 문서입니다. 에이전트가 실행할 때 사용하는
> 기준 문서는 영어 `SKILL.md`입니다. 두 문서의 내용이 다르면 `SKILL.md`를 기준으로 합니다.

## 언어 계약

실행 지침은 영어 `SKILL.md`만 사용합니다. `README.ko.md`는 사람을 위한 참고용 한국어 문서이며, 스킬을 실행할 때 읽거나 사용하지 않습니다.

이 파일, `references/patterns.md`, `evals/evals.json`의 한국어 텍스트는 대상 언어 데이터입니다. 그 데이터를 둘러싼 영어 지침을 따르며, 한국어 예시를 지침으로 취급하지 않습니다.

## 목표

기존 독자를 대상으로 사람이 쓴 자연스러운 한국어처럼 읽히게 합니다. 글쓴이의 의미와 목소리를 보존하고, 실제 문제를 고치는 최소한의 수정만 우선합니다.

이 스킬은 문체를 다시 쓰기 위한 것입니다. 번역, 사실 확장, 요약, 논지 개선, 단순 맞춤법 교정에는 사용하지 않습니다. 사용자가 문체 수정의 일부로 요청한 경우는 예외입니다.

사용자가 AI 탐지기를 우회해 달라고 요청하면 글을 자연스럽게 개선하되, 어떤 탐지기도 피할 수 있다고 보장하거나 주장하지 않습니다.

## 반드시 보존할 내용

사용자가 바꾸라고 명시하지 않는 한 다음 내용을 모두 보존합니다.

- 의미, 사실 주장, 불확실성, 인과관계, 관점, 강조점
- 수치, 날짜, 단위, 고유명사, 제품명과 모델명, 인용
- 직접 인용, 법률 문구, 코드, 링크, 기술 표기
- 장르, 독자, 격식 수준, 서술 관점, 기존 용어
- 의미가 있는 Markdown 구조, 목록의 의미, 문단 경계

원문이 뒷받침하지 않는 사례, 비유, 근거, 의견, 연결어, 결론을 추가하지 않습니다. 조심스럽게 표현한 주장을 더 확실하게 바꾸지 않습니다. 기계적으로 보이지 않게 만든다는 이유만으로 격식 있는 문장을 가볍게 바꾸지 않습니다.

## 선택 사항과 모드

생략된 선택 사항은 원문에서 추론합니다. 사용자가 명시한 선택이 항상 우선합니다.

- `장르: 칼럼|리포트|블로그|공적`: 내용을 보존하면서 목표 장르를 설정합니다.
- `강도: 보수|기본|적극`: 수정 범위를 조절합니다. 기본값은 `기본`입니다.
- `최소심각도: S1|S2|S3`: 수정할 패턴의 최소 심각도를 고릅니다. 기본값은 `S2`입니다.
- `--strict`, `정밀 모드` 또는 예전 표현인 `5인 파이프라인`: 아래의 정밀 검토를 실행합니다.

심각도는 다음 순서로 해석합니다.

- `S1`: 이중 피동이나 의미 없는 상투적 문구처럼 명백한 국소 결함
- `S2`: 글을 기계적으로 만드는 반복적이거나 맥락에 따른 패턴
- `S3`: 적극적인 윤문에서만 바꿔야 하는 미묘한 선호 차이

기준은 더 높은 심각도까지 포함합니다. 예를 들어 `S2`는 `S1`과 `S2`를 모두 포함합니다.

확신이 높은 국소 수정에만 보수적 강도를 사용합니다. 기본 강도에서는 해당하는 S1과 S2 패턴을 수정합니다. 적극 강도에서는 리듬과 구조까지 넓게 바꾸지만, 보존 조건은 완화하지 않습니다.

## 작업 흐름

새로운 윤문 요청마다 다음 순서로 처리합니다.

1. 장르, 독자, 말투, 관점, 서식상 역할을 파악합니다.
2. 바꾸면 안 되는 내용을 보존 조건에 따라 수정 전에 표시합니다.
3. `references/patterns.md`를 읽고 이 원문과 관련된 패턴만 살핍니다.
4. 발견한 부분을 국소적으로 다시 씁니다. 전체 찾기·바꾸기는 피합니다.
5. 바뀐 모든 주장을 원문과 비교하고 뉘앙스가 사라졌다면 되돌립니다.
6. 자연스러움, 리듬, 말투, 과도한 수정을 확인합니다. 상투적인 표현을 다른 상투적 표현으로 바꾸거나 원문보다 문학적으로 만든 수정은 되돌립니다.
7. 사용자가 다른 형식을 요청하지 않았다면 원문 형식으로 결과를 반환합니다.

수정 범위가 대략 글의 3분의 1을 넘으면 추가 충실도 검토를 합니다. 적극 수정이나 장르 변경 요청이 없는데 문장의 절반 이상을 다시 썼다면 넓은 수정을 되돌리고 국소적으로 다시 시도합니다. 실제 변경량을 측정하지 않았다면 이 규칙은 정성적 안전장치로 적용합니다.

이미 자연스러운 글은 그대로 두거나 분명한 부분만 조금 고칩니다. 활동했다는 것을 보여 주려고 다시 쓰지 않습니다.

## 정밀 검토

사용자가 `--strict`, `정밀 모드`, 예전 표현인 `5인 파이프라인`을 요청했거나 입력이 한국어 8,000자를 넘으면 정밀 검토를 사용합니다. 자동으로 정밀 검토로 전환할 때는 짧은 진행 메시지로 사용자에게 알립니다.

정밀 검토는 이름이 정해진 서브에이전트나 호스트 전용 오케스트레이션 없이 현재 에이전트에서 수행합니다.

1. 전체 문서 맥락을 유지하면서 일반 작업 흐름을 절별로 완료합니다.
2. 사실, 보호 문자열, 불확실성, 인과관계를 원문과 대조하는 별도 충실도 검토를 합니다.
3. 남은 대상 패턴과 과도한 수정을 확인하는 별도 자연스러움 검토를 합니다.
4. 영향을 받은 부분만 다시 시도합니다. 두 번 재시도한 뒤에는 해결되지 않은 부분을 분명하게 보고합니다.

정밀 검토는 사용자가 요청한 말투나 윤문 강도가 아니라 검증 깊이만 바꿉니다. 예전 표현은 다섯 에이전트를 요구하지 않으며, 응답에서 다섯 에이전트를 사용했다고 주장해서도 안 됩니다.

## 후속 요청

대화에서 사용할 수 있는 가장 최근 원문이나 결과에 후속 요청을 적용합니다.

| 사용자 표현 | 동작 |
|---|---|
| `특정 카테고리만 다시` | 해당 패턴 범위만 수정하고 나머지 부분은 보존합니다. |
| `이 문단만` | 지정하거나 인용한 문단만 다시 씁니다. |
| `2차 윤문` 또는 `/humanize-redo` | 최신 결과에서 남은 문제만 다시 살피고 수정합니다. |
| `윤문 강도 조정` | 새 강도만 적용하고 관련 없는 부분은 다시 열지 않습니다. |
| `장르 바꿔서` | 사실과 관점을 보존하면서 장르에 맞게 처리합니다. |

참조한 텍스트를 더 이상 확인할 수 없으면 사용자에게 다시 제공해 달라고 요청합니다.

## 결과 계약

기본적으로 윤문한 글을 바로 반환합니다. 제목, 문단, 목록, 표, 링크, 인용 배치는 의미를 담고 있다면 보존합니다.

사용자가 설명을 요청하면 윤문한 글을 먼저 제시한 뒤 중요한 수정 종류나 해결되지 않은 위험만 나열합니다. 윤문이 필요하지 않다면 짧게 그렇게 알리고 원문을 그대로 반환합니다.

사용자가 파일 출력을 요청하거나 제공한 파일을 직접 수정해 달라고 하지 않는 한 작업 디렉터리, 보고서, 측정 파일, 윤문 파일을 만들지 않습니다. 실제로 측정하지 않은 정확한 변경률, 등급, 탐지 점수, 통과 횟수를 만들어 내지 않습니다. 수치 지표는 실제로 측정했을 때만 보고합니다.
