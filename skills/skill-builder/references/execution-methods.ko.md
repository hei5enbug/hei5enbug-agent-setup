# 실행 방식

> 영어 원본: [execution-methods.md](execution-methods.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

출력 품질과 측정한 전체 비용으로 프롬프트 실행, 기존 도구 또는 포함 스크립트를 선택한다.
Skill Builder 자체와 그 스킬로 만든 스킬을 개선할 때 적용하며 정상 실행에서는 선택한 방식을 반복 시험하지 않는다.

## 결정과 비교 범위

의미, 의도, 모호함과 품질은 처음부터 모델이 판단한다. 정확한 계산, 파싱, 스키마 검사와 파일 변환은
기존 도구에 맡긴다. 혼합 작업은 정확한 동작과 문맥 판단으로 나눈다. 프롬프트를 반복 실행하는 orchestration
스크립트는 결정적 판단이 아니라 모델 보조 방식이다.

파일과 텍스트에는 호스트 검색을, 문법 인식 질의에만 구조 검색을 사용한다. `fd`, `rg`, `ast-grep`은 예시이며
필수 의존성이 아니다. 기능과 설치 위치를 확인한다.

스크립트를 추가하기 전에 지원 입력, 출력, 성공, 실패와 미지원 사례를 정의한다. 기존 도구와 단순 조합을
먼저 비교하고 재사용이나 신뢰성 이점이 개발, 테스트, 의존성과 유지보수를 정당화할 때만 추가한다.
구현 언어나 모델 이름에서 속도, 정확성 또는 비용 절감을 추론하지 않는다.

실행 선택이 불확실하거나 방식이 바뀌거나 최적화가 로딩 지침이나 작업을 바꾸면 paired comparison을 한다.
동작이 같은 작은 문구 수정은 직접 검토한다. 문맥 판단에 일부러 열등한 스크립트 대안을 만들지 않는다.
한 방식만 계약을 만족하면 이유를 기록하고 측정 우위를 주장하지 않는다.

## 평가 모델 adapter

이 설정은 Skill Builder의 시험 실행과 기타 비검토 참여자, 읽기 전용 검토 역할에 적용한다. 메인 세션의 모델과
사고 강도는 바꾸지 않는다. 메인 세션이 작업 정의와 rubric을 맡고, 같은 자료를 한 번 직접 검토해 최종 판단한다.

시작하기 전에 각 작업자를 목적과 결과 위치로 분류한다.

| 작업자 목적 | 결과 위치 | 역할 |
|---|---|---|
| 개발 중인 실제 스킬 초안 작성이나 수정 | 스킬이 있는 저장소나 작업 트리 | 구현 |
| 채점용 임시 시험 아티팩트 생성 | 평가 작업 공간 | 시험 실행 |
| 시험 아티팩트를 실제 스킬에 반영 | 스킬이 있는 저장소나 작업 트리 | 구현 |
| 시험 실행과 조사·최적화 같은 기타 비검토 작업 | 평가 작업 공간이나 인라인 결과 | 비검토 참여자 |
| 검토 페르소나, 채점, 비교 또는 분석 | 평가 작업 공간이나 인라인 결과 | 읽기 전용 검토 |

호스트 세션 지침에 구현 실행 규칙이 있으면 구현 작업자는 아래 표 대신 그 규칙을 따른다. 그렇지 않으면 단독 사용처럼
구현을 포함한 모든 작업자에 아래 표를 적용한다. 평가 참여자는 아래 모델 어댑터를 사용한다. Skill Builder의 검토와
참여자 계약은 일반 호스트 스킬 작업자 라우팅과 대상 스킬 메타데이터보다 우선한다.

스킬이 맡긴 검토 페르소나, grader, comparator, analyzer 같은 검토 역할은 읽기 전용 판단
작업이다. 근거를 인용해 검토 결과만 반환한다. 파일을 쓰지 않고 에이전트 파일이 정한 JSON을 반환하며, 메인 세션이
그 JSON을 에이전트 파일이 지정한 경로에 저장한다. 먼저 호스트의 스킬 작업자 지침에 따라 다른 모델 계열을 사용한다.
해당 CLI가 없거나 인증되지 않았거나 사용량 제한에 걸리거나 지정 모델을 시작하지 못하거나 시간 초과되거나 모델 근거가
없으면 아래 `reviewer` 대체 경로를 사용하고 대체 사실을 한 번 보고한다. 메인 세션은 같은 자료를 한 번 직접
검토해 최종 판단한다. 추가 검토는 하지 않는다.

| 실행 호스트 | 시험 실행 및 기타 비검토 참여자 | 사고 강도 | 검토 경로 |
|---|---|---|---|
| Codex | `gpt-6.1-sol` | `xhigh` | `claude -p`와 `claude-opus-5-5`, `high`; 대체는 `gpt-6.1-sol`, `xhigh` `reviewer` |
| Claude Code | `claude-opus-5-5` | `high` | `codex exec`와 `gpt-6.1-sol`, `xhigh`; 대체는 `claude-opus-5-5`, `high` `reviewer` |
| 다른 호스트 | 사용 가능한 상위 모델 | 적합한 최고 지원 강도 | 검증된 교차 계열 검토 경로와 문서화된 대체를 사용한다. 없으면 검토를 사용할 수 없다고 표시한다. |

시험 실행과 기타 비검토 참여자는 호스트 모델 계열의 상위 모델을 사용한다. 검토 역할에는 다른 계열을 쓴다.
검토 역할을 `scout`에 맡기거나 `reviewer`가 시험 출력을 쓰게 하거나 필요한 사고 강도를 낮추지 않는다. runner 호출만으로
실제 설정이 확인되지는 않는다.

시험 출력 작성자는 호스트 어댑터에 고정된 모델과 사고 강도를 사용한다. 결과는 평가 작업 공간에 둔다. 메인 세션이 스킬의
승인 절차로 선택하기 전에는 시험 출력을 반영하지 않는다. 모든 참여자의 실제 모델과 사고 강도를 기록한다. 필수 설정을
확인할 수 없으면 해당 실행을 미검증으로 표시하고, 조용히 다른 모델로 바꾸거나 사고 강도를 낮추지 않는다.

일반적인 실행 방식 비교에서는 양쪽 모델과 사고 강도를 고정한다. 구체적으로 승인된 모델 또는 사고 강도 실험만 임시 평가
작업 공간에서 미리 정한 후보 설정 하나를 바꿀 수 있다. 운영 설정을 바꾸거나 시험 결과를 저장소에 반영해서는 안 된다.

## 짝지은 시험

플러그인 세션 규칙이 적용되면 모델 시험 전에 [작업 효율](../../../instructions/work-efficiency.ko.md#모델-평가)을 읽는다.
이 참조가 공통 묶음 상한, 사전 점검, 이어서 실행, 중단 규칙을 관리한다.
필수 참조를 사용할 수 없으면 해당 평가를 중단한다. 독립 사용에서는 아래 절차를 유지한다.

1. 작업, 품질 조건, 입력, 출력 계약과 현재 스킬 snapshot을 고정한다. 정확성, 완전성, 예외와 사용자 비용
   한도를 포함한다. 처음에는 경계 사례를 포함한 대표 사례 2개에서 3개로 시험 예산을 정한다.
2. 별도 출력과 컨텍스트에서 같은 입력으로 두 방식을 실행한다. 방식 비교는 방식만, 이전·새 비교는 스킬
   버전만 바꾼다. 프롬프트 실행은 아티팩트를 만들고 도구 실행은 실제 도구를 실행해야 한다.
3. 승인된 격리 작업자가 있으면 사용하고 아니면 순서대로 실행해 독립성 저하를 밝힌다. 상대 출력이나 예상
   판정을 보여 주지 않고 파일·제한 자원을 공유하는 실행을 동시에 하지 않는다.
4. 메인 세션이 실제 출력을 고정 조건과 비교한다. 정확한 조건만 도구로 검사하고 의미 품질은 아티팩트와
   근거로 판단한다. 평균뿐 아니라 경계 사례와 개별 실패를 본다.
5. 판정, 시간 또는 토큰 변동이 선택을 바꿀 만큼 크면 영향받은 쌍을 반복한다. 예산에서 멈추고 불확실한
   결과를 보고한다. 같은 질문에 답하는 이전 시험을 재사용한다.

## 측정과 결정

원본 입력, 프롬프트나 명령, 출력과 실제 모델·도구 설정을 시험 기록과 함께 보존한다.
반복 실행 비용과 개발·평가 부담을 나눈다.

| 측정 | 기록 |
|---|---|
| 품질 | 완료 조건별 근거와 기준 대비 회귀 |
| 실행 시간 | 읽기, 시작, 도구, 재시도를 포함해 작업 시작부터 사용할 수 있는 아티팩트까지의 경과 시간 |
| 모델 토큰 | 부모, 작업자, 재시도 전체에서 호스트가 보고한 입력·출력과 그 밖의 토큰 범주 |
| 개발 비용 | 반복 실행과 분리한 작성, 디버깅, 설정, 테스트의 관찰 시간·토큰 |
| 평가 부담 | 측정 대상 작업과 분리한 시험 설정, 채점, 비교 비용 |

호스트가 보고한 지표나 측정한 timestamp를 사용하고, 문자 수를 토큰 대신 쓰지 않는다.
겹치지 않는 사용량 기록만 합치고, 부모 합계에 이미 포함된 작업자 사용량을 다시 더하지 않는다.
빠졌거나 일부만 집계된 합계는 0이 아니라 없음 또는 불완전으로 표시한다.
금액은 제공되었거나 확인된 요율과 토큰 범주로 계산한다. 토큰 수만으로는 가격이 되지 않는다.
토큰 합계만으로 서로 다른 모델의 비용이 더 낮다고 주장하지 않는다.

필수 품질 조건을 만족하지 못하거나 중요한 품질 회귀를 만드는 방식은 제외한다.
통과한 방식끼리는 사용자 한도 안에서 전체 실행 시간과 토큰을 비교한다.
하나를 개선하면서 다른 하나를 관찰된 변동 이상으로 악화시키지 않는 방식을 선호한다.
토큰을 아끼지만 더 느린 방식은 명시적인 사용자 선호나 기존 지연 예산으로 그 교환을 정당화한다.
그렇지 않으면 기준 방식을 유지하고 장단점을 보고한다.
둘 다 실패하면 품질 조건을 낮춰 승자를 고르지 말고 방식이나 지침을 고친다.
측정이 빠졌거나 시험이 결정적이지 않으면 실제로 확인한 범위로만 주장한다.
측정하지 않은 비용 절감은 후보로 제시하고, 비교가 채택을 뒷받침할 때까지 기준 방식을 기본으로 유지한다.

평가 작업 공간에 간결한 `method-comparison.md`를 저장하거나 같은 내용을 답변에 그대로 제시한다.

- 작업, 고정한 조건, 사례, 설정, 시험 예산, 근거 경로
- 사례별 품질 판정, 실행 시간, 토큰 집계 범위, 재시도, 개발·평가 비용 구분
- 선택한 방식, 이유, 전환 조건, 검증하지 못한 주장, 남은 제한

전체 평가 절차를 실행할 때는 기존 `grading.json`과 `timing.json` 형식을 사용한다.
두 파일을 쓰기 전에 이 디렉터리의 `schemas.md`를 읽는다.
기존 benchmark 아티팩트의 스킬·기준 설정 이름에 방식 이름을 겹쳐 쓰지 않는다.
방식 라벨과 추가 비용 분해는 `method-comparison.md`에 둔다.

## 결과 적용

선택한 방식과 전환 조건을 대상 스킬에 간결하게 쓴다. 시험 기록과 측정은 매번 읽는 지침 밖에 둔다.
불필요한 참조 읽기, 도구 출력, 모델 호출과 중복 검사를 확인하되 입력이 바뀔 수 있는 검사와 요구사항,
예외, 품질을 보존한다. 원본이 같을 때만 파싱 결과를 재사용하며 무조건 한 번만 읽으라는 규칙으로 바꾸지 않는다.
동작을 바꾸는 절감은 같은 사례와 조건으로 원본에 대해 검증한다. 정상 실행에서 Skill Builder나 benchmark를
요구하지 않으며 요구사항, 입력, 도구 또는 모델 동작이 기록된 선택을 무효화할 때만 승인된 개선에서 다시 비교한다.

## 스킬별 평가 설정 우선순위

Skill Builder 평가 참여자는 항상 위 표의 모델과 사고 강도를 사용한다. Skill Builder 평가 계약은 일반 호스트의
스킬 작업자 라우팅보다 우선한다. 대상 스킬의 메타데이터나 frontmatter로 평가자 설정을 낮추지 않는다. 실제
설정이 표와 일치할 때만 기본 역할을 실행한다. 일치하는 역할이 없으면 실제 모델과 사고 강도를 검증할 수 있는
Skill Builder 승인 runner를 쓰거나 기능 미지원 경로를 따른다. runner 호출만으로 실제 설정을 확인할 수 없다.

일반적인 실행 방법 비교에서는 양쪽 모델과 설정을 고정한다. 구체적으로 승인된 모델 또는 사고 강도 실험만
임시 평가 작업 공간에서 미리 고정한 후보 설정 하나를 바꿀 수 있다. 운영 설정을 바꾸거나 시험 결과를
저장소에 반영해서는 안 된다. 필요한 설정을 확인할 수 없거나 runner를 사용할 수 없으면 해당 실행은 검증되지
않은 것으로 처리하고 다른 설정으로 대체하지 않는다.
