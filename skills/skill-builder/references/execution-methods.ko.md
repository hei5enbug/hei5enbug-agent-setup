# 실행 방식

> 영어 원본: [execution-methods.md](execution-methods.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

출력 품질과 측정한 전체 비용으로 프롬프트 실행, 기존 도구 또는 포함 스크립트를 선택한다.
Skill Builder 자체와 그 스킬로 만든 스킬을 개선할 때 적용하며 정상 실행에서는 선택한 방식을 반복 시험하지 않는다.

## 결정과 비교 범위

의미, 의도, 모호함과 품질은 처음부터 모델이 판단한다. 정확한 계산, 파싱, 스키마 검사와 파일 변환은
기존 도구에 맡긴다. 혼합 작업은 정확한 동작과 문맥 판단으로 나눈다. 프롬프트를 반복 실행하는 orchestration
스크립트는 결정적 판단이 아니라 모델 보조 방식이다.

파일과 텍스트에는 호스트 검색을, 문법 인식 질의에만 구조 검색을 사용한다. `fd`, `rg`, `ast-grep`은 예시이며
필수 의존성이 아니다. 기능과 설치 위치를 확인한다.

스크립트를 추가하기 전에 지원 입력, 출력, 성공, 실패와 미지원 사례를 정의한다. 기존 도구와 단순 조합을
먼저 비교하고 재사용이나 신뢰성 이점이 개발, 테스트, 의존성과 유지보수를 정당화할 때만 추가한다.
구현 언어나 모델 이름에서 속도, 정확성 또는 비용 절감을 추론하지 않는다.

실행 선택이 불확실하거나 방식이 바뀌거나 최적화가 로딩 지침이나 작업을 바꾸면 paired comparison을 한다.
동작이 같은 작은 문구 수정은 직접 검토한다. 문맥 판단에 일부러 열등한 스크립트 대안을 만들지 않는다.
한 방식만 계약을 만족하면 이유를 기록하고 측정 우위를 주장하지 않는다.

## 평가 모델 adapter

Skill Builder가 조사, 초안, 실행, 평가, 비교, 분석 또는 최적화를 위해 시작한 모든 작업자와 runner에 적용한다.
메인 세션 모델은 바꾸지 않으며 메인 세션이 작업 정의, rubric, 검토와 최종 결정을 책임진다.

| 실행 호스트 | 필수 모델 | 필수 사고 강도 | 경계 |
|---|---|---|---|
| Codex | `gpt-5.6-luna` | `xhigh` | Codex에서 Sonnet을 시작하지 않는다. |
| Claude Code | Sonnet 5 | `high` | Claude Code에서 `gpt-5.6-luna`를 시작하지 않는다. |
| 다른 호스트 | 사용 가능한 경량 모델 | 적합한 최고 지원 강도 | 실제 설정을 기록한다. |

두 방식이 모델을 쓰면 같은 모델과 설정을 사용한다. 도구 전용 방식에는 모델이 동작하지 않음을 기록하되
orchestration 모델 비용은 포함한다. 모델 선택기와 사고 강도 제어를 확인하고 ID나 CLI 플래그를 지어내지 않는다.
별칭은 실제 ID를 기록하고 요구 버전인지 확인한다. 모든 작업자와 runner의 실제 모델·강도를 기록한다.
필수 설정을 사용할 수 없으면 대체하거나 낮추지 않고 해당 실행을 미검증으로 표시한다.

## 짝지은 시험

1. 작업, 품질 조건, 입력, 출력 계약과 현재 스킬 snapshot을 고정한다. 정확성, 완전성, 예외와 사용자 비용
   한도를 포함한다. 처음에는 경계 사례를 포함한 대표 사례 2개에서 3개로 시험 예산을 정한다.
2. 별도 출력과 컨텍스트에서 같은 입력으로 두 방식을 실행한다. 방식 비교는 방식만, 이전·새 비교는 스킬
   버전만 바꾼다. 프롬프트 실행은 아티팩트를 만들고 도구 실행은 실제 도구를 실행해야 한다.
3. 승인된 격리 작업자가 있으면 사용하고 아니면 순서대로 실행해 독립성 저하를 밝힌다. 상대 출력이나 예상
   판정을 보여 주지 않고 파일·제한 자원을 공유하는 실행을 동시에 하지 않는다.
4. 메인 세션이 실제 출력을 고정 조건과 비교한다. 정확한 조건만 도구로 검사하고 의미 품질은 아티팩트와
   근거로 판단한다. 평균뿐 아니라 경계 사례와 개별 실패를 본다.
5. 판정, 시간 또는 토큰 변동이 선택을 바꿀 만큼 크면 영향받은 쌍을 반복한다. 예산에서 멈추고 불확실한
   결과를 보고한다. 같은 질문에 답하는 이전 시험을 재사용한다.

## 측정과 결정

원본 입력, 프롬프트나 명령, 출력과 실제 모델·도구 설정을 보존한다. 반복 실행 비용과 개발·평가 비용을 나눈다.

| 측정 | 기록 |
|---|---|
| 품질 | 완료 조건별 근거와 기준 대비 회귀 |
| 실행 시간 | 읽기, 시작, 도구, 재시도를 포함해 사용할 수 있는 아티팩트까지의 경과 시간 |
| 모델 토큰 | 부모, 작업자, 재시도를 포함한 호스트 제공 입력·출력 등 범주 |
| 개발 비용 | 작성, 디버깅, 설정, 테스트의 관찰 시간·토큰 |
| 평가 부담 | 시험 설정, 평가와 비교 비용 |

호스트 지표나 측정 timestamp를 사용하고 문자 수를 토큰으로 바꾸지 않는다. 겹치지 않는 사용량만 합치고
부모 합계에 포함된 작업자를 다시 더하지 않는다. 빠진 값은 0이 아니라 없음 또는 불완전으로 표시한다.
금액은 확인된 요율과 토큰 범주로 계산하며 토큰 합계만으로 다른 모델의 비용을 비교하지 않는다.

필수 품질을 실패하거나 중요한 회귀가 있는 방식은 제외한다. 통과한 방식은 사용자 한도 안에서 시간과 토큰을
비교한다. 하나를 개선하며 다른 하나가 관찰 변동보다 나빠지지 않는 방식을 선호한다. 토큰과 시간이 엇갈리면
명시적인 사용자 선호나 기존 예산이 없을 때 기준을 유지하고 장단점을 알린다. 둘 다 실패하면 품질 조건을
낮추지 않고 방식이나 지침을 고친다. 측정이 없거나 불확실하면 확인한 범위만 주장한다.

평가 작업 공간의 `method-comparison.md`나 답변에 작업, 고정 조건, 사례, 설정, 예산, 근거 경로, 사례별 판정,
시간, 토큰 범위, 재시도, 별도 비용, 선택 방식, 이유, 전환 조건, 미검증 주장과 제한을 기록한다.
전체 평가에서는 `grading.json`, `timing.json` 형식을 사용하고 작성 전에 `schemas.md`를 읽는다.

## 결과 적용

선택한 방식과 전환 조건을 대상 스킬에 간결하게 쓴다. 시험 기록과 측정은 매번 읽는 지침 밖에 둔다.
불필요한 참조 읽기, 도구 출력, 모델 호출과 중복 검사를 확인하되 입력이 바뀔 수 있는 검사와 요구사항,
예외, 품질을 보존한다. 원본이 같을 때만 파싱 결과를 재사용하며 무조건 한 번만 읽으라는 규칙으로 바꾸지 않는다.
동작을 바꾸는 절감은 같은 사례와 조건으로 원본에 대해 검증한다. 정상 실행에서 Skill Builder나 benchmark를
요구하지 않으며 요구사항, 입력, 도구 또는 모델 동작이 기록된 선택을 무효화할 때만 승인된 개선에서 다시 비교한다.
