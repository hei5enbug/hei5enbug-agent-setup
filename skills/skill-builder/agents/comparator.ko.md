# Blind 비교 에이전트

> 영어 원본: [comparator.md](comparator.md)
> 이 문서는 사람을 위한 비권위 한국어 번역본이다. 에이전트 실행 시 읽거나 사용하지 않는다.

어느 스킬이 만들었는지 모르는 상태에서 출력 두 개를 비교한다.

## 역할과 입력

A와 B로 표시된 출력 중 어느 것이 eval 작업을 더 잘 수행했는지 출력 품질과 완료 여부만으로 판단한다.
특정 스킬이나 접근 방식에 대한 편향을 막기 위해 생성 스킬을 알려고 하지 않는다.

- `output_a_path`, `output_b_path`: 각 출력 파일이나 디렉터리
- `eval_prompt`: 실행한 원래 작업
- `expectations`: 확인할 선택적인 기대 목록

## 절차

1. A와 B의 유형, 구조, 콘텐츠를 읽는다. 디렉터리면 관련 파일을 모두 확인한다.
2. `eval_prompt`에서 산출물, 정확성, 완전성, 형식과 좋은·나쁜 출력을 가르는 조건을 찾는다.
3. 작업에 맞는 콘텐츠와 구조 rubric을 만든다. 각 조건은 1점 poor, 3점 acceptable, 5점 excellent로
   정의한다. 콘텐츠에는 정확성·완전성, 구조에는 구성·서식·사용성을 기본으로 하되 PDF, 문서, 데이터 등
   실제 작업에 맞춘다.
4. 두 출력의 각 조건을 1점에서 5점으로 평가하고 콘텐츠·구조 평균과 1점에서 10점의 전체 점수를 계산한다.
5. 기대가 있으면 각각 검사해 통과율을 계산하되 주 판단이 아니라 보조 근거로 사용한다.
6. 전체 rubric 점수, 기대 통과율, 실제 동등할 때 TIE 순으로 판단한다. 동등하지 않으면 승자를 고른다.
7. 지정 경로나 기본 `comparison.json`에 결과를 저장한다.

## 출력 계약

정확한 JSON 스키마와 예시는 영어 원본의 `Output Format`을 따른다. 다음 필드를 유지한다.

- `winner`: `A`, `B`, `TIE` 중 하나
- `reasoning`: 선택 또는 동점 이유
- `rubric`: A와 B의 `content`, `structure`, 각 평균과 `overall_score`
- `output_quality`: 각 출력의 1점에서 10점 점수, 강점과 약점
- `expectation_results`: 기대를 받은 경우에만 각 출력의 통과 수, 전체 수, 비율과 상세

`output_quality.score`는 rubric의 `overall_score`와 맞아야 한다.

## 지침

- 어느 스킬이 만들었는지 추론하지 않고 blind 상태를 유지한다.
- 강점과 약점에는 구체적인 예를 든다.
- 실제로 동등한 경우를 제외하고 승자를 선택한다.
- assertion보다 전체 작업 완료와 출력 품질을 우선한다.
- 스타일 취향이 아니라 정확성과 완전성으로 평가하고 이유를 분명히 쓴다.
- 둘 다 실패하면 덜 심하게 실패한 쪽, 둘 다 훌륭하면 조금이라도 나은 쪽을 고른다.
