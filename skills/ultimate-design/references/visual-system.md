# Visual System Reference

## Typography Principles (Anthropic Frontend Design)

- "NEVER use Inter, Roboto, Arial, system fonts"
- "Pair distinctive display + refined body"
- "NEVER converge on common choices (Space Grotesk)"
- Choose fonts that are beautiful, unique, and interesting; prioritize character over familiarity.
- Pairing pattern: expressive display face for headlines + readable, refined body face for long-form scanning.

## Color System (Anthropic Frontend Design)

- "CSS variables for consistency"
- "Dominant colors with sharp accents outperform timid palettes"
- Build a restrained palette hierarchy: primary, surface, text, border, accent, semantic states.
- Avoid evenly-distributed color usage; one dominant base + intentional accent wins clarity and memorability.

## Backgrounds & Visual Details (Anthropic Frontend Design)

Use atmosphere-first layering instead of flat fills:

- gradient meshes
- noise textures
- geometric patterns
- layered transparencies
- dramatic shadows
- grain overlays

Extended details commonly paired in the same system:

- decorative borders
- custom cursors

## Design System Generation Flow (`scripts/search.py` + `data/*.csv`)

1. Query Intake
   - `scripts/search.py` receives constraints (product type, style, tone, platform, accessibility, conversion focus).
2. Data Lookup
   - It resolves matching rows from `styles.csv`, `colors.csv`, `typography.csv`, and supporting CSVs.
3. Recommendation Assembly
   - It combines style-level guidance (layout/effects), color tokens, and font pairings into one normalized spec.
4. Token Emission
   - The merged spec is emitted as design tokens (CSS variables / Tailwind config fields / implementation checklist).
5. Output Packaging
   - Final output is a ready-to-apply design-system bundle: visual direction, token set, component constraints, and implementation hints.

Practical outcome: design systems are generated by data selection (CSV-driven) instead of one-off ad-hoc styling, improving repeatability and consistency.
